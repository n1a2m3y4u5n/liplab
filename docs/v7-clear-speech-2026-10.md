# V7 명료 발화 → 대화체 진폭 비계: 사전 기준과 0단계 결과 (2026-10-07)

종합 계획(`docs/master-plan-2026-10.md`) 트랙 V의 V7이다. 아바타가 처음에는 입을 크게 벌려 또박또박 보여 주고, 학습자가 숙달할수록
대화체 크기로 줄이는 진폭 단계를 둘지, 둔다면 단계 크기를 얼마로 할지를 538 라벨로 정하려 했다(idea-sweep 가7).

## 1. 사전 기준(10/3 가7, 10/4 종합 계획에서 고정, 이 문서에서 바꾸지 않음)

- **0단계(0원):** 538 라벨만으로 같은 화자가 여러 소음 조건을 녹음했는지 센다. **조건 쌍이 있는 화자가 30명 이상일 때만 1단계로 간다.**
- **1단계(채택 판정):** 화자마다 소음 조건 발화와 무소음 발화의 jawOpen 95백분위 비를 구하고, 화자 부트스트랩 95% 구간의 **하한이 1.0보다 클 때만**
  그 비를 '명료' 단계 진폭으로 채택한다. '대화체' 단계는 자유발화 분포에서 가져온다.
- 미달이면 '명료' 단계를 채택하지 않고 부정 결과로 적는다. 이번 작업 범위에서는 미달일 때 앱을 바꾸지 않고 문서만 남긴다
  (가7의 '문헌 값 사용'은 따로 결정할 일로 넘긴다, 5절).

통과했을 때 하려던 앱 반영(기록용): 숙달 단계별 진폭 배율을 `frontend/src/lib/talkers.js`의 화자 배율(`amp`, `AMP_KEYS`) 경로에 곱하고,
학습자 숙달은 기존 단계 상태 API 값(`/api/curriculum/stages`의 status)으로 고른다. 진폭 배율은 538 집계 상수로만 둔다.

0단계 집계는 이 문서를 커밋하기 전에 같은 작업 안에서 먼저 돌렸다. 기준은 위 두 문서에 이미 고정되어 있었고, 집계를 본 뒤 바꾼 것은 없다.

## 2. 자료와 방법(0단계)

- 538 파일 이름은 `lip_<묶음>_<소음 환경>_<성별>_<나이대>_<인물>_<시점>_<대본>` 꼴이다(예: 묶음 J, 환경 1, 인물 C901). 받기 도구의 자체검사
  (`liplab-lab/tools/dl_more.sh`)에 남은 tar 안쪽 경로도 `소음환경1/C(일반인)/...` 꼴이라, 소음 환경은 녹음 묶음 단위로 붙는다.
- `scripts/v7_noise_pairs.py`가 맥에 남은 manifest와 받기 기록(`liplab-lab/data` 아래 tsv·log·out·json)에서 파일 이름을 모아 인물 번호별
  소음 환경 수를 센다. 받기 중인 작업 폴더(`data/v1_538/.work`)와 받기 프로세스는 건드리지 않았다. 출력은 집계뿐이다
  (`liplab-lab/data/v7/step0.json`).
- 대상: D 벤치 30명, 9/25 새 화자 38명, 지금 진행 중인 V1 받기에서 끝난 화자와 그 tar 안에서 이름이 보인 인물을 합친 것이다.

## 3. 0단계 결과

| 항목 | 값 |
|---|---|
| 이름이 보인 파일 | 357개 |
| 서로 다른 인물 | 152명(C 계열 110, E 계열 42) |
| 소음 환경별 인물 | 환경 1: 47, 2: 28, 3: 26, 4: 21, 5: 22, 6: 8 |
| 묶음별 | J는 환경 1·2·6, K는 환경 3·4·5에만 있다 |
| **둘 이상의 소음 환경을 녹음한 인물** | **0명**(기준 30명) |

- 인물 번호가 환경마다 따로 매겨지는 체계였다면, 번호 범위(C001~C957, E007~E274)와 인원으로 보아 다른 환경 사이에 같은 번호가 평균 7.5번
  겹쳐야 한다(무작위 배정 가정, 0번일 확률 약 0.06%). 하나도 겹치지 않으므로 인물 번호는 자료 전체에서 하나이고, **한 인물은 한 소음
  환경에서만 녹음했다**고 본다. 반대로 번호는 전체에서 하나인데 인물마다 두 환경을 녹음했다면, 152명 표본에서 같은 인물이 약 4.7번 보여야 한다
  (같은 가정, 0번일 확률 약 1%). tar마다 앞쪽 인물만 받는 표집이라 무작위 가정은 어림이다.
- 같은 사람이 번호를 바꿔 다른 환경에 다시 나왔을 가능성은 라벨로 확인할 수 없다. 그런 경우가 있더라도 라벨로 짝을 지을 수 없으므로
  0단계 조건(라벨로 센 조건 쌍)은 같다.

## 4. 판정

- **0단계 미달(조건 쌍 화자 0명 < 30명).** 1단계 비(화자 안 소음/무소음 jawOpen)를 538로는 계산할 수 없어 판정 불가이며, 사전 기준대로
  **'명료' 단계를 채택하지 않는다. 앱은 바꾸지 않았다.**
- V2(`docs/avatar-validity-2026-10.md` 10.5절)의 화자 사이 비교(소음 라벨 1인 화자와 2인 화자의 J 진폭 중앙값이 두 절반에서 방향이 엇갈림)는
  환경과 인물이 섞인 비교라 이 판정에 쓰지 않는다. 그 비교를 늘려도(화자를 더 받아도) 화자 안 비라는 기준을 대신하지 못한다.
- 주장 문장: "538은 인물마다 소음 환경이 하나라(인물 152명 중 둘 이상 0명) 같은 사람의 소음·무소음 입 벌림 차이를 측정할 수 없다. 명료 발화
  진폭 단계는 538 근거가 없어 넣지 않았다."

## 5. 넘기는 결정

- 가7은 미달일 때 문헌 값(시청각 롬바르드 말뭉치의 입 움직임 증가)을 쓰자고 했다. 그 값은 영어 화자, 다른 측정기에서 나온 것이라
  앱의 진폭 배율로 옮기려면 따로 근거가 필요하다. 이번에는 넣지 않았고, 넣을지는 사용자 결정으로 남긴다.
- 화자 안 비교가 가능한 경로는 두 가지다. (1) P2 촬영 목록에 같은 사람의 '또박또박'·'평소 대화체' 낭독을 한 쌍으로 넣는다(동의 범위 안,
  소음 대신 명료 지시로 같은 비를 측정). (2) 같은 인물이 여러 조건을 녹음한 한국어 시청각 자료를 찾는다. 둘 다 이번 작업에서는 하지 않았다.
- 538의 '자유발화' 라벨(전문가 화자 일부)로 낭독과 대화체를 같은 인물 안에서 비교하는 것은 V7 기준이 아니어서 이번에 하지 않았다. 라벨
  JSON(`Sentence_info`의 topic, `speaker_info`의 Specificity)은 받기 도중에만 읽고 남기지 않아서, 하려면 라벨을 다시 스트리밍해야 한다.

## 7. 10/9 재검토: 소음 설계는 538에서 원리상 불가, 낭독·자유발화 설계(V7b)를 새로 등록

### 7.1 10/7에 판정 불가로 끝난 이유

0단계 기준(소음 조건 쌍이 있는 화자 30명 이상)에서 조건 쌍 화자가 0명이었다(3절). 같은 인물이 둘 이상의 소음 환경에 나오지 않았다.

### 7.2 소음·무소음 설계가 538에서 원리상 불가한 근거

- **녹음 설계.** OLKAVS 논문(Park 외 2023, arXiv 2301.06375, 2.2절)은 소음을 스튜디오 안에 틀어 녹음했고(롬바르드 효과가 생길 수 있는 설계),
  시나리오 여섯 가지(무소음 29%, 나머지 다섯이 14%씩)를 두었다고 적는다. 화자 안에서 시나리오를 바꿨다는 서술은 없다.
- **자료 구조.** 10/9에 라벨 tar 두 개(TL1, TL121)를 끝까지 받아 이름을 셌다. 경로는 `TLn/소음환경N/C(일반인)|E(전문가)/성별/묶음/파일`이고,
  두 tar의 인물 모두가 대본 12개 × 시점 5개 = 60파일을 한 소음 환경 폴더 안에 다 갖고 있다. 한 인물의 녹음 일정 전체가 한 환경에서 끝나므로
  같은 인물 번호로 다른 환경의 녹음이 따로 있을 자리가 없다. 10/7의 인물 152명 집계(둘 이상 0명)와도 맞는다.
- 따라서 538을 더 받아도 화자 안 소음/무소음 비는 계산할 수 없다. 화자 사이 비교는 사람과 환경(녹음 묶음)이 섞여 V7 기준을 대신하지 못한다
  (4절). **'명료(롬바르드)' 단계의 진폭은 538로 정할 수 없다.** 같은 사람의 소음·무소음 영상은 P2 촬영(같은 사람의 '또박또박'·'평소 대화체'
  짝)이나 다른 자료에서 구해야 한다.

### 7.3 새 설계 V7b: 전문가 화자 안 낭독 대 자유발화

- **근거.** 논문 2.1절은 화자의 30%가 전문가(아나운서·배우와 지망생)이고 전문가 발화의 50%가 주어진 기사에 대한 자유발화라고 적는다. 라벨에는
  자유발화 표시가 없지만, TL121의 전문가 E090은 대본 001~006이 다른 화자와 같은 대본 문장(낭독)이고 007~012는 주제가 바뀌고 머뭇거림·고쳐
  말하기가 있는 자유발화였다. 이 대비는 같은 사람 안의 '또박또박 낭독'과 '대화체'라서 V7의 아래쪽 끝(대화체 단계)을 화자 안 비로 정할 수 있다.
  지금 아바타의 기준 진폭은 538 낭독으로 보정되는 쪽(V15)이므로, 비계는 '낭독 크기 → 대화체 크기' 두 단계가 된다. 낭독보다 큰 '명료' 단계는
  7.2절 때문에 이 설계로도 정하지 않는다.
- **자료.** V1 받기 기록에서 영상 tar 머리가 전문가의 정면 대본 001부터 시작한 22개 배치(spk345·347·353·374·377·379·387·407·409·411·437·447·
  471·473·477·503·507·509·511·607·612·627). 영상 tar 안에서 한 인물의 정면 대본은 001부터 차례로 이어진다(10/9 spk407에서 001~007 확인).
  배치마다 앞 4.2GB를 받아 대본 001~008을 얻고, 받기 도구(`tools/dl_more.sh`, 같은 문장 자르기 규칙)로 문장 클립을 자른다. 이번 세션 안에 받기가
  끝난 화자만 쓴다(목록 순서는 두 절반을 번갈아 둔다).
- **조건.** 낭독 = 대본 005·006, 자유발화 = 대본 007·008(시간상 이웃한 대본끼리 비교해 녹음 순서·피로의 영향을 줄인다).
  화자 포함 규칙(라벨만으로 정함): 10/9 라벨 머리 조사(`liplab-lab/data/v18/tl_survey.jsonl`, 배치마다 라벨 tar 앞 25MB의 문장 해시)를 다른 인물의
  문장 모음으로 쓰고, 대본 005·006의 문장 중 모음과 같은 것이 3개 이상, 대본 007·008에서 1개 이하일 때만 넣는다. 조건마다 품질을 통과한 클립이
  20개 이상이어야 한다.
- **측정.** 클립을 V2와 같은 MediaPipe 추출기(파드)로 재고, 라벨 문장 구간(클립 앞뒤 0.08초 여유를 뺀 구간)에서 얼굴이 잡힌 프레임의 jawOpen을 모은다.
  화자 s의 비 r_s = 낭독 jawOpen 95백분위 / 자유발화 jawOpen 95백분위.
- **절반.** `crc32(화자 ID) % 2`. 절반 0은 탐색(측정 절차 점검, 비의 점 추정), 절반 1은 확인이다.
- **판정: 확인 절반 화자의 log r_s 평균을 지수로 되돌린 기하평균 비의 화자 부트스트랩 95% 구간(4,000회, 시드 0) 하한 > 1.0이면 '대화체' 단계를
  채택한다.** 확인 절반 화자가 8명 미만이면 판정 불가로 적는다.
- **보고만:** jawOpen 50백분위 비, 돌출 R(funnel + pucker)·폭 S 95백분위 비, 말 속도(초당 음절, 라벨 문장 글자 수 기준) 비, 화자별 값.
- **통과하면 앱 반영(플래그 뒤, 기본값 변경은 사용자 결정):** 대화체 단계의 MediaPipe jawOpen이 낭독 단계의 1/r(두 절반을 합친 기하평균)이 되도록,
  `talkers.js`의 입 벌림 배율(`AMP_KEYS`)에 m = r^(−1/γ)를 곱한다. γ는 V15 9.5절의 아바타 반응(입 벌림 0.8 → J 0.45배, 1.25 → 2.0배)에서
  γ = 평균(ln 0.45/ln 0.8, ln 2/ln 1.25) ≈ 3.3으로 둔다. 학습자 숙달 단계로 고르는 경로는 1절 기록대로이고, 빌드 플래그 `VITE_AMP_SCAFFOLD=1`일 때만 켠다.
  미달이면 앱을 바꾸지 않고 부정 결과로 적는다.
- **주장 상한.** 전문가(아나운서·배우 지망생 포함)의 낭독과 기사에 대한 자유발화의 차이다. 일반인 대화체나 청각장애인 대화 상대의 입 움직임을
  대표한다고 주장하지 않는다. 낭독 대본과 자유발화는 내용도 다르다.
