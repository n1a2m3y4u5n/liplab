## 3. 청크 주의 학습

- 주의 가리개는 **창 단위 입력**으로 구현한다. 학생은 창 안의 소리만 받으므로 창 밖을 볼 수 없고, 합성곱 특징 추출부의 그룹 정규화·위치 합성곱의 가장자리까지
  스트리밍 추론과 같은 조건이 된다(전체 입력에 블록 가리개를 거는 방식은 위치 합성곱과 그룹 정규화가 창 밖을 보게 되어 추론과 어긋난다).
- 흐름: 학습 풀 항목을 패스마다 섞어(시드 0 + 패스 번호) 차례로 이은 흐름을 만든다. 이음매에서 교사 목표가 없는 프레임 하나(두 발화에 걸친 프레임)는 손실에서 뺀다.
  항목 길이는 320표본 배수로 자른다(끝 나머지 버림).
- 창 길이: 단계마다 하나를 뽑는다. 확률 0.6으로 L + C + R(L = C = 4초, R ~ U[1, 2]초), 0.4로 U[3, 9]초(첫 창·마지막 창처럼 짧은 창). 320표본 배수.
  한 묶음 = 같은 길이의 창 floor(240초 / 창 길이)개(최대 64).
- 창 자르기: 흐름에서 겹치지 않게 차례로 자른다(다음 창 시작 = 이번 창 시작 + 창 길이 − R). 손실 프레임은 창 처음부터 창 끝 R초 전까지다. 창 끝이 발화 끝과 같으면
  끝까지 넣는다(마지막 창은 미래 소리가 없고 교사도 그렇다). 짧은 창(0.4 몫)은 R = 1초로 둔다.
- 목표는 각 발화를 통째로 넣은 교사 로짓(전체 문맥)이다. 학생 프레임 j는 창 시작/320 + j의 흐름 프레임과 맞는다.
- 메모리: 묶음을 마이크로 묶음으로 나눠 기울기를 모은다(손실은 묶음 전체 손실 프레임 평균, 원 등록의 묶음 평균과 같은 식). bf16 자동 혼합 정밀도(원 등록과 같음).
- 체크포인트: 250단계마다와 패스 끝마다 `runs/HC/ckpt.pt`(이어 학습 가능). 결과 `runs/HC/final.pt`.

## 4. 스트리밍 추론(판정에 쓰는 고정 설정)

- (9절에서 L을 2.0초로 바꿈) C = 4.0초, L = 4.0초, R = 1.0초. 녹음 길이 n. t = 0, C, 2C, …에서 t + C + R ≤ n이면 창 [max(0, t − L), t + C + R]을 넣고 [t, t + C)의 프레임만 남긴다.
  더 넣을 수 없으면(녹음 끝) 남은 [t_e, n)을 창 [max(0, t_e − L), n]으로 한 번 넣고 그 프레임을 남긴다. n ≤ C + R이면 창 하나(전체 순전파와 같다).
- 남긴 로그확률을 이어 붙여 앱과 같은 강제정렬·채점(`dgop_acoustic.assess_text`, b675975 backend)에 넣는다. 정렬 몫·채점 몫 둘 다 같은 창 나누기를 쓴다.
- 학생 실행은 주 산출물(가중치 전용 int8 ONNX)을 ONNX Runtime CPU 2스레드로 한다(원 등록 6절).
