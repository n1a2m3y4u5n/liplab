# 서버 음성(C17) 자극 품질 점검과 재합성 (2026-10)

2026-10-07 작성. 소리 조건(`docs/sound-condition.md`)과 소리 듣기 트랙이 함께 쓰는 Supertonic 3 합성 클립 4,498개(m1·f1 각 1,277,
m2·f2·m3 각 648)를 전수 점검하고, 기준에 못 미친 클립을 같은 목소리로 다시 합성한다. 1~6절은 점검을 돌리기 전에 정해 커밋한
판정 규칙이다(사전 기준). 실행 뒤에 규칙을 바꾸지 않으며, 바꿔야 할 결함이 드러나면 결과 절에 '사후 변경'으로 따로 적는다.

규칙을 쓰기 전에 본 자료는 두 가지다. (1) 10/7 본 합성 때 남은 m1의 base 전사·D-GOP 기록(1,277개), (2) 지금 클립 중 무작위
200개의 앞뒤 무음과 대략의 레벨(앞 무음 10~90백분위 100~160 ms, 뒤 무음 100~180 ms, 말소리 창 평균 레벨 10~90백분위 약 4 dB 폭).
D-GOP 문턱과 5절의 정리 여부 규칙은 이 자료를 보고 정했다.

## 1. 측정

모든 측정은 파드에서 한다(GPU는 전사, CPU는 D-GOP·정렬·신호). 기존 클립은 저장소의 Ogg Opus를 풀어(48 kHz) 측정하고, 새 후보는
합성기가 낸 무손실 소리로 측정한다.

### 1.1 전사와 소리 나는 대로 비교

- 전사: faster-whisper `large-v3`(CTranslate2 float16, GPU), `language="ko"`, beam 5, temperature 0, `condition_on_previous_text=False`,
  `without_timestamps=True`, VAD 없음. 전사 뒤 앱과 같이 `speak_service.collapse_repeats`로 되풀이를 접는다.
- 비교: 목표 글과 전사를 같은 방식으로 바꾼다. 숫자를 한국어 읽기로(`korean_numbers.normalize_numbers`), 한글만 남기고 띄어쓰기를
  없앤 뒤 `scoring.to_pronounced_jamos`로 소리 나는 대로 자모열을 만든다. 표준 발음에서 소리로 가를 수 없는 모음 합류
  (ㅐ=ㅔ, ㅒ=ㅖ, ㅙ=ㅞ=ㅚ)는 같은 자모로 본다. 띄어쓰기를 없애는 것은 '고장 났어'와 '고장났어'처럼 띄어쓰기만 다른 전사를 맞음으로
  보기 위해서다.
- **PER** = 두 자모열의 편집 거리 ÷ 목표 자모 수. PER 0이 소리 나는 대로 완전 일치다.
- 참고 기록: `listen_curriculum.word_score`(낱말 단위, `sentence_feedback.consonant_feedback`)의 낱말 정답 비율. 판정에는 쓰지 않는다.

### 1.2 D-GOP와 음절 시각

- `dgop_acoustic.assess_text`(배포와 같은 int8 자체 학습 정렬기·채점기, 앵커 `dgop_calibration_ours.json`)의 표시 점수 **S**(0~100).
- 같은 정렬의 자모 구간으로 `sound_clips.syllable_times`를 구한다(지금 목록과 같은 방법).

### 1.3 신호

- **활성 레벨 L**: ITU-T P.56 방법 B(`frontend/src/lib/listenMix.js`의 `activeLevel`과 같은 알고리즘을 Python으로 옮김), dBFS.
- **말소리 구간**: 10 ms 창 RMS가 L − 35 dB를 넘는 첫 창의 시작과 마지막 창의 끝. 앞 무음 = 첫 창 시작, 뒤 무음 = 길이 − 마지막 창 끝.
- **잘림**: |x| ≥ 0.99인 표본 수.
- **돌발 큰 소리**: 5 ms 창 RMS가 L + 15 dB를 넘는 창 수.
- **모음 끊김**: 정렬된 중성(`n:`) 구간의 RMS가 L − 30 dB보다 낮은 중성 수(소리가 없는 곳에 모음이 놓였다는 뜻).
- **긴 쉼**: 이웃 음절 사이 틈(앞 음절 마지막 자모 끝부터 다음 음절 첫 자모 시작까지). 같은 어절 안과 어절 사이를 나눈다.
- **꼬리 군소리**: 마지막 자모 끝 뒤로 말소리 창이 이어지는 길이(ms).
- **말 빠르기**: 5음절 이상은 음절 수 ÷ (마지막 자모 끝 − 첫 자모 시작) 음절/초, 2~4음절은 음절당 ms, 1음절은 말소리 구간 길이.
  기준 분포는 기존 클립 점검 결과의 목소리 × 길이 묶음(1, 2~4, 5 이상)마다 중앙값과 MAD이고, 강건 z = 0.6745 × (x − 중앙값) ÷ MAD.
  새 후보도 이 기존 기준으로 z를 구한다.
- **레벨 편차**: L − 그 목소리 기존 클립 L의 중앙값. 새 후보는 레벨을 맞추기 전 합성 원본으로 측정한다.

### 1.4 음절 시각 유효성

음절 시각이 있고, 개수가 `sound_clips.syllable_positions(글)`의 개수와 같고, 시작이 단조 증가하고(뒤 음절 시작 ≥ 앞 음절 시작),
모든 음절이 t0 < t1이고, 마지막 t1이 소리 길이를 넘지 않아야 한다. 기존 클립은 목록에 적힌 시각을 검사하고, 풀어 낸 소리로 다시
정렬한 시각과의 음절 시작 차도 기록한다(인코딩으로 시각이 밀렸는지 확인).

## 2. 판정 규칙

클립마다 통과, 의심, 실패 세 등급 중 하나를 준다. 발음·신호·음절 시각 각각의 등급 가운데 가장 나쁜 것이 클립 등급이다.
의심 항목이 여러 개면 그 수를 함께 센다(후보 선택에 쓴다).

### 2.1 발음

길이 묶음은 목표 글의 음절 수(`syllable_positions`)로 나눈다. S가 없으면(정렬 실패) 묶음과 상관없이 실패다.

| 묶음 | 통과 | 의심 | 실패 |
|---|---|---|---|
| 문장(5음절 이상 또는 띄어쓰기 있음) | PER = 0 | 0 < PER < 0.15 이고 S ≥ 80 | PER ≥ 0.15, 또는 PER > 0 이고 S < 80 |
| 낱말(2~4음절, 띄어쓰기 없음) | PER = 0 이고 S ≥ 45 | PER = 0 이고 S < 45, 또는 PER > 0 이고 S ≥ 70 | PER > 0 이고 S < 70 |
| 한 음절, 전사가 한글 한 음절일 때 | PER = 0 이고 S ≥ 30 | PER = 0 이고 S < 30, 또는 PER > 0 이고 S ≥ 60 | PER > 0 이고 S < 60 |
| 한 음절, 전사를 쓸 수 없을 때(빈 전사, 두 음절 이상, 한글 아님) | S ≥ 60 | 40 ≤ S < 60 | S < 40 |

근거. 문장은 large-v3가 문맥으로 거의 정확히 받아쓰므로 전사를 주 증거로 하고, D-GOP는 전사가 조금 어긋날 때의 보조 증거로 쓴다.
한 음절과 짧은 낱말은 받아쓰기가 불안정하다(10/7 비교에서 turbo로도 한 음절 완전 일치 19/25). 그래서 전사와 D-GOP가 함께 나쁠 때만
실패로 하고, 한쪽만 나쁘면 의심으로 둔다. D-GOP 문턱은 기존 m1 분포(문장 5백분위 83.3, 낱말 5백분위 67.4, 한 음절 10백분위 52.9)에서
정했다. 한 음절은 모음 하나짜리('아' 23.9, '에' 26.9)처럼 전사가 맞아도 S가 낮은 경우가 있어 전사 일치 때의 문턱을 낮게 두었다.

### 2.2 신호

| 항목 | 의심 | 실패 |
|---|---|---|
| 말소리 구간 | | 50 ms 미만(사실상 무음) |
| 잘림 | 1~2표본 | 3표본 이상 |
| 돌발 큰 소리 | 1창 이상 | |
| 모음 끊김 | 1개 이상 | |
| 같은 어절 안 쉼 | | 400 ms 초과 |
| 어절 사이 쉼 | 1,000 ms 초과 | |
| 꼬리 군소리 | 300 ms 초과 | |
| 말 빠르기 | 강건 \|z\| > 3.5, 또는 1음절 구간이 120 ms 미만·1,000 ms 초과 | 5음절 이상에서 9.0음절/초 초과 또는 2.5음절/초 미만 |
| 레벨 편차 | \|편차\| > 6 dB | |
| 앞뒤 무음(기존 클립만) | 앞이나 뒤가 60 ms 미만 또는 400 ms 초과 | |

새 후보는 5절의 정리로 앞뒤 무음과 레벨이 정해지므로 앞뒤 무음 항목을 보지 않고, 레벨 편차는 정리 전 원본으로 본다.

### 2.3 음절 시각

1.4의 조건을 하나라도 어기면 실패다.

## 3. 후보 합성(best-of-N)

같은 목소리(목록의 `engine_voice`)로 아래 후보를 만든다. 합성 직전에 numpy 난수 시드를 후보 번호로 정한다. 엔진이 시드를 받거나
numpy 난수를 쓰지 않으면 결과 절에 실제 방식을 적는다.

| 후보 | total_steps | speed | 글 | 시드 |
|---|--:|--:|---|--:|
| c0 | 8 | 1.05 | 그대로(지금 클립과 같은 설정) | 0 |
| c1 | 16 | 1.05 | 그대로 | 1 |
| c2 | 8 | 1.05 | 그대로 | 2 |
| c3 | 32 | 1.05 | 그대로 | 3 |
| c4 | 16 | 1.00 | 그대로 | 4 |
| c5 | 16 | 1.05 | 끝에 문장 부호가 없으면 마침표를 붙인다 | 5 |
| c6 | 32 | 0.95 | 그대로 | 6 |
| c7 | 16 | 1.10 | 그대로 | 7 |

1단계는 c0·c1이고, 1단계에 통과 후보가 없는 클립만 2단계 c2~c7을 만든다. 숫자·로마자가 든 글은 지금 목록에 없으므로(검사 0개)
표기 정규화 후보는 따로 두지 않는다. 합성에 넣는 글은 지금과 같이 `korean_numbers.normalize_numbers`를 거친 글이다.

### 3.1 선택 기준

후보마다 1~2절과 같은 판정을 하고, 다음 키를 사전식으로 비교해 가장 작은 후보를 고른다.

1. 등급(통과 < 의심 < 실패)
2. 의심 항목 수
3. PER
4. −S(D-GOP가 높을수록 앞)
5. 말 빠르기 \|z\|(기준 중앙값에 가까울수록 앞)

## 4. 교체 규칙

- 5절의 일괄 정리를 하면 모든 클립을 다시 합성한다. 고른 새 후보의 등급이 기존 클립 등급보다 나쁘지 않으면 새 후보로 바꾸고,
  나쁘면 기존 클립을 그대로 둔다(파일 이름도 그대로).
- 일괄 정리를 하지 않으면 의심·실패 클립만 후보를 만들고, 고른 후보의 등급이 기존보다 좋을 때만 바꾼다.
- 2단계까지 해도 통과 후보가 없는 클립은 '미해결'로 결과 절에 모두 적는다(교체 여부는 위 규칙대로).

### 4.1 콘텐츠 검수 반영(실행 전 추가, 2026-10-07)

점검을 띄운 직후, 소리 듣기 콘텐츠 검수(`docs/review/listen-content-review-2026-10.md`)가 integrate에 들어와 듣기 글이
648개에서 618개로 바뀌었다(소리 구별 음절 8, 훈련 문장 47, 대화 대사 25가 새로 들어오고, 쓰지 않게 된 글이 빠짐). 기존 점검의
측정이 하나도 끝나기 전에 아래를 더했다.

- 대상은 지금 인벤토리(`sound_inventory.py`, 모든 화면의 출처)가 쓰는 글만이다. 인벤토리에서 빠진 글의 클립(m1·f1 각 52, m2·f2·m3 각
  110, 합계 434개)은 점검하지 않고 목록에서 지운다. 인벤토리는 레슨·문맥 추론·3단계 문장·대화·듣기 출처를 모두 모으므로, 다른 화면이
  쓰는 글은 지워지지 않는다.
- 목록에 없던 글(m1·f1 각 78, m2·f2·m3 각 80, 합계 396개)은 1단계 후보부터 만들고, **통과 등급 후보만** 넣는다. 의심·실패만 남으면
  목록에 넣지 않고(화면은 '소리 준비 중') 결과 절에 적는다. 새 소리 구별 음절(무·부·누·두·수·후·서·저·달·단·박·방 등)과 브, 된소리,
  히·시, 막음 받침 음절은 한 음절 합성 오류 위험이 커서 이렇게 정했다.
- 그래서 점검 대상은 기존 4,064개와 새 글 396개, 합계 4,460개다.

## 5. 앞뒤 무음과 레벨 일괄 정리

결정 규칙: 기존 클립 전체에서 앞 무음의 10~90백분위 폭이 40 ms를 넘거나, 뒤 무음의 폭이 60 ms를 넘거나, 활성 레벨 L의 10~90백분위
폭이 3 dB를 넘으면 전체를 정리한다. 듣기 트랙의 같은지 다른지 문항은 두 클립을 600 ms 쉼으로 잇기 때문에 실제 말소리 사이 간격이
'앞 클립 뒤 무음 + 600 ms + 뒤 클립 앞 무음'이 되고, 소리 조건의 다시 보기는 클립 레벨을 그대로 튼다. 그래서 둘 다 일정해야 한다.

정리 방법. 무손실 원본이 필요하므로 다시 합성한 소리에만 한다. 지금 클립의 Ogg Opus를 풀어 다시 인코딩하면 손실 압축이 두 번
겹친다. 그래서 정리를 하면 4절대로 전부 다시 합성한다.

- 1.3의 말소리 구간 앞뒤로 150 ms씩 남긴다. 원본에 그만큼 무음이 없으면 0으로 채우고, 남으면 자른다. 양 끝 10 ms는 코사인
  페이드로 0에서 시작하고 0으로 끝낸다.
- 활성 레벨을 −24 dBFS로 맞춘다. 그때 최대 표본이 −1 dBFS를 넘으면 넘는 만큼 더 낮춘다(그 수를 기록한다).
- 음절 시각은 정리한 소리로 정렬한다(정리 전 시각을 옮기지 않는다).

## 6. 인코딩과 목록

- 인코딩은 지금과 같다. Ogg Opus 24 kbps VBR(48 kHz 모노), AAC-LC 24 kbps(24 kHz 모노, faststart).
- 파일 이름. 지금 규칙 `clip_id(키, 목소리)`는 글과 목소리만 해시하므로 소리를 바꿔도 이름이 같다. 소리 파일은
  `Cache-Control: immutable`로 1년 캐시되므로 이름이 같으면 이미 받은 브라우저는 옛 소리를 계속 쓴다. 그래서 `clip_id`에 선택 인자
  `rev`(다시 만든 소리 Ogg 파일의 sha1 앞 12자)를 더해, 바뀐 클립은 `sha1(목소리 + 키 + rev)` 앞 16자로 새 이름을 받는다. 목록 항목에
  `rev`를 적는다. 바뀌지 않은 클립은 옛 이름(`rev` 없음) 그대로다.
- 저장소의 소리 자료(목록 + 클립 + 소음)는 50 MB 이하를 지킨다.
