근거: `STATUS.md`, `docs/*-2026-10*.md`, 원장 0.6절. 등급 표기는 원장 0절 정의를 따른다. 결과가 기준에 못 미쳤으면 그렇게 적는다.

### 3.1 말하기 채점 (기계 판정)

- 새 청각장애(범주 28) 화자 18명 340조각으로 말하기 판정을 확인했다. 문장 일치 판별 AUC 0.971 [0.946, 0.994], 합격선 65에서 맞게 읽은 문장 불합격 11.8% [2.0, 25.5](40개 중 23개가 한 화자), 다른 문장 합격 1.5%. 대본 읽기 자료에 한한다(`docs/scoring-608-newspk-2026-10.md`).
- 같은 엄격도(정상 화자의 다른 문장 합격 5% 이하, 합격선 57)에서 청각장애 화자의 다른 문장 합격은 10.1%였다. 정상 화자에 맞춘 문턱이 청각장애 화자에게 그대로 옮겨 가지 않는다(`docs/pilot/claim-ledger.md` 0.3절).
- 전음성(범주 27) 화자 30명은 65점에서도 다른 문장 8.8%가 합격했다. 합격선 61, 고정 헤드, 집단 문턱, 묶음 판정 네 방법이 모두 기준에 못 미쳐 바꾸지 않았다(`docs/newdata-c27-judgments-2026-10.md`).
- 한두 소리 대치는 거의 가르지 못한다. 초성 1~2자리를 바꾼 538 교체 목표의 99.4%가 합격한다(`docs/speak-phoneme-floor-2026-10.md`). 10/21 대치 잡기 사전 등록 확인 판정도 실패였다(538 거짓 보류 3.91% > 3%, 특성 시간 0.216초 > 0.15초; `docs/scoring-subst-2026-10.md` 11절).
- 기준에 못 미쳐 앱에 넣지 않은 시도: 화자 적응 반례 정규화, 늦은 융합, 고정 헤드, 608 도메인 적응(ΔE −0.004 [−0.011, +0.003]), 최저 음소 규칙, Praat식 CPPS, 음소 칩 E1 보정(초성 ㄴ 거짓 빨강 15.5%). 원장 0.3절·0.6절 S1~S14.
- 9월 AUC 0.896 대비 '개선'은 주장하지 않는다. 오른 값은 조각 정제와 화자 묶음의 차이다.
- 긴 녹음 채점 지연을 줄이는 스트리밍 경로(지연 중앙 0.81초)와 코칭 비동기 수신으로 녹음 뒤 지연을 줄였다. 점수 보존은 아직 확인하지 않았다(`docs/scorer-stream-latency-2026-10.md`, 원장 S15).

### 3.2 아바타·독화 (기계 판정)

- 앱 기본 아바타의 입 움직임은 538 실제 화자와 같은 방법으로 쟀을 때 미리 정한 두 기준에 못 미쳤다(진폭이 사람 범위 안인 무리 1/13, 기준 11; `docs/avatar-validity-2026-10.md`). 새로 만든 문맥 평균 표(V3 간이판)도 확인 화자에서 2.0배 진폭 5/13(기준 11)으로 미달해 앱에 연결하지 않았다(`docs/avatar-v3-2026-10.md`). 사람이 읽는 정도는 측정하지 않았다.
- 아바타 기계 판독 곡선은 관문 0에서 미달(기준 V1 4지 16.0% [10.7, 22.0] < 25%)해 확인 없이 앱을 그대로 뒀다(STATUS.md 10/21, `docs/avatar-readability-2026-10.md`).
- 웹캠 '기계 확인'은 처음 보는 화자 26명에서 우연 수준(4지 21.8%, 우연 25%)이라 실험 기능으로 표시한다. ROI 입술 모델을 연결하는 빌드 플래그(`VITE_LIPREAD_ROI=1`)는 만들었으나 기본 끔이고, 입모양 목표 검증은 평가 40명 AUC 0.917 [0.900, 0.932]로 통과했다. 이웃 단어는 0.73~0.78로 약하다(`docs/lipread-verify-roi-2026-10.md`). 입모양을 읽는다는 주장은 하지 않는다.
- 3D 동시조음 E2는 사전 등록과 플래그 뒤 구현까지 했고 측정은 하지 않았다(`docs/coarticulation-e2-2026-10.md`).

### 3.3 소리 듣기 트랙 (기계 판정, 모의실험)

- 소음 속 검사의 SNR 맞추기 규칙과 검사 폼 등가는 가상 청취자와 음성 인식기 모의로 골랐다. 사람 청취 확인은 없다(원장 L1·L2).
- 배치검사 1차(96개 조합)와 2차(A 384·B 512개 후보)는 모두 기준 미달이라 넣지 않았다. 실시간 대화 합성은 지연 기준(최댓값 5.21초 > 5.0)에 못 미쳐 쓰지 않고, 미리 합성한 장면을 34개에서 58문항으로 늘렸다. 새 24문항은 LLM 1차 검수만 했고 사람 검수는 아직이다(원장 L4·L5·L7·L8).
- 10/27에 소리 듣기 전용 학습 경로, 하루 2묶음 몫, 묶음 보상, 체험 계정 잠금 분리를 구현했다(STATUS.md 10/27; 기본 끔 플래그는 켜지 않음). 이는 기능 구현이며 학습 효과 근거가 아니다. '치료'·'청력 개선'은 쓰지 않는다.

### 3.4 파일럿 도구·제품 (기계 판정)

- 타이핑 답 자동 채점 규칙(strict-v2·v3)을 고정했다. 판본 동일성만 결정적으로 확인했고 사람 채점과의 일치(ICC)는 측정하지 않았다(원장 P1).
- 쉬운 한국어 기준으로 화면 문구를 고쳤다. 이름표 90.4%, 덮기 95% 이상 파일 68.7%로 목표(95%·90%)에는 못 미친다(원장 P2).
- 채점 회귀 점검(O4)을 한 명령으로 돌릴 수 있게 했다(원장 P3).
- 10/27 dev 사용 중 결함을 고쳤다(계정 전환 401 로그아웃, 콘텐츠 시그니처 재사용, 문맥 문항 규칙 게이트). npm test 379/379, backend pytest 907/907(STATUS.md 10/27 2차 전체 검증).

쓸 수 있다(원장 0.5절 문장, 대본 읽기 자료에 한함): 608 새 화자 18명에서 문장 일치 판별 AUC 0.971. 같은 엄격도에서 다른 문장 합격 10.1%. 초성 한두 자리 바꿈 99.4% 합격. 앱 기본 아바타는 기계 측정 기준 미달. 학습 효과·전이는 사람 대상으로 측정하지 않았다. 기준에 못 미친 기능은 앱에 넣지 않았다.

쓰지 않는다: '청각장애 화자에게도 공정하다', '9월보다 채점이 개선되었다', '아바타 입모양이 실제와 같다', '학습 효과가 있다', '음소별로 틀린 소리를 알려 준다', '기계가 입모양을 읽어 준다', '실시간 대화 생성', '청력이 개선된다', '명료도 지수', '사람이 검수한 대화 문항'(원장 0.5절 목록 전체).
