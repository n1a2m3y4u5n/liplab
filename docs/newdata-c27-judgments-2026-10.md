## 1. 공통

- **집단.** 확인 자료는 608 범주 27(전음성 난청) 새 화자다. 범주 28(감음신경성) 확인을 대신하지 않는다. 판정 문구는 모두 '전음성 집단에서'로
  적고, 앱 상수를 바꾸자는 제안은 범주 28 근거와 함께만 낸다.
- **점수.** 앱 상수와 경로에 관한 판정(P1, P4)은 지금 앱 D-GOP(이 브랜치 backend, 끝 자르기·끝 구간 다시 나누기 기본 켬, int8, CPU 2스레드)로 낸다.
  S18 헤드(P2)는 헤드를 맞춘 b675975 경로의 특성으로 낸다. 채점 오류는 0점으로 센다(개수 보고).
- **짝.** 자기 문장 1 + 다른 문장 2(같은 범주 27 세트의 자기 문장 목록, 음절 수 ±30%, 한글만 남긴 문자열이 자기 문장과 같은 후보 제외,
  random.Random(0), cuts608.json 순서). 10/9 새 화자 확인과 같은 규칙이다(`scripts/newdata_c27/c27_pod.py` jobs).
- **구간.** 화자 부트스트랩 2,000회(시드 0, 화자를 복원 추출하고 뽑힌 화자의 모든 행), 95% 백분위.
- **다리(유효성).** 10/6 밤 run1의 538 클립 30개(이름 순 20개마다 하나)를 같은 파드에서 다시 채점한다. b675975 경로는 run1 특성과 헤드 확률 차
  ≤ 0.005·D-GOP 차 ≤ 0.1(맞춘 행 25개 이상), 지금 앱 경로는 10/9 ns 실행(`pod_runs/20261009_o11jkbqreech6s/ns`)의 끝 자르기 점수와 |차| ≤ 0.1.
  어기면 그 경로의 판정은 '보류'.
- **최소 자료.** 정제 뒤 화자 10명 이상, 자기 문장 100개 이상. 모자라면 '판정 불가'.
- **538 쪽.** 538 조건은 새 538 화자를 받지 않고 기존 자료를 다시 쓴다(2-1 재등록 4절의 허락과 같은 근거, 538 조건은 지금까지 여유가 컸다).
  재사용이라 538 수치는 확인이 아니라 조건 점검으로만 적는다.

## 3. P3 0점 음소 다음 후보: 낮은 음소 개수 규칙(탐색에서 끝남)

`docs/speak-phoneme-floor-2026-10.md` 8.3절의 다음 후보를 기존 덤프로 탐색했다(`scripts/newdata_c27/explore.py`, 후보와 기준은 실행 전에 코드에 적었고
결과와 함께 이 커밋에 넣는다).

- 후보 N(τ, z): 지금 합격(≥ 65)인 문장에서, 끝 음절을 뺀 채점 음소 m개 가운데 점수 < τ인 개수 L이 m·p0 + z·√(m·p0·(1 − p0))보다 크면 보류.
  p0 = 538 자기 문장 전체에서 그 음소가 τ 미만인 비율. τ ∈ {0.05, 0.2, 0.5}, z ∈ {2, 3}, 6개.
- 기준은 최저 음소 등록의 K1~K4 그대로(538 거짓 보류 ≤ 3%, 608 거짓 보류 ≤ 8%, 538 대치 잡기 ≥ 30%, 608 순이득 ≥ 0), 점추정, 기존 자료 전부(538 79명,
  608 범주 28 33명, 대치는 538 21명·608 10명).
- **결과: 실패(탐색).** 6개 모두 K1과 K3를 동시에 못 넘었다. 538 거짓 보류 9.4~17.2%에 538 대치 잡기 10.5~18.8%로, 538에서 순이득이 0에 가깝다
  (+0.5~+3.6%p). 608은 거짓 보류 16.2~29.7%, 대치 잡기 45.3~58.4%였다. p0는 τ = 0.05에서 9.6%, 0.2에서 13.0%, 0.5에서 17.8%다.
- 따라서 범주 27로 확인하지 않는다(확인할 후보가 없다). 범주 27 수치는 8절에 보고만 한다(N(0.05, 3)).

## 5. P4 같은 엄격도 다른 문장 합격 격차 후보(탐색: 기존 자료, 확인: 범주 27)

배경: 538에서 다른 문장 합격이 5% 이하가 되는 가장 낮은 정수(같은 엄격도) 57에서 608 범주 28의 다른 문장 합격은 13.0%(탐색 자료 33명)다. 앱은 65를 써서
다른 문장 합격을 1.9%로 막는 대신 자기 문장 불합격이 12.0%다. 학습을 바꾸지 않고 문턱 쪽에서 두 오류를 함께 줄이는 후보 둘을 본다.

- 탐색 자료(`explore.py` P4): 끝 자르기 판, 608 범주 28 33명(10/7 V2 15명 341·673짝 + 10/9 새 18명 340·673짝), 538 79명(10/6 600클립 + 10/9 새 21명 600클립).
- **C1 집단 기준 문턱**: 608과 538의 다른 문장 합격이 모두 5% 이하인 가장 낮은 0.1 간격 값. 탐색 결과 **t_G = 61.2**(608 다른 문장 합격 4.9%, 자기 문장 불합격 8.5%,
  538 다른 문장 합격 0.5%).
- **C2 여러 번 녹음 묶음(k = 3)**: 한 화자의 같은 종류(자기 또는 다른) 문장 서로 다른 3개의 점수 평균으로 판정한다(KSC `remedies.r2`와 같은 모의:
  화자마다 1,000번 뽑기, np.random.default_rng(1), 화자 이름 순, 화자별 비율의 평균). 문턱은 608과 538의 묶음 다른 문장 합격이 모두 5% 이하인 가장 낮은 정수.
  탐색 결과 **t_3 = 58**(608 묶음 다른 문장 합격 4.4%, 묶음 자기 문장 불합격 5.6%). 비교 기준 k = 1·65점(지금 앱)의 화자 평균 자기 문장 불합격은 12.7%.
- 확인(범주 27, 같은 모의 규칙):
  - C1 통과: 다른 문장 합격(≥ 61.2) 점추정 ≤ 5%이고 자기 문장 불합격이 65점보다 낮다(차의 구간 상한 < 0).
  - C2 통과: 묶음 다른 문장 합격(k = 3, ≥ 58) 점추정 ≤ 5%이고 묶음 자기 문장 불합격 − 지금 앱(k = 1, 65) 자기 문장 불합격의 구간 상한 < 0
    (화자별 비율을 한 번 계산한 뒤 화자 재표집, KSC와 같은 방식).
  - 538은 탐색 자료의 값을 조건 점검으로 적는다(C1 0.5%, C2 0.02%).
- 처리: C1 통과는 P1과 같은 종류의 합격선 제안이라 앱을 바꾸지 않는다. C2가 통과하면 묶음 판정을 플래그 뒤에 구현하고(기본 끔) 기본값은 사용자 결정으로 둔다.
