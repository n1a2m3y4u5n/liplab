- **9/27 늦은 밤: 배치검사 길이·대화·숫자 읽기(배포 안 함).** 적응형 배치검사를 고정 8문항에서, 시작 단계가 분명해지면(최소 5문항,

  77.7%에서 80.7%로 올랐다. 4단계 대화에서 AI가 같은 문장을 되풀이하거나 역할을 바꾸던 것을 고쳤고, 상황 문장이 기준에 못 미치면
  한 번 다시 받아 대체 문장으로 떨어지는 비율이 표본 30번 중 2번에서 0번이 됐다. 숫자 읽기는 사람 수 '분'(두 분), 시각(세시 삼십분),
  단위 기호(퍼센트·킬로미터 등), 전화번호를 더했다. 세부는 `STATUS.md` 9/27 늦은 밤.
- **9/27 밤: 배치·숙달·문항 질을 더 다듬었다(배포 안 함).** 배치검사가 '맞힌 최고 난이도'로 수준을 정해 찍어서 맞힌 문항 하나로
  문장 단계부터 시작하게 되던 것을 우연 정답을 반영한 추정으로 바꿔, 가상 학습자에서 시작 단계 일치가 50.8%에서 80.1%로 올랐다(폼).
  말하기 여섯 단계와 대화 단계도 최근 답에 무게를 두는 숙달 판정으로 바꿔 숙달이 빨라지면서 거짓 숙달도 줄었다. 1단계 입모양 퀴즈의
  약 15%가 화면에서 거의 같은 입모양을 오답 보기로 내 풀 수 없던 것을 고쳤고, 1단계 짝 미리보기의 틀린 예(바다/파도, 밥/입)를
  바꿨다. 아바타가 문항마다 새 WebGL 컨텍스트를 만들던 것과, 분석 화면이 기록 표를 통째로 훑던 것(인덱스)을 고쳤다. 세부는
  `STATUS.md` 9/27 밤.
- **9/27 저녁: 문항·피드백·속도를 더 다듬었다(배포 안 함).** 3단계 숙달도 이동 평균(문턱 80)으로 바꿔 거짓 숙달이 17.1%에서
  10.9%로 줄었다. 문장 4지선다 보기가 같은 레슨 문장이라 뒤 문항의 답(주관식·서술형의 40~56%)을 미리 보여 주던 것, 문맥 추론이
  같은 날 같은 문항을 다시 내던 것, 분석 탭 주별 정확도가 문항 유형 구성만 바뀌어도 내려가던 것을 고쳤다. 입모양 혼동 설명과
  조음 안내(ㅁ '터뜨린다', ㅅ '잇몸에 댄다', 소리 없는 ㅇ을 연구개음으로)를 자모·위치에 맞게 바로잡고, 음절·단어 말하기에서는
  억양을 지적하지 않는다. 아바타 입모양에 '괜찮아요 → 괜차나요', '꽃 → 꼳'을 반영했다. 정적 파일이 재검증 때마다 11MB 모델을
  다시 받던 것을 고치고 GLB를 압축해 보낸다. 약점 입모양 순위를 지식추적 숙달도 순으로 바꾸는 것은 시뮬레이션까지 하고 멈췄다.
  세부는 `STATUS.md` 9/27 저녁.
- **9/27: 채점·숙달·보기·리포트·콘텐츠를 다듬었다(배포 안 함).** 독화 이해 채점을 입모양 기준으로 바꿔 무관한 문장이
  46.9점에서 3.3점으로, 말을 덧붙인 답이 100점에서 42.3점으로 내려갔고, 객관식은 정확 일치로 채점한다. 1·2단계 숙달은 최근
  답에 무게를 두는 이동 평균으로 바꿔 거짓 숙달이 12.4%에서 6.5%로 줄었다. 2단계 단어 보기는 입모양이 똑같은 오답(문항의 57%)을
  빼고 진도에 따라 보기를 어렵게 한다(예전에는 입모양을 완벽히 읽어도 기대 정답률 65%). 학습 효과 리포트의 '초기 대비 최근'은
  단계별 문항 유형이 바뀌는 효과에 섞여 향상한 학습자의 84%를 '떨어졌다'로 보였는데, 유형별 비교로 고쳤다. 문맥 추론 문항은
  186개를 모두 읽어 결함 71개 중 26개를 고치고 45개를 뺐고(서빙 91), 2단계 단어 풀에서 드문 말 50개를 뺐다. 발음 규칙(못하다 →
  모타다)과 숫자 읽기(3시 → 세 시)를 넣고, 아바타 입모양 전환을 프레임 시간에 맞췄다. 기계 확인(축 D)은 보기를 입모양이 뚜렷이 다른
  단어로 바꿔도 새 화자 30.3%로 관문 미달이라 그대로 둔다. 말하기 음소 칩의 빨강 규칙을 바꾸는 실험도 사전 관문 미달이라 그대로지만,
  지금 규칙이 맞게 읽은 문장에도 빨강을 많이 칠한다는 것(원본 문장당 5.5개, 저하된 발화에서는 거의 전부)이 드러나 새 화자로 다시
  확인할 계획이다. 세부는 `STATUS.md` 9/27.
- **9/26: 개발 서버가 쉬다 켜질 때의 대기를 줄였다(저녁에 배포).** 켜진 뒤 모두 준비되기까지 약 4분이었고, 원인은 서버 디스크 읽기
  속도(초당 약 17MB)였다. 쉴 때 멈추지 않고 일시정지하게 바꿨고(시험에서 깨운 뒤 첫 채점 3.6초), 채점 모델을 미리 int8 파일로
  만들어 읽는 양을 1/3.5로 줄였으며(점수는 비트 단위로 같음), 예열에서 아바타 모델까지 미리 읽게 했다. 학습 경로 4단계
  '학습 시작하기'가 반응하지 않던 문제도 고쳤다. 계획서 대비 이행률은 75%(부분 인정 83%)로, 배포로 B축이 61%에서 79%로
  올랐고, D축은 제품 립리딩이 처음 보는 사람에게 우연 수준이라 한 항목을 낮춰 95%다. 배포 뒤 실측: 새로 켜지면 2분 14초에 모두
  준비되고(채점 모델은 각 22초), 쉬다 깨우면 대개 2초 안에 모델이 그대로 있다. 다만 fly가 깨우면서 기계를 다른 호스트로 옮기면
  새로 켜는 것과 같다(9/26 두 번 중 한 번).
- **9/25 저녁: 개발 서버에 배포했다(https://liplab-dev.fly.dev).** 자체 채점 모델(int8)이 서버에서 돌고, 새 앱 아이콘과
  랜딩 아래 개발자 정보(K-AI 공모전 B트랙 중고등부 대상 수상작, 만든 사람들)가 들어갔다. 전시앱과 KT 비교 데모는 그대로다.
- **9/25 오후: 발음 채점 모델을 int8로 줄여 개발 서버를 다시 4GB 기계로.** 가중치만 int8로 두고 계산은 그대로 해서, 학습 전에
  적은 다섯 조건(재검 관문 재현, 538·608 점수 일치, CPU 경로, 호스팅 메모리)을 모두 통과했다. 점수 차는 평균 0.2~0.4점,
  메모리는 최대 3.15GB(fp32 4.3GB). 배포는 아직 하지 않았다.
- **9/25 오후: 제품 립리딩 모델 교체는 새 화자로도 관문 미달.** P2 모델과 후보 로그우도 채점을 함께 쓰는 조합을 처음 보는
  12명으로 쟀더니 23.9% → 28.3%(+4.4점, 관문 +5점). 제품은 그대로 두었다. 채점 방식만 바꾸는 더 작은 변경을 새로 등록해
  다른 화자로 확인하는 중이다.
- **9/25 오후: 음소 점수는 한두 음절 자음 바꿈을 잡는다.** 문장 점수로는 못 거르던 ㅁ↔ㅂ·ㄴ↔ㄷ 바꿈을 자체 모델의 초성
  점수는 깨끗한 발화에서 AUC 0.99로 가른다(가장 낮은 초성이 바꾼 자리인 비율 93%). 저하가 크면 약해지므로 상대 순위로만 보이자.

- **9/25: 발음 채점 모델을 직접 학습했다.** 팀원 체크포인트는 옛 채점식 기준이라 쓰지 않고, 같은 레시피로 채점기·정렬기를
  공개 자료(Zeroth)로 다시 학습했다(RunPod A100 약 3시간). 학습 전에 적은 관문에서 1차(538 10화자)는 강도 순서 +2.7%p
  [0.0, 5.7]로 경계에서 떨어졌고, 1차 뒤 등록한 독립 재검(새 20화자)은 +3.8%p [2.3, 5.5]로 통과했다. 실제 청각장애 발화의
  정상 대비 분리도는 0.892에서 0.933으로 올랐다. 그래서 개발 서버 채점 모델을 자체 모델로 바꿨다(배포 전, `docs/scorer-selftrain.md`).
- **9/25: 608 실제 청각장애 발화를 확보했다.** 감음신경성 27명 669문장. 전사 오류 0.66(정상 0.19), D-GOP 38(정상 80)로
  합성 경과 중 사이에 놓인다(그림 7). 자기지도 음성변환(kNN-VC)으로 만든 발화는 실제 발화를 규칙 합성보다 덜 닮아 부정 결과로 남긴다.

  (`sqlalchemy[asyncio]`로 수정, 지금 떠 있는 전시앱은 옛 이미지라 영향 없음).

- 두 브랜치(`feat/content-scale`, `feat/sublexical-feedback`)를 새 통합 브랜치로 합쳤다. 원래 브랜치는 그대로 두었다.
  발음 채점식은 팀 표준(naive D-GOP), 화면은 Figma 디자인, 촉각 기능은 뺐다.
