# V3 입모양 표 train538 재적합 사전 등록 (2026-11-02)

옛 V3 간이판(`docs/avatar-v3-2026-10.md`)은 확인에서 2.0배 진폭(13무리 중 5개, 기준 11)만 미달했다. 이 문서는 새로 받은 train538 자료(`docs/train538-reacquire-prereg-2026-10-28.md`)로 표를 다시 만들고, 그 미달을 겨냥한 이득을 탐색 절반에서만 고른 뒤 확인 절반으로 한 번 판정하는 절차를 고정한다.

**이 문서를 커밋할 때까지 확인 절반의 지표는 계산하지 않았다.** 확인 절반 클립의 MediaPipe 추출·CTC 정렬은 10/29 재생성에서 끝났지만(`rebuild.log`) 그 값으로 만든 표·지표는 없다. 탐색 렌더 작업에는 탐색 절반 문장만 넣었고, 평가도 탐색 절반 화자만 담은 `sel_explore.json`으로 했다. 등록 전에 확인 절반에서 본 것은 화자 수·문장 수와 7절의 인물 감사(번호·성별·연령대)뿐이다.

## 1. 질문

문맥 평균 궤적 표를 train538 탐색 화자로 다시 만들고 탐색에서 고른 이득을 얹으면, 새 확인 화자에서 옛 V3의 판정 기준을 모두 넘는가.

## 2. 자료와 화자 분리

- 자료: `liplab-lab/data/train538/rebuild/`. 64명, 화자당 12클립, 768클립. `sel.json` sha256 11dd0f9d2321ab5f4bf856fd5d3aaa887b76f71ae897eacbce6c047f99e2ed58. MediaPipe 0.10.14, `dgop_ours` CTC 정렬, 66ms 앞당김은 옛 V3와 같다. 클립 고르기는 10/28 등록 3절대로 `v2_avatar_validity.py select`다(시드 0 섞기는 같고, 옛 확인 화자에 쓴 한글 4~40음절 거르기는 없다).
- **탐색:** `crc32(spk) % 2 == 0`, 29명, 348클립, 기본 문장 114개.
- **확인:** `crc32(spk) % 2 == 1`, 35명, 420클립, 기본 문장 139개. 옛 V3 확인 19명 배치와 겹치지 않는 train538 새 화자다.
- 안쪽 겹(탐색 안에서 설계를 고를 때): `sha256("v3-538-fold:" + spk)` 첫 바이트 % 2. 15명·14명이다. crc32의 최하위 비트는 입력에 선형이라, 접두어를 붙인 crc32로 겹을 나누면 절반 값과 묶여 한쪽으로 몰린다(실제로 29명이 한 겹에 들어가 sha256으로 바꿨다).
- **E2 클립·인물은 쓰지 않는다.** 재생성 격리 검사 `E2_GUARD_OK 1920`을 통과했고, 등록 전 감사에서 64명의 인물·배치가 `docs/train538-e2-cohort-2026-10-28.json`과 겹치지 않았다. E2 평가 클립 360개는 읽지도 쓰지도 않는다.
- **OLKAVS는 쓰지 않는다.** 모든 클립이 AI Hub 538 train538 폴더에서 왔다.
- 인물 감사: 64명이 모두 다른 인물이고, 두 절반에 함께 나오는 인물은 없다. 옛 V3 확인 19명과 V1 평가 40명은 인물 번호가 남아 있지 않아 배치 번호로만 뺐으므로, 다른 배치의 같은 인물은 걸러지지 않았다(10/28 등록 2절의 한계).
- **옛 결과와 직접 비교할 수 없다.** 옛 V3는 탐색 75명, 확인 19명(전문가)이고 이번은 탐색 29명, 확인 35명으로 화자 묶음이 다르다. 사람 범위의 기준값이 화자 집단마다 달라지므로 수치를 옛 값과 나란히 놓고 나아졌다고 주장하지 않는다.

## 3. 미달 원인을 겨냥한 설계

옛 확인에서 2.0배 진폭의 벗어난 8무리는 모두 사람보다 작은 쪽이었다. 11.3절의 해석은 평균이 움직임 폭을 줄이고, 이득이 탐색 화자에 맞춰져 있었다는 것이다. 그래서 이번 탐색의 손잡이는 표 평균 μ를 중심으로 곱하는 채널 무리 이득 네 개(벌림·돌출·폭·닫힘)와 양순 닫힘 규칙이다. 표의 꼴과 조합('add'), 칸 조건(20구간·5화자), 시간 보간, 판정 지표는 옛 V3와 같다. 처음 지시의 고정 표 `v3_table_explore.json`(이득 1.0, 양순 규칙 없음)은 탐색에서 8개 기준 중 겹별 4·5개만 넘어(4절), 11/02 추가 지시대로 같은 칸에 고른 이득을 얹은 표를 고정한다.

## 6. 판정 기준(`docs/avatar-v3-2026-10.md` 6절 그대로)

분석은 `v3_avatar.py evaluate --verdict`로 한다. 모두 기본 얼굴, 같은 확인 문장, 확인 화자 35명의 분포다. 8개를 모두 넘어야 통과다.

1. RSA: V3 1.0배 ρ ≥ 확인 화자 LOO 분포 하위 10백분위(13무리가 모두 찬 화자), 그리고 V3 ρ > V1 ρ.
2. 진폭: V3 2.0배에서 13무리 중 11개 이상의 스칼라 진폭 A가 확인 화자 10~90백분위 안, 그리고 그 수가 V1 이상.
3~4. 양순 닫힘(1.0배·2.0배): 무리 1 구간 입술 간격 최소값이 확인 화자 양순 구간 90백분위 이하인 비율 ≥ 0.95.
5~6. 원순 돌출(1.0배·2.0배): 무리 4 구간 돌출 R이 확인 화자 10~90백분위 안인 비율 ≥ 0.80.
7~8. 판독 대리(1.0배·2.0배): 16특징 다항 로지스틱 판독기의 13무리 매크로 재현율 ≥ V1 − 0.02. 옛 V3처럼 판독기는 탐색 화자로만 학습한다(이번은 29명).

**비교 대상:** 현재 앱 표 V1(기준). 옛 V3 동결 표(표 sha256 d8d1f30f…, 앱 모듈 `v3app`)와 V15 표는 같은 문장으로 렌더해 보고만 하고 판정에 쓰지 않는다. 옛 6.4절의 보고 항목도 함께 적는다.

**옛 등록과 다른 점(결정):** 옛 6.3절은 통과하면 플래그 뒤로 앱에 넣게 했지만, 이번에는 **통과해도 앱 표·빌드 플래그를 바꾸지 않고 제안만 적는다**(11/02 지시).

## 8. 주장 상한

MediaPipe가 재는 2D 정면 블렌드셰이프와 랜드마크에서의 기계 지표다. 사람 판독 결과가 아니고, 판독 대리는 사람 판독이 아니며, 청각장애 학습자의 독화 정확도에 관한 주장이 아니다. 옛 확인에서 판독기의 새 화자 성능이 약했으므로(0.153) 판독 대리는 약한 근거다. 통과해도 '기계 지표에서 사람 범위 안'까지만 말한다.
