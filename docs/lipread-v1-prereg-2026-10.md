# V1 사전등록: 538 화자를 늘린 제품용 독화기 재학습(2026-10-15, 받기·학습 전)

종합 계획(`master-plan-2026-10.md`)의 V1을 실행하기 전에 자료, 분할, 후보 모델, 선택 규칙, 판정 기준을 고정한다. 이 문서는
받기와 학습을 시작하기 전에 커밋하며, 실행 뒤에는 결과 절(9절 이후)만 덧붙인다. 평가 화자 40명의 목록은 받기가 끝난 뒤
3.2절의 규칙으로 한 번 만들고, 학습을 시작하기 전에 별도 커밋으로 덧붙인다.

## 1. 질문과 범위

웹캠 '기계 확인'(`LipReadCheck`, 단어 레슨의 '기계가 내 입모양 읽기')은 처음 보는 사람에게 4지선다 25.9%로 우연 수준이다
(`d-bench-v2.md` 8절, 채점만 바꾼 값). 학습 화자를 18명에서 약 130명으로 늘려 같은 제품 구조를 다시 학습하면, 처음 보는 화자
40명에서 4지 정확도가 40%를 넘는가.

- V16(Auto-AVSR 얼린 전단)은 사전 기준을 통과했지만 가중치가 LRS3 비상업 조건이라 제품에 넣을 수 없다(`v16-autoavsr-prereg.md` 2절).
  그래서 이 V1의 판정 대상은 **제품에 그대로 넣을 수 있는 구조**로 한정한다. 입력은 브라우저 MediaPipe가 내는 입 블렌드셰이프
  27채널, 모델은 지금 제품과 같은 BiGRU 3층 자모 CTC(`train_lipread.build`, ONNX 계약 `bs [B,T,27] → logits [B,T,53]`)이고,
  538 자료 밖의 사전학습 가중치는 쓰지 않는다. Auto-AVSR를 538 화자로 늘리는 연구용 시험은 이번에 하지 않는다.
- 538 자료는 10/6 관리자 확인으로 LIPLAB용 해외 처리(RunPod)가 허용되어 있다. 재배포는 하지 않으며 원자료·조각별 자료·가중치는
  저장소에 넣지 않는다.

  새 루트 `liplab-lab/data/v1_538r`로 받는다(`tools/v1r_dl.sh`). 10/6 받기와 큐·선택 규칙이 같고, 영상 앞부분만 1.8 GB에서
  1.0 GB로 줄였다(10/6 성공 87명 중 79명이 첫 mp4 하나로 30문장을 채웠다). 한 화자 = 한 인물이며, 기존 68명과 이 루트에

  나올 것으로 본다.

### 3.2 평가 화자 40명(받은 뒤, 학습 전에 고정)

- 후보: 이번 받기(`data/v1_538r/.state/<spk>.done`)에서 커밋된 화자. 기존 68명은 후보가 아니다.
- 선택: 후보마다 `sha256("liplab-v1-eval:" + spk)`의 16진 문자열을 구해 작은 순서로 40명(`v1-data-plan.md` 4절과 같은 규칙).
  성별·시점 비율은 보고만 하고 다시 고르지 않는다. 목록은 이 문서 부록 A에 덧붙여 커밋한 뒤 파드에 올린다.
- 후보가 80명 미만이거나, 평가 40명을 빼고 남는 화자(학습+검증)가 120명 미만이면 학습하지 않고 큐의 나머지 43개를 더 받는다.

### 3.3 검증 화자와 내용 분리

- 검증 12명: 평가 40명을 뺀 모든 화자(기존 68명 포함) 중 `sha256("liplab-v1-val:" + spk)`가 작은 순서로 12명. 체크포인트와
  후보 선택에만 쓴다.
- 학습 화자: 나머지 전부.
- 내용 분리: 검증·평가 화자가 읽은 문장과 같은 문장(한글 음절만 비교, `folds.norm_text`)의 학습 클립은 그 어절 조각까지 학습에서
  뺀다. 뺀 수를 보고한다.

### 3.4 특징과 벤치

- 파드에서 새 클립의 MediaPipe 블렌드셰이프·입술 좌표를 뽑고(`remote.sh extract`, 기존과 같은 mediapipe 0.10.14),
  강제정렬로 어절 구간을 만든다(`remote.sh align`, 적격 행 대비 90% 관문). 기존 68명과 합쳐 `d_bench.py build --rule 3,3`으로
  벤치 하나를 만든다. 4지 hard의 어휘와 오답 보기는 이 벤치의 규칙(인스턴스 3개·인물 3명 이상, 자모 편집거리 최근접 3개,
  같은 음절수 우선, seed 777)을 그대로 따른다.

## 4. 후보 모델과 학습(`liplab-lab/tools/v1_train.py`)

- 공통: 구조 `train_lipread.build(27, 53)`, 입력 입 블렌드셰이프 27채널(화자 정규화 없음, 제품과 같음), 학습 항목은 학습 화자의
  문장 전체와 어절 'wide' 구간. 증강은 P2와 같음(채널 이득 U(0.9, 1.1), 가우시안 σ 0.01, 속도 0.8~1.25, 좌우 거울상 p 0.5,
  시간 마스크 ≤3프레임). AdamW lr 3e-4, wd 1e-4, 배치 64, 기울기 노름 5로 자름, 최대 60에폭, 2에폭마다 검증, 검증 10회 동안
  나아지지 않으면 멈춤. 시드 0·1·2.
- 후보 A: 위 그대로(P2 방식을 화자만 늘린 것).
- 후보 B: A에 더해, 어절 항목의 절반(p 0.5)을 2.5초(75프레임) 창 안의 임의 위치에 두고 나머지를 같은 학습 화자의 쉬는 프레임
  (발화 앞 리드인·뒤 꼬리, `d_bench._rest_runs`와 같은 재료)으로 채운다. 제품 기계 확인이 2.5초를 녹화해 통째로 넣는 조건에
  학습을 맞춘 것이다.
- 체크포인트: 각 실행에서 검증 화자 4지 hard(아래 주 셀과 같은 채점, dup1과 dup2의 평균, 화자 평균)가 가장 높은 에폭.
- 선택: 6개 실행의 최고 체크포인트 × dup ∈ {2, 1} 12개 중 검증 4지가 가장 높은 하나(동점이면 A s0, s1, s2, B s0, s1, s2 순서,
  dup2 먼저). 평가 화자는 선택에 쓰지 않는다.

## 5. 판정(주 지표 하나)

- 주 지표: 선택한 모델 하나를 평가 화자 40명에 `d_bench.py product4way`(코드 수정 없음)로 건다. 셀은 4지 hard,
  채점 ctc_ll(후보 자모열의 CTC 로그우도 / 길이^α, α = 1), 입력 idle75(어절 구간을 그 화자의 쉬는 프레임으로 채운 2.5초 창),
  선택한 dup. 문항마다 맞으면 1, 화자별 평균을 낸 뒤 화자 평균.
- **관문: 주 지표 ≥ 40% 그리고 화자 부트스트랩(10,000회, seed 0, 백분위) 95% CI 하한 > 30% → PASS, 아니면 FAIL.**
  (종합 계획의 "새 화자 4지 ≥ 40%, 하한 > 30%"를 그대로 쓴다.) 판정 코드는 `liplab-lab/tools/v1_judge.py`.
- 보고만(판정에 쓰지 않음): 현재 제품 모델의 현재 해독(greedy_lev · dup2 · idle75)과 화자별 짝 차이, 현재 모델의 ctc_ll 셀(P3 셀),
  선택 모델의 greedy_lev 셀과 다른 dup, 나머지 5개 실행의 같은 셀, product4way의 그룹 부트스트랩 CI, 검증 화자 학습 곡선.

## 6. 결과에 따른 조치

- PASS: 제품 모델 교체를 **제안**한다(ONNX 내보내기, 채점 ctc_ll 연결, `SEQ_HZ`를 선택한 dup에 맞춤). 오프라인 특징은 파이썬
  MediaPipe라 브라우저 tasks-vision과의 차이는 앱 녹화로 따로 확인해야 하므로, 배포는 하지 않는다.
- FAIL: 종합 계획 8장 위험 대응대로 웹캠 기계 확인을 연구 기능으로 내리는 앱 변경(빌드 플래그와 문구)을 준비한다.
  기본값을 바꾸는 것은 제안으로만 남긴다.
- 결과를 보고 후보·하이퍼파라미터·셀을 바꿔 다시 판정하지 않는다. 새 시도는 새 사전등록으로 한다.

## 7. 멈춤 규칙

- 받기는 IP당 한 세션이므로 다른 AI Hub 받기가 끝난 뒤 시작한다. 회선이 필요하면 `data/v1_538r/.limit_rate`에 `2M` 같은 값을
  써서 다음 요청부터 줄인다(`LIPLAB_LIMIT_RATE`와 같은 뜻).
- 맥 디스크 여유가 8 GB 아래로 떨어지면 받기를 멈춘다. 영상 원본은 자른 뒤 바로 지우고, 파드 추출이 끝나 블렌드셰이프·입술 좌표·
  정렬·입 영역(88×88)을 받은 뒤에는 자른 클립(mp4·wav)도 지운다.
- 파드 추출 품질 관문(`EXTRACT_MIN_FRAC` 0.9)이나 정렬 관문(90%)에 못 미치면 학습하지 않고 원인을 기록한다.
