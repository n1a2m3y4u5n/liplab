# 작은 ROI 증류 모델 개발 선택 사전 등록 (2026-11-02)

## 질문과 고정 범위

폰 대응을 위해 ROI 픽셀 모델을 작게 만들 때 검증 정확도를 유지하면서 파일과 WASM CPU 시간을 줄일 수 있는지 고른다. 선생은 **완료된 B33 seed0 선택 체크포인트** 하나로 고정한다. 앱 R2와 B33 중 결과를 보고 고르지 않는다. 선생 파일 SHA256은 첫 실행 provenance에 기록하고 이후 바꾸지 않는다. 평가19명·clean_eval·E2·KMSAV·WavLM·OLKAVS를 읽거나 사용하지 않는다. 앱 변경·배포·플래그 기본값 변경은 없다.

기존 B33 `prep.json`의 학습33명·검증12명·문장 제외·어휘53·4지 문항을 그대로 사용한다. prep의 화자 수와 모든 clip의 train/val 역할, KMSAV 부재를 실행기가 검증한다. 검증 화자는 기존 선택에도 쓰였으므로 **검증12명 개발 선택이며 판정 없음, 깨끗한 평가 대기**다.

## 학생 구조와 학습

학생은 입력80×80의 정규화 후 고정 평균풀링으로40×40으로 줄인다. 시간축 보폭은1이다. Conv3d1→8(5×7×7, 공간보폭2), BN/ReLU/공간maxpool, 프레임별 잔차 블록16·32·64·96 한 개씩(공간보폭1·2·2·2), 전역평균, 선형96→128, LayerNorm128, 양방향GRU2층 hidden128 dropout0.2, 선형256→53 CTC다. 선생은 기존24stem·ResNet폭0.5 2·2·2·2·256출력·BiGRU3층256이다. 실행 전 구조 smoke에서 학생 파라미터≤선생의1/4를 확인하며 넘으면 학습하지 않는다. 구조나 폭을 결과를 보고 재선택하지 않는다.

선생을 매 배치 재계산해1080을 오래 점유하지 않도록, 학습33명 clip만 한 번 순회해 원래80×80 중앙 자르기·정규화·eval 선생의 프레임별53로짓을 float16으로 캐시한다. 메모리와 시간을 제한하기 위해 clip을 **최대400프레임의 겹치지 않는 창**으로 나누며 마지막 창은 실제 길이만 쓴다. 검증 clip에는 캐시를 계산하지 않는다. 학생의 원래 B33 프레임 번호·속도 변환·동일 화자 idle 연결에 맞춰 캐시를 재색인한다. 선생의 깨끗한 문맥 로짓을 학생의 무작위 자르기·거울상·시간마스크 입력에 맞추는 증강 일관성 증류이며, 매 증강 입력에 선생을 다시 실행한 결과라고 부르지 않는다. 패딩 프레임은 KL에서 제외한다.

손실은 `0.5×원래 CTC + 0.5×T²×유효 프레임 평균 KL(softmax(teacher/T) || softmax(student/T))`, T=2다. 선생은 eval/no_grad로 고정한다. seed0 한 번, AdamW lr3e-4 wd1e-4, 배치32, 프레임별 미니그룹 상한4000과 그룹별 배치 평균 보정, 최대40에폭, 2에폭마다 검증, patience6회 검증 미개선, 기울기5, idle0.5, 속도0.8~1.25·무작위80자르기·거울상0.5·시간마스크≤3은 B33 규칙이다. 1080 AMP는0이다. 동기 배치로 캐시와 목표의 대응을 보장하고 CPU4스레드, GPU 메모리 상한0.92를 쓴다. OOM이면 구조·배치·상한 변경이나 재학습 없이 기술 실패를 보고한다. 체크포인트는 검증4지 dup1·2 화자평균의 평균 최고값(엄격한 개선)으로 고른다. 시드 추가·재시작·이어학습을 하지 않는다.

## 한 번의 개발 선택과 통과 기준

학습 종료 후 선택된 학생과 고정 선생을 같은 B33 검증12명 문항에서 한 번씩 다시 계산한다. 원래 hard CTC likelihood α1, idle75, dup1·2 각각 화자평균 후 두 평균의 평균을 쓴다. 미분할 문항을 임의로 버리지 않는다. CER도 같은 검증 문장 전체에서 보고한다. 주 정확도 관문은 **학생−선생 ≥−0.02**다(CER는 기술·보조 보고, 별도 관문으로 바꾸지 않는다).

두 모델을 동일한 FP32·opset17 ONNX로 내보낸다. 입력은 원화소 범위 float32 `[B,T,80,80]`, 내부 동일 z정규화, 출력 `[B,T,53]`다. 75프레임 고정 입력에서 원래 PyTorch와 export wrapper 및 ONNX CPU 로짓 최대차이<1e-3를 기술 유효성 조건으로 확인한다. quantization 차이를 혼합하지 않는다. 파일 크기 관문은 **학생 ONNX 바이트≤선생 FP32 ONNX의40%**다.

WASM은 동일 PC(lab-sub CNSAI2025)의 설치된 onnxruntime-web1.19.2, Node24, WASM CPU EP 한 스레드에서 두 세션을 미리 생성한 뒤 측정한다. CPU KMSAV 작업을 중단하지 않는다. 입력은 PRNG xorshift seed20261102로 만든 동일 `[1,75,80,80]` 정수0~255 float32이며 실제 인물 프레임·평가 자료를 쓰지 않는다. 모델당5회 예열 후, 선생→학생/학생→선생 순서를 번갈아20쌍 측정한다. 모델 로딩·파일 읽기·입력 생성·출력 유효성 확인은 타이머 밖이고 `session.run` walltime만 잰다. 각 모델20회 중앙값으로 **학생 시간≤선생의50%**를 판단한다. 원시 시간·PC/CPU·ORT/Node버전·입력과 모델 SHA를 보존한다. 다른 PC나 native ORT 시간으로 WASM 관문을 대체하지 않는다. 실행 불가라면 속도 관문 미확인으로 남긴다.

**파라미터≤1/4와 세 관문(정확도·파일·WASM 시간)을 모두 충족할 때만 작은 ROI 경로를 후속 독립 평가 후보로 남긴다.** 어느 하나 미달이면 이 구조·증류 경로는 이번 선택에서 포기한다. 정확도만 좋아진 모델을 폰 대응 성공으로 부르지 않는다. 추가 시드나 문턱·시간 표본 재선택은 없다.
