# LIPLAB 발화(말하기) 피드백 — 설계

> 상태: 착수 (브랜치 `feat/speaking`, YMJ 기반)
> 한 줄: 독화(읽기=입력)의 짝인 **발화(말하기=출력)**. 청각장애인은 자기 발음을 못 들어
> 피드백 루프가 끊겨 어눌해짐 → **끊긴 청각 피드백을 '시각/AI 피드백'으로 대체**한다.
> "귀 대신 눈으로 내 발음을 확인한다."

## 스택 (전부 무료 소프트웨어, 유료 API 없음)

| 조각 | 방법 | 위치 |
|---|---|---|
| 실시간 볼륨·피치·파형 | Web Audio API (`AnalyserMode` + autocorrelation) | 브라우저 (서버 0) |
| 명료도(ASR) | **faster-whisper**(오픈소스, small) | Fly.io 서버 |
| 음소별 피드백 | **기존 음운 유사도 채점(scoring.py) 재활용** — 전사 vs 목표 자모 정렬 | 기존 백엔드 |
| 코칭 | Claude (기존 Anthropic 키) | 기존 llm_service |
| 목표 입모양 | 기존 viseme 아바타(AvatarVRM/MouthAvatar) | 재활용 |

- 유료 발음평가(Azure)는 불필요: 유일한 실질 우위(음향 음소 스코어)가 **농인 발화엔 검증 안 됨**.
- Whisper는 오픈소스라 큰 모델도 무료 — 유료 API도 같은 모델을 대신 돌려주는 것. 차이는 '모델 크기/서버 사양'이지 유·무료가 아님.

## 정직한 한계

- ASR은 '정상 발화'로 학습돼 어눌한 발음은 오인식 가능 → **음소 피드백은 ASR 정확도에 의존**.
- 그래서 ASR에만 기대지 말고 **시각 바이오피드백(볼륨·피치)을 축**으로 삼는다(농인 언어치료 정통 방식).
- 진짜 음향 음소 스코어(wav2vec2 음소모델·GOP 자체호스팅)는 무거운 '나중' 옵션.

## Increment

1. **시각 피드백 MVP (의존성 0)** — 마이크 녹음 + 실시간 볼륨·피치·파형 + 목표 단어/아바타 + 규칙기반 즉시 코멘트("너무 작아요 / 톤이 평평해요"). 커리큘럼 단어 재활용.
2. **서버 Whisper** — 녹음 업로드 → faster-whisper 전사 → 기존 jamo 채점(음소 피드백) → Claude 코칭.
3. (후) 문장/운율, 진행도, 적응, 발음 전용 콘텐츠.

## Fly.io 메모

- HTTPS 필요(마이크) — Fly.io 기본 제공 ✔.
- Increment 1은 서버 부담 0(브라우저 내).
- Increment 2: faster-whisper 모델(small ~0.5GB) 상주 → 머신 RAM 확보. 단기·저부하라 크레딧으로 커버. 실배포는 사용자 몫(배포 보류 원칙).

## 재사용 자산

커리큘럼 단어(WORD_BANK) · viseme 아바타 · 음운 유사도 채점(scoring.py) · Claude(llm_service).
발화는 독화와 별개 축이라 커리큘럼 StageGate 없이 독립 진입.
