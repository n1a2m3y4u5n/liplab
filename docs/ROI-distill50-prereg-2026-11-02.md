## 같은 증류·학습

고정 선생 eval/no_grad로 학습 clip만 한 번 순회한다. 최대400프레임의 겹치지 않는 창, 중앙80자르기·원래 정규화의53로짓을 float16 캐시하며 마지막 창은 실제 길이만 쓴다. 검증 clip에는 캐시를 만들지 않는다. 학생 프레임 번호·속도·동일 화자 idle 연결에 맞춰 목표도 재색인하는 기존 증강 일관성 증류다. 목표 저장 float16은 가중치 양자화가 아니다.

손실은 `0.5×CTC + 0.5×T²×유효 프레임 평균 KL(teacher/T||student/T)`, T=2다. CTC는 배치 항목 평균, KL은 미니그룹 보정 후 배치 전체 유효 프레임 평균이고 패딩을 제외한다. 원래 무작위80자르기·거울상0.5·시간마스크≤3·속도0.8~1.25·idle0.5를 유지한다.

두 실행 각각 **seed0 또는 seed1 한 번**, AdamW lr3e-4 wd1e-4, 배치32,4000프레임 그룹 상한, 최대40에폭,2에폭마다 검증, patience6회 미개선, 기울기5, AMP0, CPU4스레드, 동기 배치다. 검증4지 dup1·2 화자평균의 평균 최고값(엄격한 개선)으로 각 실행의 체크포인트를 고른다. 초기 setup과 최종 원래 trainer 인자에 해당 시드를 모두 전달한다. 출력이 비어 있을 때만 시작하며 resume·추가 시드·구조/배치/상한 변경 재시도는 없다.

seed0은 lab-main RTX3060, seed1은 lab-sub RTX3060에서 동시에 실행한다. 둘 다 GPU 메모리 상한0.45다. 예상 총시간은 **각30~50분**, 두 시드는 병렬이다. OOM 또는 기술 실패면 바꾸지 않고 그대로 기록한다.

## 각 시드의 세 관문과 두 시드 결론

각 학생 학습 종료 뒤 같은 B33 seed0 선생과 그 시드에서 선택된 학생을 같은 검증12명에서 한 번 비교한다. hard CTC likelihood α1, idle75, dup1·2 각각 화자평균 후 평균을 쓴다. 미분할 문항을 버리지 않는다. CER는 같은 검증 문장 전체에서 보조 보고하며 별도 관문으로 쓰지 않는다.

각 시드가 다음을 **모두** 만족해야 그 시드 통과다.

1. 검증4지 학생−고정 선생 ≥−0.02.
2. FP32 학생 ONNX 바이트 ≤같은 선생 ONNX의60%.
3. 같은PC·같은입력 CPU WASM 학생 중앙시간 ≤선생의60%.

**seed0과 seed1이 모두 세 관문을 통과해야만 “안정 통과”다.** 하나라도 미달·기술 미확인이면 안정 통과가 아니며 시드별 결과를 그대로 보고한다. 높은 시드를 골라 다른 시드 실패를 덮거나 중간 에폭·다른 저장형식·재측정으로 다시 고르지 않는다. 이 결론도 독립 판정이 아니라 반복 사용된 검증12명의 개발 선택이다.38%의 과거 수치와 주석은 변경하지 않는다.

## 동일 FP32 내보내기·WASM

각 시드의 선생과 학생을 FP32/opset17로 내보낸다. 입력 원화소 범위 float32 `[B,T,80,80]`, 내부 시퀀스 z정규화, 출력 `[B,T,53]`다.75프레임 합성 입력에서 PyTorch 원경로↔wrapper 및 wrapper↔ONNX CPU 로짓 최대차이<1e-3를 기술 유효성 조건으로 확인한다. 기술 조건 미달을 파일·시간 통과로 덮지 않는다.

WASM은 동일 lab-sub CNSAI2025 PC, onnxruntime-web1.19.2, Node24, WASM CPU EP1스레드다. 동일 PRNG xorshift seed20261102의 `[1,75,80,80]` 정수0~255 float32 합성 입력을 사용하며 실제 평가 클립을 읽지 않는다. 두 세션을 미리 만든 뒤 모델당5예열, 선생→학생/학생→선생 순서를 번갈아20쌍의 `session.run` walltime만 잰다. 로딩·입력 생성·출력 확인은 타이머 밖이며 각20회 중앙값을 비교한다. 원시 시간·PC/CPU·ORT/Node버전·입력/모델 SHA를 남긴다.

실행 순서는 **C seed0→C seed1→별도 등록 D**로 고정한다. C 각 시드의 모델별 측정은 한 번이며 타 PC·native ORT·유리한 재측정으로 대체하지 않는다. 기존 WASM 공용 도구의 과거50% 보조 boolean은 쓰지 않고 원시 `latency_ratio`에 이 등록의 **0.60**을 적용한다. Android 실측 주장을 하지 않는다.
