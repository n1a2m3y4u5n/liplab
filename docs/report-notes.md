## 축 A. 농인 발화 합성과 음성구동 아바타(A4)

- **합성 교란의 검증(A, 그림7).** AI Hub 538 실발화 10화자 300문장에 경·중·심 교란을 적용했다.
  ASR CER 0.194, 0.503, 0.723, 0.922, D-GOP 원점수 80.2, 49.6, 26.7, 5.8(9/24 정렬 수정판). 클립의 95.7%에서 D-GOP가
  강도 순서를 지켰다. 첫 판(macOS TTS 7문장)과 9/23 결함판(16.4·9.1·5.3·2.1, 82.3%)은 결론에서 뺐다.
  근거: `docs/deaf-synthesis.md`, `docs/dgop-remeasure-538.json`.
- **A4 제품 모델.** 동결 WavLM-large와 BiGRU 머리, 20화자 학습. 처음 듣는 화자의 jawOpen 상관 r 0.657
  (3개 홀드아웃). 평가 화자로 학습 시점을 고른 값이라 낙관적이다(화면 문구도 그렇게 적었다).
  **A2(9/24)의 정직한 첫 추정:** 한 번도 쓰지 않은 10화자에서 깨끗한 발화 r **0.627**. 다만 합성 농인풍 교란 심 조건에서는
  0.07~0.10으로, 증강 없는 20화자 기준 모델(0.25~0.30)보다 약하다. 근거: `docs/deaf-synthesis.md` 3.2절.
- **A1(농인 합성 증강의 견고성).** 10화자, 화자·문장이 겹치지 않는 5겹 교차검증, 4조건 × 3시드 = 60적합,
  사전등록 sha256 `f7db54f8…`. 합성 심 조건 jawOpen r이 0.202에서 0.308(augF, +0.106 [+0.040, +0.178])로 오르고,
  일반 잡음 증강보다도 +0.079 높다. 깨끗한 발화는 −0.022 [−0.046, +0.001]로 사전등록 비열등 기준(−0.02)을 조금 넘어
  판정은 '승자 없음'이다. 보고서에는 "증강은 합성 교란 견고성을 크게 높였으나 깨끗한 발화 비용이 기준을 넘어 제품에
  넣지 않았다"로 쓴다. 표는 `docs/deaf-synthesis.md` 3.1절.
- **예시 음성.** 앱의 A4 예시 5개는 합성 음성(TTS)이며 입모양은 현재 모델로 다시 계산했다(9/23).
- **A-6·A-9(공유 백본).** 계획서는 B~E가 한 백본을 공유하는 구조였지만, 실측에서 축마다 맞는 백본이 달랐다(A4는 WavLM,
  D-GOP 채점은 한국어 CTC 헤드가 필요). 그래서 '모델 하나'가 아니라 '적재·캐시·장치 관리 지점 하나'로 구현했다
  (`backend/backbone_service.py`, 상태 `GET /api/backbone/status`). 같은 모델 id와 장치를 쓰는 축은 가중치 한 벌을 나눠 쓴다.
  보고서에는 "통합 백본 대신 축별 백본을 한 서비스에서 관리"로 쓰고, 그림 12와 맞춘다. AV-HuBERT(A-5)는 라이선스 때문에 쓰지 않았다.
- **A-2·A-10(자기지도 음성변환 충실도, 9/25, 부정 결과).** kNN-VC(WavLM-large 6층, HiFi-GAN)로 538 정상 60문장을 608 감음신경성
  화자 6명의 목소리로 바꾼 360개는 CER 0.35·D-GOP 65.6으로, 실제 608(0.66·38.0)보다 원문(0.20·79.5)에 가깝다. 실제 608 분포와의
  1차 Wasserstein 거리도 규칙 합성 경·중(CER 0.21·0.22, D-GOP 16.3·17.2)보다 멀다(0.33, 27.7). 음색은 옮기지만 원 화자의 조음을
  따르기 때문이다. 합성 코퍼스는 규칙 합성으로 가고, 계획서 A-10의 충실도 확인 결과로 적는다. 근거: `docs/scorer-selftrain.md` 5절.

## 축 B. 전사 비의존 발음채점(D-GOP)

- **정렬 blank 결함(9/24 발견·수정, 재측정 완료).** `dgop_acoustic.align_targets`가 CTC blank를 "<pad>"로 찾고 없으면 id 0을
  썼다. 팀 자모 vocab은 "<pad>"가 0이라 맞았지만, kresnik 음절 vocab은 blank가 "[PAD]"(1204)이고 id 0이 음절 '볍'이라 '볍'을
  blank로 두고 정렬했다. 고친 판으로 538 300문장을 다시 재자 원점수가 원본 80.2·경 49.6·중 26.7·심 5.8(옛 16.4·9.1·5.3·2.1),
  강도 순서 95.7%(옛 82.3%), 전사 정확도와 상관 0.986(옛 0.86)이 됐다. ASR CER은 두 판이 같다. 보고서에는 수정판 수치를 쓴다.
  근거: `docs/dgop-demo.md`, 결함판 원자료 `docs/dgop-remeasure-538-before-blank-fix.json`.

- **보고서에 쓸 논지는 견고성이 아니라 전사 비의존성과 연속성이다(그림6).** 깨끗한 정상 발화도 문장 전체를
  정확히 옮긴 경우는 4.3%뿐이고(CER 0.194), D-GOP는 전사 없이 명료도에 비례한다(전사 정확도와 스피어만 0.986).
  단, D-GOP와 ASR이 같은 모델(kresnik)이라 이 상관은 독립 검증이 아니다.
  합성 교란에서는 두 지표가 비슷한 폭으로 떨어지므로 "D-GOP가 ASR보다 견고하다"고 쓰지 않는다.
  근거: `docs/dgop-demo.md`.
- **A-7(D-GOP 표시점수 앵커).** 9/23에는 지금 앵커로 정상 발화가 59.7점(합격선 65 통과 15%)이라 새 앵커가 필요해 보였지만,
  원인은 정렬 결함이었다. 고친 정렬에서는 지금 앵커(9/9)로도 정상 발화 표시점수 중앙값 91.1점, 65점 통과 100%다. 교란 발화는
  경 81.5·중 67.5·심 42.9점. 538 수정판 중앙값으로 다시 맞춘 후보 앵커(원본 82.5→90, 경 50.9→72, 중 25.0→58, 심 3.8→40)는
  교란 발화를 더 낮게(경 72·중 58) 매긴다. **9/24 결정:** 공개 kresnik 모델을 정렬기·채점기로 쓸 때는 그 모델로 맞춘 후보 앵커를
  쓴다(`backend/data/dgop_calibration_kresnik.json`, 채점기에 따라 자동 선택). 지금 앵커(9/9)는 팀원 채점기용이라 그 모델에
  남긴다. 608 실제 청각장애 발화나 파일럿 발화가 생기면 다시 맞춘다. 근거: `liplab-lab/data/a7_calibration_538_fixed.json`.
  **9/25 608 확인:** 이 앵커로 실제 청각장애 발화 669문장은 중앙값 66.2점(평균 57.1점), 58점 미만 39%, 40점 미만 25%로
  바닥·천장에 몰리지 않아 앵커를 유지한다. 근거: `docs/scorer-selftrain.md` 3절.
- **실제 청각장애 발화(그림8, 9/25 측정).** 608 TS02(101GB)를 끝까지 흘려받아 범주 28(감음신경성) 세션 27개(27명, 30분 이하,
  화자당 1개)를 확보했다(9/24에는 라벨로 고른 세션이 TS02에 없었고, 범주 28은 deflate 압축이라 풀기를 더해 다시 받았다).
  세션을 kresnik 강제정렬로 문장 단위로 잘라(세션당 최대 40문장, 669문장) 538과 같은 채점으로 쟀다(`liplab-lab/tools/b608_measure.py`).
  kresnik 음절 CER 평균은 정상 0.19 대 청각장애 0.66(3.4배), 문장 전체를 맞게 옮긴 비율은 약 4% 대 1.8%, D-GOP 원점수는
  80.2 대 38.0이다. 실제 발화는 CER로도 D-GOP로도 합성 '경'과 '중' 사이에 놓인다(그림 7에 608 추가). 9/23의 1.83배(n=5)는
  이 값으로 바꾼다. 범주 28에는 노인성 난청(70~90대)도 섞여 있어 선천성 농인 발화와 같지 않다고 적는다.
  근거: `docs/scorer-selftrain.md` 3절, `docs/figures/fig7_b_remeasure.png`.
- **B-5·B-6(9/24 구현, 검증 결과 판별력 저하).** 음소마다 소리 점수와 입모양 점수를 섞는다(영상 가중 0.25 + 0.5 × (1 − 소리/100),
  음소 정렬 구간 ±0.08초의 웹캠 입모양). 538 200클립 검증에서 맞는 문장과 다른 문장을 가르는 AUC가 소리만보다 낮았다
  (심 교란 0.778 → 0.583, 중 0.974 → 0.800). 지금 입모양 점수(규칙 프로파일 코사인)는 그 자체로 우연 수준(AUC 0.49~0.53)이라
  섞으면 차이만 줄인다. **9/24 결정·적용:** 채점 점수는 소리만으로 내고 입모양 점수는 따로 보여 준다(D-GOP·전사 경로 모두).
  계획서 B의 '웹캠 입모양 후기융합'에서 달라진 설계로 보고서에 적는다. 연구용 재현은 `LIPLAB_AV_FUSION=1`.
  근거: `docs/bfuse-validation.md`.
- **B-8(호스팅에서 D-GOP 켜기, 9/24 코드 반영, 배포 전).** 개발 서버(liplab-dev) 설정이 torch CPU와 모델 두 개를 이미지에 넣고
  D-GOP를 주 경로로 쓴다(전사는 폴백). 전시앱 설정은 그대로다. 자세한 내용은 `DEPLOY.md` 9항.
  배포 전 점검(같은 의존성, CPU 2스레드): 최대 메모리 3.1GB, 채점 문장당 1.4~1.7초, 맞는 문장 86~95점·다른 문장 0~45점.
- **자체 학습 정렬기·채점기(A-1·A-2 레시피 재학습, 9/25).** 팀원 체크포인트는 옛 채점식 기준이라 쓰지 않고, 같은 레시피로
  Zeroth(공개)에서 다시 학습했다(RunPod A100 약 3시간). 사전등록 관문(538 합성 저하 단조 비율 +2%p 이상, 화자 부트스트랩 CI
  하한 > 0)에서 1차(10화자)는 +2.7%p [0.0, 5.7]로 떨어졌고, 1차 뒤 등록한 독립 재검(새 20화자)은 +3.8%p [2.3, 5.5]로 통과했다.
  실제 청각장애 발화(608 27명 669문장)의 정상 대비 분리도 AUC는 kresnik 0.892, 자체 0.933. 다른 문장을 목표로 주면 두 모델 모두
  합격선을 넘지 않고, 한두 음절 비음·파열음 바꿈은 둘 다 문장 점수로 거르지 못한다(음소별 점수로 보여 줄 부분).
  liplab-dev 채점 모델을 자체 모델로 바꿨다(배포 전, 메모리 5.0GB라 8GB 기계). 보고서에는 1차 FAIL과 재검 통과를 함께 적는다.
  근거: `docs/scorer-selftrain.md`.
- **int8(9/25 오후).** 정렬기·채점기 가중치를 int8로 두는 설정을 사전등록 점검으로 채택했다(재검 관문 재현 +3.5%p [2.2, 5.0],
  표시 점수 차 평균 538 0.20점·608 0.36점, 호스팅 최대 3.15GB). liplab-dev 기계를 8GB·CPU 4개에서 4GB·CPU 2개로 되돌렸다
  (배포 전). 근거: `docs/scorer-selftrain.md` 7절.
- **음소 단위 교체 검출(9/25 오후, 보조).** 문장 점수로 못 거르던 한두 음절 ㅁ↔ㅂ·ㄴ↔ㄷ 바꿈을 자체 모델의 초성 점수는 깨끗한
  발화에서 AUC 0.99로 가르고, 문장에서 가장 낮은 초성이 바꾼 자리인 비율이 93%(우연 10%)다. 중·심 저하에서는 0.73·0.60으로
  떨어진다. 계획서의 '음소별 D-GOP 피드백'을 뒷받침하되, 저하 발화에서는 상대 순위로만 보이는 쪽으로 적는다.
  근거: `docs/scorer-selftrain.md` 6절.

## 축 C. 시각 지각공간

- 데이터(538 30화자 900클립 입모양)로 만든 공간에서 화자를 바꿔도 비심이 우연보다 잘 갈린다(균형 정확도 자음 0.366,
  모음 0.408, 우연 0.2, 10화자판은 0.345·0.386). 손코딩 음운 공간과의 거리 상관은 0.39, 0.28(10화자 0.30, 0.22)로 약하다. 그래서 음운 유사도는 규칙,
  시각 혼동은 데이터로 따로 쓴다. 근거: `docs/perceptual-space-demo.md`.
- **6.1 채점 근거 문구.** 예전 소규모 대조 실험의 상관(−0.19)은 방향이 음수였다. 보고서의 "데이터 공간으로
  채점 근거를 대체한다"는 서술은 "규칙이 주, 데이터는 보조"로 고친다.
- **C-현황(입모양 지속시간 상수).** 538 실발화 280문장의 강제정렬 음절 간격과 비교하면 엔진은 실제 말(초당 6.0음절)보다
  1.9배 느리고(초당 3.2음절), 받침 음절을 실제(1.2배)보다 길게(1.6배) 만든다. 음절 단위 순위상관 0.30. 학습용 느린 속도로는
  받아들일 수 있어 앱은 바꾸지 않았다. 근거: `docs/engine-duration-check.md`.
- **표6-C1(데이터 유래 자모 유사도).** 공개 자원 1.2.0에서 첫 판(4화자, 거의 모든 쌍 0.99, 손코딩과 −0.19)을
  10화자 LDA 판(자음 120쌍·모음 153쌍, 손코딩과 0.30·0.22)으로 바꿨고, 1.3.0(9/24)에서 30화자 900클립 판(자음 153쌍·모음 171쌍,
  손코딩과 0.39·0.28, ㅁ·ㅂ 0.92)으로 다시 바꿨다.
  채점과 문항 선정에는 쓰지 않는다. 근거: `docs/korean-speechreading-resources.md`, `backend/data/c_jamo_similarity.json`.
- **C-4(데이터 공간에서 난이도·최소대립쌍 도출).** 30화자 공간으로 만든 단어 난이도는 규칙 난이도와 ρ 0.32(0.24~0.39),
  문장은 0.09로 거의 맞지 않는다(10화자판 0.25·0.07). 최소대립쌍 수준에서는 입술 닫힘 대 나머지를 AUC 0.99로 가르지만,
  입 안쪽 자음 무리 안의 세부 구분은 0.80(자모 쌍 0.74)이다. ㅐ·ㅣ가 닮고 된소리 ㅃ이 ㅂ·ㅁ과 떨어지는 것은 10·30화자판이
  같았다. 채점·문항은 규칙판을 유지한다. 근거: `docs/c4-data-derived.md`.
- **C-8(공개 배포 묶음).** `scripts/build_resource_release.py`가 자원 JSON·README(한/영)·LICENSE·CITATION.cff·zenodo.json·
  SHA256SUMS를 만든다. AI Hub에서 계산한 자모 유사도는 재배포 허용을 확인하기 전까지 묶음과 공개 API 모두에서 뺀다
  (`LIPLAB_PUBLISH_DATA_DERIVED=1`일 때만 싣는다). 공개 채널(저장소·Zenodo)과 저자 정보는 사용자 결정이다.

## 축 D. 웹캠 채점과 자체 립리딩

## 축 J. 시각 증강 기호

- **J-2(유성 대신 긴장).** 한국어 장애음은 평음·경음·격음의 3항 대립이고, 유성성은 평음이 유성음 사이에서
  울리는 변이음이라 뜻을 가르지 않는다. 그래서 기호는 기식(격음), 긴장(경음), 울림(비음)에 대응시키고 유성은
  따로 표시하지 않는다.
- **발음 모드.** 기호는 표준발음법을 거친 실제 발음에 붙는다(국물의 비음화, 먹고의 경음화). 186문장 중 63문장(34%)의
  기호가 표기 기준과 달라졌다. 기호가 붙는 음절 55.8%, 문장당 기호 수 상한 2개로 평균 1.99개. 근거: `docs/cue-overlay.md`.
- **J-3.** 단어·문장 퀴즈에서 답을 확인한 뒤(틀렸을 때 무엇이 달랐는지 보는 순간) 학습자의 약한 표적 입모양 음절에만
  기호를 입꼬리 옆에 겹치고, 숙달되면 흐려진다. 문제를 푸는 동안에는 보이지 않는다. 보기가 최소대립 짝이라 기호만
  보고도 답이 드러나기 때문이다(예: 물·풀·불은 비음·기식·없음으로 갈림). 표준검사와 문맥 추론 문항에도 넣지 않는다.
- **J-12 준비.** 파일럿에서 기호 없이 학습하는 집단을 둘 수 있다(`LIPLAB_PILOT_NOCUE_COHORTS`). 그 집단은 기호 API가 빈 목록을
  주고 범례·웹캠 울림 기호도 숨는다. 기호가 화면에 뜬 순간은 기록하지 않으므로, 효과는 집단 비교와 기호 없는 사후 검사로 본다.
- **J-9(실제 촬영 영상 위 기호, 9/24).** 538 화자 영상에 강제정렬 음절 시각을 맞춰 기호를 입 옆에 띄우는 연구용 페이지
  (`/lab/cue-video`)를 만들고 8클립으로 확인했다. 같은 시각 창으로 모음 개방(AUC 0.752)과 양순 폐쇄(0.718)가 갈려 음절 시각과
  영상이 맞는다. 규칙 기호라 아바타가 아닌 촬영 영상에도 얹힌다는 계획서의 F 대비 논거를 실증한 것이다. AI Hub 영상은
  재배포할 수 없어 공개 화면은 자체 촬영 영상으로 만든다(`cue_video.py own`). 근거: `docs/cue-video-demo.md`.

## 축 K. 입술 너머 얼굴 신호

- 비음 AUC 약 0.60~0.64(우연보다 높음), 유성 AUC 약 0.55(우연 수준)라 유성은 화면에 표시하지 않는다.
  미세 움직임 확대(EVM) 전처리는 +0.01에 그쳐 채택하지 않았다(K-8). 근거: `docs/k-facecue.md`.
- **K-5(K→B 융합, 9/24 구현, 검증 결과 효과 없음).** 웹캠 비음 확률로 입모양이 같은 짝(ㅁ/ㅂ, ㄴ/ㄷ, ㅇ/ㄱ)의 입모양 점수를
  최대 ±8점 조정한다. ㅁ↔ㅂ·ㄴ↔ㄷ를 바꾼 문장을 가르는 AUC 차이가 모든 조건에서 0.000이었다(비음 신호가 약함). 입모양을
  채점에 섞지 않기로 하면서 기본 경로에서 껐다(연구용 융합에서만 돈다).
- **K-1(목 부위)은 하지 않는다.** 유성의 직접 단서인 성대 진동(80~300Hz)은 초당 30프레임 웹캠으로 담을 수 없다.
- **K-4(K→J, 9/24 화자 영상 측정, 부정 결과).** 538 30명 200클립에서 K 비음 확률은 J 울림 기호 음절(1,317)과 같은 입모양
  파열음 음절(1,434)을 가르지 못했다(음절 AUC 0.486 [0.466, 0.508]). 초성·받침, 양순·치조·연구개로 나눠도 0.45~0.49이고
  K 입력 8차원 하나하나도 우연 수준이다. K의 프레임 AUC 0.60~0.64는 음향 대리 라벨 기준이라 음절 수준 동구형이음 구별로
  이어지지 않았다. J 기호는 문장 규칙으로만 켜고, 웹캠 울림 기호는 껐다(9/24 결정). K 표시는 연구 빌드에서만 보인다.

## GPU 사용과 배분(4.2-6, 9/24 기준)

- RunPod billing API로 파드 24대와 네트워크 볼륨의 사용액을 받아 축별 원장을 만들었다(`liplab-lab/notes/gpu-ledger.md`,
  재생성 `tools/gpu_ledger.py`). 충전 $75(영수증 3건) − 사용 $55.66 = $19.34로 API 잔액과 맞는다.
- 과금 시간 75.6시간 중 H100은 5.2시간이다(계획 약 370시간). 나머지는 A6000·RTX 3090으로, 실험 규모(수백~수천 클립)에
  맞춰 싼 GPU를 썼다. GPU 편성액 1,032,000원 중 집행은 약 104,000원(10%)이다.
- LIPLAB 사용 $53.94의 묶음별 비율은 백본·합성(A) 40%(계획 40%), 발음평가·조음(B·E) 25%(35%), 립리딩(D) 16%(25%),
  C 9%, K 9%다. 한 파드에서 여러 축을 돌린 경우 축 수로 균등 배분했고, 9/14~9/16 파드 일부는 같은 날 작업으로 추정 배정했다.
- 파드 1대($1.72)는 LIPLAB이 아닌 다른 과제(수행평가)에 쓰였다. 원장에 '기타'로 구분해 적었고, 사용자 결정(9/24)으로
  프로젝트 예산에서 처리한다.
