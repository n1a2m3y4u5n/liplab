# 입모양 엔진 지속시간 점검(C-현황, 선택 과제)

> 2026-09-23. 계획서 C-현황은 "음운 유사도와 비심 지속시간이 수작업 상수이고 경험적으로 검증된 적이 없다"는
> 문제를 들었다. 유사도는 축 C에서 다뤘고, 여기서는 지속시간 상수(`backend/engine.py`의 `DURATION_MAP`)를 실제 발화
> 시간과 비교한다. 앱 동작은 바꾸지 않았다(4절 제안).

## 1. 방법

- 실측: AI Hub 538 실발화 10화자 280문장(정렬 성공분)의 wav2vec2 강제정렬 음절 위치(`d/spans.jsonl`, 30fps).
  CTC 정렬은 음절의 경계가 아니라 음절 안의 한 점(피크)을 준다. 그래서 같은 어절 안에서 이웃한 두 음절 피크 사이의
  간격(IOI)을 앞 음절의 길이로 봤다. 어절 경계를 넘는 간격은 쉼이 섞여 따로 셌다. 600ms가 넘는 어절 안 간격은 뺐다.
- 엔진: `engine.text_to_visemes(문장)`이 만든 프레임 길이를 음절별로 더한 값(초성·중성·종성·전환 프레임, 최소 50ms 보정 포함).
- 도구: `liplab-lab/tools/c_duration_check.py`, 결과 `liplab-lab/data/c_duration_538.json`.

## 2. 결과

| 항목 | 실제 발화 | 엔진 | 엔진/실제 |
|---|---|---|---|
| 어절 안 음절 길이 평균(중앙) | 166ms(150) | 313ms(290) | 1.88 |
| 말속도(어절 안) | 초당 6.0음절 | 초당 3.2음절 | |
| 받침 없는 음절 | 157ms | 266ms | 1.70 |
| 받침 있는 음절 | 188ms | 425ms | 2.26 |
| 초성 없는 음절(ㅇ 초성) | 163ms | 217ms | 1.33 |
| 어절 사이 간격 평균(중앙) | 259ms(183) | 음절 길이 + 쉼 120ms | |
| 문장 길이(첫~끝 음절) 평균 | 4.5초 | 8.1초 | 1.78 |

- 음절 4,107개에서 엔진 길이와 실제 간격의 순위상관은 0.30이다. 문장 길이의 순위상관(0.88)은 대부분 음절 수에서 온다.
- 엔진은 전체적으로 실제 말보다 약 1.9배 느리다. 학습용으로 천천히 보여 주는 속도로는 받아들일 수 있다.
- 방향은 맞지만 폭이 어긋난다. 실제로도 받침이 있는 음절이 없는 음절보다 길지만(20%), 엔진은 받침 프레임(130ms)과
  전환 프레임 때문에 60% 길게 만든다. 초성이 없는 음절은 초성 프레임이 빠져 다른 음절보다 상대적으로 짧다.
- 초성 종류(평음·경음·격음·비음·유음) 사이의 실제 길이 차이는 작다(159~192ms). 엔진은 격음 초성을 150ms로 가장 길게 둬
  격음 음절이 실제보다 2.2배 길다.

## 3. 한계

- CTC 피크 간격은 음절 길이의 근사다. 피크 위치는 음절 안에서 조금씩 흔들리므로 음절 하나의 값은 잡음이 크고, 평균과 비율로만 읽는다.
- 낭독체 문장(538)이다. 대화체·청각장애 화자의 말속도는 다를 수 있다.

## 4. 제안(적용하지 않음, 결정 필요)

- 기본 재생 속도는 지금처럼 천천히 두되, 플레이어의 '자연 속도'를 엔진 길이의 약 0.53배로 정의할 수 있다.
  전체 배율만 바꾸는 것이라 입모양 순서와 상대 길이는 그대로다.
- 받침 프레임만 줄이는 것은 개선이라고 하기 어렵다. `final_consonant`를 130ms에서 70ms, 50ms로 줄이면 받침 음절의 상대 길이는
  1.60배에서 1.37배, 1.30배로 실제(1.20배)에 가까워진다. 그러나 음절 단위 순위상관은 0.30에서 0.26, 0.24로 떨어진다.
  실제로도 받침 음절이 길어서, 엔진의 순위 정보 상당 부분이 받침 유무에서 오기 때문이다. 상수를 고치려면 음절 길이를 실측값에
  맞춰 회귀로 다시 추정하는 편이 낫다(이번 자료로 가능하나 립싱크 화면 전체의 타이밍이 바뀌므로 화면 확인과 함께 한다).
