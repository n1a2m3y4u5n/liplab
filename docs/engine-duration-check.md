# 입모양 엔진 지속시간 점검(C-현황, 선택 과제)

> 2026-09-23. 계획서 C-현황은 "음운 유사도와 비심 지속시간이 수작업 상수이고 경험적으로 검증된 적이 없다"는
> 문제를 들었다. 유사도는 축 C에서 다뤘고, 여기서는 지속시간 상수(`backend/engine.py`의 `DURATION_MAP`)를 실제 발화
> 시간과 비교한다. 앱 동작은 바꾸지 않았다(4절 제안).

## 1. 방법

- 실측: AI Hub 538 실발화 10화자 280문장(정렬 성공분)의 wav2vec2 강제정렬 음절 위치(`d/spans.jsonl`, 30fps).
  CTC 정렬은 음절의 경계가 아니라 음절 안의 한 점(피크)을 준다. 그래서 같은 어절 안에서 이웃한 두 음절 피크 사이의
  간격(IOI)을 앞 음절의 길이로 봤다. 어절 경계를 넘는 간격은 쉼이 섞여 따로 셌다. 600ms가 넘는 어절 안 간격은 뺐다.
- 엔진: `engine.text_to_visemes(문장)`이 만든 프레임 길이를 음절별로 더한 값(초성·중성·종성·전환 프레임, 최소 50ms 보정 포함).
- 도구: `liplab-lab/tools/c_duration_check.py`, 결과 `liplab-lab/data/c_duration_538.json`.

## 2. 결과

| 항목 | 실제 발화 | 엔진 | 엔진/실제 |
|---|---|---|---|
| 어절 안 음절 길이 평균(중앙) | 166ms(150) | 313ms(290) | 1.88 |
| 말속도(어절 안) | 초당 6.0음절 | 초당 3.2음절 | |
| 받침 없는 음절 | 157ms | 266ms | 1.70 |
| 받침 있는 음절 | 188ms | 425ms | 2.26 |
| 초성 없는 음절(ㅇ 초성) | 163ms | 217ms | 1.33 |
| 어절 사이 간격 평균(중앙) | 259ms(183) | 음절 길이 + 쉼 120ms | |
| 문장 길이(첫~끝 음절) 평균 | 4.5초 | 8.1초 | 1.78 |

- 음절 4,107개에서 엔진 길이와 실제 간격의 순위상관은 0.30이다. 문장 길이의 순위상관(0.88)은 대부분 음절 수에서 온다.
- 엔진은 전체적으로 실제 말보다 약 1.9배 느리다. 학습용으로 천천히 보여 주는 속도로는 받아들일 수 있다.
- 방향은 맞지만 폭이 어긋난다. 실제로도 받침이 있는 음절이 없는 음절보다 길지만(20%), 엔진은 받침 프레임(130ms)과
  전환 프레임 때문에 60% 길게 만든다. 초성이 없는 음절은 초성 프레임이 빠져 다른 음절보다 상대적으로 짧다.
- 초성 종류(평음·경음·격음·비음·유음) 사이의 실제 길이 차이는 작다(159~192ms). 엔진은 격음 초성을 150ms로 가장 길게 둬
  격음 음절이 실제보다 2.2배 길다.

## 3. 한계

- CTC 피크 간격은 음절 길이의 근사다. 피크 위치는 음절 안에서 조금씩 흔들리므로 음절 하나의 값은 잡음이 크고, 평균과 비율로만 읽는다.
- 낭독체 문장(538)이다. 대화체·청각장애 화자의 말속도는 다를 수 있다.

## 4. 제안과 결정(9/24)

- **결정:** 지속시간 상수는 그대로 둔다. 립싱크 플레이어의 2x 버튼을 '2x·실제'로 표시해 실제 말 빠르기에 가깝다고 알린다
  (엔진 대비 약 0.53배). 받침 상수만 줄이는 안과 회귀 재추정은 적용하지 않는다(아래 이유).


- 기본 재생 속도는 지금처럼 천천히 두되, 플레이어의 '자연 속도'를 엔진 길이의 약 0.53배로 정의할 수 있다.
  전체 배율만 바꾸는 것이라 입모양 순서와 상대 길이는 그대로다.
- 받침 프레임만 줄이는 것은 개선이라고 하기 어렵다. `final_consonant`를 130ms에서 70ms, 50ms로 줄이면 받침 음절의 상대 길이는
  1.60배에서 1.37배, 1.30배로 실제(1.20배)에 가까워진다. 그러나 음절 단위 순위상관은 0.30에서 0.26, 0.24로 떨어진다.
  실제로도 받침 음절이 길어서, 엔진의 순위 정보 상당 부분이 받침 유무에서 오기 때문이다. 상수를 고치려면 음절 길이를 실측값에
  맞춰 회귀로 다시 추정하는 편이 낫다(이번 자료로 가능하나 립싱크 화면 전체의 타이밍이 바뀌므로 화면 확인과 함께 한다).

## 5. 상수 회귀 재추정 사전등록(9/29, 적합 전에 씀)

9/24 결정에서 미룬 회귀 재추정을 한다. 목표는 음절의 상대 길이를 실제 발화에 가깝게 하면서 전체 템포(엔진/실제 약 1.9배,
1.0배는 학습용 속도, 2.0배는 실제 말 근사)를 그대로 두는 것이다. AI Hub 유래 상수가 저장소에 들어가지 않도록 적합은 공개
말뭉치(Zeroth-Korean)로만 하고, 538은 검증에만 쓴다(수치만 이 문서에 남긴다). 아래는 적합 결과를 보기 전에 정했다.

### 5.1 자료

- 적합: Zeroth-Korean train(`kresnik/zeroth_korean`, 공개) parquet 3개 조각(00000·00002·00004, 약 1.1만 발화).
  정렬은 앱 채점 경로의 정렬 모델(`dgop_acoustic.DEFAULT_MODEL_ID`, kresnik/wav2vec2-large-xlsr-korean)과 538 spans를 만든
  `build_cd.align_clip`(CTC 강제정렬, 30fps 글자 구간)을 그대로 쓴다(`liplab-lab/tools/zeroth_align.py`). 1절과 같은 거르기
  (정렬 성공, CER 0.6 이하, 글자 수 일치, 어절 안 간격 0 초과 600ms 이하)를 쓴다.
- 검증: AI Hub 538에서 이미 정렬해 둔 spans(9/24·9/25 파드 실행, 같은 정렬기) 가운데 1절 점검에 쓴 spk301~310을 뺀
  58명 1,510클립. 1절 결과를 보고 모델 꼴을 정했으므로 그 10명은 검증에서 뺀다(비교용으로 따로 보고만 한다). 검증은 파드에서 돌린다.

### 5.2 모델 꼴

음절 길이(엔진) = 초성 프레임 + 중성 프레임 + 종성 프레임 + 전환 프레임. 프레임 구조(입모양 순서, 프레임 수, transition_ms)는
바꾸지 않고 `DURATION_MAP`의 길이만 바꾼다. 매개변수 13개:

- 초성 5: 평음·경음·격음(ㅎ 포함)·비음·유음(지금 `get_phoneme_type` 분류 그대로).
- 중성 3: 단모음 짧음·단모음 긺(ㅏㅗㅜ)·이중모음(w계·ㅢ, 활음 70ms + 나머지). 여기에 초성 없는 음절의 모음 연장 1개를 더한다.
  1절에서 초성 없는 음절은 실제로 다른 음절과 길이가 거의 같았는데(163ms 대 166ms) 엔진은 초성 프레임이 빠져 짧았다.
- 종성 3: 장애음(ㄱ·ㄷ·ㅂ·ㅅ 등)·비음(ㄴ·ㅁ·ㅇ)·유음(ㄹ). 지금은 130ms 하나다.
- 전환 프레임 1: 받침 뒤 다음 초성으로 가는 동시조음 프레임(11·12·13). 지금은 35ms가 최소 보정으로 50ms가 된다.

초성 상수와 중성 상수는 어절 안 간격만으로는 나눠지지 않는다(모든 초성에 δ를 더하고 모든 중성에서 δ를 빼도 음절 길이가 같다).
그래서 초성 프레임의 가중 평균(Zeroth 적합 자료의 초성 종류 빈도로 가중)을 지금 값과 같게 묶는다. 자음 입모양이 보이는 시간은
평균으로는 지금과 같고, 종류별 차이만 자료로 정한다.

### 5.3 적합 절차

1. 엔진 음절 길이는 상수에 대해 선형이다. 설계 행렬은 실제 `engine.text_to_visemes`에 상수를 하나씩 1ms 올려 음절별 길이의
   변화로 구한다(코드와 모델이 어긋나지 않게).
2. 지금 상수로 Zeroth 적합 자료의 평균 비율 r0 = 엔진 음절 평균 / 실제 간격 평균을 잰다.
3. 실제 간격(ms)을 β로 최소제곱 적합한다. 제약은 초성 가중 평균 묶음(β 공간에서 지금 값/r0)과 아래 최소 길이(β ≥ 최소/r0).
   중성 상수가 절편 구실을 하므로 적합 자료에서 평균 비율은 r0로 유지된다. 새 상수 = r0 × β를 5ms 단위로 반올림하고,
   최소 길이 아래로 내려가면 최소 길이를 5ms 단위로 올린 값으로 둔다.
4. 보고용으로 Zeroth 안에서 화자 5겹 교차검증(화자 단위로 나눠 4/5로 적합, 1/5에서 순위상관)을 낸다. 판정에는 쓰지 않는다.
5. 모델 꼴은 하나만 적합하고 538에는 한 번만 댄다. 적합이 안 되거나 판정을 못 넘으면 상수를 바꾸지 않고 결과를 남긴다.

### 5.4 최소 프레임 길이(visemeTiming 기준)

`frontend/src/lib/visemeTiming.js`는 프레임 길이 d(엔진 ms), 재생 속도 s에서 전환을 max(16, min(transition_ms, 0.6d))/s 동안
옮기고 프레임은 d/s 동안 보인다. 16ms 이상인 프레임은 계산상 늘 목표에 닿지만, 화면에 목표 입모양이 한 장이라도 그려지려면
전환이 끝난 뒤 60Hz 화면 한 장(16.7ms) 이상 머물러야 한다. 2.0배에서 이 조건은 d − max(16, min(tr, 0.6d)) ≥ 33.3ms이고,
엔진이 쓰는 transition_ms 20·30·35·40에서 각각 d ≥ 54·64·69·74ms다. 그래서 최소 길이를 초성·중성(단모음) 74ms,
종성 69ms, 전환 프레임 54ms, 이중모음 합계 144ms(활음 70ms 뒤 나머지 74ms)로 둔다. 지금 전환 프레임(50ms, tr 20)은
2.0배에서 목표에 머무는 시간이 15ms라 이 조건에 4ms 모자란다.

### 5.5 판정 기준(538 검증 58명, 모두 넘어야 적용)

| 번호 | 기준 | 문턱 |
|---|---|---|
| 1 | 음절 단위 순위상관(엔진 음절 길이 대 실제 어절 안 간격, 동률은 평균 순위) | 0.40 이상(9/23 값 0.30) |
| 2 | 받침 있는/없는 음절 길이 비(엔진)와 실제 비의 차이 | 0.15 이내(9/23 실제 1.20) |
| 3 | 모든 한글 프레임이 5.4절 최소 길이 이상(검증 문장과 앱 콘텐츠 전체) | 위반 0 |
| 4 | 평균 엔진/실제 비율(템포 유지) | 1.8~2.0 |
| 5 | 피크 간격 대응 순위상관(엔진 모음 중심 사이 간격 대 실제 피크 간격)이 지금 상수보다 떨어지는 폭 | 0.02 이하 |

- 5번은 음절 합계만 맞추느라 입모양 사건의 시각이 오히려 어긋나지 않았는지 보는 안전 기준이다. CTC 피크는 음절 안의 한 점이라
  실제 간격은 앞 음절의 모음 뒤쪽·받침과 다음 음절의 초성을 함께 담는다. 엔진도 같은 식으로 재면 이 대응이 된다.
- 순위상관 동률 처리: 1절 도구(`c_duration_check.py`)는 argsort 순위라 동률을 임의로 끊었다. 새 상수는 값의 종류가 늘어
  동률이 줄기 때문에 그대로 비교하면 새 상수에 유리하다. 그래서 지금 상수와 새 상수 모두 평균 순위(scipy `spearmanr`)로 다시 잰다.
  1번 문턱은 이 방식의 값에 댄다. 화자 부트스트랩 95% 구간도 함께 보고한다(판정은 점추정).
- 통과하면 `engine.py`에 적용하고 동결 폼·단어 입모양 서명(순서)이 그대로인지, 프레임 구조가 같은지 확인한다. 떨어지면 상수를
  그대로 두고 부정 결과로 남긴다.
