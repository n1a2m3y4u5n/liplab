# C65 seed1 lab-main 이전·병렬 실행 기술 부록 (2026-11-02)

## 시작 전 변경 범위

사용자의 추가 지시에 따라 원래 등록 **48a398cc**의 C65 seed1만 lab-sub 순차 대기에서 **lab-main RTX3060의 새 실행**으로 옮긴다. lab-sub에서 이미 진행 중인 seed0은 그대로 둔다. seed0 종료를 기다리지 않고 main seed1을 시작해 두 GPU에서 병렬 학습하는 **실행 PC·배치 시점의 기술 변경**이다. 이 부록을 커밋한 뒤에만 main seed1을 시작한다.

학생 소스 `scripts/nextreg_distill65.py`는48a398cc와 변경이 없음을 확인했다. 현재 실행 파일 SHA256은 **92b916951fdb4975dc05b42ee09167ccd22dbb465cfb74f848516afa15468165**다. 코드는 이 부록 때문에 수정하지 않으며 학습 중인 seed0의 프로세스·입력·출력·부분 체크포인트도 바꾸지 않는다. seed0이나 seed1을 멈췄다가 이어 붙이는 변경이 아니다. main seed1은 비어 있는 자기 출력 경로에서 **seed1 처음부터 한 번** 실행한다.

## 고정 과학 조건

원래 C65 구조3,940,973파라미터(선생의65.17231257457204%), stem16·잔차24/48/96/192·fc256·BiGRU2층332·53출력은 그대로다. 선생은 두 시드 모두 B33 seed0 SHA256 **d499c9f26affd57ef9cc4014c48337669ecfed7466a1ef8ac81c68742007ca1a**로 유지한다. 학습33명·검증12명·문장 제외·어휘·분할·배치32·4000프레임 그룹·최대40에폭·2에폭마다 검증·patience6·lr3e-4·wd1e-4·AMP0·CPU4스레드·GPU cap0.45는 바꾸지 않는다.

같은400프레임 train-only 선생 캐시, T=2,0.5CTC+0.5T²KL, 같은 증강·체크포인트 선택 규칙이다. 학생 시드는 local0/main1이며 초기 setup과 최종 trainer 인자 모두 해당 시드를 유지한다. KMSAV·평가19명·clean_eval·E2·OLKAVS·새 자료를 쓰지 않는다.

**두 시드는 여전히 모두 필수이며 seed0의 과학 관문 결과와 관계없이 seed1을 한 번 실행한다.** 각 시드의 관문은 선생 대비4지 차≥−0.02, FP32 ONNX 크기≤75%, 같은PC WASM 시간≤60% 그대로다. 두 시드가 각각 세 관문을 모두 넘어야만 안정 통과다. 좋은 시드만 고르거나 이전38%·50% 결과·기준을 바꾸지 않는다. 개발 선택이며 판정 없음, 깨끗한 평가 대기다.

## 로컬 중복 실행 방지 인계

기존 local 순차 controller는 이미 메모리에 로드돼 있으므로 파일에 새 flag를 쓰는 것만으로 seed1 취소가 보장되지 않는다. root가 main 시작 전에 별도 **S4U 인계 watcher**를 등록·시작하고 실제 생존을 확인한다. watcher는 현재 seed0을 중단하지 않고 종료를 기다린다.

원래 controller는 seed0 Python의 `WaitForExit` 뒤 정상 종료면 `seed0-trained.txt`, 기술 실패면 `seed0-failed.txt`를 쓴다. watcher는 **정상/실패 종료 marker 모두**를 감시한다. 정상 marker만 기다리면 seed0 기술 실패 후에도 local seed1이 시작될 수 있으므로 실패 marker도 같은 인계 신호로 처리한다. marker가 현재 실행의 것임을 확인하고 자기 seed0 프로세스가 이미 종료됐음을 확인한 뒤에만 기존 순차 controller를 **중지·사용 안 함**으로 바꾼다.

기존 controller의 seed1 진입 전에는 idle 확인3회(30초 간격)의 **최소60초 대기 창**이 있다. watcher는 seed0 종료 직후 이 창 안에서 기존 controller를 중지해 local seed1 생성 전에 막는다. main seed1 시작 전에 watcher가 유효하게 대기 중이고 기존 local seed1 프로세스가0개임을 확인한다. 인계 후에도 local seed1이 생성되지 않았고 main seed1만 한 개임을 확인·기록한다. 인계가 보장되지 않으면 main을 먼저 중복 시작하지 않고 root가 제어 문제를 해결한다.

controller의 이 **의도적 중지·disable은 학습 실패가 아니다.** seed0의 실제 Python 종료코드·성공/실패 marker·로그는 그대로 보존하고, main seed1의 새 시작·PID·GPU 기록과 controller 인계 이유를 별도로 남긴다. seed0이 기술 실패였다면 그 실패는 숨기지 않되 controller 인계 자체를 seed0/seed1 실패로 세지 않는다. 다른 프로젝트·DACON·다른 학습 프로세스를 중단하지 않는다.

## main 시작·비교·시간 측정

main은 사전에 nvidia-smi로 DACON/Python GPU 점유 부재와 시스템 여유 RAM16GB 이상을 확인하고 Ollama를 내린다. cap0.45·AMP0·CPU4를 유지한다. 승인된 B33 입력과 같은 고정 선생만 main 자기 새 작업 경로에 복사하고, 시작 후 실제 seed1 PID·명령·GPU 사용·출력 경로를 확인한다. local seed0의 계속된 생존도 확인한다. 입력 사본·캐시는 원래 규칙대로 회수와 비교 후 자기 폴더에서만 삭제한다.

학습 시간 설정은 시드당30~50분 그대로이며, 이번에는 두 시드가 병렬이므로 원래 순차60~100분 예측은 남은 경과 시간에 적용하지 않는다. 자원 대기·후속 비교·내보내기·WASM 대기는 별도다. 성능 관측으로 에폭이나 종료 규칙을 줄이지 않는다.

WASM 측정 순서는 **C0→C1→D0→D1→C65 seed0→C65 seed1→새 별도 등록 D65 seed0(마지막)**으로 유지한다. C65 두 측정은 같은 lab-sub PC·같은 고정 합성 입력·같은20쌍 프로토콜에서 한 번씩 하며 이전 후보를 재측정하지 않는다. D1의 네 관문은 시드별로 통과했지만 D0 실패로 기록용인 기존 해석을 유지한다. 그 결과가 C65 조건·시드·교사·관문을 바꾸는 근거가 아니다.

산출물은 원래 `out/nextreg-2026-11-02/distill65/seed0`·`seed1`로 회수해 원래 기준으로 묶는다. PC 변경·watcher/원래 controller 상태·main 시작과 실제 GPU 사용은 보고서·outbox에 추가하고, 앱·플래그·배포·푸시는 하지 않는다.

## 실행 확인

이 문서는 시작 전 기술 등록이다. 실제 인계·main seed1 시작 확인은 root가 등록 커밋 뒤 실행하고 보고서에 남긴다. 이 부록을 작성하면서 GPU 실행·실제 평가·기존 소스·기존 등록 결과를 수정하지 않았다.
