# 채점 모델 경량화(S4): D-GOP 교사를 작은 학생 모델 하나로 증류 (2026-10-07, 사전 등록)

`docs/master-plan-2026-10.md`의 S4와 `docs/idea-sweep-2026-10-03.md`의 나27을 한다. 1~9절은 학생 모델을 학습하기 전에 적고 따로
커밋한다. 결과는 10절 뒤에 붙인다. 측정 전에 바꾼 것이 있으면 9.3절에만 덧붙인다.

## 1. 목적

지금 앱의 전사 비의존 발음 채점(D-GOP)은 정렬기와 채점기 두 모델(각 wav2vec2-large 311M, int8 파일 각 355MB)을 서버 CPU에서 돌린다
(`docs/scorer-selftrain.md` 7절). 두 모델의 프레임 사후확률을 작은 모델 하나(약 95M)에 증류해, 같은 채점 함수로 비슷한 판별력을 내는지 본다.
통과하면 채점을 브라우저(ONNX Runtime Web, WASM 또는 WebGPU)로 옮길 수 있어 목소리가 기기 밖으로 나가지 않고(제안서 4.9절), 서버의 켜질 때
지연과 메모리·비용이 줄어든다. 이번 작업에서 앱의 제품 채점기는 바꾸지 않는다.

## 2. 교사와 학생

### 2.1 교사

- 정렬기·채점기 int8(`liplab-lab/models/dgop_ours_2026-09-25_int8`, sha256 정렬기 `18681947…`, 채점기 `e8340d58…`). 9/25 Zeroth-Korean
  재학습판이고 지금 liplab-dev가 쓰는 판이다. 어휘는 위치 접두 자모 49개(blank `<pad>` 포함).
- 채점 코드는 10/6 점수 재생성과 같은 앱 커밋 b675975의 `backend`(`dgop_acoustic.assess_text`, `phone_confidences`)를 그대로 쓴다.
  b675975 이후 `dgop_acoustic.py`에는 말 빠르기(S7) 계산만 더해졌고 `dgop.py`·`jamo_vocab.py`·`ctc_align`은 바뀌지 않았다.
- 증류 목표를 만들 때는 int8 가중치를 GPU에서 fp32로 풀어 쓴다(계산은 9/25 int8 점검의 CPU·GPU 경로 일치와 같다).

### 2.2 학생(한 모델, 출력 두 개)

학생은 인코더 하나 위에 선형 CTC 출력층 두 개(정렬기 몫 A, 채점기 몫 S, 각 49차원)를 둔다. 합성곱 특징 추출부의 보폭이 교사와 같아(320표본,
약 20ms) 프레임 수가 교사와 같다. 채점은 A 출력으로 강제정렬하고 S 출력의 구간 평균 분포에서 목표 자모 확률을 읽는, 교사와 같은 함수다.
순전파가 한 번이라 교사(311M 두 번)보다 계산이 크게 준다. 입력은 16kHz 원 파형이고, 정규화는 모델 안에 넣는다.

| 초기값 | 구성 | 파라미터(어림) | 출처·라이선스 |
|---|---|---|---|
| H: 한국어 HuBERT | `team-lucid/hubert-base-korean` 그대로(12층, 768차원), 출력층 둘은 새로 초기화. 입력 정규화 없음(원 모델 설정) | 약 95M | 모델 카드 Apache 2.0. 사전학습 자료는 AI Hub 자유대화 음성(109), 다화자 음성합성(542), 방송 콘텐츠 대화체(463) 약 4,000시간(카드 기재) |
| X: 축소 XLS-R | 교사 채점기(XLS-R 300M 계열, Zeroth 미세조정)의 합성곱·투영·위치 합성곱과 트랜스포머 24층 가운데 6층(0, 5, 9, 14, 18, 23번)과 마지막 층 정규화. 출력층 S는 교사 채점기, A는 교사 정렬기의 출력층에서 복사. 입력은 교사와 같이 평균 0·분산 1 정규화 | 약 89M | XLS-R 300M Apache 2.0, 미세조정 자료 Zeroth-Korean CC BY 4.0 |

두 초기값의 크기를 비슷하게 맞추려고 X는 6층으로 정했다(1층 약 12.6M). 두 학생 모두 합성곱 특징 추출부는 학습하지 않는다(얼림).

## 3. 증류 자료와 라이선스

증류는 교사 출력을 목표로 쓰므로 전사가 필요 없다. 평가에 쓰는 AI Hub 538·608 음성은 학습에 한 개도 쓰지 않는다(평가 화자 분리가 저절로 성립한다).
큰 자료는 모두 파드에서 Hugging Face로 직접 받고 맥을 거치지 않는다.

| 자료 | 쓰는 범위 | 라이선스 | 비고 |
|---|---|---|---|
| Zeroth-Korean(`kresnik/zeroth_korean`, 원 출처 OpenSLR 40) | 학습 22,263발화(51.6시간) 원본 + 발화마다 저하 사본 하나. 시험 457발화는 학생 고르기용 개발 자료 | CC BY 4.0(OpenSLR 40 표기, HF 사본 카드에는 표기 없음) | 교사의 학습 자료와 같다 |
| YODAS 한국어(`espnet/yodas` ko000, 수동 자막 부분) | 셔드 8개(0, 35, 70, 105, 140, 175, 210, 245번), 같은 영상의 이어진 구간을 10초 이하 덩어리로 이음. 깨끗한 덩어리 80시간까지, 그중 절반(덩어리 이름 crc32 짝수)에 저하 사본 | CC BY 3.0(데이터셋 카드). 영상 자체가 CC 라이선스인 것만 모았다고 적혀 있다 | 아래 3.1 |

### 3.1 Emilia 대신 YODAS를 쓰는 이유

나27은 Emilia-YODAS 한국어(CC BY 4.0)를 제안했다. 10/7 확인에서 `amphion/Emilia-Dataset`은 Hugging Face 게이트(gated: auto)가 걸려 있어, 로그인한
계정이 이용 조건에 동의해야 받을 수 있다. 계정 동의는 사용자 몫이라 이번에는 하지 않는다. Emilia-YODAS의 원천인 `espnet/yodas`는 게이트가 없고
같은 유튜브 CC 영상 묶음이라 대신 쓴다. Emilia는 YODAS를 정제(음성 구간·화자 분리)한 판이고, YODAS 원본에는 음악·잡음·다른 언어 구간이 더 섞인다.

### 3.2 저하 사본

`liplab-lab/tools/make_deaf_corpus.py`의 `sample_aug(rng, 'stretch')`와 `perturb_safe`(포먼트 0.84~1.0, 말속도 0.78~0.97, 고역 감쇠 1,900~4,000Hz,
SNR 8~30dB, 난수 씨앗은 발화 이름의 crc32)로 만든다. 교사 정렬기를 학습할 때 쓴 증강과 같은 계열이다. 저하 사본에도 교사를 다시 돌려 그 출력을
목표로 쓰므로, 학생은 저하된 발화에서 교사가 확률을 어떻게 낮추는지를 배운다.

## 4. 학습(두 초기값에 같은 예산)

- 교사 출력 미리 계산: 모든 학습 발화(원본·저하)에 교사 정렬기·채점기를 한 번 돌려 프레임 로짓(float16)을 저장한다. 두 학생이 같은 목표를 쓴다.
  묶음 순전파(길이 정렬, attention mask)와 발화 하나씩 순전파의 로짓 차이를 표본 20개로 점검해 기록한다.
- 손실: 출력마다 프레임 평균 KL(교사 ∥ 학생), 온도 1, 두 출력의 합. D-GOP는 온도 1의 사후확률을 그대로 읽으므로 온도를 바꾸지 않는다.
- 입력 자르기: 덩어리를 길이로 묶고 묶음 안의 가장 짧은 길이(최대 10초)로, 320표본 배수 위치에서 자른다. 학생 프레임 j가 교사 프레임
  (시작/320 + j)와 정확히 맞으므로 덧대기(padding)가 없다. 교사 목표는 전체 발화 문맥에서 계산한 값이다.
- 최적화: AdamW(β 0.9·0.98, 가중치 감쇠 0.01), 최고 학습률 1e-4, 처음 5% 선형 예열 뒤 0까지 선형 감소, bf16, 기울기 자르기 1.0.
  드롭아웃은 은닉·주의·투영 0.05, layerdrop 0, 시간 가리기(SpecAugment) 없음. 두 초기값에 같은 값이다(이 자료로 조정하지 않는다).
- 예산: 묶음당 음성 합계 240초 이하, 단계 수 N = ceil(2 × 학습 자료 총 초 / 240)(자료를 두 번 도는 양). 두 학생이 같은 순서·같은 묶음·같은 N을 쓴다.
- 개발 손실(보고만): YODAS 덩어리 끝 1%와 Zeroth 시험 457발화(원본·저하)의 KL.

## 5. 내보내기

- ONNX(opset 17): 입력 파형 [1, 표본 수] float32, 출력 정렬 로짓·채점 로짓 [1, 프레임, 49]. 위치 합성곱의 weight norm은 일반 가중치로 접는다.
- 주 산출물(판정 대상): 가중치 전용 int8. 행렬곱·합성곱 가중치를 출력 채널별 대칭 int8(scale = max|w|/127)로 두고 DequantizeLinear로 풀어
  fp32로 계산한다. 서버 int8(`backend/quant_int8.py`)과 같은 방식이고, WASM과 WebGPU에서 모두 도는 표준 연산만 쓴다.
- 보고만: onnxruntime 동적 양자화판(활성값도 int8로 곱함)의 크기·지연·판별력.

## 6. 평가 자료와 절차

모든 채점은 b675975 `backend`의 `assess_text`·`phone_confidences`를 그대로 부르고, 음향 출력(`ctc_outputs` 또는 `ctc_log_probs`)만 학생으로 바꿔 끼운다.
학생은 파드 CPU에서 ONNX Runtime으로 돌린다. 학생 순전파는 클립마다 한 번이고, 두 출력이 정렬기 몫·채점기 몫으로 들어간다.

### 6.1 E1: 10/6 재생성 짝(문장 판별)

- 10/6 `dgop_full.jsonl`의 608(감음신경성 24명, 자기 문장 363)과 538(정상 58명, 자기 문장 600)의 `same`·`diff` 짝 그대로.
- 10/7 규칙: 한글만 남긴 목표 문장이 자기 문장과 같은 `diff` 짝은 뺀다. 608 다른 문장 724 → 703짝, 538은 1,198짝 그대로.
- 소리: 608은 `cuts608.json`의 시작·끝 초로 원본 세션 FLAC을 같은 방식(`sf.write`)으로 다시 자르고, 538은 10/6과 같은 클립(wav)을 쓴다.
- 교사 기준값은 10/6 CPU int8 점수다(같은 행). 이 짝에서 608 AUC 0.9034, 538 AUC 0.9981, 합격선 65에서 자기 문장 불합격은 538·608 합쳐 963문장 중
  78개(8.10%)다.
- 다리(유효성): 같은 파드에서 교사 int8(GPU)로 E1 전체를 다시 채점해 10/6 값과 비교한다. 표시 점수 차 0.5 이하인 행이 99% 이상이고 608 AUC 차가
  0.002 이하여야 한다. 어기면 소리 재현에 문제가 있는 것으로 보고 판정을 보류(HOLD)한다.
- 채점 실패(점수 없음)는 원점수 0으로 친다(자기 문장이면 불합격, 다른 문장이면 불합격).

### 6.2 E2: 사·자·차·하 대치(앱 방향)

- `scripts/speak_app_direction_pod_eval.py`(9/29)의 짝 규칙·자리 고르기·시드를 그대로 쓰고 자음 부분만 잰다. 자료는 538 클립 1,740개(58명)와
  10/6 608 컷 363개(24명, 9/29의 9/28 컷 360개는 남아 있지 않다).
- 지표는 `docs/speak-consonant-check.md` 앱 방향 재측정과 같다. ㅅ = ㄷ→ㅅ, ㅈ = ㄷ→ㅈ와 ㅊ→ㅈ 합산, ㅊ = ㅈ→ㅊ의 같은 녹음 AUC,
  ㅎ = ㄱ→ㅎ 같은 녹음 AUC와 ㅎ 탈락 고정 목표 AUC. 교사(GPU int8)와 학생을 같은 파드·같은 짝으로 잰다.

### 6.3 개발 자료(학생 고르기 전용)

Zeroth 시험 457발화 × 소리 조건 4개(원본, `make_deaf_corpus.PRESETS`의 mild·mod·sev, 씨앗 crc32(발화 이름)) × 목표(자기 문장, 음절 수 ±30%인
다른 시험 문장 2개, Random(0)). 교사(GPU int8)와 학생(ONNX int8, CPU)의 원점수를 같은 행끼리 비교한다. 538·608은 쓰지 않는다.

### 6.4 지연과 크기

- 지연: 파드 CPU, ONNX Runtime 스레드 2개(intra-op), 한 번에 한 문장. 문장 하나의 끝에서 끝 시간(오디오 디코딩 → 학생 순전파 → 강제정렬 → 채점,
  목표 하나)을 E1의 538 50문장·608 50문장(이름 순 등간격)에서 잰다. 앞의 3문장은 데우기로 버린다. CPU 모델명을 기록한다.
- 같은 파드에서 교사 int8(torch CPU 2스레드, 앱 경로)도 같은 문장으로 잰다(비교용).
- 크기: 채점에 필요한 ONNX 파일 하나의 바이트 수.

## 7. 판정 기준

### 7.1 고르기(학습 뒤, 평가 전에 정함)

두 학생 중 6.3 개발 자료에서 교사와의 원점수 평균 절대차가 작은 쪽을 고른다(같으면 개발 자료 원본·mod·sev 자기 대 다른 문장 AUC 평균이 높은 쪽).
판정은 고른 학생으로만 한다. 고르지 않은 학생의 수치도 같은 표에 보고하지만, 고른 학생이 떨어졌을 때 대신 채택하지 않는다(사후 선택이 된다).

### 7.2 통과 조건(고른 학생, 주 산출물인 가중치 전용 int8 ONNX, 모두 만족해야 통과)

| 번호 | 기준 | 값 |
|---|---|---|
| C1 | 608 AUC 하락(E1, 자기 363 대 다른 703) | 학생 AUC ≥ 교사 0.9034 − 0.01 = **0.8934** |
| C2 | 같은 엄격도에서 538 다른 문장 합격 | ≤ **5%**. 엄격도 맞추기: 학생 합격선 τ를 E1 자기 문장 963개(538·608 합침)의 불합격 비율이 교사(합격선 65)의 8.10%와 같아지는 학생 원점수 분위수로 정한다(numpy `quantile(…, 0.0810, method="inverted_cdf")`, τ 미만이 불합격). 그 τ에서 538 다른 문장 1,198짝 가운데 τ 이상의 비율 |
| C3 | 사·자·차·하 대치 AUC 유지(E2) | ㅅ, ㅈ, ㅊ, ㅎ(ㄱ→ㅎ), ㅎ 탈락 다섯 값이 538과 608에서 모두 **≥ 0.80** |
| C4 | 크기 | ONNX 파일 ≤ **105MB**(10⁶바이트 기준, '100MB 안팎'을 5% 여유로 둠) |
| C5 | 지연(중급 노트북 CPU의 대리) | 6.4의 100문장에서 문장당 시간의 95백분위 ≤ **3.0초** |

- 전부 만족: '통과(브라우저 채점 후보)'. 11절에 통합 계획을 적는다. 앱 코드는 이번에 바꾸지 않는다.
- 하나라도 미달: '미달'. 무엇이 모자랐는지와 수치를 부정 결과로 남기고 앱은 그대로 둔다.
- 다리(6.1)가 어긋나면 'HOLD'로 적고 판정하지 않는다.

### 7.3 보고만(판정에 쓰지 않음)

- C1의 차이에 대한 화자 짝지은 부트스트랩 95% 구간(2,000회, 시드 0), 538 AUC, 608 다른 문장 합격(같은 τ), 화자 절반별 608 AUC.
- 학생 표시 점수: 개발 자료(6.3)에서 교사 원점수 앵커가 놓인 분위수의 학생 원점수를 학생 앵커로 삼는 분위수 맞추기 보정을 만들고, E1에서 교사 표시
  점수와의 차(평균, 95백분위)와 합격선 65의 불합격·다른 문장 합격.

## 9. 한계와 기록

### 9.1 한계(미리)

- C1은 608 24명의 점추정이다. 화자 수가 적어 부트스트랩 구간이 넓을 것이고(10/6 S19의 AUC 차 구간 폭 약 0.08), 0.01 하락 기준은 그 구간보다 좁다.
  통과해도 '같다'가 아니라 '이 자료에서 0.01 넘게 떨어지지 않았다'로만 쓴다.
- 지연은 파드 서버 CPU의 네이티브 ONNX Runtime 값이다. 브라우저 WASM은 보통 이보다 느리고(SIMD·스레드 지원에 따라 다름), 실제 노트북·태블릿에서의
  값은 따로 재야 한다.
- 학생은 교사를 따라 하도록만 배운다. 교사보다 나아질 이유가 없고, 교사의 약점(중·심 저하에서의 음소 위치 짚기, 거센소리 대치 ㅋ→ㄱ·ㅍ→ㅂ)도 물려받는다.
- 초기값 H의 사전학습 자료는 AI Hub 자료다. 모델 카드는 Apache 2.0이지만 제품에 넣기 전에 해당 AI Hub 자료의 파생 모델 이용 조건을 확인해야 한다.
  X는 XLS-R(Apache 2.0)과 Zeroth(CC BY 4.0)만 거친다.
- YODAS는 CC BY 3.0이라 학생 모델을 공개하거나 배포할 때 출처 표시가 필요하다(Zeroth도 CC BY 4.0).

### 9.3 측정 전 변경 기록

모두 학생을 학습하기 전(교사 목표를 계산하는 동안, 10/7 11:50~12:10)에 정했다. 판정 기준(7.2)은 바꾸지 않았다.

- 파드: A100 80GB PCIe SECURE `ubn4h922kfnx03`. 보이는 코어는 252개지만 cgroup v1 할당이 26코어라, 병렬 수 계산을 cgroup v1(`cpu.cfs_quota_us`)도
  읽게 고친 뒤 처음부터 다시 시작했다(설치 단계에서 멈추고 다시 띄움, 결과 없음).
- 자료 양(실측): 학습 풀 97,100개 234.8시간(Zeroth 원본 51.7, 저하 59.3, YODAS 원본 79.1, 저하 44.7). YODAS 셔드 8개가 각각 약 10시간이라 80시간
  상한에 마지막 셔드에서 닿았다. 개발 KL용 YODAS 1%는 '끝 1%' 대신 덩어리 이름 crc32 % 100 = 0인 것으로 뽑았다(셔드를 하나씩 흘려 쓰기 때문, 보고만 하는 값).
- 교사 목표의 정밀도: 증류 목표는 TF32 행렬곱으로 계산했다. 같은 20개 표본에서 TF32 묶음 계산과 하나씩 계산한 로짓 차는 중앙값 0.028, 최대 0.40이고,
  TF32를 끄면 최대 0.016(float16 저장 반올림 수준)이었다. 차이는 TF32 때문이고 묶음 덧대기 때문은 아니다. 목표의 잡음이 학생 오차보다 훨씬 작다고 보고
  다시 계산하지 않았다. 평가(6절)의 교사는 TF32를 끈 fp32로 계산한다.
- 주 산출물의 양자화 범위: 5절은 합성곱 가중치도 int8로 둔다고 적었다. 학습 전 X(교사 층을 그대로 가져와 출력이 교사와 비슷함)에서 ONNX fp32 대비 int8판의
  출력 확률 차를 재 보니, 행렬곱만 int8이면 최대 0.00001, 합성곱까지 int8이면 0.66(위치 합성곱이 대부분, 특징 추출 합성곱만이면 0.12)이었다. 서버 int8도
  합성곱은 양자화하지 않는다. 그래서 **행렬곱 가중치는 int8, 합성곱 가중치(특징 추출 7층과 위치 합성곱)는 float16**으로 저장하고 Cast로 fp32로 푼다.
  크기는 X 102.4MB, H 104.6MB로 C4(105MB) 안이고, 이 크기는 학습과 관계없이 구조로 정해진다. 합성곱까지 int8인 판(X 89.8MB, H 95.7MB)은 쓰지 않는다.
