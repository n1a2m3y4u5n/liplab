# 자체 학습 발음 채점 모델과 실제 청각장애 발화 평가(A-1·A-2·B, 2026-09-25)

팀원 비공개 체크포인트(`duadnwls/liplab-dgop-*`)는 옛 채점식(음소 확률 × 확신도)을 기준으로 설계·검증돼 쓰지 않기로 했다
(작성자 확인). 같은 레시피(`scripts/train_jamo_ctc.py`, `scripts/train_aligner.py`)로 채점기와 정렬기를 우리가 다시 학습하고,
지금 앱이 쓰는 공개 모델(kresnik/wav2vec2-large-xlsr-korean)과 같은 채점식(naive, `dgop.sentence_dgop`)·같은 정렬 코드(9/24
blank 수정판)로 비교했다. 판정 기준은 학습 전에 적었다(`liplab-lab/notes/scorer_prereg_2026-09-25.md`).

요약: 1차 평가(538 10화자)는 단조 비율이 +2.7%p 올랐지만 신뢰구간 하한이 0이라 관문에서 떨어졌고, 실제 청각장애 발화(608)의
정상 대비 분리도는 0.892에서 0.933으로 올랐다. 1차 뒤 등록한 독립 재검(538 새 20화자)에서 +3.8%p [2.3, 5.5]로 관문을 통과해,
우리 정렬기·채점기를 liplab-dev 채점 모델 후보로 올렸다(배포 전). 자기지도 음성변환(kNN-VC)은 실제 청각장애 발화를 규칙 합성보다
덜 닮아 부정 결과로 남긴다.

sha256 채점기 `6b960da4…`, 정렬기 `0e586260…`)에 보관했다.

## 2. 평가 1(주 판정): AI Hub 538 실발화 + 합성 저하

538 10화자 300문장에 규칙 저하(경·중·심)를 걸어 문장마다 원점수가 원본 ≥ 경 ≥ 중 ≥ 심 순서인지 본다.

| 모델 | 원본 | 경 | 중 | 심 | 단조 비율 | AUC(원본 > 심) |
|---|---|---|---|---|---|---|
| kresnik(지금 앱) | 80.2 | 49.7 | 26.6 | 5.8 | 95.7% | 1.000 |
| 우리 모델 | 85.0 | 53.6 | 30.5 | 9.2 | 98.3% | 1.000 |

- 단조 비율 +2.7%p, 화자 부트스트랩 95% CI [0.0, 5.7]. 관문(Δ ≥ +2%p **이고 CI 하한 > 0**)에서 하한이 정확히 0이라 **FAIL**이다.
  AUC는 두 모델 모두 1.000으로 합성 저하가 너무 쉬워 가르지 못한다(9/14 E1과 같은 천장).
- kresnik 결과는 9/24 재측정(80.2·49.6·26.7·5.8)과 같게 재현됐다.

## 3. 평가 2(보조): 실제 청각장애 발화(AI Hub 608 범주 28 감음신경성)

608 TS02(101GB)를 끝까지 흘려받아 범주 28 세션 27개(27명, 30분 이하, 화자당 1개)를 확보했다. 세션 전체를 kresnik으로
강제정렬해 문장으로 자르고(`b608_measure.py`, 세션당 최대 40문장) 두 모델로 같은 문장을 채점했다.

| | kresnik | 우리 모델 |
|---|---|---|
| 채점된 문장 | 660/669(정렬 실패 9) | 669/669 |
| 원점수 평균(정상 538 / 청각장애 608) | 80.2 / 38.0 | 85.0 / 50.6 |
| 분리도 AUC(정상 > 청각장애) | 0.892 | **0.933**(+0.041) |

- 전사 오류(kresnik 음절 CER 평균)는 정상 0.19, 청각장애 0.66(3.4배)이고, 문장 전체를 맞게 옮긴 비율은 1.8%다.
  그림 7에 608을 더했다(`docs/figures/fig7_b_remeasure.png`): 실제 청각장애 발화는 전사 오류(0.66)로도 D-GOP(38.0)로도
  합성 '경'(0.50, 49.7)과 '중'(0.72, 26.6) 사이에 놓인다. 규칙 합성의 강도 범위가 실제 발화를 덮는다는 뜻이다(A-10).
- 표시 점수 확인(A-7): 지금 앱의 kresnik 앵커(`backend/data/dgop_calibration_kresnik.json`)로 환산하면 608 문장은 중앙값
  66.2점(평균 57.1점)이고, 58점('중' 앵커) 미만 39%, 40점('심' 앵커) 미만 25%다. 바닥이나 천장에 몰리지 않아 앵커를 유지한다.
- 608 범주 28에는 노인성 난청 화자(70~90대)도 섞여 있어 선천성 농인 발화와 같지 않다.

## 4. 독립 재검(538 spk311~330, 20명 600문장): 통과

1차가 화자 10명이라 신뢰구간이 넓어 경계에서 떨어졌으므로, 1차에 쓰지 않은 화자로 같은 관문을 한 번 더 쟀다(학습·1차 결과를
본 뒤 실행 전에 등록: `liplab-lab/notes/scorer_prereg_replication_2026-09-25.md`). 두 번째 시험이라 1차와 합치지 않고
재검 결과만으로 판정한다. 첫 재검 파드는 워치독 마감에 결과를 잃어 같은 설계로 다시 돌렸다(RTX 4090, 추론만).

| 모델 | 원본 | 경 | 중 | 심 | 단조 비율 | AUC(원본 > 심) |
|---|---|---|---|---|---|---|
| kresnik(지금 앱) | 79.8 | 53.4 | 29.4 | 5.8 | 95.8% | 1.000 |
| 우리 모델 | 84.7 | 57.3 | 31.7 | 8.3 | 99.7% | 1.000 |

- 단조 비율 +3.8%p, 화자 부트스트랩 95% CI [2.3, 5.5], AUC 차 0.000으로 세 조건을 모두 만족해 **통과**다.
  ASR CER은 두 모델이 같다(전사는 둘 다 kresnik, 0.19·0.47·0.70·0.92).
- 1차(+2.7%p, [0.0, 5.7])와 재검(+3.8%p, [2.3, 5.5]) 모두 같은 방향이다. 보고서에는 1차 FAIL과 재검 통과를 함께 적는다.
- 사전등록 규칙대로 우리 정렬기·채점기를 liplab-dev 채점 모델 후보로 올린다(6절). 평가 2의 보류 조건(608 분리도가 0.02
  넘게 낮음)에는 해당하지 않는다(+0.041).

## 5. 보고용 부가 측정(판정에 쓰지 않음)

- A-3(Zeroth test 50발화 합성 저하): 우리 모델 단조성 1.000, 분리도 1.000, 정렬 견고성 1.000(천장).
- 표시 앵커(우리 모델용, `backend/data/dgop_calibration_ours.json`): kresnik 앵커와 같은 538 10화자 300문장의 조건별 원점수
  중앙값 86.0·54.5·30.4·8.2를 표시 90·72·58·40에 맞췄다. 맞출 때 쓰지 않은 재검 20화자에서 표시 중앙값은 90.0·74.7·58.9·39.4로
  거의 그대로다(kresnik 앵커는 같은 화자에서 89.2·75.2·60.7·41.8). 608 실발화는 우리 모델로 표시 중앙값 72.3점(65점 이상 64%)이다.
  A-4 절차(Zeroth 50발화 severity 0~4)로 맞춘 앵커(91.2·44.6·24.1·7.1·3.0 → 90·72·58·40·20)는 538 조건을 88.5·77.1·63.2·42.0으로
  매겨 kresnik 앵커와 눈금이 달라 쓰지 않는다.
- A-2·A-10(자기지도 음성변환 충실도, `liplab-lab/tools/a2_knnvc.py`): kNN-VC(WavLM-large 6층 최근접 이웃, HiFi-GAN)로 538 정상
  60문장을 608 화자 6명의 목소리로 바꿨다(360개). 변환본은 CER 0.35, D-GOP 65.6으로 원문(0.20, 79.5)에서 조금만 움직였고 실제
  608(0.66, 38.0)과는 멀다. 실제 608 분포와의 1차 Wasserstein 거리는 CER 기준 kNN-VC 0.33, 규칙 합성 경 0.21·중 0.22·심 0.35,
  D-GOP 기준 kNN-VC 27.7, 경 16.3·중 17.2·심 32.2다. 목표 화자별로 보면 실제 CER이 0.24~1.00으로 넓은데 변환본은 0.26~0.47에
  머문다. kNN-VC는 음색을 옮기지만 원문 화자의 조음·운율을 따르므로 청각장애 발화의 명료도 저하는 재현하지 못한다.
  그래서 합성 코퍼스는 규칙 합성(경~중)을 쓰고, 음성변환은 부정 결과로 보고한다(계획서 A-10의 충실도 확인과 폴백).
- 맞는 문장과 틀린 문장 가르기(`liplab-lab/tools/mismatch_check.py`, 재검 589클립, 목표 문장 규칙은 `bfuse_validate.py`와 같다):

  | 소리 | 틀린 목표 | kresnik AUC | 우리 AUC | 차이 [95% CI] | 틀린 목표 65점 이상(kresnik / 우리) |
  |---|---|---|---|---|---|
  | 원본 | 다른 문장 | 1.000 | 1.000 | 0.000 | 0% / 0% |
  | 원본 | ㅁ↔ㅂ·ㄴ↔ㄷ 1~2음절 | 0.675 | 0.678 | +0.003 [−0.012, +0.019] | 99% / 100% |
  | 중 | 다른 문장 | 0.972 | 0.972 | +0.000 [−0.007, +0.008] | 0% / 0% |
  | 중 | ㅁ↔ㅂ·ㄴ↔ㄷ | 0.545 | 0.524 | −0.021 [−0.027, −0.016] | 26% / 19% |
  | 심 | 다른 문장 | 0.765 | 0.794 | +0.029 [+0.002, +0.059] | 0% / 0% |

  다른 문장을 목표로 주면 두 모델 모두 합격선(65점)을 넘긴 적이 없다. 우리 모델은 틀린 문장에 조금 높은 표시 점수를 주지만
  (원본 중앙값 50.3점, kresnik 41.2점) 심한 저하에서는 더 잘 가른다. 한두 음절의 비음·파열음 바꿈은 같은 클립 안에서는
  참 문장이 이기지만(원본 승률 98~99%) 점수 차가 2~3점이라 문장 점수로는 걸러지지 않는다. 문장 점수의 한계이며, 이런 오류는
  음소별 점수로 보여 줘야 한다.
- 4.2-11 예비: 608 라벨에는 중증도 등급이 없어(`Disease_info`·`Patient_info`만) 전문가 판정의 대리로 쓸 수 없다. 전사 오류를 명료도
  대리로 삼으면 화자 27명의 평균 D-GOP(우리 모델)와 평균 CER(1로 자름)의 순위상관은 0.94 [0.83, 0.97]이다. kresnik D-GOP는
  0.99지만 전사와 같은 모델이라 독립 검증이 아니다. 전문가 판정과의 상관(본 검증)은 라벨셋이 있어야 한다.

## 6. 음소 단위로 본 교체 검출(9/25 오후, 보조 측정)

5절에서 한두 음절의 비음·파열음 바꿈은 문장 점수로 거의 드러나지 않았다(원본 AUC 0.68). 같은 클립, 같은 교체 문장, 같은 소리
조건에서 교체된 자리의 점수만 따로 봤다(`liplab-lab/tools/phone_swap_check.py`, 584클립, 교체 자리 1,140개). 오디오는 참 문장을
읽은 것이고 목표만 교체 문장으로 바꿨으므로, 교체 자리는 틀리게 읽은 음절에 해당한다.

| 소리 | 단위 | 경고 AUC [95% CI] | 오경보 5%에서 검출 | 가장 낮은 단위가 교체 자리(우연) | 문장 AUC |
|---|---|---|---|---|---|
| 원본 | kresnik 음절 | 0.973 [0.968, 0.978] | 90.0% | 79.3% (8.5%) | 0.677 |
| 원본 | 우리 초성 | 0.990 [0.986, 0.993] | 97.5% | 93.3% (10.1%) | 0.681 |
| 원본 | 우리 음절 평균 | 0.901 [0.885, 0.914] | 16.3% | 26.2% (8.5%) | 0.681 |
| 중 | kresnik 음절 | 0.796 [0.772, 0.819] | 0% | 29.3% (8.5%) | 0.545 |
| 중 | 우리 초성 | 0.726 [0.704, 0.747] | 0% | 21.2% (10.1%) | 0.525 |
| 심 | kresnik 음절 | 0.672 [0.656, 0.687] | 0% | 12.7% (8.5%) | 0.515 |
| 심 | 우리 초성 | 0.600 [0.580, 0.618] | 0% | 12.5% (10.1%) | 0.509 |

- 경고 AUC는 맞게 읽은 모든 단위 대 틀린 자리, CI는 화자 부트스트랩. 우연 기대값은 문장마다 (교체 수)/(단위 수)의 평균이다.
- 깨끗한 발화에서는 음소 점수가 교체를 잘 잡는다. 자모 어휘인 우리 모델의 초성 점수가 가장 좋다(문장에서 점수가 가장 낮은 초성이
  교체 자리인 비율 93%). 음절 평균은 바뀐 초성 옆의 맞게 읽은 모음·받침이 희석해 약하다.
- 저하가 커지면 모든 단위의 점수가 함께 0 근처로 내려가(중 조건 중앙값 0.02~0.04) 고정 문턱으로는 하나도 못 잡고 상대 순위만
  남는다(중 AUC 0.73~0.80, 심 0.60~0.67). 중 조건에서는 kresnik 음절이 우리 초성보다 낫다.
- 앱 반영 제안: 음소 피드백은 "이 문장에서 가장 약한 초성 1~3개"처럼 상대 순위로 보이고, 문장 점수가 낮은(저하가 큰) 발화에서는
  음소 표시를 약하게 하거나 불확실하다고 적는다. 사후확률 문턱 하나로 맞고 틀림을 가르지 않는다.
- 한계: 목표 문장을 바꾼 모사다. 실제로 ㄷ을 ㄴ으로 발음한 녹음(발음 오류 코퍼스)으로는 아직 재지 않았다.

## 7. 앱 반영(liplab-dev 후보, 배포 전)

- 배포는 사용자 지시 뒤에 한다. 전시앱(`fly.toml`)은 바꾸지 않는다.
- 호스팅 점검(이미지와 같은 의존성, torch CPU 2스레드, 실제 음성 3문장, 같은 파드에서 비교):

  | | kresnik(9/24 설정) | 우리 모델 |
  |---|---|---|
  | 올라오는 모델 | 1개 + 아바타 백본 | 정렬기·채점기 2개 + 아바타 백본 |
  | 최대 메모리 | 3.1GB | 5.0GB |
  | 발음 채점 지연(문장당) | 0.9~1.2초 | 1.6~2.0초 |
  | 맞는 문장 / 다른 문장 표시 점수 | 86~95 / 0~45 | 88~93 / 45~48 |

- int8(9/25 오후, 사전등록 `liplab-lab/notes/int8_prereg_2026-09-25.md`): 정렬기·채점기의 선형층 가중치를 채널별 int8로 두고
  계산은 fp32로 한다(`backend/quant_int8.py`, `BACKBONE_QUANT=int8`, CPU에서만 켜짐). 아바타 백본은 fp32 그대로다.

  | 조건 | 기준 | 결과 |
  |---|---|---|
  | 1. 재검 관문 재현(kresnik 대비) | 9/25 관문 그대로 | 단조 비율 Δ +3.5%p [2.2, 5.0], AUC Δ 0 → 통과(fp32는 +3.8%p) |
