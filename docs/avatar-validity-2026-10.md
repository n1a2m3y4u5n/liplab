# 아바타 자극 타당성 첫 측정: V2·V13·V14 (2026-10-06)

종합 계획(`docs/master-plan-2026-10.md`)의 V2(아바타 타당성 감사), V13(재표적 왕복 검사, 병렬 탐색 나3), V14(TTS→음성 구동 기준선, 나7)를
한 파드 세션에서 측정한다. 1~8절은 측정하기 전에 적고 따로 커밋한다(사전 등록). 결과는 9절 이후에 덧붙인다.

## 1. 질문

1. 규칙 엔진(`backend/engine.py`)과 앱 렌더러(`AvatarVRM.jsx`, `lib/visemeShapes.js`)가 만드는 아바타 입 움직임은 실제 한국어 화자의
   입 움직임과 얼마나 닮았는가. 입모양 무리 사이의 거리 구조(RSA)와 무리별 움직임 크기(진폭)의 두 면에서 본다.
2. 차이 가운데 얼마가 엔진의 문제이고 얼마가 CC 두상 리그(턱 뼈, 모프 척도)의 한계인가(V13).
3. 무료 TTS 음성을 제품의 음성 구동 모델(A4, `kr_a4_wavlm.pt`)에 넣으면 규칙 엔진보다 실제 화자에 가까운가(V14).

## 2. 비교 원칙

- **같은 측정기로 잰다.** 아바타를 영상으로 렌더하고, 실제 538 영상과 같은 MediaPipe 추출기(`liplab-lab/tools/extract_blendshapes.py
  --lips --no-audio`, mediapipe 0.10.14, `face_landmarker.task` float16/1, VIDEO 모드, CPU)로 잰다. 엔진이 아바타에 넣는 계수와
  MediaPipe 추정치를 직접 비교하지 않는다.
- **앱 코드를 그대로 쓴다.** 렌더 하네스(`scripts/v2_render/main.js`)는 앱의 `visemeShapes.js`, `talkers.js`, `coarticulation.js`,
  `visemeTiming.js`와 `realistic_face.glb`를 가져다 쓰고, 화면마다의 계산은 `RealisticFace.useFrame`을 줄 단위로 옮겼다. 앱과 다른
  점은 세 가지다. (1) 시계: 1/60초 눈금을 결정론적으로 돌리고 두 눈금마다 한 장(30fps)을 찍는다. (2) 카메라: 앱의 입 클로즈업으로는
  MediaPipe가 얼굴을 찾지 못하므로 정면 얼굴 전체를 찍는다. 화각은 앱과 같은 16°, 538 정면 클립(640×360)과 눈꼬리 사이 거리가 비슷하게
  거리를 맞춘다(538 30클립에서 중앙값 78px. 하네스 값은 파드에서 재서 결과에 적는다). (3) 눈 깜빡임: 앱은 2.5~6초마다 무작위로 깜빡여 재현할 수 없어 뺐다.
  선행 동시조음(E)은 앱 기본값처럼 끈다.
- 렌더는 리눅스 파드의 헤드리스 Chromium(Playwright)에서 하고, JPEG(품질 0.95)로 받아 H.264(crf 18, 640×360, 30fps)로 묶는다.
  538 클립도 H.264 640×360 30fps다.

## 3. 자료

- 실제 화자: AI Hub 538 정상 화자 문장 클립 중 정면(촬영 방향 A). 로컬에 있는 화자 전부다. 9/24 스냅숏(`expand538` 정면 5명,
  `expand538_more` 정면 48명)과 10/6 받기 중인 V1 화자 가운데 이 등록 시점에 끝난 22명(`data/v2_avatar/v1_done_snapshot.txt`,
  sha256 6444245f…). 받는 중인 폴더는 읽기만 한다.
- 화자마다 클립을 이름순으로 정렬한 뒤 시드 0 난수로 섞어 앞 12개(coart-e와 같은 규칙). 75명 900클립.
- 화자 절반: `crc32(화자 ID) % 2`(coart-e와 같은 규칙). 절반 0(37명)은 탐색, 절반 1(38명)은 확인이다. 판정은 확인 절반에서만 한다.
- 아바타 문장: 화자마다 섞은 순서의 앞 4개 문장을 기본 얼굴로, 앞 2개를 가상 화자 6명으로 렌더한다. 문장은 그 화자의 절반에 속한다.
  고른 목록은 `liplab-lab/data/v2_avatar/sel.json`(sha256 3f73ba0b…)이며 저장소에는 넣지 않는다.
- 렌더 조건(1,484개):
  - 기본 얼굴: 1.0배·2.0배, 295문장씩
  - 가상 화자 6명(`talkers.js`의 t1~t4, h1·h2): 1.0배(학습자 속도 1, 화자 자기 말 속도 적용), 149문장씩
  - 렌더 앞뒤에 0.4초씩 쉼 자세를 둔다. 분석은 발화 구간만 쓴다.
- 시간이 모자라면 가상 화자 렌더는 목록 앞(확인 절반 먼저)부터 된 만큼만 쓰고, 렌더한 문장 수를 보고한다.

## 4. 입모양 무리와 구간

- 무리: 엔진이 실제로 내는 입모양 13개 = 1~8, 10~13, 쉼 14. 이중모음 정지 모양 9는 9/27부터 엔진이 활음 프레임(4·5 등)으로 바꿔 내지
  않고, 15는 한글 아닌 문자에만 나온다. 종합 계획의 '14무리'는 9를 포함한 수다.
- 실제 화자의 구간: coart-e의 방법을 그대로 쓴다(`scripts/coart_pod_eval.py`의 `engine_frames`, `align_ctc`, `frame_starts`). 자체
  정렬기(`backend/models/dgop_ours/aligner`)의 CTC 강제정렬로 자모 토큰 시각을 얻고, 엔진 프레임을 그 시각에 놓는다. 구간은 프레임
  시작부터 다음 프레임 시작까지(마지막은 끝 음절 끝까지)다. 영상은 음성보다 66ms 앞선다고 보고 구간을 66ms 앞당긴다(coart-e 탐색 절반이
  고른 값, 다시 고르지 않는다). 음절 수가 엔진과 다른 클립은 뺀다.
- 아바타의 구간: 하네스가 기록한 재생 일정(프레임 시작·끝, 영상 시각) 그대로다.
- 구간 값: 구간 뒤쪽 절반 [t0 + 0.5(t1 − t0), t1]에 든 영상 프레임의 평균. 그런 프레임이 없으면 0.75 지점에서 50ms 안의 가장 가까운
  프레임, 그것도 없으면 그 구간을 뺀다. 실제와 아바타에 같은 규칙을 쓴다.
- 클립 품질: 발화 구간 앞뒤 0.15초를 더한 범위에서 얼굴을 찾은 프레임 비율이 0.8 이상이고 15프레임 이상(coart-e와 같음).
- 화자(또는 아바타 조건)마다 무리별 구간이 3개 미만이면 그 무리는 비었다고 본다.

## 5. 특징

- RSA 특징 13개(MediaPipe 블렌드셰이프, 좌우는 평균): jawOpen, mouthClose, mouthFunnel, mouthPucker, smile, stretch, upperUp,
  lowerDown, press, mouthRollLower, mouthRollUpper, mouthShrugLower, mouthShrugUpper.
- 진폭 채널: 벌림 J = jawOpen, 돌출 R = funnel + pucker, 폭 S = (smileL + smileR + stretchL + stretchR)/2(coart-e와 같음).
  보고만 하는 채널: C = mouthClose, G = 안쪽 입술 간격(랜드마크 13·14)을 눈꼬리 거리(33·263)로 나눈 값.

## 6. 판정 기준

### 6.1 V2-1 거리 구조(RSA)

- 화자마다 RSA 특징을 그 화자의 모든 구간 값으로 z 점수화(표준편차 1e-4 미만인 특징은 0)하고, 무리별 평균 벡터 사이의 유클리드 거리로
  13×13 거리 행렬(78쌍)을 만든다. 아바타 조건도 같다.
- 실제 화자 분포: 확인 절반 실제 화자 k마다, k의 행렬과 나머지 화자 행렬 평균의 스피어만 ρ(한 명 빼기, LOO).
- 아바타: 아바타 행렬과 확인 절반 실제 화자 전체 평균 행렬의 스피어만 ρ.
- **통과: 기본 얼굴 1.0배의 ρ가 LOO 분포의 하위 10백분위 이상.** 13무리 가운데 비는 무리가 있는 실제 화자는 분포에서 뺀다(수를 보고).
- 보고만: 기본 얼굴 2.0배, 가상 화자 6명 각각(같은 문턱으로 통과 여부), 탐색 절반의 같은 값, LOO 참조 각각과의 ρ 평균.

### 6.2 V2-2 진폭 백분위

- 화자(또는 아바타 조건)마다 채널별 바닥값 = 발화 구간 전체 프레임의 5백분위. 무리 진폭 = 무리 구간 값 평균 − 바닥값.
  MediaPipe가 얼굴마다 다른 정지 값(중립 얼굴의 기울기)을 내므로 바닥값을 뺀다.
- 무리의 스칼라 진폭 A = √(J′² + R′² + S′²), J′ 등은 0 아래를 0으로 자른 바닥값 뺀 진폭.
- 실제 범위: 확인 절반 실제 화자들의 같은 값의 10~90백분위(선형 보간).
- **통과: 기본 얼굴 2.0배(앱의 '2x·실제', 엔진 길이의 약 0.53배로 실제 말 속도에 가까움, `engine-duration-check.md`)에서 13무리 중
  11개 이상의 A가 실제 10~90백분위 안.** 종합 계획의 '14무리 중 12개'를 13무리에 맞춘 것으로, 범위 밖으로 허용하는 무리 수(2개)는 같다.
- 보고만: 기본 얼굴 1.0배, 가상 화자 6명(1.0배), 채널별(J·R·S·C·G) 범위 안 무리 수, 세 채널이 모두 범위 안인 무리 수, 탐색 절반.
- 보정 정보(판정에 쓰지 않음): 확인 절반 실제 화자 한 명을 빼고 나머지로 범위를 잡았을 때 그 화자가 같은 기준(11/13)을 넘는 비율.
  10~90백분위 기준은 사람에게도 무리마다 20%의 밖 확률을 주므로, 사람이 이 기준을 얼마나 넘는지 함께 적어야 결과를 읽을 수 있다.

### 6.3 V13 재표적 왕복

- 대상: 화자마다 섞은 순서 앞 2개 클립(150개, 두 절반 모두. 리그 측정이라 절반을 나누지 않는다).
- 실제 클립의 MediaPipe 52계수를 앱의 음성 구동·거울 경로(`bsFrameRef`: 원본 계수를 목표로 LERP 34/s, jawOpen은 턱 뼈 30°)로
  아바타에 입혀 같은 길이로 렌더하고, 같은 추출기로 다시 잰다. 얼굴이 안 잡힌 프레임은 앞 값을 잇는다.
- 채널: jawOpen, mouthClose, 돌출 R(funnel + pucker), 폭 S(smile/stretch). 클립마다 원래 값과 다시 잰 값의 Pearson r(지연 0, 둘 다
  얼굴이 잡힌 프레임).
- **채널별 r 중앙값 ≥ 0.80이면 그 채널은 V2 지표를 그대로 쓰고, 미달이면 V2 판정에서 '리그 한계'로 표시한다**(나3).
  mouthClose는 V2 진폭 판정 채널(J·R·S)이 아니므로 표시만 한다.
- 보고만: 채널별 기울기(다시 잰 값 ~ 원래 값, 진폭 전달 비율), ±3프레임 안에서 r이 가장 큰 지연.

### 6.4 V14 TTS→A4

- 문장: 확인 절반 화자의 섞은 순서 첫 클립부터 화자 순으로 50문장(문장 중복 없음).
- TTS: MeloTTS 한국어(MIT), 기본 화자·속도. 설치나 합성이 파드에서 30분 안에 되지 않으면 V14는 하지 않고 이유를 적는다.
- A4: 제품 추론 경로(`backend/audio2face.blendshapes_from_audio`, `kr_a4_wavlm.pt`, WavLM-large 백본)로 실제 음성과 TTS 음성에서
  52계수(30fps)를 낸다.
- **영역 점검(먼저): 문장마다 실제 음성 A4의 jawOpen과 TTS 음성 A4의 jawOpen(음절 시작 시각을 잇는 조각 선형 사상으로 실제 시각에 맞춤)의
  Pearson r, 중앙값 ≥ 0.5여야 다음으로 간다.** 음절 시각은 두 음성 모두 같은 CTC 정렬기로 얻는다.
- 통과하면 TTS→A4 계수로 아바타를 렌더하고(V13과 같은 `bsFrameRef` 경로), TTS 음성 정렬로 무리 구간을 잡아(실제와 같이 66ms 앞당김)
  확인 절반 실제 분포와 비교한다. 같은 50문장의 규칙 엔진 렌더(기본 얼굴 1.0배·2.0배)와 RSA ρ, 진폭 범위 안 무리 수를 나란히 적는다.
  50문장뿐이라 판정이 아니라 비교로만 보고하고, V3 비교 기준을 TTS→A4로 올릴지는 이 결과와 나1을 보고 따로 정한다.

### 6.5 보고만 하는 것

- 나1 핵심 자세(가독성 대리 지표): ㅁ·ㅂ·ㅍ 구간 안쪽 입술 간격 최소값이 실제 양순 구간 90백분위 이하인 비율, 원순 모음 구간 돌출이
  실제 10~90백분위 안인 비율, ㅏ 구간 벌림의 실제 화자 백분위.
- 말 속도: 실제 화자의 음절 속도(초당 음절) 분포와 아바타 조건의 속도.
- 가7 관련: 538 라벨의 소음 조건별 화자 J 진폭. 화자마다 소음 조건이 하나라 화자 사이 비교일 뿐이고, 가7 판정(화자 안 비교)은 아니다.
- V2의 셋째 지표(실화자 독화기 판독)는 V1이 아직 없어 이번에는 하지 않는다.

## 7. 결과에 따라 쓸 문장(미리 적음)

- RSA 통과: "기본 얼굴의 입모양 무리 사이 거리 구조는 538 실제 화자 사이의 차이 범위 안에 든다(확인 화자 38명, LOO 하위 10백분위 이상)."
- RSA 미달: "기본 얼굴의 거리 구조는 실제 화자끼리보다 실제 화자 평균과 덜 닮았다(LOO 하위 10백분위 미만). 어느 무리 쌍이 어긋나는지를
  V3·V15 개선 대상으로 넘긴다."
- 진폭 통과·미달: "2.0배에서 13무리 중 n개의 진폭이 실제 화자 10~90백분위 안이다(기준 11개)." 미달 무리와 방향(크다·작다)을 적고, 같은
  기준을 실제 화자가 넘는 비율을 함께 적는다.
- V13 채널 미달: "이 채널은 리그를 거치면 실제 궤적이 r < 0.80으로만 되살아나, V2에서 이 채널의 차이를 엔진 탓으로 돌리지 않는다."
- 주장 상한: MediaPipe가 재는 2D 정면 블렌드셰이프에서의 유사도다. 청인·청각장애인의 독화 정확도에 관한 주장이 아니며, 입술 돌출(깊이)은
  정면에서 약하게만 잡힌다(V18).

- RSA: "기본 얼굴의 거리 구조는 실제 화자끼리보다 실제 화자 평균과 덜 닮았다(확인 화자 31명, ρ 0.61, LOO 하위 10백분위 0.82). 어긋나는
  쌍은 ㅏ–ㅣ, ㅣ–치경, 양순 전환과 나머지이며 V3·V15 개선 대상으로 넘긴다."
- 진폭: "2.0배에서 13무리 중 1개의 진폭이 실제 화자 10~90백분위 안이다(기준 11개, 같은 기준을 실제 화자는 65%가 넘음). ㅏ 벌림, ㅣ
  당김, ㅗㅜ 돌출은 크고 나머지 무리의 돌출은 작다."
- V13: "벌림(r 0.796)·폭(0.704)·mouthClose(0.246)는 리그를 거치면 r < 0.80으로만 되살아나 V2에서 이 채널의 차이를 엔진 탓으로만 돌리지
  않는다. 돌출(0.836, 기울기 0.99)의 차이는 엔진 탓이다."
- 주장 상한: MediaPipe가 재는 2D 정면 블렌드셰이프에서의 유사도다. 독화 정확도에 관한 주장이 아니며, 실화자 독화기 판독(V2 셋째 지표)은
  V1 뒤에 한다.


### 10.8 후속(10/7): V15 간이 경로

10.6의 입모양 표 입력으로 538 탐색 절반 분포에 맞춘 표를 만들어 확인 절반에서 다시 쟀다(`docs/viseme-calibration-2026-10.md`). RSA는 0.612 →
0.865로 사람 범위 안에 들었지만 2.0배 진폭(7/13), 1.0배 원순 돌출, 무리별 구별성이 사전 기준에 못 미쳐 앱 기본은 바꾸지 않았다. 10.1의
mouthClose 리그 한계는 음성 구동·웹캠 경로의 보정 사상으로 왕복 r이 탐색 0.345 → 0.541, 확인 0.162 → 0.411로 올랐다.
