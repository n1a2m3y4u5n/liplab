# V1-538 사전등록: train538 자료로 제품용 독화기 다시 학습(2026-10-29, 학습 전)

`lipread-v1-prereg-2026-10.md`(이하 '옛 V1')의 구조·학습 설정·판정 기준을 그대로 두고, 자료만 train538(`train538-reacquire-prereg-2026-10-28.md`)로
바꿔 다시 학습할 때의 분할·입력·학습 설정·판정 기준·주장 상한을 **학습 전에** 고정한다. 이 문서를 커밋한 뒤에 입력을 만들고 학습한다.
결과를 본 뒤에는 이 규칙을 바꾸지 않는다. 바꾸면 10절에 '사후 변경'으로 적는다.

## 1. 질문과 범위

학습 화자가 옛 V1과 다른 538 화자 묶음일 때, 같은 제품 구조(입 블렌드셰이프 27채널 → BiGRU 3층 자모 CTC, `train_lipread.build(27, 53)`,
ONNX 계약 `bs [B,T,27] → logits [B,T,53]`)가 처음 보는 538 화자에서 4지 hard 40%를 넘는가.

- 옛 V1 판정은 미달이었다(평가 40명 30.1% [27.9, 32.4], 옛 V1 9절). 그 자료(기존 68명 + v1_538r 111명)는 lab-sub에 없다.
  이번 시험은 train538 64명만 쓴다. 학습 화자가 옛 V1(약 127명)보다 훨씬 적다(4절 33명).
- 판정 대상은 제품에 그대로 넣을 수 있는 구조뿐이다. 538 자료 밖의 사전학습 가중치는 쓰지 않는다.
  - **OLKAVS 사전학습 모델은 이 경로에 쓰지 않는다.**
  - **KMSAV(CC BY-NC-SA)는 이 판정 경로(학습·검증·평가·벤치·어휘·오답 보기)에 섞지 않는다.**
  - Auto-AVSR 등 비상업 가중치도 쓰지 않는다(옛 V1 1절과 같음).
- 어절 구간을 자르는 음성 강제정렬기(5절)는 학습 가중치가 아니라 입력 구간의 경계만 정한다. 독화 모델에는 들어가지 않는다.

## 2. 옛 결과와 직접 비교할 수 없다

- 화자 묶음이 다르다. 옛 V1 평가 40명(`scripts/lipread_v1/eval40.txt`)의 배치는 train538 받기에서 뺐으므로(받기 사전등록 2절)
  이번 평가 화자 19명과 한 명도 겹치지 않는다. 학습 화자 수(약 127명 대 33명), 벤치 어휘(4지 보기 후보), 평가 문항이 모두 다르다.
- 어절 구간 정렬기가 다르다(5절). 옛 V1은 kresnik/wav2vec2-large-xlsr-korean 글자 CTC, 이번은 dgop_ours 자모 CTC다.
- 그래서 이번 주 지표와 옛 V1의 30.1%의 차이를 '화자를 바꾼 효과'나 '개선'으로 해석하지 않는다. 두 수치를 한 표에 둘 때는
  '다른 화자·다른 벤치'라고 같이 적는다.

## 3. 격리(학습·평가 모두)

- **E2 평가 클립 360개(`liplab-lab/data/e2_538/clips`)와 E2 인물(계획 인물 55명 전부)은 쓰지 않는다.** train538 받기 단계에서 배치·인물을
  뺐고(받기 사전등록 2절), 10/29 인물 감사(`data/train538/person-audit-2026-10-29.json`)에서 E2 manifest·계획·cohort와 겹치는 인물·배치·클립
  이름이 모두 0이다. 재생성 격리 검사(`E2_GUARD_OK 1920`, `rebuild/rebuild.log`)도 통과했다. 입력 준비 스크립트는 E2 폴더를 읽지 않는다.
- 옛 V1 평가 40명·V3 확인 19명·TL1~4 배치도 받기에서 빠졌다(감사 값 0). 인물 번호 64명은 서로 다르다(`dup_persons` 없음).

## 4. 자료와 분할(지금 고정)

- 자료: `liplab-lab/data/train538`(manifest.tsv 1,920클립, 화자 64명 = 인물 64명, 화자당 30클립, 정면 A, 30fps mp4 + 16kHz wav).
- **평가 화자 19명**: 받기 사전등록 3절 규칙, `sha256("liplab-train538-eval:" + spk)` 앞 8자리(16진) < 0.30 × 2³². 화자마다 정해지므로 받은
  수와 상관없다. 결과(감사의 `v1_eval_speakers` 19와 같음):
  spk303, spk315, spk316, spk326, spk327, spk328, spk329, spk341, spk342, spk348, spk349, spk371, spk376, spk381, spk414, spk477, spk494, spk606, spk621
  (`scripts/lipread_v1/eval19_538.txt`와 같다).
- **검증 화자 12명**: 평가 19명을 뺀 45명 중 `sha256("liplab-v1-val:" + spk)` 16진 문자열 오름차순 앞 12명(옛 V1 3.3절과 같은 규칙·같은 수,
  `v1_train.py split --val-n 12`). 결과: spk301, spk306, spk317, spk322, spk336, spk351, spk361, spk366, spk464, spk476, spk506, spk616.
  체크포인트와 후보 선택에만 쓴다.
- **학습 화자 33명**: 나머지 전부.
- 내용 분리: 평가·검증 화자가 읽은 문장과 같은 문장(한글 음절만 비교, `folds.norm_text`)의 학습 클립은 그 어절까지 학습에서 뺀다
  (받기 사전등록 3절, 옛 V1 3.3절). manifest 기준 학습 990클립 중 89클립이 빠질 것으로 본다. 실제 수는 `split.json`의
  `train_clips_dropped_shared_text`로 보고한다.
- 옛 V1 3.2절의 '후보 80명 이상, 학습+검증 120명 이상' 조건은 이번 자료(64명, 학습+검증 45명)로는 채울 수 없다. 이 조건을 이번 시험에는
  적용하지 않는다. 그 대가로 7절의 주장 상한을 둔다. 판정 기준(6절)은 낮추지 않는다.

## 5. 입력(CPU로 준비, lab-sub)

- 블렌드셰이프·입술 좌표: train538 V3 재생성에서 뽑은 것을 그대로 쓴다(`data/train538/rebuild/real_bs/`, `extract_blendshapes.py --lips
  --no-audio`, venv-mp MediaPipe 0.10.14, 1,920개). 옛 V1 파드 추출과 같은 판의 MediaPipe다.
- 어절 구간(`d/spans.jsonl`): `build_cd.py`(liplab-lab/tools)의 텍스트 정규화·건너뛰기 규칙·bs 재색인·출력 형식을 그대로 쓰되, 정렬 함수만
  `scripts/lipread_v1/v1_538_spans.py`로 바꿔 끼운다.
  - 정렬기: kresnik 모델이 lab-sub에 없고 받기가 금지라서, train538 V3 재생성이 쓴 로컬 dgop_ours 자모 CTC 정렬기
    (`liplab/backend/models/dgop_ours/aligner`)를 쓴다. 음절 k의 구간 = [초성(없으면 중성) 시작, 종성(없으면 중성) 끝) → 30fps 프레임.
    음절 수가 글자 수와 다르면 그 클립은 `align_fail`.
  - 잘린 클립 검사: 그리디 자모 토큰열과 목표 자모열의 편집거리 / 목표 길이(자모 CER) > 0.6이면 flag(평가·학습 제외). 기준값 0.6은 그대로이고
    단위만 글자 → 자모로 바뀐다.
  - 정렬 관문: 적격 행 대비 정렬 성공 90% 미만이면 학습하지 않는다(옛 V1 7절, `remote.sh align`과 같음).
- 벤치: `d_bench.py build --spans <spans> --bs real_bs --rule 3,3 --out bench_v1_538.pkl`(코드 수정 없음). 4지 hard 어휘와 오답 보기는
  이 벤치의 규칙(인스턴스 3개·인물 3명 이상, 자모 편집거리 최근접 3개, 같은 음절수 우선, seed 777)을 따른다. 64명뿐이라 어휘가 옛 V1보다
  작을 것이다. 어휘 수는 보고만 한다.
- 입 영역(ROI 88×88 흑백, `lip_roi_extract.py`): 옛 V1과 같이 연구용으로만 뽑고 이 판정에는 쓰지 않는다.
- GPU를 쓰지 않는다(`CUDA_VISIBLE_DEVICES=` 빈 값, `DGOP_DEVICE=cpu`). 동시 프로세스 4개 이하.

## 6. 학습·선택·판정(옛 V1 4~5절 그대로)

- 후보 A·B × 시드 0·1·2, `v1_train.py train`의 기본값(AdamW lr 3e-4, wd 1e-4, 배치 64, 기울기 노름 5, 최대 60에폭, 2에폭마다 검증,
  검증 10회 동안 나아지지 않으면 멈춤, 증강 P2와 같음, 후보 B idle_p 0.5). 코드와 값을 바꾸지 않는다.
- 체크포인트·선택: 옛 V1 4절 그대로(검증 화자 4지 hard ctc_ll α=1 idle75, dup1·dup2 평균 최고 에폭 → 12개 중 검증 4지 최고, 동점 순서도 같음).
  평가 화자는 선택에 쓰지 않는다.
- 주 지표: 선택 모델 하나를 평가 화자 19명에 `d_bench.py product4way`(코드 수정 없음)로 건다. 4지 hard, ctc_ll α=1, idle75, 선택한 dup,
  화자 평균.
- **관문(옛 V1과 같음): 주 지표 ≥ 40% 그리고 화자 부트스트랩(10,000회, seed 0, 백분위) 95% CI 하한 > 30% → PASS, 아니면 FAIL.**
  판정 코드 `v1_judge.py`(수정 없음). 평가 화자가 19명이라 CI가 옛 V1보다 넓어져 PASS가 더 어렵다. 기준은 그대로 둔다.
- 보고만(판정에 쓰지 않음): 옛 V1 5절의 보고 항목 전부(현재 제품 모델 `kr_d_lipread_1120.pt` greedy_lev·dup2·idle75와 화자별 짝 차이 등).
  현재 제품 모델의 학습 화자가 이번 평가 화자와 같은 인물인지는 확인하지 못했다(538 spk301~330 번호가 겹침). 그래서 '선택 모델 − 현재 제품'
  차이는 참고로만 적는다.
- 실행: lab-sub RTX 3060 1장. 다른 작업이 GPU를 쓰는 중이면 시작하지 않는다. 옛 V1의 블루스크린(여러 학습 동시) 때문에 동시 학습은 2개까지
  (`V1_PAR` ≤ 2)로 한다. 순서·동시 수는 결과에 영향을 주지 않는다.

## 7. 주장 상한

- PASS여도 '538 정면 화자 19명(학습 33명)에서 제품 구조가 관문을 넘었다'까지만 말한다. 사람 검증이 아니고, 웹캠·브라우저 tasks-vision
  입력에서의 성능도 아니다. 제품 모델 교체는 **제안**만 하고 배포하지 않는다(옛 V1 6절).
- FAIL이면 옛 V1과 같은 결론(블렌드셰이프 27채널·작은 BiGRU로는 40%에 못 미침)을 다른 화자 묶음에서 한 번 더 본 것으로 적는다.
  학습 화자가 33명뿐이라 '화자를 늘려도 안 된다'의 근거로는 쓰지 않는다.
- 옛 V1 30.1%와의 차이는 해석하지 않는다(2절). 결과를 보고 후보·하이퍼파라미터·셀·분할을 바꿔 다시 판정하지 않는다. 새 시도는 새 사전등록으로 한다.

## 8. 멈춤 규칙

- 정렬 관문(90%) 미달, 벤치 평가 화자 19명 중 4지 문항이 있는 화자가 10명 미만, 또는 학습 항목이 0이면 학습하지 않고 원인을 기록한다.
- 입력 준비 중 시스템 메모리 여유가 10 GB 아래로 떨어지면 동시 프로세스를 줄인다.
