# 문장 끝 토큰 정렬 결함의 근본 수정 2차: 끝 구간 다시 나누기 (사전 등록 2026-10-09)

2026-10-09 작성. `docs/dgop-final-vowel-2026-10.md`(10/7, 임시 수정 M2 채택)와 `docs/dgop-aligner-tailaug-2026-10.md`(10/7 밤, 끝 무음 증강
재학습 부정 결과)의 후속이다. 1~8절은 확인 자료의 측정 결과를 보기 전에 적어 커밋한 사전 기준이다. 결과를 본 뒤 기준을 바꾸지 않으며,
바꿔야 할 일이 생기면 결과 절에 '사후 변경'으로 따로 적는다.

## 1. 배경과 등록 전 관찰

### 1.1 지금 상태

- 자체 학습 자모 CTC 정렬기·채점기는 문장 끝 토큰을 말소리 안이 아니라 입력의 마지막 프레임에 낸다(538 '요' 끝 92.2%, Zeroth train 95.3%).
  원인은 학습 자료의 짧은 끝 무음이고, '요'처럼 끝 음절이 모음 하나이면 말소리 안에서 빈칸이 이겨 ㅛ가 거의 나오지 않는다(10/7 7.2절).
- 앱은 정렬 전에 '말소리 끝 + 50 ms'에서 자른다(M2, `dgop_acoustic.trim_trailing_silence`). 끝 모음이 무음에 놓이는 비율은 0~1.3%가 되었지만,
  끝 모음 시작은 실제 시작이 아니라 말소리 끝 근처의 한 프레임이다. 10/7 밤 측정(확인 절반)에서 지금 앱(K0_t)의 끝 모음 시작과 MFA 끝 모음
  시작의 절대 차 중앙은 538 24·29 ms(R·T)지만 서버 음성은 150 ms였다('요' 끝이 59%). 자르기는 608 AUC도 조금 낮췄다(0.902 → 0.896,
  정제본 0.958 → 0.954). 서버 음성 음절 시각은 `qa_rules.fix_tail_syllables`로 따로 고쳐 두었다.
- 끝 무음 증강 재학습은 끝 출력 위치를 바꾸지 못했다. CTC 손실은 정렬을 모두 더해 계산하므로 토큰을 언제 내는지에 값을 매기지 않는다.
  다음 후보로 'MFA 표지 보조 손실', '늦은 끝 토큰 벌점 CTC', 'MFA 정렬 + 지금 채점기'를 적어 두었다.
- 음소 피드백 신뢰도(S2)는 끝 음절을 판정하지 않았고, 정렬 수정이 들어오면 같은 절차로 다시 측정하기로 했다.

### 1.2 자료 사정

10/6·10/7 측정에 쓴 538 600클립(58명)의 소리 파일(`liplab-lab/data/s12stage`)은 10/8 저장 공간 정리 뒤 남아 있지 않다(휴지통도 비워졌다).
남은 것은 10/7 측정(`dgop_tail_pod`, 파드 `20261007_gf8ifdceixcoar`)이 저장한 정렬기·채점기 로그확률(끝 자르기 없는 R·T, int8, GPU TF32 끔,
538 600클립·608 363조각), 10/7 밤 tailaug 파드의 문장별 결과(K0_t 포함)와 MFA 참조(538 590클립, 서버 음성 903클립)다. 그래서 옛 538 자료로는
끝 자르기 없는(n) 설정만 다시 계산할 수 있고(`scripts/dgop_fix2/offline.py`), 끝 자르기를 켠(t) 설정과 합성 저하는 소리가 있는 새 자료로 측정한다.

저장된 로짓으로 다시 계산한 K0_n(옛 538·608, 절반 0)은 10/7 밤 tailaug 파드의 K0_n과 표시 점수 차가 538 최대 0.5·평균 0.002, 608(30초 이하)
최대 0.8·평균 0.004였다. 30초 넘는 608 조각 36개만 크게 달랐는데, tailaug 측정이 앞 30초만 넣었기 때문이다(정제 규칙으로 어차피 빠진다).

### 1.3 등록 전 관찰(탐색 절반 0만)

후보를 정하려고 옛 538 절반 0(29명)의 저장된 로짓만 보았다. 절반 1과 새 자료는 보지 않았다.

- **빈칸을 뺀 사후확률.** 정렬기 로그확률에서 빈칸을 빼고 다시 정규화하면, ㅛ 구간에서 ㅛ가 앞 모음보다 높다. 앞 토큰의 CTC 구간 시작부터
  '말소리 끝 + 50 ms'까지를 [앞 토큰, 끝 모음]으로 둘로 나누는 분할(점수 합 최대)의 끝 모음 시작은 MFA와의 절대 차 중앙이 '요' 끝 54클립에서
  R 31 ms·T 17 ms였다(CTC 구간 시작은 295 ms·1,291 ms). '요'가 아닌 끝 모음 240클립에서는 늘 나누면 27·25 ms(CTC 22·23 ms)로 조금 나빠졌고,
  끝 토큰이 말소리 끝 근처 이후에 나왔을 때만 나누면 21·20 ms였다.
- **분할 구간으로 채점하기.** 끝 모음 점수를 분할 구간의 사후확률 평균으로 바꾸면, 끝 모음을 가까운 모음으로 바꾼 목표와의 AUC가 CTC 구간(입력 끝
  프레임) 점수보다 낮았다('요' R 0.964 → 0.901, 그 밖 0.884 → 0.853, 빈칸을 뺀 분포 기준). 맞는 토큰 값도 대부분 0.45 아래로 떨어졌다(빈칸을 빼지
  않은 분포도 AUC 0.73~0.80). 입력 끝 프레임의 끝 모음 확률은 트랜스포머가 문장 전체를 보고 내는 값이라 분별 정보가 있다. 그래서 이번 후보는
  **시각만 바꾸고 채점은 CTC 구간 그대로 둔다.**

## 2. 후보

| 이름 | 끝 자르기 | 시각 | 채점 |
|---|---|---|---|
| **K0_t**(기준선, 지금 앱) | 켬(말소리 끝 + 50 ms) | CTC 구간 | CTC 구간 |
| K0_n(참고, 10/7 M0) | 끔 | CTC 구간 | CTC 구간 |
| **N1_n** | 끔 | 끝 구간 다시 나누기(3절) | K0_n과 같다 |
| **N1_t** | 켬 | 끝 구간 다시 나누기 | K0_t와 같다 |

- N1은 재학습 없이 정렬 뒤처리만 바꾼다. 정렬기가 끝 토큰을 입력 끝에 내는 버릇은 그대로 두고, 그 버릇이 만드는 시각 결함을 빈칸 없는 단조
  분할(HMM식 분할)로 바로잡는다. N1_n은 자르기를 없애 608 AUC 비용을 되찾는 쪽이고, N1_t는 점수를 지금 앱과 똑같이 두고 시각만 고치는 쪽이다.
- **'MFA 정렬 + 지금 채점기'는 후보로 두지 않는다.** MFA(Kaldi, conda)는 앱 이미지(4GB 기계, CPU 2개)에 넣을 수 없고, 끝 모음 시작 기준(C2)이
  MFA 자신이라 순환이다. MFA는 독립 참조로만 쓴다. N1은 MFA가 가진 성질(빈칸 없이 구간을 나눔)을 지금 정렬기 사후확률 위에서 흉내 낸 것이다.
- 재학습 후보(MFA 표지 보조 손실, 늦은 끝 토큰 벌점 CTC)는 7절 조건에서만 한다.

## 3. 끝 구간 다시 나누기(N1) 정의

`backend/dgop_acoustic.py`의 `retime_tail`, `phone_confidences`에서 `DGOP_TAIL_RESEG=1`일 때만 켠다(기본 끔).

1. 정렬은 지금과 같다(CTC 강제정렬, 끝 자르기 설정에 따라 자른 소리 또는 그대로). 채점(구간 평균 분포의 목표 확률)은 이 CTC 구간으로 한다.
2. 말소리 끝 E = `speech_end_seconds`(정렬기에 넣은 소리, 10/7 4.2절 정의). 없으면 바꾸지 않는다. 끝 프레임 e = round((E + 0.05) / 프레임 길이),
   마지막 프레임을 넘으면 마지막 프레임.
3. k = 목표 자모열의 마지막 중성, K = 마지막 토큰(k 뒤 종성이 있으면 그 종성), p = k 앞에서 어절 경계(|)가 아닌 가장 가까운 토큰.
4. 문(gate): **all**은 늘, **late**는 K의 CTC 시작 ≥ e − 2프레임일 때만 다시 나눈다. 둘 중 하나를 3.3절로 고른다.
5. 프레임 [p의 CTC 시작, e]의 정렬기 로그확률에서 빈칸을 빼고 다시 정규화한 값으로, 상태 [p, k, …, K]가 순서대로 한 프레임 이상씩 차지하는 분할 가운데
   점수 합이 가장 큰 것을 고른다(동점이면 머무름). 프레임이 상태 수보다 적으면 바꾸지 않는다.
6. k…K의 시각(t0·t1)만 그 분할로 바꾸고 `retimed`를 표시한다. p와 다른 토큰의 시각, 모든 점수는 그대로다.

### 3.3 문 고르기(탐색 절반 0)

옛 538 절반 0(저장된 로짓, n 설정, R·T)에서 all과 late의 '끝 모음 시작과 MFA의 절대 차 중앙'을 R·T 평균으로 비교해 작은 쪽을 고른다.
차가 2 ms 이하이면 late(바꾸는 토큰이 적다). 고른 문을 `TAIL_RESEG_GATE`에 적고 결과를 이 문서 8.1절에 적은 뒤 커밋하고, 그다음 확인 측정을 한다.
확인 측정은 두 문을 모두 기록하지만 판정은 고른 문으로만 하고, 다른 문은 보고만 한다.

## 5. 측정과 기준(확인 자료, R과 T 모두)

정의는 10/7 문서 5.1절과 tailaug 5.1절을 잇는다. 끝 모음 = 목표 자모열의 마지막 중성 토큰. **무음에 놓임** = 끝 모음 시작 − 말소리 끝 > 100 ms
(538·608은 R 소리의 말소리 끝, 서버 음성은 '길이 − 150 ms'). **시작 오차** = 끝 모음 시작 − MFA 끝 모음 시작(앞이 활음이면 활음 시작).
표시 점수, AUC(자기 문장 대 다른 문장), 65점 맞게 말함 불합격·다르게 말함 합격, 코칭(`main._weak_phones` 규칙으로 끝 모음 지목), 말 빠르기
(`speak_cues.rate_pause`의 rate, '느림' < 4.08)도 같다. 538 옛 자료의 빠르기는 소리 없이 같은 식(음절 수 / 첫 토큰 시작~마지막 토큰 끝)으로 낸다.

자료 범위: 538 = 538n(두 후보), 538 옛 절반 1(N1_n만). 608 = 608n(두 후보), 608 옛 절반 1 정제본(N1_n만). 기준값 K0_t는 같은 자료·같은 소리 조건의 값이다.

| 기준 | 내용 |
|---|---|
| C1 시각 | 끝 모음 무음에 놓임 ≤ 5%(538, 서버 음성). 538은 다시 나누기의 끝이 같은 말소리 끝이라 순환적이므로 서버 음성을 함께 본다 |
| C2 실제 시작 | 시작 오차 절대값 중앙 ≤ 40 ms, '요'로 끝나는 클립만 ≤ 60 ms(538, 서버 음성). MFA가 정렬한 클립이 각 80% 이상 |
| C3 분리도 | 608 AUC ≥ K0_t − 0.005, 538 AUC ≥ 0.99 |
| C4 다른 문장 | 538·608 다른 문장 65점 합격 ≤ 5% |
| C5 지연·경로 | 파드 CPU 2스레드, 538n 6문장 T 소리 × 3바퀴(첫 바퀴 제외) `phone_confidences` 시간 중앙 ≤ K0_t × 1.10(N1_t), × 1.25(N1_n). 첫 바퀴의 CPU 결과가 GPU 측정과 표시 점수 차 ≤ 0.5, 시각 차가 한 프레임(0.02초) 넘는 토큰 ≤ 1%, 특징 추출부 공유 켜짐(int8 재검) |
| C6 맞는 문장·코칭 | 맞게 말함 불합격 608 ≤ K0_t + 2%p, 538 ≤ K0_t + 1%p. 끝 모음 코칭 지목 538·608 ≤ K0_t + 2%p |
| C7 눈금 | 538n R 자기 문장 표시 점수 중앙이 K0_t ± 2.0 안, 서버 음성 R 점수 평균 ≥ K0_t − 1.0 |
| C8 말 빠르기 | 538 rate(T)/rate(R) 중앙 0.97~1.03, 538 T '느림' ≤ K0_t R + 2%p |
| C9 저하 강도 순서 | 538n 합성 저하에서 원점수 원본 ≥ 경 ≥ 중 ≥ 심 단조 비율 ≥ K0_t − 2%p, AUC(원본 > 심) ≥ K0_t − 0.01 |

- C1·C2는 10/7·tailaug의 시각 기준을, C3~C8은 tailaug 5.3절(10/7 C2~C6에서 이어받은 비열등 기준)을, C9는 자체 학습 채점기 관문
  (`docs/scorer-selftrain.md` 2·4절의 단조 비율)을 비열등 형태로 잇는다. '요' 끝 기준(C2 둘째 항)은 결함이 '요'에 몰려 있어 새로 넣었다.
- N1_t의 점수 기준(C3·C4·C6·C7·C9)은 구성상 K0_t와 같다. 계산은 그대로 하고 같은지 확인한다.
- 보고만: 바꾼 클립 비율(`retimed`), 고르지 않은 문의 값, 538 R 빠르기 중앙(K0_t와 3% 넘게 다르면 적고 `RATE_P*`는 바꾸지 않는다), 서버 음성에서
  `fix_tail_syllables`가 바꾸는 클립 비율과 '요' 끝 클립 마지막 음절 시작의 MFA 차(새 정렬 대 지금 목록), 608 전체본 값, 합성 저하 조건별 평균.

## 6. 채택 규칙

1. C1~C9를 모두 만족한 후보가 후보군이다.
2. 둘 다 통과하면 N1_t를 고른다. 단 N1_n의 608n T AUC가 N1_t보다 0.005 이상 높고 N1_n 지연 중앙이 K0_t의 1.25배 이하이면 N1_n을 고른다
   (자르기가 깎던 AUC를 되찾는 경우). 하나만 통과하면 그것을 고른다.
3. 둘 다 떨어지면 앱은 그대로 두고, 7절 조건이 맞으면 재학습 후보로 간다. 아니면 부정 결과로 남긴다.
4. 계산은 `scripts/dgop_fix2/analyze.py confirm`이 내는 `PICK`을 따른다.

**채택했을 때 할 일.** `dgop_acoustic`의 새 경로(`DGOP_TAIL_RESEG`, 문 상수)는 이미 들어가 있고 기본은 끈다. 기본값 변경(켜기, N1_n이면 자르기 끄기)은
사용자 결정으로 남기고 권고만 적는다. 모델 파일은 바뀌지 않으므로 int8 재검은 C5(CPU·GPU 경로 일치)로 한다. 백엔드 테스트(`test_dgop*.py test_ctc_align.py
test_speak*.py test_sound*.py`)를 돌린다. 서버 음성 음절 시각 목록은 다시 만들지 않고, 보정 비율만 보고한다(5% 이하이면 다음 합성부터 보정이 필요 없다고 적는다).

**S2 다시 측정.** 채택한 설정의 점수로 `docs/phoneme-feedback-reliability-2026-10.md` 9.10절 절차를 끝 음절을 넣어 다시 한다.
- S2(10/7)는 끝 자르기 없이(K0_n) 채점했다(S2 `measure.py`는 자르지 않고, 다리 기준인 10/6 값도 자르기 전이다). N1_n의 점수는 K0_n과 같으므로,
  N1_n을 고르면 S2 원자료(`liplab-lab/data/pod_runs/20261007_9q5h6hblgxungw/s2/`)가 그대로 채택 설정의 점수다. 그때는 파드 없이 같은 원자료를
  끝 음절을 포함해(끝 음절 토큰을 주 분석에서 빼지 않고) 같은 기준으로 다시 판정한다.
- N1_t를 고르면 A0 소리가 없어 S2 탐색을 다시 할 수 없다. A1(`v1_538` 630클립)만 파드에서 자른 설정으로 다시 채점해 보고하고, 판정은 '판정 불가'로 적는다.

## 7. 재학습 후보(조건부 2단계)

N1_n·N1_t가 모두 떨어지고, 떨어진 기준이 시각(C1·C2·C8)일 때만 한다. 점수 기준에서만 떨어졌으면 시각 결함이 아니라 자르기 설정 문제이므로 하지 않는다.
- R1 MFA 표지 보조 손실: Zeroth train을 MFA로 정렬해 끝 모음 구간 프레임에 끝 토큰 교차 엔트로피 보조 손실을 더해 정렬기를 이어 학습.
- R2 늦은 끝 토큰 벌점 CTC: 끝 토큰을 '말소리 끝 + 여유' 뒤에 내는 경로의 확률에 벌점을 주는 CTC 변형으로 정렬기를 이어 학습.
학습 전에 이 문서에 부록(자료, 하이퍼파라미터, 538 소리가 있는 평가 자료, 기준)을 따로 커밋한다. 이번 작업 예산(5달러) 안에서만 한다.

## 8. 절차와 비용

- 맥: `scripts/dgop_fix2/offline.py`(옛 자료 저장된 로짓 → 줄), `analyze.py explore`(문 고르기, 절반 0), `session.sh stage`(묶음, `build_jobs.py`).
- 파드: `session.sh launch`가 잔액(10달러 아래면 멈춤)을 보고 liplab-lab의 `tools/pod/pod.sh`만 불러 파드를 만든다(이름 `liplab-al`, 상태 `.alstate`,
  워치독 90분, 파드 자폭 타이머). `run.sh`: 설치 → MFA 말뭉치 → MFA(백그라운드, CPU) → selftest → main·tts·deg → MFA 읽기 → CPU 지연·경로.
  끝나면 `session.sh finish`(받기 → terminate → status로 이 파드가 없어진 것을 확인). 다른 작업의 파드(liplab-ad 등)는 건드리지 않는다.
- 판정: `offline.py --half 1` → `analyze.py confirm --gate (8.1절의 문)`.
- A40 SECURE(시간당 약 0.5달러) 우선, 예상 1시간 안, 1달러 안. 이 작업 상한 5달러. 유료 API·SpeechSuper는 쓰지 않는다. 소리는 재생하지 않는다.
  맥에서는 모델 추론을 하지 않는다(저장된 로짓의 정렬·분할은 numpy·torch 연산만).
- 새 가중치는 없다(N1은 모델을 바꾸지 않는다). 재학습을 하게 되면 `liplab-lab/models/dgop_ours_2026-10-09_fix2*/` 새 폴더에 둔다.

### 8.1 문 고르기 결과와 사후 변경 1(탐색 절반 0만, 확인 자료를 보기 전)

- **사후 변경 1(묶음 일반화).** 등록한 정의(3절 3·5항)로 절반 0을 처음 돌려 보니, 끝 모음 앞 토큰도 함께 입력 끝에 몰려 나온 클립(예: '다'의 ㄷ과 ㅏ,
  '세요'의 ㅅ·ㅔ·ㅛ)은 p의 CTC 시작이 끝 프레임 e보다 뒤라 다시 나누지 못했다(538 T 무음에 놓임 3.7%, 608 T 11.6%). 그래서 묶음을 '마지막 중성과 그 뒤
  토큰, 그리고 그 앞에서 CTC 시작이 e − 2프레임 이후인 토큰들'로 넓히고, p를 그 묶음 바로 앞의 어절 경계가 아닌 토큰으로, 상태를 p 뒤 모든 토큰(사이의
  어절 경계 포함)으로 바꿨다. 절반 0에서 비교한 값(late 문): 538 끝 모음 시작 오차 중앙 R 22 → 22 ms·T 20 → 20 ms, 90백분위 190 → 181·260 → 213 ms,
  무음에 놓임 2.4 → 0.7%·3.7 → 2.0%, 608 무음에 놓임 R 1.1 → 0.5%·T 11.6 → 4.2%. 같이 본 다른 안(끝 토큰이 입력 마지막 세 프레임 안일 때만 바꾸는 문)은
  538 R '요' 오차가 194 ms로 나빠 버렸다. 판정 기준과 채택 규칙은 바꾸지 않았다.
- **문 고르기(3.3절, 사후 변경 1 뒤).** 538 옛 절반 0, n 설정의 끝 모음 시작 오차 중앙 R·T 평균: all 26.3 ms, late 21.0 ms. **late**를 고른다
  (`TAIL_RESEG_GATE = "late"`). 그때 절반 0 값(보고만): 538 R·T 오차 중앙 22·20 ms, '요' 끝 31·18 ms(K0_t 245·275 ms), 무음에 놓임 0.7·2.0%, 바꾼 클립
  37·33%, rate(T)/rate(R) 1.000, T '느림' 10.1%(K0_t R 9.5%). 608 바꾼 클립 86·83%, rate(T)/rate(R) 0.988(K0_n 0.817).
  점수는 구성상 K0_n과 같다(538 AUC 0.999·0.998, 608 정제본 0.975·0.977, K0_t 0.970·0.973).
