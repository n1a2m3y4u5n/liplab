# 당사자 파일럿 문서

> 작성 2026-09-24. 고도화계획서 §4.7(당사자 파일럿 및 연구윤리)을 실행하기 위한 문서다.
> 앱이 실제로 모으고 넘기고 지우는 범위는 `docs/pilot-data-spec.md`가 기준이고, 이 폴더의 문서는 그 명세와 같게 쓴다.
> 앱이나 명세가 바뀌면 이 폴더의 문서를 함께 고친다.

## 문서 목록

| 파일 | 내용 | 읽는 사람 |
|---|---|---|
| `checklist.md` | 실행 전 결정부터 파기 대장 보관까지 순서대로 확인하는 목록. 가명 찾는 방법과 앱 밖 자료 파기 기록 양식 포함 | 연구 책임자, 운영자 |
| `protocol.md` | 연구 계획서 요약. 목적, 대상, 설계, 측정 지표, 분석 계획, 알려진 제약, 위험과 보호조치, 철회, 보관·파기, 일정, 역할 | 연구진, 윤리 심의·자문 |
| `consent_participant.md` | 만 14세 이상 참여자용 설명문과 동의서 | 참여자 |
| `consent_guardian.md` | 법정대리인 동의서. 만 14세 미만을 넣기 전에 앱에 먼저 필요한 절차를 맨 앞에 적었다 | 법정대리인 |
| `recruitment.md` | 기관 게시용 모집 안내문 | 협력 기관, 지원자 |
| `survey.md` | 사후 설문(사용성 10문항, 시각 기호, 가장 어려웠던 점, 자유 의견, 선택 응답 배경 문항)과 SUS 사용 메모 | 참여자 |

## 쓰는 순서

1. `checklist.md` 1절: 윤리 심의 여부, 보관 기간, 개인정보 보호책임자, 파일럿 서버와 파기 방법을 정한다. 앞의 셋을 정하기 전에는 파일럿을 켜지 않는다.
2. `protocol.md`, 동의서, 안내문, 설문의 대괄호 칸을 채운다. 윤리 심의를 받으면 이 문서들을 함께 낸다.
3. `checklist.md` 2절: 파일럿을 켜고 시험 계정으로 한 번 돌려 본다.
4. `recruitment.md`로 모집한다.
5. 설명과 동의: `consent_participant.md`, 필요하면 `consent_guardian.md`. 동의한 사람에게만 참여 코드를 준다(`checklist.md` 3절).
6. 1회차 사전 검사, 학습, 중간 점검, 마지막 회차 사후 검사와 `survey.md`(`checklist.md` 4~6절).
7. 가명 내보내기와 분석(`checklist.md` 7절, `protocol.md` 6절).
8. 보관 기한 뒤 파기와 대장 보관(`checklist.md` 8·9절). 동의 철회는 기한과 무관하게 그때그때 처리한다.

## 표기

- 대괄호 안에 설명이 든 칸(예: [연구 종료일])은 연구 책임자가 정해 채운다. 이름이 같은 칸은 모든 문서에서 같은 값이다.
- 체크리스트 줄 앞의 빈 네모와 동의서·설문의 □는 표시 칸이다.
- 동의서와 설문 맨 위의 "연구진 참고" 상자는 참여자에게 주기 전에 지운다.

## 먼저 알아 둘 앱의 제약

자세한 내용과 근거는 `protocol.md` 7절에 있다.

- 가입할 때의 연령 확인은 확인란 하나이고, 서버는 나이나 보호자 동의를 따로 확인하지 않는다. 앱에 법정대리인 동의 절차가 없다.
- AI가 만드는 문장과 대화에는 사전·사후 검사 단어가 나올 수 있다. 자가진단(배치검사)과 훈련 콘텐츠에서는 검사 단어를 뺐다.
- 시각 기호가 언제, 몇 개, 어떤 세기로 보였는지는 기록되지 않는다. 집단별로 기호를 끄는 설정(`LIPLAB_PILOT_NOCUE_COHORTS`)은 있어,
  기호 없이 학습하는 집단을 두면 기호를 켠 집단과 끈 집단을 비교할 수 있다.
- 원음성과 얼굴 영상을 저장하지 않으므로, 이 파일럿으로 발화 자료를 모을 수 없다.
