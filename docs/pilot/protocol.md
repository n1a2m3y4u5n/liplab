## 2. 목적

이 파일럿은 탐색 연구다. 효과를 입증하는 것이 아니라 아래 세 가지를 소규모로 확인하고, 다음 연구의 설계를 정하는 것이 목적이다.

1. **사전·사후 독화 정확도 변화.** 앱으로 [학습 기간]주 학습한 뒤 동형 검사(A폼, B폼)의 정확도가 어떻게 달라지는지 집단별·개인별로 본다.
   계획서 §4.2는 당사자 파일럿의 성공 기준을 "학습 전 대비 학습 후 독화 정확도의 향상이 관찰되는 것"으로 두었다.
   표본이 작으므로 이를 통계적으로 입증하려 하지 않고, 관찰된 변화의 방향과 크기, 불확실성을 기술한다.
2. **시각 기호(축 J)의 학습 부담과 소거 후 전이.** 앱은 입모양이 같은 소리를 가르는 자질(기식·긴장·울림)에 작은 기호를 붙이고,
   숙달도가 오르면 기호를 흐리게 한다(`docs/cue-overlay.md`). 기호의 뜻을 익히고 기억하는 부담, 입모양을 보는 데 방해가 되는지,
   구별에 도움이 되는지를 사후 설문으로 묻는다. 기호가 사라진 뒤에도 구별이 유지되는지(소거 후 전이)는 기호가 나오지 않는
   사후 검사(B폼) 수행과 설문 B5로 간접적으로 본다. 기호의 효과만 떼어 보는 비교는 기호 없이 학습하는 집단을 둘 때만 할 수 있다
   (7절 3, [기호 없는 집단 여부]).
3. **사용성.** 청각장애 참여자가 글 안내만으로 가입, 참여 코드 입력, 검사, 학습을 할 수 있는지, 어디서 막히는지를
   사후 설문, 학습 기록, 회차 진행 메모로 확인한다.

부수 목적은 표준검사(축 I)의 실제 응답 확보다. 가명 내보내기(2판)에 동형 폼의 문항별 정오답과 고른 보기가 들어 있어
문항 단위 분석(실측 KR-20, 문항 정답률)을 할 수 있다(5.1, 6.3).

범위 밖: 발화 녹음과 얼굴 영상 수집. 앱은 원음성과 웹캠 영상을 저장하지 않는다. 따라서 계획서 §3.1의 "소량의 당사자 발화로
보정 계층만 미세조정"하는 일과, §4.2의 라벨 평가셋(당사자 파일럿에서 수집한 발화에 언어재활 자문을 거쳐 구축)은 이 파일럿으로 할 수 없다.
필요하면 녹음 절차, 보관·파기, 동의서를 따로 만든다.

## 3. 대상

### 3.1 집단과 인원

| 집단 | 누구 | 하는 일 | 인원 | 집단 이름 |
|---|---|---|---|---|
| 당사자 학습 집단 | 청각장애(농·난청)가 있는 사람 | 사전 검사, 앱 학습, 사후 검사 | [당사자 인원] | [집단 이름 1] |
| 비당사자 대조군 | 청각장애가 없는 사람 | 당사자 학습 집단과 같다 | [대조군 인원] | [집단 이름 2] |
| 검사만 집단(선택) | 청각장애가 없는 사람 | 학습 없이 같은 간격으로 사전·사후 검사만 | [검사만 집단 인원 또는 두지 않음] | [집단 이름 3] |

- 인원은 모집 가능성으로 정한다(계획서 §4.7의 "당사자 소수"). 규준 산출에 필요한 집단별 30명 이상(`assessment-design.md` 7절)은
  이 파일럿의 목표가 아니다.
- 비당사자 대조군은 계획서 §4.7의 설계대로 당사자와 같은 학습을 한다. 두 집단의 사전 점수 차이는 알려진 집단 비교
  (`assessment-design.md` 5절)의 예비 자료가 된다.
- 검사만 집단은 학습 없이도 생기는 변화(같은 형식의 검사를 두 번 보는 효과, A·B폼 난이도 차이)를 따로 보려는 것이다
  (`assessment-design.md` 4·5절의 검사-재검사·반응성 설계). 두지 않으면 학습 집단의 변화에 이 효과가 섞여 있음을 한계로 적는다.
- 기호 켬·끔 비교(J-12)를 하려면 기호 없이 학습하는 집단을 따로 둔다(7절 3). 둘지: [기호 없는 집단 여부].
  두면 위 표에 그 집단의 이름과 인원을 더한다.
- 집단 이름은 가명 내보내기에 그대로 나온다. 청각 상태를 직접 드러내지 않는 이름(예: g1, g2, g3)을 쓰고,
  이름과 집단의 대응은 이 계획서에만 둔다. 이름은 16자까지 저장되며 쉼표와 콜론은 쓸 수 없다.

## 4. 설계

### 4.1 절차

| 회차 | 시기 | 하는 일 | 걸리는 시간 |
|---|---|---|---|
| 설명·동의 | 0주 | 설명문 읽기, 질문, 서면 동의, 소통 방법 선택 | [설명·동의 시간] |
| 1회차 | 0주 | 새 계정 가입, 참여 코드 입력, 사전 검사(A폼 24문항), 앱 사용 안내 | [1회차 시간]. 검사는 5분 안팎 |
| 학습 | 1~[학습 기간]주 | 앱으로 스스로 학습. 권장량 [권장량] | |
| 중간 점검 | [중간 점검 시기] | 가명 내보내기로 학습한 날 수를 보고, 전원에게 같은 안내를 보낸다 | |
| 마지막 회차 | [학습 기간]주 끝 | 사후 검사(B폼 24문항), 사후 설문 | [마지막 회차 시간] |

- 학습 기간은 2~4주 안에서 정하고 모든 참여자에게 같게 한다.
- 검사만 집단은 1회차와 마지막 회차만 하고, 그사이 앱으로 학습하지 않는다.
- 검사 방식: [대면 또는 원격]. 대면이면 장소는 [검사 장소], 기기는 [연구진 기기 또는 참여자 기기]. 한 참여자의 사전·사후는 같은 기기로 한다.
- 검사 화면에는 소리가 없다(입모양 애니메이션과 보기 네 개). 학습 화면 일부(성도 실험실 등)에는 소리가 있다.
  비당사자 집단이 학습할 때 소리를 끌지: [소리 조건].
- 검사는 마지막 문항까지 풀어야 저장된다. 중간에 나가면 기록이 남지 않는다.

### 4.2 폼 순서와 역균형

- 기본안: 모든 참여자가 사전에 A폼, 사후에 B폼을 푼다. 앱은 A를 '사전검사', B를 '사후검사'로 표시한다.
  앱 안의 사전·사후 비교(`/api/assessment/progression`)는 먼저 푼 동형 폼을 사전, 그 뒤에 푼 다른 폼을 사후로 계산한다.
- 한계: A·B는 난이도 지수로 맞춘 폼이다(평균 난이도 차 0.01 이내). 실제 응답으로 두 폼의 난이도가 같은지는 확인한 적이 없어,
  기본안에서는 폼 차이가 학습 효과와 섞인다.
- 역균형(참여자 절반은 B를 먼저)을 쓰면 폼 차이를 따로 볼 수 있다. 대신 작은 집단을 다시 둘로 나누게 된다.
  B를 먼저 푸는 참여자에게는 첫 검사가 '사후검사'로 표시되고 학습 효과 리포트의 비교 설명도 'A(사전)·B(사후)'로 나오지만,
  비교 값은 먼저 푼 B를 사전으로 계산한다(응답의 `order`가 "B→A"). 분석은 가명 내보내기의 폼과 날짜로 하므로 화면 표시와 무관하다.
- 결정: [역균형 여부]. 검사만 집단을 둔다면 그 집단에서만 A 먼저와 B 먼저를 반씩 배정하는 방법도 있다.

### 4.3 앱 사용 안내(참여자에게 글로 준다)

1. [파일럿 서버 주소]에서 회원가입한다. '둘러보기'(공용 데모 계정)로는 파일럿에 참여할 수 없다.
2. 첫 화면 "어디서부터 시작할까요?"에서 '나중에 할게요'를 고른다('시작하기'는 자가진단으로 간다). 1회차에는 사전 검사를
   다른 검사보다 먼저 하기 위해서다. 자가진단은 사전 검사를 마친 뒤에는 써도 된다(7절 2).
3. 프로필 → 파일럿 참여 → 받은 참여 코드 입력 → 참여하기. "참여 중이에요"가 보이면 된다. 코드는 대소문자를 가리지 않는다.
4. 사전 검사: 분석 → 전체 통계 → 학습 효과 리포트(사전·사후 검사) → 사전 검사(A).
5. 학습: [권장 활동과 양]. 말하기 연습과 웹캠 입모양 연습은 [말하기·웹캠 연습 권장 여부].
6. 사후 검사: 마지막 회차에 같은 화면에서 사후 검사(B).

하지 말 것(이유를 함께 안내한다)
- 학습 초기화: 파일럿 참여 중이면 사전·사후 검사(A·B) 결과와 참여 코드·집단은 남는다. 나머지 학습 기록(문제 풀이, 문장·말하기
  연습, 자가진단 결과, 단계 진도, 복습 목록 등)과 XP·연속 학습은 지워진다. 가명 내보내기의 학습량(`trials_by_stage`, `speak`,
  `active_days`)도 그만큼 줄어든다.
- 검사 다시 하기: 결과 화면의 '다시 검사'나 사전·사후 버튼을 다시 누르지 않는다. 같은 문항을 반복해서 보게 된다.
- 참여 코드를 다른 사람에게 알려 주기.

집단 배정
- 운영자가 집단마다 다른 코드를 정해 서버에 넣고(`LIPLAB_PILOT_CODES='코드:집단,…'`), 동의서를 받은 사람에게
  그 집단의 코드만 글로 준다. 참여자가 집단을 고르지 않는다.
- 참여한 뒤에는 화면에서 코드를 바꿀 수 없다. 1회차에 연구진이 "참여 중이에요"를 함께 확인한다.
  잘못 넣었을 때 바로잡는 방법: [코드 오입력 처리 방법].

| 학습한 날 수 | `trial_attempts`, `speak_attempts`, `progress`, `placement_results`의 날짜 | `active_days` |
| 참여 뒤 학습량 | 위 세 줄과 같은 기록 중 참여 코드를 넣은 뒤의 것 | `since_join`(`trials_by_stage`, `speak`, `active_days`) |
| 집단, 학습 트랙 | `learning_profiles` | `cohort`, `track` |

- 내보내기 판은 `version: 2`다. 날짜(`date`, `joined_on`, `active_days`의 날 구분)는 `tz_offset_min`(기본 −540, 한국 시각) 기준 현지 날짜다.
- `trials_by_stage`, `speak`, `active_days`는 계정의 모든 기록을 센 값이고, `since_join`은 참여 코드를 넣은 뒤의 기록만 센다.
  그래도 참여 전에 푼 검사와 학습 기록이 `tests`와 전체 집계에 섞이지 않도록 연구용 새 계정을 쓴다.
- 지금 앱 화면은 트랙을 perception으로만 설정한다(설정 전이면 빈 값). `track`은 집단을 가르는 정보가 아니다.

### 5.2 앱에 저장되지만 내보내기에 없는 것

- 자가진단의 문항 기록, 오류 입모양·음소, 문장 연습 기록, 웹캠 교정 세션 요약, 입력 문장, 음성 인식 결과(전사문), 코칭 문구.
- 이번 분석에는 쓰지 않는다. 내보내기 항목을 바꾸려면 `pilot-data-spec.md` 3절과 동의서의 "연구진이 받는 것"을 먼저 고치고,
  참여가 시작된 뒤에 바꾸면 다시 동의를 받는다.

### 5.3 앱이 기록하지 않는 것

- 시각 기호가 언제, 몇 개, 어떤 세기로 보였는지.
- 전체 학습 시간. 문장 연습의 문항별 걸린 시간만 저장되며 내보내기에는 없다.
- 원음성, 웹캠 영상.

### 5.4 앱 밖에서 모으는 것

- 사후 설문(`survey.md`): 사용성 10문항, 시각 기호 문항, 가장 어려웠던 점, 자유 의견, 선택 응답 배경 문항.
- 회차 진행 메모: 앱 오류, 참여자가 물은 내용. 이름을 적지 않고 집단만 적는다.
- 동의서와 참여자 연락 대장(이름, 연락 방법, 앱 계정 이메일, 집단, 동의일, 해당하면 법정대리인 이름·관계·연락처).
  분석에 쓰지 않고 연락과 철회 처리에만 쓴다.
- 설문과 앱 기록의 연결: 설문 연결에 선택 동의한 참여자만 설문지에 가명(pid)을 적는다. 운영자가 `checklist.md` 부록 A의 방법으로
  가명을 찾아 적고, 찾는 데 쓴 목록은 남기지 않는다. 동의하지 않은 참여자의 설문지에는 집단만 적는다.
- 설문 방식: [종이 또는 온라인 도구]. 온라인 도구를 쓰면 그 업체가 응답을 저장하므로 업체 이름과 저장 위치를 동의서 5-5에 적는다.

## 6. 분석 계획

분석은 `scripts/pilot_analysis.py`가 이 절의 규칙대로 한다. 가명 내보내기 JSON을 넣으면 보고서(report.md), 수치(results.json),
참여자별 표(participants.csv)를 만든다. 예: `python scripts/pilot_analysis.py export.json --learning [집단] --control [집단]
--withdrawn [철회 가명] --min-active-days [기준] --plots`. 통계 값(KR-20, 신뢰구간, 효과크기)은 `scripts/test_pilot_analysis.py`가
손으로 계산한 값과 맞춰 본다.

### 6.1 분석에 쓰는 기록(자료를 보기 전에 정한다)

- 사전 점수: 학습을 시작하기 전에 처음 완료한 A폼(역균형이면 그 참여자의 첫 폼).
- 사후 점수: 학습 기간이 지난 뒤 처음 완료한 B폼(역균형이면 두 번째 폼).
- 같은 폼을 다시 푼 기록, 계획과 순서가 다른 기록, `form_version`이 다른 기록은 빼고 건수를 보고한다.
- 자가진단(form이 placement) 기록은 정확도 분석에 쓰지 않는다.
- 위 규칙의 확정일: [규칙 확정일]. 규칙을 바꾸면 바꾼 날과 이유를 적는다.

### 6.2 주분석(기술 통계)

- 개인별: 사전·사후 정답 수(24문항 중)와 변화량을 모든 참여자에 대해 표와 선 그래프로 보인다.
  우연 수준(보기 네 개 중 하나, 24문항 중 6개 안팎)에 가까운 점수와 천장에 가까운 점수는 따로 표시한다.
  신뢰도를 확인한 적이 없으므로(파일럿에서 계산하는 KR-20은 참고로만 쓴다, 6.3) 개인 변화가 의미 있는지는 판정하지 않는다.
- 집단별: 사전·사후 정확도와 변화량의 평균, 표준편차, 중앙값, 범위. 평균 변화의 95% 신뢰구간을 함께 적고,
  인원이 적어 구간이 넓다는 점을 밝힌다.
- 효과크기: 평균 변화를 사전·사후 표준편차의 평균으로 나눈 값(d_av)과 작은 표본 보정값(Hedges g_av)을 같이 적는다.
- 집단 비교: 당사자 학습 집단과 비당사자 대조군의 평균 변화 차이와 그 신뢰구간, 사전 점수 차이.
- 검사만 집단을 두었다면 그 집단의 평균 변화를 "학습 없이 생기는 변화"의 추정치로 함께 보인다.
  역균형을 했다면 A·B폼 정확도 차이도 보인다.
- 가설 검정은 주분석으로 쓰지 않는다. 보고서에 "효과가 입증되었다", "유의하다"는 표현을 쓰지 않고 관찰된 변화와 불확실성을 적는다.

### 6.3 보조 분석

- 학습량: 학습한 날 수, 단계별 시행 수와 정답률, 말하기 시도 수. 값은 `since_join`(참여 뒤 기록)을 쓴다. 학습량과 변화량의 관계는 산점도로만 보인다.
- 권장 학습량을 채운 참여자만 본 결과를 전체 결과와 나란히 적는다. 기준: [권장 학습량 기준(예: 학습한 날 수)].
- 사용성: 문항별 응답 분포와 중앙값을 집단별로 보인다. 검증된 척도가 아니므로 합산 점수는 참고로만 쓴다(`survey.md` 메모).
- 시각 기호: 문항별 응답 분포와 "기호를 본 적이 없다"는 응답 비율. 설문을 연결한 참여자는 기호 응답과 사후 점수를 개별 사례로만 기술한다.
  기호 없는 집단을 두었다면 설문 B절은 기호를 켠 집단만 보고, 기호를 켠 집단과 끈 집단의 사전·사후 변화를 나란히 적는다(7절 3).
- 자유 의견: 두 사람이 따로 분류하고, 다른 부분은 협의로 정한다. 인용할 때는 가명도 적지 않는다.
- 표준검사: 가명 내보내기의 문항 기록(`tests[].items`)으로 폼별 KR-20, 문항 정답률, 점이연 상관을 계산하고, 고른 보기(`chosen`)로
  어떤 오답 보기를 많이 골랐는지 본다. 인원이 적어 신뢰도의 근거로 쓰지 않고 판본 v2 문항 교체의 참고로만 쓴다.

### 6.4 결측과 철회

- 사후 검사를 하지 않은 참여자는 변화량 분석에서 빼고, 인원과 사유(연락 두절, 중단 등)를 이름 없이 보고한다. 값을 채워 넣지 않는다.
- 동의를 철회한 참여자의 자료는 모든 분석에서 뺀다.

## 7. 알려진 제약(앱과 계획서의 차이)

1. **연령 확인.** 가입 화면은 "만 14세 이상이거나 보호자 동의를 받았어요" 확인란 하나이고, 서버(`POST /api/auth/register`)는
   이 확인 여부만 검사한다. 나이를 묻지 않고 보호자 동의를 따로 확인하지 않는다. 그래서 연령은 연구진이 동의 단계에서 확인한다.
   `pilot-data-spec.md` 2절도 같게 적었다.
2. **문항 노출.** 훈련 콘텐츠(단어, 최소대립쌍, 문맥 문항)와 자가진단(적응형 배치검사 포함)에서는 검사 단어 48개를 정답과 보기에서
   모두 뺐다(`assessment-design.md` 3절, 명세 2절). AI가 만드는 문장·대화에서는 빼지 않아 검사 단어가 나올 수 있다. 검사 단어에 흔한 낱말이
   많아 문장 단위로 거르지 않는다. 이 노출은 막을 수 없으므로 결과를 해석할 때 한계로 적는다.
3. **시각 기호.** 단어·문장 단계에서 기호는 답한 뒤 입모양을 다시 볼 때 나오고, 숙달도에 따라 흐려진다(`docs/cue-overlay.md` 4절).
   계획서 §3.10이 그린 "구분이 필요한 순간에만 입 근처에 겹쳐" 보이는 표시와 다르다. 기호가 언제, 몇 개, 어떤 세기로 보였는지는
   기록되지 않는다(5.3). 집단별로 기호를 끌 수는 있다. `LIPLAB_PILOT_NOCUE_COHORTS='집단,…'`에 넣은 집단은 기호 없이 학습한다
   (기호 API `/api/cues`가 빈 목록을 주고, 화면은 범례와 웹캠 연습의 울림 기호도 숨긴다). 이런 집단을 두면 기호를 켠 집단과 끈 집단을
   비교해 기호의 효과를 따로 볼 수 있다(J-12). 대신 작은 집단을 다시 나누게 되고, 기호를 켠 집단이 기호를 얼마나 보았는지는 여전히
   알 수 없다. 두지 않으면 기호의 효과만 떼어 볼 수 없다. 결정: [기호 없는 집단 여부].
4. **발화 자료.** 원음성과 얼굴 영상을 저장하지 않으므로 계획서 §3.1·§4.2의 발화 기반 보정과 라벨 평가셋은 이 파일럿에 들어 있지 않다(2절).
5. **파기 스크립트와 대장 위치.** 배포 이미지(`Dockerfile`)에 `/app/scripts/pilot_retention.py`로 들어 있어, 배포 서버에서
   `fly ssh console -C "python /app/scripts/pilot_retention.py …"`로 실행한다. 대장의 기본 위치는 `/data`가 있고 쓸 수 있으면
   `/data/pilot_destruction_ledger.jsonl`, 아니면 실행 폴더의 `pilot_destruction_ledger.jsonl`이다. 연구 시작 전에 보고 모드로 시험하고,
   파일럿 앱의 `/data`가 볼륨인지 확인해 대장 위치를 정한다(`checklist.md` 1절).
6. **가명 확인.** 참여자에게 자기 가명을 보여 주는 기능이 없다. 철회와 설문 연결 때 운영자가 참여자 계정 이메일로 가명을 찾는다
   (`POST /api/pilot/lookup`, 운영자 계정만, `checklist.md` 부록 A). 참여자가 계정을 지운 뒤에는 찾을 수 없다(9절).

## 9. 중단·철회(`pilot-data-spec.md` 5절과 같다)

- 참여자는 언제든 이유를 말하지 않고 그만두거나 동의를 철회할 수 있다. 요청은 [문의 연락처]로 글로 받는다.
- **그만두기**(더 참여하지 않음): 그때까지의 자료는 보관 기한까지 두었다가 10절대로 파기한다. 참여자가 자료 삭제도 원하면 철회로 처리한다.
- **동의 철회**(자료 삭제)
  1. 운영자가 `POST /api/pilot/lookup`으로 그 참여자 계정 이메일의 `pid`를 찾는다(`checklist.md` 부록 A).
     참여자에게 가명을 보여 주는 기능은 없다.
  2. `pilot_retention.py --withdraw <pid> --apply --mode delete`로 지운다. 배포 서버에서는 `fly ssh console`로
     `/app/scripts/pilot_retention.py`를 실행한다(`checklist.md` 8절). 기한과 무관하게 바로 처리되며,
     범위는 계정 삭제(`DELETE /api/account`)와 같다(명세 1절의 사용자 표 전부와 계정).
  3. 이미 연구자에게 넘긴 가명 자료에서 같은 `pid` 행을 지우도록 연구자에게 알린다.
  4. 대장(`pilot_destruction_ledger.jsonl`)에 한 줄이 남는다. 대장에는 가명만 남는다.
- 앱 밖 자료도 정리한다. 그 참여자의 설문지와 진행 메모의 해당 부분을 지운다. 동의서와 철회 요청 기록은 [철회 기록 보관 여부와 기한].
- 처리 기한: 요청을 받은 날부터 [처리 기한]일 안. 처리 결과를 참여자에게 글로 알린다.
- 이미 공개한 집단 결과에서는 뺄 수 없다. 이 점을 동의서에 적는다.
- 참여자가 앱에서 직접 계정을 지우면 앱 기록은 지워지지만, 계정이 없어져 운영자가 `pid`를 찾을 수 없으므로 3을 할 수 없다.
  그래서 철회는 연구진에게 알리는 방법으로 받는다고 동의서에 적는다.
- 철회한 뒤 앱을 다시 쓰려면 새 계정을 만들어야 한다. 이전 기록은 남지 않는다.

## 10. 자료 보관·파기

| 자료 | 위치 | 보관 기한 | 파기 방법 | 기록 |
|---|---|---|---|---|
| 앱 기록(명세 1절) | 파일럿 서버 DB | 연구 종료일([연구 종료일])부터 [보관 일수]일 | `pilot_retention.py --apply --mode` [파기 방식(delete 또는 unlink)] | 파기 대장 |
| 서버 백업(볼륨 스냅샷) | 호스팅 | [백업이 남는 기간] | 호스팅의 보관 설정에 따라 만료(확인 필요) | 확인 결과를 대장 비고에 적는다 |
| 가명 내보내기 사본 | [내보내기 파일 보관 장소] | [사본 보관 기한] | 파일 삭제(서버 밖 사본이라 스크립트가 지우지 못한다) | 앱 밖 자료 파기 기록 |
| 동의서, 연락 대장 | [동의서 보관 장소] | [동의서 보관 기한] | [동의서 파기 방법] | 앱 밖 자료 파기 기록 |
| 설문지, 진행 메모 | [설문지 보관 장소] | [설문지 보관 기한] | [설문지 파기 방법] | 앱 밖 자료 파기 기록 |
| 파기 대장 | [대장 보관 장소] | 연구 기록과 함께 [대장 보관 기한] | | |

- 보관 기간은 윤리 심의 승인 내용을 따른다.
- 파기 방식: 연구 참여만을 위해 만든 계정이면 `delete`, 계속 쓰는 학습자면 `unlink`가 맞다(명세 4절). 이 파일럿은 연구용 새 계정을 쓰므로
  `delete`를 기본으로 제안한다. 스크립트는 한 번 실행에 한 방식만 쓴다(`--cohort`로 집단별로 나눠 실행할 수는 있다).
  참여자마다 다른 방식을 고르게 하는 기능은 없다.
- 동의 철회는 기한과 무관하게 9절대로 바로 처리한다.
