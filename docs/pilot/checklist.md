# 파일럿 실행 체크리스트

> 작성 2026-09-24. 위에서부터 순서대로 한다. `docs/pilot-data-spec.md`는 보관 기간, 연구 윤리 절차, 개인정보 보호책임자를 정하기 전에는
> 파일럿을 켜지 않는다고 정했다. 그래서 1절을 모두 마치기 전에는 2절(파일럿 켜기)로 넘어가지 않는다.
> 대괄호 안에 설명이 든 칸은 정해서 채우는 값이고, 줄 앞의 빈 네모는 완료 표시 칸이다.

  만 14세 미만은 앱에 법정대리인 동의 절차가 생기기 전까지 받지 않는다(`consent_guardian.md` 앞부분).

- [ ] **1.4** 연구 종료일 [연구 종료일], 보관 일수 [보관 일수], 파기 방식 [파기 방식(delete 또는 unlink)]을 정한다.

처리방침과 서버
- [ ] **1.8** 개인정보 보호책임자를 정하고 처리방침에 적는다: [보호책임자 이름], [보호책임자 연락처].
  `frontend/src/pages/Legal.jsx`의 `PRIVACY_OFFICER.contact`가 비어 있어 화면에 "연락처는 공개 전 기재"로 보인다.
  처리방침 시행일을 바꾸면 `backend/main.py`의 `_TERMS_VERSION`·`_PRIVACY_VERSION`도 같은 날짜로 맞춘다(가입 동의 기록에 남는 판본).
- [ ] **1.9** 파일럿 서버를 준비한다: [파일럿 서버 주소], 앱 이름 [파일럿 앱 이름]. 전시앱(`liplab.fly.dev`)을 덮어쓰지 않고 새 fly 앱으로 연다(`DEPLOY.md` 6).
- [ ] **1.10** 가명 비밀키 `LIPLAB_PILOT_SECRET`을 파일럿 서버에 넣고, 파기가 끝날 때까지 바꾸거나 지우지 않는다. 가명은 이 키로 만든
  HMAC이므로, 키가 바뀌면 이미 내보낸 `pid`와 대조할 수 없고 파기 스크립트도 참여자를 찾지 못한다. 이 키가 없으면 로그인 비밀키(`JWT_SECRET`)를
  쓰는데, 로그인 비밀키는 보안 사고 때 바꿀 수 있으므로 반드시 따로 넣는다. 따로 넣어 두면 `JWT_SECRET`은 보안상 필요할 때 바꿔도 가명이 달라지지 않는다.
  키와 DB가 함께 있으면 가명을 계정으로 되돌릴 수 있으므로 운영자 밖으로 알리지 않는다.

  ```bash
  fly secrets set -a [파일럿 앱 이름] LIPLAB_PILOT_SECRET="$(openssl rand -hex 32)"   # 한 번만 실행한다
  ```
  넣은 뒤에는 `fly secrets list -a [파일럿 앱 이름]`로 이름이 있는지만 확인하고, 이 명령을 다시 실행하지 않는다(다시 실행하면 키가 바뀐다).
- [ ] **1.11** 단계 잠금: `LIPLAB_UNLOCK_ALL`은 기본값이 1(모든 단계 열림)이다. 순차 학습을 강제하려면 0으로 둔다: [단계 잠금 설정].
- [ ] **1.12** 기호 켬·끔: 기호 없이 학습하는 집단을 둘지 정한다: [기호 없는 집단 여부]. 두면 그 집단 이름을 2.2에서
  `LIPLAB_PILOT_NOCUE_COHORTS`에 넣는다. 기호 노출은 어느 집단에서도 기록되지 않는다(`protocol.md` 7절 3).
- [ ] **1.13** 가명 내보내기 판(`version: 2`)이 넘기는 항목(명세 3절)과 동의서 5-3의 "연구진이 받는 것"이 같은지 확인한다. 동형 폼의
  문항별 정오답과 고른 보기, 참여일이 들어 있다. 내보내기 항목이 바뀌면 명세와 동의서를 먼저 고치고, 참여가 시작된 뒤라면 다시 동의를 받는다.
- [ ] **1.14** 배포 서버에서 파기 스크립트를 보고 모드로 한 번 실행해 본다. 스크립트는 배포 이미지에 `/app/scripts/pilot_retention.py`로 들어 있다(`Dockerfile`).

  ```bash
  fly ssh console -a [파일럿 앱 이름] -C "python /app/scripts/pilot_retention.py --study-end [연구 종료일] --retain-days [보관 일수]"
  ```
  대장의 기본 위치는 `/data`가 있고 쓸 수 있으면 `/data/pilot_destruction_ledger.jsonl`, 아니면 실행 폴더의 `pilot_destruction_ledger.jsonl`이다.
  파일럿 앱에 볼륨이 `/data`로 붙어 있는지(`fly.toml`의 `[[mounts]]`, `fly volumes list -a [파일럿 앱 이름]`) 확인해 대장이 볼륨에 남게 한다.
  다른 곳에 두려면 실행할 때마다 `--ledger [대장 경로]`를 준다.

## 2. 파일럿 켜기(1절을 마친 뒤)

- [ ] **2.1** 참여 코드와 집단 이름을 정한다. 형식은 `코드:집단`이고 쉼표로 이어 쓴다.
  - 코드는 대소문자를 가리지 않고(서버가 대문자로 바꾼다) 32자까지 쓸 수 있다. 추측하기 어려운 값으로 한다.
  - 집단 이름은 16자까지 저장되고(넘으면 잘린다), 비우면 `default`가 된다. 코드와 이름에 쉼표와 콜론을 쓰지 않는다.
  - 청각 상태를 드러내지 않는 코드와 이름을 쓴다(`protocol.md` 3.1).
- [ ] **2.2** 파일럿 서버에 비밀값으로 넣는다. `LIPLAB_ADMIN_EMAILS`에는 파일럿 서버에 가입한 운영자 계정의 이메일을 쉼표로 넣는다.
  공용 데모 계정은 넣어도 막힌다. 운영자 계정은 참여 코드를 넣지 않는다.

  ```bash
  fly secrets set -a [파일럿 앱 이름] \
    LIPLAB_PILOT=1 \
    LIPLAB_PILOT_CODES='[코드1]:[집단 이름 1],[코드2]:[집단 이름 2],[코드3]:[집단 이름 3]' \
    LIPLAB_ADMIN_EMAILS='[운영자 이메일]'
  ```
  기호 없는 집단을 두기로 했으면(1.12) 같은 명령에 `LIPLAB_PILOT_NOCUE_COHORTS='[기호 없는 집단 이름]'`을 더한다. 코드가 아니라
  집단 이름을 저장된 그대로(16자까지, 대소문자 구별) 쓰고, 여럿이면 쉼표로 잇는다. `LIPLAB_PILOT_SECRET`은 1.10에서 넣었으므로 이 명령에 넣지 않는다.
- [ ] **2.3** 시험한다. 시험용 코드(예: 집단 이름 `test`)를 잠시 추가하고 시험 계정으로 넣은 뒤 다음을 본다.
  프로필에 "파일럿 참여" 줄이 보이는지, 가명 내보내기(7.2)에 그 계정이 나오고 `joined_on`이 참여한 날인지, 파기 스크립트 보고 모드(8.1)가
  그 계정을 찾는지, 부록 A로 찾은 가명이 내보내기의 `pid`와 같은지. 기호 없는 집단을 두었으면 그 집단으로 가는 시험용 코드로도 한 번 넣어 기호와 범례가 보이지 않는지 본다.
  끝나면 시험 계정을 앱의 계정 삭제(프로필 → 계정 설정)로 지우고 시험용 코드를 뺀다.

## 7. 가명 내보내기

- [ ] **7.1** `GET /api/pilot/export`는 파일럿이 켜져 있을 때(`LIPLAB_PILOT=1`) `LIPLAB_ADMIN_EMAILS`에 있는 계정만 부를 수 있다.
  파일럿을 끄기 전에 최종 내보내기를 한다. 내보내기 판은 `version: 2`이고, 날짜는 `tz_offset_min`(기본 −540, 한국 시각) 기준이다.
- [ ] **7.2** 받는 방법. 아래는 예시이며 2.3에서 한 번 시험한다. 비밀번호는 화면에 보이지 않게 입력받는다.

  ```bash
  python3 - <<'EOF'
  import getpass, json, urllib.request
  BASE = "[파일럿 서버 주소]"
  body = json.dumps({"email": "[운영자 이메일]", "password": getpass.getpass()}).encode()
  req = urllib.request.Request(BASE + "/api/auth/login", data=body, headers={"Content-Type": "application/json"})
  token = json.load(urllib.request.urlopen(req))["access_token"]
  req = urllib.request.Request(BASE + "/api/pilot/export", headers={"Authorization": "Bearer " + token})
  with open("pilot_export_[내보낸 날짜].json", "wb") as f:
      f.write(urllib.request.urlopen(req).read())
  EOF
  ```
- [ ] **7.3** 파일을 [내보내기 파일 보관 장소]에 두고, 사본을 누가 어디에 두었는지 사본 목록에 적는다. 철회 처리(8.3)와 파기(8.5)에 쓴다.
- [ ] **7.4** 분석 담당에게는 이 파일만 넘긴다. 이메일, 이름, 연락 대장은 넘기지 않는다.
- [ ] **7.5** 연구가 끝나면 참여 모집을 닫는다: `fly secrets unset -a [파일럿 앱 이름] LIPLAB_PILOT_CODES LIPLAB_PILOT_NOCUE_COHORTS`.
  참여 코드가 없으면 새 참여가 막히고 프로필 화면의 참여 줄도 사라진다. 기호 없는 집단도 이때부터 기호가 다시 보인다.
  `LIPLAB_PILOT=1`은 파기가 끝날 때까지 두어, 내보내기와 가명 찾기(부록 A)로 철회 요청을 처리할 수 있게 한다. 파기가 끝나면
  `LIPLAB_PILOT`도 지운다. 파기 스크립트는 DB에 남은 참여 코드로 대상을 찾으므로 어느 쪽이든 쓸 수 있다.
  `LIPLAB_PILOT_SECRET`은 파기가 끝날 때까지 지우지 않는다(1.10).

## 8. 보관 기한 뒤 파기

명령은 앱과 같은 `DATABASE_URL`·`LIPLAB_PILOT_SECRET`(없으면 `JWT_SECRET`) 환경에서 실행한다(명세 4절). 아래 예시는 저장소의 `backend/`에서
실행하는 형태다. 배포 서버에서는 1.14처럼 `fly ssh console -a [파일럿 앱 이름] -C "python /app/scripts/pilot_retention.py …"`로 실행하고,
`…` 자리에 아래 예시와 같은 인자를 준다.

- [ ] **8.1** 먼저 보고만 한다. 기본 동작이며 아무것도 지우지 않는다.

  ```bash
  python ../scripts/pilot_retention.py --study-end [연구 종료일] --retain-days [보관 일수]
  ```
- [ ] **8.2** 기한(연구 종료일 + 보관 일수)이 지난 뒤 적용한다. 기한 전에는 스크립트가 거부한다.

  ```bash
  python ../scripts/pilot_retention.py --study-end [연구 종료일] --retain-days [보관 일수] --apply --mode [파기 방식(delete 또는 unlink)]
  ```
  집단별로 나눠 처리하려면 `--cohort [집단 이름]`을, 대장 위치를 바꾸려면 `--ledger [대장 경로]`를 붙인다.
- [ ] **8.3** 동의 철회는 기한과 무관하게 바로 처리한다(`protocol.md` 9절, 명세 5절). 가명은 부록 A로 찾는다.

  ```bash
  python ../scripts/pilot_retention.py --withdraw <pid> --apply --mode delete
  ```
  이어서 사본 목록(7.3)의 모든 사람에게 같은 `pid` 행을 지우도록 알리고, 설문지와 진행 메모의 해당 부분을 지운다.
  처리 결과를 참여자에게 글로 알린다([처리 기한]일 안).
- [ ] **8.4** 출력의 "찾지 못한 가명"이 비어 있는지 확인한다.
- [ ] **8.5** 가명 내보내기 사본을 모두 지운다. 서버 밖 사본이라 스크립트가 지우지 못한다. 사본 목록에 지운 날을 적는다.
- [ ] **8.6** 앱 밖 자료(동의서, 연락 대장, 설문지, 진행 메모)를 정한 기한에 정한 방법으로 지우고 부록 B에 적는다.
- [ ] **8.7** 서버 백업(스냅샷)이 만료되는 날을 확인해 대장 비고에 적는다.
- [ ] **8.8** 파일럿 전용 서버를 없앨지 정한다: [서버 정리 여부]. 없애기 전에 대장을 서버 밖으로 옮긴다.

## 부록 A. 계정으로 가명(pid) 찾기

참여자에게 가명을 보여 주는 기능이 없어 운영자가 참여자 계정 이메일로 찾는다(명세 3·5절). `POST /api/pilot/lookup`은 내보내기와 같이
파일럿이 켜져 있을 때(`LIPLAB_PILOT=1`) `LIPLAB_ADMIN_EMAILS`에 있는 계정만 부를 수 있다. 이메일은 주소줄(쿼리)에 넣지 않고 요청 본문으로 보낸다.
아래는 예시이며, 2.3에서 시험 계정으로 결과가 가명 내보내기의 `pid`와 같은지 먼저 확인한다. 운영자 토큰은 7.2와 같은 방법으로 받는다.

```bash
BASE="[파일럿 서버 주소]"
TOKEN=$(python3 - "$BASE" <<'EOF'
import getpass, json, sys, urllib.request
body = json.dumps({"email": "[운영자 이메일]", "password": getpass.getpass()}).encode()
req = urllib.request.Request(sys.argv[1] + "/api/auth/login", data=body, headers={"Content-Type": "application/json"})
print(json.load(urllib.request.urlopen(req))["access_token"])
EOF
)
curl -s -X POST "$BASE/api/pilot/lookup" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"email": "[참여자 계정 이메일]"}'
```

- 결과는 `{"pid": "…", "joined": true, "cohort": "…"}` 꼴이다. `joined`가 false면 참여 코드를 넣지 않은 계정이라 내보내기에 나오지 않는다.
  계정이 없으면 404, 운영자 계정이 아니거나 파일럿이 꺼져 있으면 403이 온다.
- 이메일의 대소문자는 가리지 않는다.
- 7.5를 따르면 연구가 끝난 뒤에도 `LIPLAB_PILOT=1`이 남아 있어 그대로 찾을 수 있다. 파기까지 끝나 `LIPLAB_PILOT`을 지운 뒤에는
  찾을 자료가 없다.
- 참여자가 앱에서 계정을 지운 뒤에는 찾을 수 없다. 그래서 철회는 계정을 지우기 전에 연구진에게 알리도록 안내한다(동의서 8번).
- 찾은 가명을 이메일과 함께 적어 두지 않는다. 설문지에 적거나 철회 명령에 넣은 뒤 버린다.
