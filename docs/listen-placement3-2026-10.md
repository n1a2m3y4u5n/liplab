# 소리 듣기 배치검사 3차: '1단계 수준 + 낱말 확인(C)'과 '1·2단계 건너뛰지 않기(D)' 사전 등록

작성 2026-10-17. 0~7절은 시뮬레이션을 돌리기 전에 적고 커밋했다. 탐색 결과와 고른 조합은 8절, 확인 결과와 판정은 9절 이후에 덧붙인다.
1차(`docs/listen-placement-2026-10.md`)의 가상 청취자 모형(3절), 조건 G0~G8(5절), 채점 모형(4.3절, `scripts/listen_placement_model.py`)과
2차(`docs/listen-placement2-2026-10.md`)의 후보 A 절차(1절, `scripts/listen_placement2_sim.py`)를 그대로 쓰고, 2차 9절이 다음 등록 후보로 적은 두 절차만 새로 정한다.
코드는 `scripts/listen_placement3_sim.py`다(1·2차 코드는 고치지 않고 불러 쓴다).

## 0. 2차에서 이어받는 것

- 2차 A(1단계는 건너뛰지 않고 수준만 정함)는 소리 구별 쪽 과배치를 없앴지만, 심한 과배치가 G3 3.8%, G5 6.9%, G6 2.15%로 남았다(기준 2%).
  남은 것은 모두 '위 단계 참 시작 2인데 4단계 배치', 곧 조용한 곳 문장은 넘는데 낱말 고르기 수준 3만 따로 약한 학습자였다(2차 8.3절, 판정에 쓰지 않은 사후 분석).
- 2차 B(1차 배치 뒤 확인)는 1·2단계를 길게 확인하면 K1~K5를 넘었지만 확인에 평균 221초 이상이 들어 K6(확인 ≤ 180초, 합 ≤ 360초)에 걸렸다.
  확인 시간의 상당 부분은 1단계 확인(문항당 12초, 최대 20문항)이었다.
- 그래서 이번 두 후보는 남은 과배치가 생기는 '2단계를 건너뛰는 판단'만 다룬다. C는 A에 2단계 확인만 더하고(1단계 확인 시간이 들지 않음), D는 2단계도 건너뛰지 않는다.
- 후보 A의 사후 분석은 시드 0에서 나왔고, 이번 탐색도 시드 0이다. 후보를 그 분석을 보고 골랐으므로 탐색 결과는 낙관적일 수 있다. 판정은 아직 쓰지 않은 확인 시드 101·102에서만 한다.

## 1. 후보 C: 1단계는 수준만 정하고, 2단계를 건너뛸 때만 낱말 확인을 한다

### 1.1 절차

- 배치는 2차 후보 A 그대로다(2차 1.1~1.3절: 채점 모형, 문항 고르기 γ, 멈춤 m·s·대상, 위 단계 결정, 1단계 수준 결정, 같은 384개 조합, 같은 코드 `run_chunk_a`).
  결과는 위 단계 k ∈ {2, 3, 4, 5}와 1단계 시작 수준 ℓ ∈ {1, 2, 3, 4}이고, 1단계는 열린 채 '진행 중'으로 남는다(2차 1.1절).
- 배치 k ≥ 3이면(2단계를 건너뛰게 되면) 첫 회기에 낱말 고르기 수준 3(4지) 확인 문항을 n_w개 내고, 정답이 c_w개 이상이면 통과(k 그대로), 아니면 최종 위 단계를 2로 내린다
  (2~k단계 대신 2단계만 연다). k = 2이면 확인하지 않는다. 1단계는 어느 경우든 건너뛰지 않으므로 확인하지 않는다.
- 확인은 결과가 정해지는 순간 멈춘다(맞힌 수가 c_w에 닿으면 통과, 틀린 수가 n_w − c_w를 넘으면 미달). 판정은 끝까지 낸 경우와 같고 시간만 준다(2차 2.1절과 같음).
- 확인 변형은 2차 B의 낱말 몫과 같은 네 가지다: W10(8/10, 앱 숙달 기준과 같음), W15(13/15), W20(17/20), W20s(18/20).
- 탐색 조합: A 배치 384 × 확인 변형 4 = 1,536개.
- 확인 문항의 응답은 배치의 낱말 문항과 같은 모형이다(문항마다 로짓 N(0, 0.5²), 조건별 실수). 응답 난수는 배치 흐름과 따로 둔다(시드 [시드, 조건 번호, 8]).
  사람마다 20문항을 미리 뽑고 변형마다 앞에서부터 쓴다. 그래서 시드 0의 배치 흐름은 2차 A 탐색과 똑같고, 확인을 빼고 계산한 지표가 2차 결과 파일과 같아야 한다(코드 점검).
- 낱말 수준 3 문항은 앱 풀에서 겹치지 않게 32개 남짓이다. 배치 낱말 문항과 확인 20개를 합쳐 이를 넘는 드문 경우에는 앞 문항을 되풀이한다(응답 모형은 같음).

### 1.2 참 값과 지표

- 참 값은 2차 A와 같다: 위 단계 참 시작 T_up(2~5)과 1단계 참 시작 수준 L\*(1~4, κ 기준 1.0, H1 0.5, H2 1.5).
- 위 단계 지표는 최종 위 단계(확인 뒤)와 T_up으로 잰다. 수준 지표는 2차 A와 같다(확인은 수준을 바꾸지 않는다).

## 2. 후보 D: 1·2단계를 모두 건너뛰지 않고, 3~5단계 시작과 두 단계의 시작 수준만 정한다

### 2.1 절차가 정하는 것

- 결과는 세 가지다. (i) 위 단계 k ∈ {3, 4, 5}: 3~k단계를 연다. (ii) 1단계 시작 수준 ℓ₁ ∈ {1, 2, 3, 4}. (iii) 2단계 시작 수준 ℓ₂ ∈ {1, 2, 3}.
- 1단계와 2단계는 숙달로도 건너뛰기로도 적지 않는다. 두 단계는 열린 채 '진행 중'으로 남고, 앱의 수준 올리기·내리기와 숙달 기준(1단계 맨 위 수준 10번 중 9번,
  2단계 맨 위 수준 10번 중 8번)이 그대로 적용된다. 학습자는 1·2단계를 정한 수준부터 연습하면서 k단계도 함께 연습한다.
- 그러므로 D에서 학습자가 건너뛰는 연습은 3~(k−1)단계(조용한 곳 문장)와 k = 5일 때의 4단계(소음 속 듣기), 그리고 1·2단계의 시작 수준 아래 수준뿐이다.
  1·2단계 숙달은 여전히 맨 위 수준에서 앱 기준을 넘어야 하므로 거짓 숙달로 이어지지 않는다.
- '1·2단계를 다 마친 뒤 3~5단계 가운데 정한 곳에서 시작'하는 차례 방식도 판정 지표(과배치·일치·수준)는 위와 같다. 다른 것은 연습의 차례뿐이라 이번에는 판정하지 않고 앱 설계에서 정한다.

### 2.2 참 값(시뮬레이션의 정답)

- **위 단계 참 시작 T₃**: 1차 2절의 조건을 3단계부터만 본다. 조용한 곳 z < 1.386이면 3, 아니고 SRT50 > 0 dB이면 4, 모두 넘으면 5.
  지금 앱의 비교 기준은 1·2단계를 마친 뒤 3단계로 가는 것, 곧 T₃ 배치 3이다.
- **1단계 참 시작 수준 L₁\***: 2차 A의 L\*와 같다(같다·다르다 수준 ℓ의 정답 확률 1/2 + 1/2 · L(z + d_a + κ(4 − ℓ)), 문턱 1.386, 1~4).
- **2단계 참 시작 수준 L₂\***: 같은 꼴의 새 연결 가정이다. 수준 ℓ의 4지 정답 확률을 1/4 + 3/4 · L(z + d_w + κ(3 − ℓ))로 두고, 수준 ℓ을 이미 숙달함은 1차 수준 3과 같은 문턱
  z + d_w + κ(3 − ℓ) ≥ 1.012다. L₂\* = 1 + (숙달한 수준 1~2의 수)이고, 수준 3까지 숙달했어도 L₂\*는 3으로 둔다. 지금 앱의 비교 기준은 두 단계 모두 수준 1에서 시작이다.
- κ는 1단계와 2단계에 같은 값을 쓰고, 조건 H1(κ 0.5)·H2(κ 1.5)로 흔든다(2차 1.2절과 같이 G0의 같은 청취자·같은 응답 흐름에 참 수준만 바꿔 계산, 수준 기준에만 씀).
  검사는 수준 4 짝과 수준 3 낱말만 내므로 κ는 응답을 바꾸지 않는다.

### 2.3 채점·문항 고르기·멈춤·결정

- 채점 모형과 문항 후보는 1차 4.3·4.4절 그대로다.
- 격자 점마다 위 단계 확률: P(3) = 1[z < 1.386], P(4) = 1[z ≥ 1.386] 1[θ > 0], P(5) = 1[z ≥ 1.386] 1[θ ≤ 0].
  1단계 수준 확률은 2차 A와 같다(r_ℓ = P(z + d_a ≥ 1.386 − κ_m(4 − ℓ) | 자료), κ_m = 1.0).
  2단계 수준 확률: s_ℓ = P(z + d_w ≥ 1.012 − κ_m(3 − ℓ) | 자료), ℓ = 1, 2로 P(L₂\* = 1) = 1 − s_1, P(2) = s_1 − s_2, P(3) = s_2. 모두 사후분포로 평균한다.
- 문항 고르기: 후보마다 세 분포(위 단계, 1단계 수준, 2단계 수준) 엔트로피의 기대 감소 합을 (걸리는 초)^γ로 나눈 값이 가장 큰 후보. γ ∈ {0, 1}.
- 멈춤: 최소 m문항 뒤, 대상이 'upper'면 위 단계 최대 확률 ≥ s, 'all'이면 세 분포의 최대 확률이 모두 ≥ s일 때 멈춘다. 16문항·300초 상한은 1차와 같다.
- 결정: 위 단계는 mode 또는 P(T₃ ≥ k) ≥ q인 가장 큰 k(q 0.6·0.7·0.8), 두 수준은 같은 규칙으로 mode 또는 P(L\* ≥ ℓ) ≥ q인 가장 큰 ℓ(q 0.7·0.8).
- 탐색 조합: γ 2 × m {2, 4} × s {0.80, 0.85, 0.90, 0.95} × 대상 2 × 위 단계 결정 4 × 수준 결정 3 = 384개.

## 3. 조건과 시드

- 조건은 1차 5절 G0~G8 그대로다(채점 모형은 모든 조건에서 고정). 두 후보 모두 수준용 H1·H2를 더한다.
- 탐색: 시드 0, 조건마다 청취자 2,000명(1·2차와 같은 청취자). C의 배치 흐름은 2차 A와 같고, D는 새 문항 흐름이다.
- 확인: 아직 쓰지 않은 시드 101과 102, 조건마다 각 2,000명, 합친 4,000명으로 한 번 판정한다. 후보마다 8절에 고른 조합 하나만 돌린다.
- 코드 점검(smoke)은 시드 999, 조건마다 40명으로 돌아가는지와 걸리는 시간만 보고, 지표는 기록하지 않는다.

## 4. 지표와 사전 기준

### 4.1 후보 C(위 단계는 G0~G8, 수준은 G0~G8·H1·H2 모두에서)

- **K1~K5**: 2차 4.1절(A)과 같은 수치로, 최종 위 단계와 T_up으로 잰다. K1 과배치 ≤ 10%, K2 심한 과배치(≥ T_up + 2) ≤ 2%,
  K3 일치가 지금(T_up 배치 2)보다 20%p 이상 높고 아홉 조건 평균 ≥ 60%, K4(배치 검사 부분) 평균 문항 ≤ 12·평균 ≤ 240초·95백분위 ≤ 300초, K5 집단마다 과배치 ≤ 15%.
- **L1·L2**: 2차 A와 같다. 1단계 수준 심한 과배치(≥ L\* + 2) ≤ 5%, 수준 일치가 지금(모두 수준 1)보다 20%p 이상 높음.
- **K6**: 2차 B와 같은 값이다. 확인 시간 평균 ≤ 180초, 배치와 확인을 더한 평균 ≤ 360초(확인하지 않은 사람은 확인 0초로 넣어 평균).

2차 9절은 C의 시간 기준을 새로 정해야 한다고 적었다. 이번에는 기준을 늘리지 않고 2차 B의 K6를 그대로 쓴다. 근거: 확인 문항은 첫 회기의 2단계 연습 문항이지만
6분(하루 권장 15~20분의 3분의 1)을 넘는 첫 회기 검사는 2차에서 이미 받아들이지 않기로 한 값이고, 결과를 보기 전에 기준을 넉넉하게 바꾸면 사전 등록의 뜻이 약해진다.
C에서 확인 시간이 줄어드는 것은 1단계 확인이 없어서이지 기준이 바뀌어서가 아니다.

### 4.2 후보 D(위 단계는 G0~G8, 수준은 두 단계 각각 G0~G8·H1·H2 모두에서)

- **K1~K5**: 같은 수치로 위 단계 배치와 T₃으로 잰다. K1 과배치(배치 > T₃) ≤ 10%, K2 심한 과배치(배치 ≥ T₃ + 2, 곧 참 3인데 5 배치) ≤ 2%,
  K3 일치가 지금(T₃ 배치 3)보다 20%p 이상 높고 아홉 조건 평균 ≥ 60%, K4 같음, K5 집단마다 과배치 ≤ 15%.
- **L1·L2**: 1단계 수준과 2단계 수준 각각에 같은 기준을 쓴다(심한 과배치 ≤ 5%, 일치가 모두 수준 1보다 20%p 이상 높음). 2단계 수준의 심한 과배치는 참 1인데 3 배치다.
- K6은 확인이 없으므로 쓰지 않는다.

정의 차이의 근거(결과 전): D에서는 1·2단계를 건너뛰는 학습자가 없으므로(2.1절) 1·2단계 숙달 여부를 위 단계 과배치에 넣지 않는다. 2차 A가 1단계에 대해 한 것과 같은 정의를
2단계까지 넓힌 것이다. 위 단계가 세 갈래뿐이라 K3 평균 60%는 1·2차보다 쉬운 기준일 수 있지만, 수치를 바꾸지 않고 그대로 둔다.
그 대가(첫 회기 연습이 세 단계로 나뉨, 2단계 연습 문항이 지금보다 줄지 않음)는 판정에 넣지 않고 4.3절에 보고만 한다.

### 4.3 보고(판정에 쓰지 않음)

- C: 확인에서 떨어진 참 숙달자(배치 ≤ T_up인데 확인 미달로 2가 된 사람)의 비율, 확인한 사람의 비율과 낸 확인 문항 수, 확인 없이 계산한 지표가 2차 A와 같은지.
- D: 위 단계 배치 분포, 2단계를 이미 숙달한 학습자 가운데 2단계 수준 3에서 시작하는 비율, 참 T_up 2(낱말만 약함)인 학습자의 2단계 수준 배치.

## 5. 탐색에서 하나 고르는 규칙과 확인

- 후보마다 탐색 조합 가운데 그 후보의 모든 기준을 모든 조건에서 만족한 것만 남긴다. 그중 G0~G8 위 단계 최소 일치가 가장 큰 것 하나를 고른다.
  같으면 수준 일치의 최소(C는 1단계 수준, D는 두 단계 수준 모두, H1·H2 포함)가 큰 것, 그다음 평균 시간(C는 배치와 확인을 더한 시간, D는 배치 시간, 아홉 조건 평균)이 짧은 것.
- 고른 조합을 8절에 적어 커밋한 뒤 확인 시드(3절)에서 한 번만 판정한다. 남는 조합이 없는 후보는 확인을 돌리지 않고 부정 결과로 적는다.
- 확인 결과를 본 뒤 기준·조건·후보·조합을 바꾸지 않는다. 둘 다 통과하면 두 설계를 모두 적고, 확인 시간이 들지 않고 1·2단계를 건너뛰지 않는 D를 먼저 권한다.

## 6. 실행 조건

- 맥 CPU 한 대, 프로세스 6개(조건·후보·γ 단위 작업, 작업마다 OMP·OPENBLAS 스레드 1). 메모리는 작업마다 수백 MB 이하로 예상한다(합 6 GB 아래).
  조건마다 난수는 [시드, 조건 번호]로 정하고 한 조건은 한 프로세스가 차례로 돌리므로, 병렬로 나눠도 결과는 한 프로세스로 돌린 것과 같다.
- 격자를 줄이지 않는다(1·2차와 같은 2,000명, 같은 후보 문항). 유료 API·파드·AI Hub 자료·소리 파일은 쓰지 않는다.
- 결과 파일은 후보마다 상위 10개와 8절에서 인용한 조합만 전체 지표로, 나머지는 줄인 지표로 적는다(같은 코드로 다시 만들 수 있음).

## 7. 통과하면 앱에 넣을 방식, 실패하면

- 통과: 이번에는 화면·백엔드에 연결하지 않고 플래그(기본 끔) 설계만 적는다(9절 이후). 넣게 되면 1차 7절의 구조(`backend/listen_placement.py` 순수 함수,
  `/api/listen/placement/next`·`apply`, 결과 표)를 따르고, C는 '1단계 진행 중 + 1단계 시작 수준 + 2~k단계 열림 + 2단계 확인 묶음(미달이면 2단계만 열기)',
  D는 '1·2단계 진행 중 + 두 단계 시작 수준 + 3~k단계 열림'을 더한다.
- 실패: 앱에 넣지 않고 부정 결과와 배운 것을 적는다. 지금의 한 단계씩 건너뛰기는 그대로 둔다.
