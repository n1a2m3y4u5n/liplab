# 실제 영상 위 기호(J-9)와 화자 영상의 K 비음 신호(K-4), 2026-09-24

계획서 §3.10(J)은 규칙 기반 기호라서 "촬영된 실제 대화 영상에도 얹을 수 있다"는 점을 투명 두상(F) 대비 장점으로 들었고,
§3.11(K)은 K가 캐낸 신호를 J 기호를 켜는 근거로 쓰겠다고 했다(K-4). 두 가지를 AI Hub 538(OLKAVS) 화자 영상으로 확인했다.
스크립트 `liplab-lab/tools/cue_video.py`, 측정 원자료 `liplab-lab/data/k4/k4_measure.json`, 데모 페이지 `/lab/cue-video`.

## 1. 실제 영상 위 기호(J-9)

- **방법.** 음절 시각은 강제정렬(kresnik CTC, 9/24 blank 수정판)의 음절 토큰 시각이고, GPU 세션 3의 융합 검증에서
  구한 것을 그대로 쓴다. 기호는 제품의 `cue_overlay.generate_cues`(표준발음 기준)로 만들고, 입 위치는 파드에서 뽑은
  MediaPipe 입술 랜드마크(40점 중심, 입꼬리 사이 너비)로 정한다. 기호는 토큰 시각 0.05초 앞에 떠서 다음 음절 전까지,
  길어도 0.35초 보인다(`frontend/src/lib/cueVideo.js`).
- **데모 페이지.** `/lab/cue-video`는 묶음(pack.json + 영상)을 브라우저에서만 읽는다. 영상 위 입 옆에 그 순간 음절의
  기호(기식·긴장·울림)와 해당 자음을 띄우고, 아래 문장에서 음절을 누르면 그 시각으로 간다. 0.5·0.75배속을 지원한다.
  학습 화면이 아니라 연구용이라 메뉴에는 없고, 기호 없는 파일럿 집단 계정에서는 열리지 않는다.
- **확인.** 8클립(8명, 문장당 기호 24~30개)으로 재생·탐색·기호 위치를 브라우저에서 확인했다. 예: "입학했는데"의
  '했'[캔]에서 기식(ㅋ)과 울림(ㄴ)이 입 오른쪽에 함께 뜬다.
- **정렬이 맞는지(양성 대조).** 같은 시각 창(토큰 ±0.08초)으로 입에 보이는 차이를 재면 뚜렷이 갈린다. 벌린 모음(ㅏㅑ)과
  닫힌 모음(ㅣㅡ)을 jawOpen이 AUC 0.752 [0.730, 0.772], 양순 초성(ㅁㅂㅍㅃ)과 치조 초성(ㄴㄷㅌㄸ)을 입술 닫힘
  (mouthClose + roll)이 0.718 [0.680, 0.754]로 가른다(200클립). 음절 시각과 영상 시각이 어긋나 있다면 이 값이 0.5 근처로
  떨어졌을 것이다.
- **한계.** 538은 문장을 읽는 영상이라 대화 영상은 아니다. AI Hub 영상은 재배포할 수 없어 화면 캡처를 보고서나 공개 자료에
  쓸 수 없다. 공개용 화면은 팀이 직접 촬영한 영상으로 같은 절차를 밟아 만든다(아래 4절).

## 2. 화자 영상에서 K가 울림 기호를 받쳐 주나(K-4)

- **질문.** 입모양이 같은 짝(ㅁ/ㅂ·ㅍ·ㅃ, ㄴ/ㄷ·ㅌ·ㄸ, 받침 ㅇ/ㄱ·ㅋ·ㄲ)은 비음 여부로만 갈린다. 화자 영상에서 K 비음 확률이
  J가 울림 기호를 얹는 음절에서 같은 입모양 파열음 음절보다 높게 나오는가.
- **방법.** 제품 K(`models/kr_k_facecue.pt`, 제품 ONNX와 같은 가중치)를 파드 추출 blendshape에 돌려 프레임별 비음 확률을 얻고,
  음절 구간 평균을 그 발화의 중앙값과 비교했다. 비음 기대(1·0), 구간, 중앙값 규칙은 제품 K-5(`dgop.nasal_evidence_for_phones`)와
  같다. 538 30명 200클립, 음절 4,883개 중 대비가 걸린 음절 2,751개(울림 1,317, 파열음 1,434). 구간은 클립 재표집 95%.

| 비교 | AUC [95% 구간] | 음절(양성/음성) |
|---|---|---|
| 울림 기호 음절 대 같은 입모양 파열음 음절 | 0.486 [0.466, 0.508] | 1,317 / 1,434 |
| 초성만 | 0.494 [0.464, 0.524] | 519 / 1,225 |
| 받침만 | 0.453 [0.400, 0.504] | 510 / 132 |
| 양순(ㅁ 대 ㅂㅍㅃ) | 0.487 [0.427, 0.550] | 279 / 261 |
| 치조(ㄴ 대 ㄷㅌㄸ) | 0.488 [0.455, 0.523] | 779 / 417 |
| 연구개(받침 ㅇ 대 ㄱㅋㄲ) | 0.479 [0.426, 0.534] | 155 / 697 |

- 화자별 AUC는 중앙값 0.497(0.401~0.574), 30명 중 15명만 0.5를 넘었다.
- K 입력 8차원을 하나씩 써도 0.478~0.522로 모두 우연 수준이다. cheekSquint 좌우와 noseSneerRight는 이 영상에서 거의 늘 0이다.
- 같은 창으로 모음 개방과 양순 폐쇄는 0.72~0.75로 갈리므로(1절), 이 결과는 정렬 문제가 아니라 **얼굴 8차원에 음절 단위의
  비음 정보가 없다**는 뜻이다. K의 비음 AUC 0.60~0.64(`docs/k-facecue.md`)는 음향으로 만든 프레임 대리 라벨 기준이었고,
  동구형이음을 가르는 음절 수준에서는 재현되지 않았다.

## 3. 결정과 권고

- **J 기호는 문장 규칙으로만 켠다.** 학습 자료는 문장을 알고 있으므로 규칙이 정확하고, K는 기호를 켤 근거가 되지 못한다.
  데모 페이지는 K 곡선을 참고로만 보여 주고 위 결과를 함께 적는다.
- **웹캠 연습의 울림 기호(K→J, 1f9a674)는 끄거나 '실험'으로 표시하기를 권한다(결정 필요).** 학습자 본인 얼굴도 같은 종류의
  웹캠 영상이라, 지금 기호는 실제 비음 음절과 무관하게 켜질 가능성이 크다. 융합 검증에서 K-5 효과가 0.000이었던 것과 같은 방향이다.
- 비음을 얼굴에서 읽으려면 코·볼 주변 원영상 특징이나 소리 쪽 신호가 필요하다. 지금 데이터 규모에서는 재시도하지 않는다.

## 4. 재현과 자체 촬영 영상

```bash
PY=~/Downloads/liplab/backend/.venv/bin/python        # torch가 있는 환경(K .pt 추론)
cd ~/Downloads/liplab-lab
$PY tools/cue_video.py measure                         # K-4 측정 → data/k4/k4_measure.json (맥 CPU 약 30초)
$PY tools/cue_video.py pack --n 8                      # 데모 묶음 → data/cue_video_pack/
$PY tools/cue_video.py serve                           # :8765, CORS·Range 지원 정적 서버
# 브라우저: http://localhost:5173/lab/cue-video?pack=http://localhost:8765/pack.json
```

자체 촬영 영상은 두 단계다. (1) 파드에서 `extract_blendshapes.py`로 입술 랜드마크·blendshape JSON을 뽑는다(맥은 MediaPipe
blendshape가 Metal 문제로 멈춘다). (2) `cue_video.py own --video 내영상.mp4 --text "문장" --bs 내영상.json`이 음성을 강제정렬하고
(`dgop_acoustic.phone_confidences`, kresnik 적재에 메모리 약 2GB) 기호·K 곡선·입 위치를 붙여 `data/cue_video_own/pack.json`에
더한다. 이 경로는 모델 호출만 bfuse 정렬로 바꿔 끼운 시험으로 배선을 확인했다. 자체 영상은 재배포 제약이 없어 보고서와
공개 자료에 캡처를 쓸 수 있다.
