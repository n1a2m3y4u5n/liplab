## 2. 계획과 달라진 설계(보고서에 편차로 적을 것)

- **공유 백본 하나 → 축별 경량 모델과 공용 적재 서비스(A-9).** 음성구동 아바타는 백본을 WavLM으로 바꾼 것이 성능을 올렸고
  (같은 조건 r 0.610 → 0.697), 립리딩과 지각 공간은 백본보다 데이터 규모가 한계였다.
- **AV-HuBERT를 쓰지 않음.** 비상업 라이선스와 규모 문제. 입모양 쪽은 MediaPipe 계수 특징으로 대신했다.
- **자기지도 음성변환(A-2) 미실행.** 변환 목표인 실제 청각장애 발화(608)를 받지 못해 규칙 교란 합성으로 대신했다.
- **B의 불확실성 보정 항을 뺌.** 실측에서 효과가 없고 방향이 반대라 naive 채점과 표시 앵커 보정으로 바꿨다(부정 결과).
- **소리·입모양 융합의 판별력 저하.** 웹캠 입모양 점수가 문장을 가르지 못해(AUC 0.49~0.53) 섞으면 판별력이 낮아졌다.
- **C의 수작업 계수는 대체하지 않고 병행.** 규칙은 음운 유사도, 데이터는 시각 유사도로 서로 다른 것을 잰다.
- **D의 원영상 3D-CNN보다 얼굴 계수 특징이 나음.** 같은 벤치에서 7.6% 대 18.6%(900클립 규모).
- **E는 MNGU0 없이 USC-TIMIT만 사용.** MNGU0는 단일 화자라 처음 듣는 화자 평가에 보탬이 작다.
- **F는 TalkingHead 대신 자체 한국어 비심 엔진.** TalkingHead에 한국어 비심이 없다.
- **G는 신규 DB 표 대신 검수 승인 JSON 판본.** 단일 서버와 git 판본 관리로 충분하다.
- **K→J 연결은 규칙만.** 화자 영상에서 K가 울림 음절을 가르지 못했다(음절 AUC 0.486).
- **GPU는 H100 약 370시간 대신 H100 5.2시간과 A6000·RTX 3090 등 약 69시간.** 실험 규모가 수백~수천 클립이라 작은 GPU로
  충분했다. GPU 편성액의 약 10%를 썼다(`liplab-lab/notes/gpu-ledger.md`).

## 3. 2구간으로 넘어가며 풀어야 할 것

- 608 청각장애 발화: 약 3시간 끊김 없는 다운로드를 다시 할지(그림 8, A-2, A-10, 앵커 선택이 여기에 걸림).
- 팀원 정렬·채점 모델의 HF 토큰: A-3·A-4 재측정과 앱 연결(GPU 약 25분).
- D-GOP 배포 활성 방식: torch 이미지 또는 로컬 시연.
- 파일럿: 연구 윤리 절차, 보관 기간, 보호책임자, 참여 코드와 집단. 파일럿이 I 신뢰도, J 효과, C 계수 재적합의 근거가 된다.
- 자산: CC5 얼굴 2~3개(F·H), 3D 성도 모델과 TTS 구매 여부.
- 공개: 공개 자원 게시 채널과 저자 정보.
