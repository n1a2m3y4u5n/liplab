# 입모양 표 자료 기반 보정(V15 간이 경로, V3-lite): 사전 등록 (2026-10-07)

종합 계획(`docs/master-plan-2026-10.md`)의 V15·V3 갈래 가운데 신경망 없이 규칙 엔진의 목표 표(`frontend/src/lib/visemeShapes.js`)만
538 실제 화자 분포로 다시 맞추는 간이 경로다. 오늘 아침 V2 감사(`docs/avatar-validity-2026-10.md` 9~10절, 사전 등록 ccdad72)에서 기본
얼굴은 두 기준을 모두 넘지 못했다(확인 절반 RSA ρ 0.612 < LOO 하위 10백분위 0.818, 2.0배 진폭 13무리 중 1개). 원인은 ㅏ 턱 과다,
ㅣ 입꼬리 당김 과다(실제 90백분위의 약 6배), ㅗㅜ 돌출 과다, 비원순 무리의 돌출 부족(실제 중앙값 0.18~0.37), 쉼·전환의 턱 부족이었고,
V13 왕복에서 mouthClose(r 0.246, 기울기 0.06), 폭(기울기 0.55), 벌림(0.76)이 리그를 거치며 줄었다.

1~8절은 확인 절반을 재기 전에 적고 따로 커밋한다(사전 등록). 탐색 절반에서의 보정·결과는 9절, 확인 절반 결과는 10절에 덧붙인다.

## 1. 질문

1. 538 탐색 절반 화자의 무리별 분포로 목표 표를 다시 맞추면, 확인 절반에서 V2의 두 기준(거리 구조, 진폭 범위)을 넘는가.
2. 그렇게 맞춘 표가 가독성(나1)을 잃지 않는가. 양순 닫힘, 원순 돌출, 무리별 구별성을 지금 표와 같은 문장에서 비교한다.
3. CC 두상에서 mouthClose가 거의 전달되지 않는 까닭은 무엇이고, 음성 구동·거울 경로(`bsFrameRef`)에서 보정할 수 있는가(V13 재측정).

## 2. 자료와 절반

- 실제 화자: V2와 같은 선택(`liplab-lab/data/v2_avatar/sel.json`, sha256 3f73ba0b…), 75명 900클립. 절반 0(37명)은 탐색, 절반 1(38명)은
  확인이다(`crc32(화자 ID) % 2`). MediaPipe 추출과 CTC 정렬은 V2에서 만든 파일을 그대로 쓴다(`pod_runs/20261006_oel3rwn7y5zjbv/v2_part2/out/`).
  측정기(mediapipe 0.10.14, `face_landmarker.task` float16/1, VIDEO 모드), 구간 규칙(66ms 앞당김, 구간 뒤쪽 절반 평균), 품질 기준,
  특징(RSA 13개, J·R·S·C·G)은 V2 4~5절과 같다. 분석 코드는 `scripts/v2_avatar_validity.py`를 그대로 쓰고, 이번에 더하는 지표(6.3의
  구별성)만 새 스크립트에 둔다.
- 아바타 문장: V2의 기본 얼굴 문장(절반마다 화자당 앞 4문장, 탐색 151·확인 162클립)과 가상 화자 문장(앞 2문장). 렌더 하네스
  (`scripts/v2_render`)와 카메라·조명·시계도 V2와 같다.
- **보정에는 탐색 절반만 쓴다.** 실제 화자 분포는 절반 0의 화자만, 아바타 쪽 학습 자료(아래 3절의 순방향 사상)는 정지 자세 스윕,
  탐색 절반 문장의 V2 렌더, 탐색 절반 V13 클립만 쓴다. 확인 절반의 실제 화자 값과 확인 문장 렌더의 측정값은 10절 판정 전까지 보지 않는다.
  V2 10절의 확인 절반 집계(ρ 0.612 등)는 이미 공개된 값이라 원인 진단(위 문단)에만 썼다.

## 3. 보정 방법(탐색 절반 안에서 자유롭게 고친다)

- **리그 측정(정지 자세 스윕).** 파드에서 하네스로 정지 자세를 렌더하고(자세마다 3장, 마지막 장을 쓴다) 같은 MediaPipe로 잰다.
  (a) 턱 각도 × mouthClose 격자, (b) mouthPress·mouthRoll·mouthShrug와 턱의 조합, (c) 슬림 전 원본 GLB(git 9f08043)의 CC 입술 모프
  (`Mouth_Lips_Jaw_Adjust`, `V_Explosive`, `Mouth_Plosive`, `Mouth_Lips_Tight` 등)와 턱의 조합, (d) 표가 쓸 수 있는 ARKit 모프 13종의
  무작위 조합(수천 자세).
- **왕복 관계(순방향 사상).** 모프 가중치와 턱 각도에서 MediaPipe 특징(RSA 13개와 G)으로 가는 사상을 (d)·탐색 V2 렌더·탐색 V13
  클립으로 학습한다(회귀 모형, 문장 단위로 나눠 검증). 앱 렌더의 모프 궤적은 하네스의 화면마다 계산(전환 이징, 프레임 길이 60% 안,
  가상 화자 배율)을 파이썬으로 옮겨 다시 만들고, 렌더 일정이 하네스 기록과 같은지 확인한다.
- **목표.** 탐색 절반 실제 화자의 무리별 중앙값이다. 진폭 채널(벌림 J, 돌출 R, 폭 S)은 V2와 같이 바닥값(발화 구간 5백분위)을 뺀 값으로
  맞추고, 비원순 무리에는 실제 화자처럼 기본 돌출을 둔다. RSA 특징은 화자 안 z 점수의 무리별 평균 모양을 맞춘다. 아바타는 렌더마다
  얼굴·자세가 같아 바닥값이 가장 낮은 정지 목표에 붙으므로, 시뮬레이션으로 바닥값까지 함께 계산해 맞춘다.
- **표의 형식은 그대로 둔다.** 무리마다 ARKit 모프 가중치(0~1)이고 `jawOpen`은 턱 뼈 각도다. 혀 표, 엔진 프레임, 전환 시간,
  선행 동시조음(끔)은 바꾸지 않는다. 양순 1·양순 전환 11은 입술을 닫는 자세로 남긴다.
- **탐색 확인.** 후보 표를 탐색 문장으로 실제 렌더하고 V2 분석으로 탐색 절반 지표를 잰다. 필요하면 고쳐 다시 렌더한다(횟수 제한 없음,
  모두 9절에 적는다).
- **동결.** 확인 절반을 재기 전에 최종 표(`scripts/data/viseme_v15.json`과 그 JS 판)를 커밋하고 sha256을 9절에 적는다. 확인 절반은 그
  표로 한 번만 렌더·측정한다. 탐색 절반에서 기준을 못 넘어도 확인은 한 번 하고 결과를 그대로 보고한다.

## 4. 앱 적용 방식

- 새 표는 `visemeShapes.js` 안에 지금 표와 나란히 둔다. 확인 판정(6절)을 모두 넘으면 새 표를 기본으로 하고 지금 표는 기록으로 남긴다.
  하나라도 못 넘으면 지금 표가 기본으로 남고, 새 표는 빌드 플래그 `VITE_VISEME_V15=1`일 때만 쓴다(선행 동시조음 `VITE_COART_E`와 같은 방식).
- 리그 보정(5절)은 음성 구동·거울 경로에만 들어가며, 탐색 V13 기준을 넘을 때만 넣는다.
- 가상 화자 6명(7절)은 배율로 남긴다. 판별 기준 단위 테스트(`talkers.test.mjs`, 문서 `talker-variation.md` 7·8절)를 새 표로도 통과해야 한다.

## 5. 리그(mouthClose) 보정과 V13 재측정

- 2절 (a)~(c)로 mouthClose가 MediaPipe에 안 잡히는 이유(모프 이름, 턱 뼈와의 상호작용, 입술 압착 모프의 효과)를 적는다.
- 건전한 보정 사상이 있으면(예: 원본 52계수 → 아바타 모프의 선형 사상, 채널 이득) `AvatarVRM`의 `bsFrameRef`·거울 경로에 넣고,
  탐색 절반 V13 클립(`sel.json`의 `v13_clips` 중 절반 0, 74개)을 그 사상으로 다시 렌더해 V2 6.3절의 왕복 r을 잰다.
- **채택: 탐색 V13에서 mouthClose r 중앙값이 0.10 이상 오르고, 다른 채널(jawOpen, R, S)의 r 중앙값이 0.02 넘게 떨어지지 않을 것.**
  확인 절반 V13 클립(76개)도 같은 사상으로 재서 보고만 한다.

## 6. 판정 기준(확인 절반, 한 번)

모두 기본 얼굴, 같은 확인 문장(162클립)이다. 지금 표의 값은 V2 렌더(`pod_runs/20261007_czde54612e5kcu/v2_final/`)를 쓴다.

### 6.1 V2-1 거리 구조(RSA)

V2 6.1절 그대로. **1.0배 ρ가 확인 절반 실제 화자 LOO 분포의 하위 10백분위(V2에서 0.818, 13무리가 모두 찬 31명) 이상.**

### 6.2 V2-2 진폭 범위

V2 6.2절 그대로. **2.0배(실제 말 속도에 맞춘 속도)에서 13무리 중 11개 이상의 스칼라 진폭 A가 확인 절반 실제 화자 10~90백분위 안.**

### 6.3 가독성 비열등(나1)

1.0배와 2.0배 각각에서 모두 넘어야 한다.

- **양순 닫힘:** 무리 1(ㅁ·ㅂ·ㅍ) 구간의 안쪽 입술 간격 최소값(G, 눈꼬리 거리로 나눔)이 확인 절반 실제 양순 구간 90백분위 이하인 비율 ≥ 95%
  (V2 `legibility.bilabial_closure_rate`).
- **원순 돌출:** 무리 4(ㅗ·ㅜ) 구간의 돌출 R(바닥값 뺀 값)이 확인 절반 실제 구간 10~90백분위 안인 비율 ≥ 80%
  (V2 `legibility.rounded_R_in_range_rate`).
- **무리별 구별성:** 조건마다 구간 값(RSA 특징 13개)을 그 조건 전체 구간의 평균·표준편차로 z 점수화하고(표준편차 1e-4 미만인 특징은 0),
  구간마다 자기 문장을 뺀 나머지 구간으로 만든 무리 중심 가운데 가장 가까운 것(유클리드)으로 분류한다. 무리별 재현율(자기 무리로 분류된
  비율)을 구별성으로 본다. **13무리 모두에서 새 표의 재현율 ≥ 지금 표의 재현율 − 0.05.** 같은 문장, 같은 속도끼리 비교한다.

### 6.4 결정

- 6.1, 6.2, 6.3을 모두 넘으면 새 표를 앱 기본으로 한다.
- 하나라도 못 넘으면 지금 표가 기본으로 남고, 새 표는 `VITE_VISEME_V15=1` 뒤에 둔다. 결과는 부정 결과로 그대로 적는다
  (어느 기준을 얼마나 못 넘었는지, 탐색 절반과 어떻게 달랐는지).

### 6.5 보고만 하는 것

- 탐색 절반의 같은 값(보정에 쓴 자료라 낙관적이다), 확인 절반 1.0배 진폭, 채널별(J·R·S·C·G) 범위 안 무리 수, ㅏ 벌림 백분위,
  RSA에서 가장 어긋난 무리 쌍.
- 가상 화자 6명(7절) 1.0배·2.0배의 RSA ρ와 진폭 범위 안 무리 수(확인 절반 문장, 앞 2문장).
- 확인 V13(5절).

## 7. 가상 화자 재선정(V5, 보고만)

- 탐색 절반 실제 화자마다 채널별 배율(무리별 진폭을 탐색 화자 중앙값으로 나눈 값의 무리 사이 중앙값, J·R·S)과 음절 속도 배율(화자 음절
  속도 / 탐색 중앙값)을 구한다. 가상 화자 매개변수는 이 배율의 탐색 10~90백분위 안에서, 순방향 사상으로 모프 배율로 옮겨 고른다.
  검사 전용 화자 5·6은 분포 안에서 훈련 화자와 다른 점이 되게 고른다(종합 계획 V5).
- 판별 기준 단위 테스트(a)~(d)를 통과해야 한다. 걸리면 4절 규칙(`talker-variation.md` 4·7절)으로 줄인다.
- 확인 절반에서 가상 화자 렌더의 지표를 보고만 한다(판정에 쓰지 않는다).

- 파드: RunPod A40·A6000·L40S SECURE, 워치독은 예상 작업 시간 + 45분, 이번 세션 지출 상한 10달러. 사용자 회선이 잠깐씩 끊기므로
  작업은 파드에서 분리 실행하고, 맥은 재시도하며 확인하고, 결과는 단계마다 나눠 받는다. 끝나면 종료하고 API로 남은 파드가 없음을 확인한다.

- 확인 절반을 잰 뒤 분석 규칙을 바꾸면 10절에 '사후 변경'으로 따로 적고 판정은 등록 규칙으로 한다.

  6.3의 구별성은 같은 측정기 공간에서의 분리도이며 사람의 판독 정확도를 대신하지 않는다.
