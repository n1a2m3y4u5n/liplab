# 화자 단위 발음 지수와 기계 전사 오류율(S20, 2026-10-09, 측정 전 사전 등록)

종합 계획 `docs/master-plan-2026-10.md`의 S20(아이디어 가8, `docs/idea-sweep-2026-10-03.md` 4절)이다. 1~8절은 특성과 전사를 계산하기 전에 적고
따로 커밋한다. 탐색 절반(절반 0)에서 정한 식은 9절에 따로 커밋한 뒤 확인 절반(절반 1)을 연다. 결과는 10절 뒤에 붙인다. 측정 전에 바꾼 것이
있으면 8.3절에만 덧붙인다.

## 1. 질문과 이름 규칙

- 말하기 훈련의 결과는 문장 하나의 합격 여부보다 학습자 발음의 주 단위 추세다. 문장 채점에 이미 쓰는 음향 정보(D-GOP 음소 점수, 정렬 시각,
  파형)로 화자 단위 지수를 만들고, 그 지수가 화자의 기계 전사 오류율(CER)과 함께 움직이는지 본다.
- 계획의 판정 기준(가8): 608 화자 절반 0에서 식을 맞추고, 절반 1에서 CER 대리 목표와 스피어만 ρ ≥ 0.6. 사람 받아쓰기 라벨(P5)로 ρ ≥ 0.5일
  때만 '명료도 추정'이라는 이름을 쓴다.
- **P5 라벨의 상태.** P5는 계획 트랙 P의 '명료도 받아쓰기 라벨(608 청취는 AI Hub 확인 뒤)'이다(`docs/master-plan-2026-10.md` 118행, 판정 기준
  '청자 간 ICC, D-GOP와 ρ ≥ 0.5'). 10/6 관리자 확인으로 팀원 청취는 허용되었지만, 2026-10-09 현재 저장소와 lab 어디에도 P5 받아쓰기 라벨은 없다.
- **이름 규칙(미리 정함).** P5 라벨이 없으므로 이번 결과는 통과하더라도 '명료도 추정'이라고 부르지 않는다. 지수 이름은 '화자 발음 지수(전사 대리)'로
  하고, 명칭 판정은 '판정 불가(P5 없음)'로 적는다. 통과는 '기계 전사 오류율의 대리 지표로서 통과'라는 뜻으로만 쓴다. P5 라벨이 생기면 이 문서의
  9절 식을 고정한 채로 사람 받아쓰기 정확도와 ρ ≥ 0.5를 따로 판정한다.

## 3. CER 대리 목표

- **주 목표 T1.** 조각마다 faster-whisper large-v3(GPU float16, 한국어 고정, 빔 5, 온도 0, vad_filter 없음, condition_on_previous_text 끔,
  초기 프롬프트 없음)로 따로 전사한다. 대본과 전사에서 한글·숫자·영문(소문자)만 남기고 나머지(띄어쓰기, 문장부호)를 지운 뒤
  조각 CER = 글자 편집 거리 / 대본 길이, 1.0을 넘으면 1.0으로 자른다(반복 환각 한 조각이 화자 평균을 지배하지 않게).
  화자 CER = 그 화자 조각 CER의 평균(조각마다 같은 무게).
- 이 인식기는 지수의 어떤 특성에도 쓰이지 않는다(특성은 자체 정렬기·채점기와 파형에서 낸다). 계획 가8이 정한 대리 목표다.
- 보고만:
  - T1p: 합친 CER(화자 편집 거리 합 / 대본 길이 합).
  - T2: 앱 전사 설정(faster-whisper base, CPU int8, 빔 1, 온도 0, vad 없음)의 화자 CER.
  - T3: 자르기 합격 비율. 세션 라벨 문장 가운데 large-v3 세션 전사와 일치율 0.5 이상으로 잘린 문장의 비율(O는 10/6 `cuts608.json`, N은 KSC
    `pod_out/cuts608.json`). 아래 한계 때문에 보는 값이다.
- **선택 치우침(미리 적는 한계).** 두 묶음의 조각은 모두 large-v3 세션 전사가 대본과 일치율 0.5 이상인 문장만 남긴 것이다. 그래서 알아듣기 어려운
  문장일수록 빠져 T1의 범위가 위쪽에서 잘린다. N의 자르기 합격 비율은 화자마다 0.1~1.0으로 크게 다르다(KSC 자르기 기록에서 센 값, CER은 아직
  보지 않았다). T1과 T3이 같은 방향인지 보고하고, 해석에 반영한다.

## 4. 후보 특성(조각 단위로 내고 화자 평균)

모두 지금 통합 브랜치의 backend(`integrate/2026-09-23` a57ee690, 끝 무음 자르기 포함)로 낸다. D-GOP는 앱 경로 그대로
`dgop_acoustic.assess_text`(자체 정렬기·채점기 int8, sha256 `18681947…`, `e8340d58…`, CPU)를 자기 대본 문장으로 부른다.

| 기호 | 정의 | 예상 방향(CER과) |
|---|---|---|
| Fc | 자음 D-GOP 정확 비율. 정렬된 채점 대상 토큰 가운데 o:·c: 토큰(silent_h 표시 제외)의 dgop ≥ 0.5 비율 | 음(−) |
| Fv | 모음 D-GOP 정확 비율. 같은 방식으로 n: 토큰 | 음(−) |
| FCR | 모음 중앙화 비(Sapir 등 2010) = (F2ㅜ + F2ㅏ + F1ㅣ + F1ㅜ) / (F2ㅣ + F1ㅏ). 화자마다 모음별 F1·F2 중앙값으로 계산 | 양(+) |
| Rate | 초당 음절(`speak_cues.rate_pause`의 rate, S7 지표) | 음(−) |
| (보고) Fs | D-GOP 문장 원점수(raw_score) 평균. 지금 앱 채점과 같은 값이라 비교 기준으로 쓴다 | 음(−) |
| (보고) VSA | 모음 삼각형 넓이(Hz², ㅏ·ㅣ·ㅜ) | 음(−) |

- **포먼트 측정.** 정렬기의 n:ㅏ, n:ㅣ, n:ㅜ 토큰(앞에 반모음이 붙은 이중모음은 토큰이 달라 자연히 빠진다)마다 창 [t0, min(t0 + 0.10초, 다음 정렬 토큰의 t0)]
  을 연다. 창이 0.03초보다 짧으면 뺀다. Praat Burg(parselmouth 0.4.7, 측정용으로만, 앱에는 넣지 않는다: GPL), 시간 간격 5ms, 포먼트 5개,
  최대 포먼트 남성 5,000Hz·여성 5,500Hz(세션 파일 이름의 성별), 창 25ms, 프리엠퍼시스 50Hz. 창 안 프레임의 F1·F2 중앙값을 그 토큰 값으로 하고,
  F1이 150~1,200Hz, F2가 500~3,500Hz 밖이면 뺀다. 화자마다 모음별 토큰이 3개 이상이어야 FCR을 낸다.
- **포먼트 측정 타당성 관문(CER을 보지 않는 확인, 모든 화자).** 화자 모음 중앙값에서 F1ㅏ > F1ㅣ, F1ㅏ > F1ㅜ, F2ㅣ > F2ㅜ, F2ㅣ > F2ㅏ를 모두 만족하는
  화자가 80% 미만이면 FCR은 '측정 타당성 미달'로 적고 지수에서 뺀다(VSA도 보고하지 않는다). 538이 아닌 608 낭독에서 정렬 점으로 연 창이라
  측정 자체가 틀릴 수 있어서다.
- **VOT는 넣지 않는다.** S6(`docs/speak-visual-cues.md` 7절)에서 정렬 점 기준 VOT·기식 길이는 정상 화자 538에서도 거센소리와 예사소리를 가르지
  못했다(확인 절반 AUC 0.59, 수정 지표 탐색 0.52). 측정 타당성이 없는 값을 화자 차로 쓰면 잡음만 더하므로, 계획 표의 'VOT'는 이번 지수 후보에서
  뺀다. 정렬 점과 무관한 파열 검출이 생기면 새로 등록한다.
- 화자 값 = 조각 값의 평균(Fc·Fv·Rate·Fs). Rate가 없는 조각(음절 3개 미만 등)은 빼고, Rate 조각이 3개 미만인 화자는 Rate 결측. FCR·Rate 결측은
  표준화 뒤 0(절반 0 평균)으로 채우고 수를 적는다.

## 5. 지수 식(절반 0에서 맞춘다)

- 표준화: 특성마다 절반 0 화자 값의 평균·표준편차로 z를 낸다. 방향을 미리 정한 대로 맞춰 '클수록 나쁨'이 되게 한다: z(−Fc), z(−Fv), z(FCR), z(−Rate).
- **주 식 M1(부호 제약 최소제곱).** 절반 0의 20명에서 T1(절반 0 평균을 뺀 값)을 위 네 z로 회귀하되 가중치 ≥ 0(scipy.optimize.nnls, 절편은 평균
  빼기로 처리). 지수 = Σ wₖ zₖ. 가중치가 모두 0이면 지수가 정의되지 않으므로 실패로 적는다. 예상과 반대 방향으로 움직이는 특성은 가중치 0이 되어
  자연히 빠진다.
- 보고만: M0(네 z의 같은 무게 평균), 단일 특성 각각, Fs 단독, 절반을 바꾼 교차(절반 1에서 맞추고 절반 0에서 확인), 33명 화자 하나 빼기 교차 검증.
- 절반 0에서 정한 값(평균·표준편차, 가중치, 결측 수, 포먼트 관문 결과)은 9절에 표와 JSON(sha256 앞 16자)으로 커밋한 뒤 절반 1을 연다.

## 6. 녹음 조건 차 통제(S24 교훈)

S24에서는 608과 538의 녹음 조건 차(잡음 바닥 608 −53dB, 538 −22dB)가 집단 차처럼 보였다. 이번 비교는 608 안에서만 하지만, O와 N은 받은 시기와
세션 구성이 다르고 화자마다 녹음 장소가 다를 수 있다. 녹음 조건이 CER과 특성을 함께 움직이면 지수와 CER의 상관이 녹음 조건을 통해 생길 수 있다.

- 조각마다 잡음 바닥 NF = 25ms 창·10ms 간격 RMS(dB)의 10백분위 − 최댓값(S24와 같은 정의), 신호 대 바닥 폭 SNRp = 95백분위 − 10백분위를 잰다. 화자 평균.
- 판정에 쓰는 통제: 절반 1에서 지수와 T1의 편 스피어만 상관(순위로 바꾼 지수·T1을 순위 NF와 묶음 표시(O=0, N=1)에 각각 최소제곱 회귀한 잔차의
  피어슨 상관). 이것을 ρ_partial로 적는다.
- 보고만: ρ(NF, T1), ρ(NF, 지수), ρ(SNRp, T1), O 대 N의 NF 차(AUC), 묶음 안 ρ(O 절반 1 8명, N 절반 1 5명), 대본 문장 길이(음절)의 화자 평균과
  T1·지수의 ρ(문장 난이도가 화자마다 다르다).

## 7. 판정 기준(절반 1, 13명)

- **C1:** ρ(지수 M1, T1) ≥ 0.60(점추정).
- **C2:** ρ_partial ≥ 0.50.
- **통과 = C1과 C2.** C1만 넘고 C2를 못 넘으면 '판정 보류(녹음 조건 차를 배제하지 못함)'로 적는다. C1 미달이면 실패(부정 결과)다.
- 구간: 절반 1 화자 부트스트랩 2,000회(시드 0, 화자를 복원 추출)의 95% 백분위 구간을 ρ와 ρ_partial에 붙인다. 구간 하한이 기준 아래이면 판정 옆에
  '여유 작음'을 적는다(S5~S7과 같은 표기). 13명에서는 하한이 기준을 넘기 어렵다는 것을 미리 적는다.
- 보고: M0·단일 특성·Fs 단독의 절반 1 ρ와 구간, M1 − Fs 단독의 ρ 차와 구간, T1p·T2·T3에 대한 같은 ρ.
- 해석 규칙(미리 정함): M1이 통과해도 Fs 단독의 ρ가 0.60 이상이고 ρ 차 구간이 0을 포함하면, 앱 제안은 새 지수가 아니라 지금 문장 점수의 화자
  평균을 쓰는 쪽으로 한다(더 단순하고 이미 계산되는 값).
- 명칭: 1절 규칙대로 '판정 불가(P5 없음)'.

## 8. 앱 반영, 실행, 한계

### 8.1 앱

### 10.5 앱 반영(2026-10-09 밤, 사용자 지시, 배포 안 함)

10.4절 첫째·둘째 제안을 분석 탭에 넣었다(브랜치 easykorean-listen-trend-2026-10).

- **서버**: `analytics.speak_sentence_weekly`(순수 함수)가 말하기 문장 점수의 주 평균을 낸다. 창은 기존 주별 추이(`weekly`)와 같은 오늘로 끝나는
  7일 창 7개이고, 문장이 `SPEAK_TREND_MIN_N` = 5개보다 적은 주는 평균을 비운다(n은 그대로 낸다). `GET /api/analysis/overview`가
  `speak_trend: {weeks: [{start, n, mean}], min_n, n}`으로 싣는다. 재료는 기존 `speak_attempts` 행이고 새 저장 필드는 없다
  (`main._speak_sentence_points`): 말하기 문장 단계(mode 'sentence') 시도만, 점수는 입모양을 섞기 전 음향 점수(`audio_score`, 없으면 `score`),
  소리가 잡히지 않은 시도는 개인 향상 경로와 같은 기준(`speak_curriculum.voiced_attempt`)으로 뺀다. 확인 시도(mode 'probe')와 낱말·음소 단계는 넣지 않는다.
  기존 정확도 추이·지난주 대비·합격·숙달 계산은 바뀌지 않는다.
- **화면**: 분석 탭 '정확도 변화' 아래에 '말하기 문장 점수' 칸(제목 옆 '참고 · 기계 채점 기준', 말하기 분홍 선)을 두고, 아래에
  "주마다 말하기 문장 점수를 평균했어요. 기계가 매긴 점수라 참고로만 보고, 단계 통과와 숙달에는 쓰지 않아요. 문장이 5개보다 적은 주는 비워 둬요."를
  적었다. 평균이 없는 주는 점을 두지 않고 선을 끊는다. 지난 7주에 말하기 문장 기록이 없으면 칸을 그리지 않는다. 화면에 '명료도'는 쓰지 않는다.
  계산은 `frontend/src/lib/speakTrend.js`.
- **테스트**: `backend/test_speak_trend.py`(창·5문장 미만·시간대·0~100 자르기·overview 칸, 임시 DB로 API 경로에서 낱말·확인·무음 제외와 음향 점수
  사용), `frontend/src/lib/speakTrend.test.mjs`.
- **한계**: S20의 Fs는 D-GOP 원점수(raw_score) 평균이고, 앱에 남는 점수는 표시용 보정 점수다. 보정이 단조라 화자 순위는 거의 같겠지만 평균의 순위가
  꼭 같지는 않다. D-GOP를 끈 배포에서는 전사 경로 점수가 들어오고, 시도마다 채점 방식을 저장하지 않아 둘을 가를 수 없다. 앱 녹음에서 같은
  관계가 서는지, 주 단위 평균의 흔들림(SEM)이 얼마인지는 아직 측정하지 않았다(10.4절 남은 일).
