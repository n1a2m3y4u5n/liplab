> 확정일 2026-09-08. 대상: `backend/dgop.py`·`dgop_acoustic.py`가 쓰는 CTC 음향 모델.
> 실행 환경: RunPod H100. 부트스트랩 데이터: Zeroth-Korean.
> 관련 문서: `DEVELOPMENT_SUMMARY.md`(축 A~K 현황), `docs/lipreading-data-research.md`(축 D 데이터)

## 0. 왜 계획서 원안을 바꾸는가

계획서 3.1과 `deaf_speech_synthesis.py` docstring은 축 A를 **"정상 발화에 조음 교란을
적용한 합성 코퍼스로 한국어 체크포인트를 미세조정"** 으로 적어 두었다. 그대로 하면
D-GOP의 변별력이 사라진다.

`dgop.py`의 점수는 `naive × confidence`이고, 뭉갠 발화에서 분포가 평평해져 confidence가
떨어지는 것 자체가 **"발음이 부정확하다"는 신호**다. 실측:

| 발화 상태 | naive(표준 GOP) | confidence | D-GOP |
|---|---|---|---|
| 또렷한 발화 | 0.85 | 0.461 | 0.392 |
| 약간 뭉갬 | 0.55 | 0.055 | 0.030 |
| 심하게 뭉갬 | 0.30 | 0.0002 | 0.0001 |

여기서 모델을 "농인 발화에 강인하게" 만들면 뭉갠 발화에도 분포가 뾰족해지고, confidence가
올라가고, **점수가 높아진다.** 발음 교정 앱인데 뭉개도 만점이 나온다.

GOP 계열은 원래 canonical(정상 발화) 모델로 재야 의미가 있는 지표다. 그래서 모델을 둘로 나눈다.

## 1. 목표

> **자모 단위 D-GOP를 낼 수 있는 채점기(Scorer)와, 뭉갠 발화에서도 구간을 놓치지 않는
> 정렬기(Aligner) 두 개를 만든다.**

| | Scorer (채점기) | Aligner (정렬기) |
|---|---|---|
| 학습 데이터 | Zeroth 정상 발화만 | Scorer에서 이어받아 합성 저하 증강 |
| 역할 | 구간별 사후확률 → D-GOP | `forced_align`으로 음소 구간 탐색 |
| 뭉갠 발화에 | **일부러 약해야 함**(그게 점수 신호) | 강인해야 함 |
| vocab | 공유 | 공유 |

`dgop_acoustic.assess_text(model_id=...)`가 `aligner_id`/`scorer_id`로 갈라진다.

## 2. vocab — 위치 구분 69토큰

`kresnik/wav2vec2-large-xlsr-korean`의 기존 vocab은 **한글 음절 단위 1,205토큰**이라
`dgop.py`가 설계한 음소별 D-GOP가 나오지 않는다(B.6에서 발견한 한계). 어차피 학습할 거면
encoder는 두고 `lm_head`만 자모 vocab으로 교체하면 이 한계가 함께 풀린다.

**확정: 49토큰** (`backend/jamo_vocab.py`). 처음에 69로 잡았으나 실측 후 줄었다 —
라벨이 `phonetic=True`를 거치면서 평파열음화로 **종성이 표준발음법 7종성(ㄱㄴㄷㄹㅁㅂㅇ)으로
수렴**하기 때문이다. 겹받침·ㅅ·ㅊ 종성은 아예 나타나지 않는다.

| 구성 | 개수 | 비고 |
|---|---|---|
| 특수 | 3 | `<pad>`(CTC blank, id 0) · `<unk>` · `\|`(어절 경계) |
| 초성 | 18 | 무음 ㅇ 제외 — 토큰을 만들지 않고 중성만 남긴다 |
| 중성 | 21 | 단모음·이중모음 전체 |
| 종성 | 7 | 평파열음화가 수렴시킨 대표음 |
| **합계** | **49** | |

**위치 구분**을 쓴다 — 초성 ㄱ(파열)과 종성 ㄱ(미파열 [k̚])은 다른 소리라 `o:ㄱ`/`c:ㄱ`로
나눈다. 덕분에 '종성 발음'만 따로 채점할 수 있어 발성 교육에 직결된다.

1,205 → 49가 되면 D-GOP 엔트로피 신호 자체가 안정된다(지금은 롱테일 1,200여 클래스가
`normalized_entropy`를 지배해 '분포가 평평하다'는 신호가 흐려진다).

`<pad>`를 id 0에 두는 것은 `dgop_acoustic.align_targets`의 기본 `blank_token`과 맞추기 위함이다.

## 3. 선결 과제 — 발음 규칙 (⚠️ 최우선)

CTC 라벨은 **실제로 소리 난 것**과 일치해야 한다. 어긋나면 학습 전체가 오염된다.
`engine.to_pronounced_syllables()`가 연음·구개음화·격음화·겹받침·ㅎ탈락은 처리하지만,
2026-09-08 실측 결과 **네 개 규칙 계열이 통째로 빠져 있다**:

| 입력 | 현재 출력 | 기대 | 빠진 규칙 |
|---|---|---|---|
| 옷 | ㅗㅅ | 옫 | 평파열음화(음절 끝소리 규칙) |
| 꽃 | ㄲㅗㅊ | 꼳 | 평파열음화 |
| 앞 | ㅏㅍ | 압 | 평파열음화 |
| 국물 | ㄱㅜㄱ ㅁㅜㄹ | 궁물 | 비음화 |
| 닫는 | ㄷㅏㄷ ㄴㅡㄴ | 단는 | 비음화 |
| 밥물 | ㅂㅏㅂ ㅁㅜㄹ | 밤물 | 비음화 |
| 신라 | ㅅㅣㄴ ㄹㅏ | 실라 | 유음화 |
| 설날 | ㅅㅓㄹ ㄴㅏㄹ | 설랄 | 유음화 |
| 학교 | ㅎㅏㄱ ㄱㅛ | 학꾜 | 경음화 |
| 있다 | ㅣㅆ ㄷㅏ | 읻따 | 평파열음화 + 경음화 |

적용 순서가 있다: **평파열음화 → 비음화 → 유음화 → 경음화**. 비음화는 대표음(ㄱ/ㄷ/ㅂ)을
전제하므로 평파열음화가 먼저 돌아야 한다(밭만 → 받만 → 반만).

이 함수는 아바타 입모양 엔진과 채점이 공유하므로, 고치면 **앱 전체 발음 정확도도 함께 오른다**.
viseme이 실제로 바뀌는 경우는 종성 ㅊ/ㅈ → ㄷ(10→6)과 비음화 종성 ㄱ → ㅇ 정도다.

## 4. 학습 로드맵

| 단계 | 내용 | H100 | 비용 |
|---|---|---|---|
| **A-0 스모크** | 30분 subset으로 데이터로더→학습→저장 왕복. **여기서 실제 처리량 실측** | ~1h | ~$3 |
| **A-1 Scorer** | Zeroth 51.6h. ① encoder freeze·head만 2~3ep ② 전체 unfreeze·low LR 10~12ep | ~13h | ~$35 |
| **A-2 Aligner** | A-1에서 시작, `deaf_speech_synthesis`로 on-the-fly severity 0~4 증강 | ~4h | ~$10 |
| **A-3 평가·연결** | 변별력 지표 측정 + `assess_text` 배선 | ~1h | ~$3 |

**총 ~$50.** 시간은 RTF 60x 가정한 추정이라 A-0에서 실측 후 확정한다.

- A-1을 2스테이지로 나누는 이유: 랜덤 초기화된 새 `lm_head`가 처음부터 full backprop을 타면
  사전학습 encoder를 망가뜨린다. CNN feature extractor는 전 구간 freeze(표준).
- A-2에서 **severity 0을 반드시 섞는다** — 저하 발화만 보면 정상 발화 정렬 능력을 잃는다.

## 5. 평가 지표 — WER이 아니다

축 A의 성패는 인식률이 아니라 **점수의 변별력**이다.

| 지표 | 목표 | 의미 |
|---|---|---|
| **단조성** (Spearman ρ) | ≥ 0.9 | severity 0→4에서 D-GOP가 단조 감소하는가 |
| **분리도** (AUC) | ≥ 0.85 | 정상 vs severity 3+ 점수 분포가 갈리는가 |
| **정렬 견고성** | severity 4에서 aligned ≥ 95% | Aligner가 제 역할을 하는가 |
| CER (Zeroth test 1.2h) | 참고용 | Scorer sanity check |

1·2번이 진짜 합격선이다. `dgop.py`가 순수 함수라 결정론적으로 측정된다.

| 항목 | 값 |

| 출처 | **`kresnik/zeroth_korean`** (Hugging Face, parquet) — 원본은 OpenSLR 40 |
| 규모 | 학습 51.6시간 22,263발화 105명 / 테스트 1.2시간 457발화 10명 |
| 스키마 | `audio`(16kHz) · `text` · `id` · `speaker_id` · `chapter_id` · `path` |
| 라이선스 | **CC BY 4.0** (인증·가입 불필요, 2026-09-08 확인) |

원본 `zeroth_korean.tar.gz`(9.6GB) 대신 HF parquet 배포판을 쓴다. **우리가 미세조정할
베이스 체크포인트 `kresnik/wav2vec2-large-xlsr-korean`과 같은 저자**의 정리본이라
tar 레이아웃을 추측할 필요가 없고 `load_dataset` 한 줄로 끝난다.

**라벨 사전점검 결과(실제 전사 500문장, 2026-09-08)**

| 점검 | 결과 |
|---|---|
| OOV | **0건** — 49토큰이 전부 커버 |
| 비한글 문자 | **없음** — 구두점·숫자·로마자 전무, 텍스트 정규화 불필요 |
| 라벨 길이 | 최소 51 / 중앙 103 / 최대 200 토큰 |

⚠️ **CTC 길이 제약** — 출력 프레임 수(≈50fps)가 라벨 길이보다 짧으면 손실이 inf가 되어
학습이 망가진다. 중앙 103토큰이면 최소 2.1초, 최대 200토큰이면 4초가 필요하다.
`scripts/prepare_zeroth_labels.py --check-duration`으로 전수 확인하고,
`train_jamo_ctc.py`가 학습 직전에 위반 표본을 자동 제외한다.

OLKAVS(AI Hub, 음성 1,150h)는 본인인증·TB급 다운로드가 필요해 부트스트랩에 쓰지 않는다.
도착하면 A-1을 더 큰 데이터로 재학습하는 선택지로 둔다(`scripts/preprocess_olkavs.py --mode audio`).

RunPod을 켜기 전에 여기까지 끝내야 GPU 시간을 태우지 않는다.

| # | 작업 | 산출물 | 상태 |
|---|---|---|---|
| 1 | §3의 네 규칙을 `phonetic=True` 모드로 추가 | `backend/engine.py`, `backend/scoring.py`, `test_phonetic_rules.py` | ✅ 14/14 통과 |
| 2 | 자모 CTC vocab | `backend/jamo_vocab.py`, `test_jamo_vocab.py` | ✅ 49토큰, OOV 0건 |
| 3 | Zeroth 라벨 사전점검·변환 | `scripts/prepare_zeroth_labels.py` | ✅ 실전사 500문장 검증 |
| 4 | A-1 학습 스크립트 + CPU 형상 검증 | `scripts/train_jamo_ctc.py --smoke` | ✅ 합성 파형 1 step 통과 |
| 5 | A-2 Aligner 학습 스크립트 | `scripts/train_aligner.py --smoke` | ✅ 증강 경로까지 검증 |
| 6 | 변별력 평가 스크립트 | `scripts/eval_dgop_discrimination.py`, `test_eval_dgop_discrimination.py` | ✅ 지표 4/4 통과 |
| 7 | `assess_text`를 aligner/scorer 2모델로 분리 | `backend/dgop_acoustic.py`, `backend/main.py` | ✅ 합성 분포 테스트 2종 추가 |

**7번 배선** — `/api/speak/assess`의 환경변수가 둘로 갈라졌다.

| 변수 | 용도 |
|---|---|
| `DGOP_ALIGNER_ID` | 강제정렬용(A-2 산출물) |
| `DGOP_SCORER_ID` | 채점용(A-1 산출물). 생략 시 정렬기와 동일 |
| `DGOP_MODEL_ID` | 구 변수명 — 하위호환으로 정렬기 겸 채점기 |

두 모델의 프레임 수가 다르면 구간을 옮길 수 없으므로 `phone_confidences`가 즉시 `ValueError`를
낸다(조용히 틀린 점수를 내지 않는다). 어절 경계 `|` 토큰은 정렬은 제약하되 점수 집계에서 제외된다.

**중요한 설계 판단(1번)**: `to_pronounced_syllables()`는 아바타 입모양 엔진과 공유하는
함수다. 확인해보니 원래의 "규칙 생략"은 viseme 경로에서는 **옳은 판단**이었다 —
비음화 ㄱ→ㅇ은 둘 다 viseme 7이고 경음화도 전부 같은 그룹이라 입모양이 안 바뀐다.
그래서 기본 경로는 손대지 않고 `phonetic=True` 플래그로만 새 규칙을 켠다.
`test_phonetic_rules.test_default_path_unchanged`가 이 불변을 지킨다.

**환경 메모**: transformers 5.x에서 `TrainingArguments`의 `warmup_ratio`·`group_by_length`가
제거됐다. RunPod에서도 로컬과 같은 버전을 쓰도록 `requirements-ml.txt`에 `>=5.16.0`으로
고정하고 `accelerate`를 추가했다(Trainer 필수 런타임).

⚠️ **torchaudio 상한(중요)**: `torchaudio.functional.forced_align`이 **2.9에서 제거**된다
(2026-09-08 실기 확인 — RunPod H100/torchaudio 2.8.0에서 deprecation 경고 확인).
`dgop_acoustic.align_targets`가 이 API에 전적으로 의존하므로 `<2.9.0` 상한을 걸었다.
2.9 이상으로 올리려면 **CTC 강제정렬(Viterbi)을 자체 구현**하거나 대체 라이브러리로
옮겨야 한다 — 축 B 후속 과제로 남긴다. 알고리즘 자체는 단순해서 자체 구현이 현실적이고,
그러면 무거운 torchaudio 의존도 함께 덜어낼 수 있다.

### A-3 변별력 — **축 A 합격**

| 지표 | 베이스라인 | 축 A | 목표 | |
|---|---|---|---|---|
| 단조성 −ρ(sev, score) | 0.840 | **0.979** | 0.90 | ✅ |
| 분리도 AUC(0 vs 3+) | 0.998 | **0.999** | 0.85 | ✅ |
| 정렬 견고성(sev 4) | 1.000 | **1.000** | 0.95 | ✅ |

severity별 D-GOP 평균:

| severity | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 베이스라인 | 6.65 | 3.58 | 2.07 | 1.15 | **1.25 ↑** |
| 축 A | 9.51 | 2.74 | 1.49 | 0.61 | **0.30** |

베이스라인은 severity 3→4에서 점수가 **되레 올라가** 심한 저하를 구별하지 못한다.
축 A 모델은 끝까지 단조 감소한다 — 이것이 §0에서 세운 가설의 실증이다.

### 정직한 한계 두 가지

**① naive(표준 GOP)도 이 실험에서는 단조롭다.** 단조성이 naive 0.995 > D-GOP 0.979로
오히려 근소하게 높다. §0의 "표준 GOP는 뭉갠 발화에서 과신한다"는 예상은 **합성 저하에
대해서는 성립하지 않았다** — deaf_speech_synthesis의 교란(저역통과·잡음·포먼트 이동)은
분포를 실제로 평평하게 만들어 naive 점수도 함께 떨어뜨린다. 과신 문제는 **실제 농인
발화**에서 검증해야 하며, 그 데이터가 아직 없다. D-GOP의 불확실성 보정이 값을 하는지는
미결로 남는다.

**② 점수 스케일이 사용 불가 수준으로 압축돼 있다.** 깨끗한 발화(severity 0)의 D-GOP가
9.51/100이다. 학습자에게 그대로 보여줄 수 없다. 원인은 구간 평균 분포에 CTC blank가
지배적인 프레임이 섞여 target_prob이 낮게 나오기 때문으로 보인다.
(→ 2026-09-09 표시용 보정으로 조치. 아래 **A-4 점수 보정** 참고.)

> ⚠️ **2026-09-09 정정 — 위 원인 추정은 틀렸다.** 진짜 원인은 `align_targets`의 구간 뭉갬
> 버그였다(아래 **A-5** 참고). blank 때문이 아니라, 중복 출현 토큰의 구간을 '첫 출현 시작 ~
> 마지막 출현 끝'으로 잡아 발화 대부분을 삼킨 탓이다. 따라서 위 표의 원점수(9.51 …)와
> **A-4 앵커는 모두 버그가 낀 값**이며, 버그를 고친 뒤 A-3·A-4를 다시 재야 한다.

## A-4 점수 보정 (2026-09-09)

위 한계 ②에 대한 조치다. **원점수는 손대지 않고 표시용 점수를 따로 만든다.**

### 방법 — severity 앵커 + log 보간

기준 발화 집합의 severity별 원점수 **중앙값**을 앵커로 잡고, 각 앵커를 "이 정도 발음은 몇 점으로
보여야 하는가"에 잇는다. 앵커 사이는 log 공간에서 선형 보간한다 — 원점수가 severity에 따라
대략 기하급수로 줄기 때문이다(9.51 → 2.74 → 1.49 → 0.61 → 0.30).

| severity | 원점수(A-3 실측) | 표시 점수 | 근거 |
|---|---|---|---|
| 0 정상 | 9.51 | **90** | 넉넉히 통과 |
| 1 경도 | 2.74 | **72** | 단어·문장 합격선(65) 바로 위 |
| 2 중등도 | 1.49 | **58** | 음소(50)는 통과, 단어·문장은 미달 |
| 3 중증 | 0.61 | **40** | 확실히 미달 |
| 4 최중증 | 0.30 | **20** | 확실히 미달 |

표시 목표는 `speak_curriculum`의 합격선(음소 50 / 단어·문장 65)에서 역산한 **제품 결정**이다
(`dgop.DISPLAY_TARGETS_BY_SEVERITY`). 양끝은 원점수 0을 0점, 최상위 앵커의 기울기를 연장한
지점(원점수 ≈ 18.9)을 100점으로 둔다 — 정상 발화 대표값보다 뚜렷하게 좋아야 만점이 나온다.

### 이 보정이 하지 않는 것

보정은 **단조 증가 변환**이다. 순위를 바꾸지 않으므로 A-3 변별력 지표(순위상관·AUC)는
보정 전후가 같다. 변별력을 사후에 만들어내는 것이 아니라, 이미 있는 변별력을 사람이 읽을 수
있는 눈금으로 옮길 뿐이다(`test_dgop.test_calibration_preserves_ranking`이 이를 고정한다).

원점수가 severity를 거스르는 구간(A-3 베이스라인의 3→4 역전)은 앵커에서 **버린다**. 역전을
앵커로 삼으면 더 나쁜 발음에 더 높은 점수가 가기 때문이다. 버려진 severity는 출력에 남는다 —
"이 모델은 그 구간을 구별하지 못한다"는 사실을 감추지 않는다.

### 구현·재적합

| 위치 | 역할 |
|---|---|
| `backend/dgop.py` | `fit_calibration`·`calibrate_score` — 순수 함수, 결정론적 테스트 |
| `backend/dgop_acoustic.py` | `load_calibration` + `assess_text`가 `score`(보정)·`raw_score`(원점수) 동시 반환 |
| `scripts/fit_dgop_calibration.py` | 기준 발화로 앵커를 재적합해 JSON 저장 |

앵커 우선순위는 `DGOP_CALIBRATION`(경로) → `backend/data/dgop_calibration.json` →
`dgop.DEFAULT_CALIBRATION`(위 표의 A-3 실측 내장값). 파일이 없거나 깨져도 내장값으로 떨어져
채점 자체는 죽지 않는다.

**체크포인트를 바꾸면 원점수 스케일도 바뀐다 — 반드시 다시 적합한다.** 내장 기본값은 축 A
산출물 전용이며, 다른 모델에 그대로 쓰면 점수가 의미를 잃는다.

### 남는 한계

앵커는 **합성 저하**(deaf_speech_synthesis)를 기준으로 잡혔다. "severity 1 = 72점"이 실제
농인 학습자의 체감과 맞는지는 검증되지 않았다 — 한계 ①과 같은 데이터 부재에 걸려 있다.
실제 발화 표본이 생기면 `DISPLAY_TARGETS_BY_SEVERITY`부터 다시 본다.

## A-5 CTC 강제정렬 자체 구현 + 구간 뭉갬 버그 (2026-09-09, 로컬)

계획서가 축 B 후속 과제로 남겨 둔 **CTC 강제정렬 자체 구현**을 했고, 그 과정에서 기존
정렬 코드의 버그를 찾았다. 버그 쪽이 훨씬 중요하다.

### 발견한 버그 — 중복 출현 토큰의 구간이 뭉개진다

기존 `dgop_acoustic.align_targets`는 정렬 경로를 **토큰 id로 필터링**해 구간을 잡았다:

```python
frames = [i for i, p in enumerate(path) if p == tid]
start, end = min(frames), max(frames)      # ← 같은 토큰의 모든 출현이 한 구간으로 합쳐진다
```

같은 토큰이 문장에 두 번 이상 나오면 **모든 출현이 '첫 출현 시작 ~ 마지막 출현 끝'이라는
하나의 거대한 구간**을 갖는다. 자모 vocab은 49토큰인데 Zeroth 라벨은 중앙값 103토큰이라
중복은 예외가 아니라 기본이다 — 실측하면 짧은 문장에서도 토큰의 20~57%가 중복 출현이다.

| 문장 | 토큰 | 고유 | 중복 출현 |
|---|---|---|---|
| 안녕하세요 | 10 | 9 | 2 (20%) |
| 오늘 날씨가 참 좋네요 | 23 | 15 | 13 (57%) |
| 학교에서 국물을 먹었습니다 | 30 | 22 | 15 (50%) |

뭉개진 구간의 평균 확률분포는 평평해진다 → `phone_confidence`가 0에 수렴 →
`dgop = naive × confidence`가 통째로 깎인다. **한계 ②(스케일 압축)의 실제 원인이다.**

합성 실험(또렷한 발화, '오늘 날씨가 참 좋네요' 23토큰 240프레임)에서 구간 폭 중앙값이
50프레임 → 10프레임으로 줄고, D-GOP 원점수가 **46.5 → 95.2**로 올랐다.

부수 피해도 있다: 같은 토큰의 두 출현이 **항상 동일한 점수**를 받는다. 학습자가 첫 'ㄴ'만
틀려도 두 'ㄴ' 모두에 같은 피드백이 간다 — 음소별 피드백이라는 D-GOP의 취지가 무너진다.

### 자체 구현 — `backend/ctc_align.py`

확장열(blank로 감싼 2L+1 상태) 위의 Viterbi. 이동은 머무름·전진·건너뜀 셋이고, 건너뜀은
`ext[s]`가 비blank이고 `ext[s-2] != ext[s]`일 때만 허용한다(같은 라벨이 연달으면 사이에
blank가 반드시 있어야 구별되므로).

`token_spans`가 blank로 끊기는 연속 구간(run)을 **순서대로 목표열에 배정**한다 — id 필터링을
쓰지 않으므로 중복 출현이 분리된다.

**torchaudio와 동일한 출력을 내는지 직접 검증한다.** 정렬이 한 프레임만 밀려도 점수가 바뀌기
때문이다. `test_ctc_align.py`가 사례 6개 + 무작위 46회에서 프레임별 라벨·점수 일치를 확인했다
(전부 일치). torchaudio가 없으면 그 테스트만 건너뛴다.

### 곁가지 — 상한의 근거가 사라졌다

- 프로젝트 전체에서 torchaudio의 **기능적 사용처가 없어졌다**(남은 건 버전 출력뿐).
- 그리고 실측하니 `forced_align`은 **torchaudio 2.11.0에도 그대로 있다**. "2.9에서 제거"는
  2.8.0의 deprecation 경고를 보고 이르게 잡은 추정이었다.

`requirements-ml.txt`의 `<2.9.0` 상한은 **기술적 근거가 없어졌지만 그대로 두었다** — 푸는 것은
학습 재현성(체크포인트 로딩·수치)에 영향이 있어 별도 판단이 필요하다.

### 이 발견이 되돌리는 것

| 대상 | 상태 |
|---|---|
| A-3 변별력 판정(단조성 0.979 등) | ✅ 재측정 완료(아래) — 버그가 낀 값이었다 |
| A-4 보정 앵커(내장 기본값 9.51 …) | ✅ 재적합 완료(아래) |
| 2모델 분리 설계(§0·§1) | 영향 없음 — 정렬/채점 역할 분리는 그대로 유효 |
| 학습된 체크포인트 2개 | 영향 없음 — 학습에는 이 코드가 쓰이지 않았다(재학습 불필요) |

또 하나 짚어 둘 것: **A-3의 '정렬 견고성 1.000'은 사실상 자명한 값이었다.** CTC 강제정렬은
구성상 목표 토큰을 하나도 빠짐없이 방출하므로, 예외가 나지 않는 한 정렬률은 항상 1.0이다.
이 지표는 "구간을 옳게 찾았는가"를 재지 못한다 — 재려면 구간 경계의 정답이 필요하다.

## A-5 재측정 결과 (2026-09-09, RunPod H100 · 같은 체크포인트)

버그 수정 후 §6(A-3) → §6.5(A-4)를 다시 돌렸다. 재학습은 하지 않았다.

### A-3 — 축 A 합격, 그리고 버그가 원인이었음이 확정됐다

| severity | 축 A (수정 후) | 축 A (09-08, 버그) | 배수 | 베이스라인 (수정 후) |
|---|---|---|---|---|
| 0 정상 | **76.56** | 9.51 | 8.1× | 8.64 |
| 1 경도 | 31.26 | 2.74 | 11.4× | 5.01 |
| 2 중등도 | 15.56 | 1.49 | 10.4× | 2.68 |
| 3 중증 | 3.20 | 0.61 | 5.2× | 1.97 |
| 4 최중증 | 0.83 | 0.30 | 2.8× | **2.00 ↑** |

| 지표 | 베이스라인 | 축 A | 목표 | |
|---|---|---|---|---|
| 단조성 −ρ(sev, score) | 0.813 | **0.998** | 0.90 | ✅ (베이스라인 ❌) |
| 분리도 AUC(0 vs 3+) | 0.996 | **1.000** | 0.85 | ✅ |
| 정렬 견고성(sev 4) | 1.000 | **1.000** | 0.95 | ✅ |

**한계 ②는 해소됐다.** 깨끗한 발화가 9.51 → 76.56이다. "CTC blank 탓"이라는 원래 추정이
아니라 구간 뭉갬 버그가 원인이었음이 실측으로 확정됐다(합성 실험 예측 46.5→95.2와 방향·규모 일치).

**베이스라인의 3→4 역전은 버그 탓이 아니었다.** 수정 후에도 1.97 → **2.00**으로 되레 올라가
단조성 0.813으로 미달한다. §0에서 세운 "정렬기/채점기를 나눠야 한다"는 설계 근거가 유지된다.

**버그가 두 모델에 다르게 작용한 이유**는 vocab 크기다. 베이스라인은 음절 vocab(1,205토큰)이라
한 문장에서 같은 토큰이 거듭 나오는 일이 드물어 뭉갬이 거의 없었다(6.65 → 8.64, 소폭). 자모
vocab(49토큰)은 중복이 기본이라 직격당했다(9.51 → 76.56). 버그의 성격과 정확히 맞는다.

### A-4 — 앵커 확정

severity별 원점수 **중앙값**을 앵커로 잡았고 5개 전부 채택됐다(`dropped_severities` 비어 있음).
중앙값 78.15가 A-3 평균 76.56과 근접해 극단값 쏠림도 없다.

| severity | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| 원점수 중앙값 | 78.15 | 31.65 | 15.20 | 2.90 | 0.85 |
| 표시 점수 | 90 | 72 | 58 | 40 | 20 |

`backend/data/dgop_calibration.json`으로 커밋했다(기본 경로라 환경변수 없이 읽힌다).
`dgop.DEFAULT_CALIBRATION` 내장 폴백도 같은 값으로 갱신해 파일이 없어도 동작이 같다.

### 이 재측정이 새로 만든 문제 — 100점 도달 불가

`sentence_dgop`의 원점수 상한은 100인데(`dgop ≤ 1` → ×100), 원점수가 8배 올라간 뒤
`fit_calibration`의 외삽이 최상위 앵커를 **raw 129**로 잡았다. 결과적으로 **달성 가능한 최고
표시점수가 94.9**이고 100점은 나오지 않는다(이전 앵커에서는 100점 지점이 raw 18.9로 도달 가능).

외삽 규칙을 바꿀지는 제품 결정이라 코드는 그대로 두고
`test_dgop.test_calibration_range_and_edges`에 사실로 고정했다. 선택지는 (1) 그대로 두기
— 발음 교정 앱에서 만점을 안 주는 편이 낫다는 판단, (2) 외삽을 원점수 상한에서 클램프,
(3) `DISPLAY_TARGETS_BY_SEVERITY`의 severity 0 목표(90)를 낮춰 외삽 여지를 만들기.

### ⚠️ 2026-09-09 후속 — 한계 ①의 진단이 절반 틀렸다

아래 절은 naive ≥ D-GOP의 원인을 *"합성 저하라서 과신이 재현되지 않았다"*로 진단했다.
**절반만 맞다.** 후속 조사에서 채점식 자체의 구조적 결함이 드러났다
(`scripts/analyze_dgop_redundancy.py`로 재현, 상세는 `docs/deaf-speech-data-research.md` §0):

- `naive`와 `confidence`의 순위상관이 **0.980**이다. 둘 다 분포 첨도의 단조 함수라 곱셈이
  순위 정보를 더하지 못하고 잡음만 더한다 → `-ρ`가 **구조적으로** naive 이하가 된다.
  아래 두 실측(1.000→0.998, 0.914→0.813)이 그 예측값이다.
- 보정 방향이 반대다. 과신은 분포가 *뾰족한데* 틀린 것인데 `confidence`가 재는 것이 그
  뾰족함이라 과신을 통과시킨다. 실제로 걷히는 것은 **과소확신**이다.

즉 **실제 농인 발화를 구해도 이 곱셈 형태로는 과신을 잡지 못한다.** 데이터 부재가 아니라
채점식이 1차 문제다. 선행 연구(Yeo et al., Interspeech 2023)가 한국어 구음장애 발화에서
엔트로피·마진 기반 GOP가 베이스라인보다 나쁘고(τ −0.264 / −0.443 vs −0.524) MaxLogit만
이긴다(−0.544)고 이미 보고했다.

별개 구현 결함: `span_distribution`이 CTC blank 프레임을 구간 평균에 포함한다. 문헌 표준은
비blank만 집계한다(Cao et al., Interspeech 2024).

### 한계 ①은 오히려 더 뚜렷해졌다

| 측정 | naive 단조성 | D-GOP 단조성 |
|---|---|---|
| 축 A | **1.000** | 0.998 |
| 베이스라인 | **0.914** | 0.813 |

**두 측정 모두에서 naive ≥ D-GOP다.** 베이스라인에서는 격차가 0.1로 벌어져, 불확실성 보정이
단조성을 오히려 **깎았다**(naive는 목표 0.90을 통과하는데 D-GOP는 미달). 즉 합성 저하
데이터에서는 D-GOP의 불확실성 보정이 값을 하지 않는다 — 중립이 아니라 손해다.

이는 §0 전제("표준 GOP는 뭉갠 발화에서 과신한다")가 **합성 저하에 대해 성립하지 않기**
때문이다. deaf_speech_synthesis의 교란은 분포를 실제로 평평하게 만들어 naive도 함께 떨어뜨린다.
D-GOP가 값을 하는지는 **실제 농인 발화**로만 판정된다 — 그 데이터가 아직 없다.

또한 '정렬 견고성 1.000'은 세 측정 모두에서 1.000이다 — 자명한 값이라 정보가 없다.
