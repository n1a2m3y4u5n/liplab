# 말하기 3단계 자음 확장 선행 검증(커리큘럼 계획 1-5, 2026-09-28)

청력 손실 발화에서 가장 흔히 무너지는 소리는 고주파 마찰음·파찰음(ㅅ ㅆ ㅈ ㅊ ㅉ)과 ㅎ인데, 말하기 3단계(자음)에는 입술·잇몸·여린입천장
파열음(마 바 파 불 풀 달 탈 가 카)만 있었다. 채점기(D-GOP)가 이 소리의 대치를 가려내지 못하면 틀린 피드백을 주게 되므로 먼저 쟀다.

## 방법과 기준(결과 전에 `docs/curriculum-roadmap.md` 1-5에 적음)

- AI Hub 538 정상 화자 문장 600개(파드에서만 처리). 목표 초성이 든 음절 하나를 골라(앞 글자에 받침이 있으면 연음·동화가 끼어 제외)
  대립 초성으로 바꾼 문장을 만들고, 같은 녹음을 제 문장과 바꾼 문장에 대어 채점해 바뀐 자리의 음소 D-GOP를 비교했다.
- 대립(결과 전에 고정): ㅅ→ㄷ·ㅆ, ㅆ→ㅅ, ㅈ→ㅊ·ㄷ, ㅊ→ㅈ, ㅉ→ㅈ, ㅎ→ㄱ. 기준선으로 지금 3단계 대립(ㅂ→ㅍ·ㅁ, ㅍ→ㅂ, ㄷ→ㅌ, ㅌ→ㄷ,
  ㄱ→ㅋ, ㅋ→ㄱ, ㅁ→ㅂ)도 같이 잼.
- 채택: 목표 초성의 AUC(제 문장 쪽 음소 점수가 더 높을 확률, 대립 합산) >= 0.80.
- 스크립트: `scripts/speak_consonant_pod_eval.py`(파드), `scripts/speak_consonant_analyze.py`(분석).

## 결과(비교 4,868쌍, 오류 0)

| 초성 | 비교 수 | AUC | 같은 녹음 승률 | 판정 |
|---|--:|--:|--:|---|
| ㅅ | 954 | 0.989 | 0.983 | 통과 |
| ㅈ | 996 | 0.979 | 0.967 | 통과 |
| ㅊ | 200 | 0.952 | 0.920 | 통과 |
| ㅎ | 422 | 0.961 | 0.927 | 통과 |
| ㅆ | 31 | 0.772 | 0.677 | 판단 불가(표본 부족) |
| ㅉ | 20 | 0.718 | 0.700 | 판단 불가(표본 부족) |
| 기존 ㄱ ㄷ ㅁ ㅂ ㅋ ㅌ ㅍ | 81~634 | 0.918~0.984 | 0.877~0.977 | 기준선 |

- 새 자음 넷은 기존 3단계 자음과 같은 수준으로 가려졌다. 된소리 ㅆ·ㅉ은 표본이 적어(문장에 드물다) 판단할 수 없다. 95% 신뢰구간이
  0.80을 포함한다(ㅆ 약 0.65~0.89, ㅉ 약 0.56~0.88). 기준을 넘었다고 볼 수 없어 넣지 않았지만 '미달'로 확인된 것도 아니다.
- 대립별 AUC(같은 결과에서 나눈 값, '낸 소리 → 대어 채점한 목표'): ㅅ→ㄷ 0.994, ㅅ→ㅆ 0.985, ㅈ→ㄷ 0.980, ㅈ→ㅊ 0.979, ㅊ→ㅈ 0.952,
  ㅎ→ㄱ 0.961, 기준선 ㅂ→ㅁ 0.957, ㅂ→ㅍ 0.973.
- 반영: 3단계에 사·자·차·하를 넣었다(13문항). 순서는 입술 → 잇몸 → 마찰·파찰 → 여린입천장 → 목.
- 대치 방향(9/29 방법 검토): 이 측정은 목표 자음을 맞게 낸 녹음을 다른 목표에 대어 채점했다. 그래서 'ㅅ AUC 0.989'는 '목표는 ㄷ인데
  ㅅ을 냄'을 가른 값이다. 앱에서 학습자가 틀리는 방향(목표는 사인데 다로 냄, 목표는 하인데 가로 냄, ㅎ 탈락)은 녹음된 소리와 목표가 반대이고, 이
  방향은 재지 않았다. 사·자·차·하는 앱에 두되, 앱 방향의 판별력은 파드에서 따로 재야 한다(예: 목표 ㄷ을 맞게 낸 녹음을 ㅅ 목표에 대어
  채점, ㄱ을 낸 녹음을 ㅎ 목표에, ㅎ 음절에서 ㅎ을 뺀 목표와 비교).
- 한계: 정상 화자 발화로 잰 값이다. 청각장애 화자에서는 D-GOP 판별력이 낮아지므로(문장 일치 판별 AUC 0.998 → 0.896, 화자 절반별 0.85~0.94,
  `docs/speak-transcript-scoring.md`) 이 자음들의 실제 피드백 정확도도 더 낮을 수 있다. 바꾼 문장은 합성 대치라 실제 오조음(예: ㅅ을
  치간음으로 내는 것)과는 다르다.

## 앱 방향 재측정(2026-09-29) 사전 등록

결과를 보기 전에 적는다. 위 측정은 '목표 자음을 맞게 낸 녹음을 다른 목표에 댄' 방향이었다. 여기서는 앱에서 학습자가 틀리는 방향,
곧 녹음에는 다른 자음이 들어 있고 목표는 3단계 자음(ㅅ ㅈ ㅊ ㅎ)인 경우를 잰다.

- 자료: AI Hub 538 정상 화자 클립 전부(58명 × 30문장 = 1,740개)와 608 감음신경성 화자 문장 컷 360개(24명). 파드에서만 처리하고 저장소에는
  집계 수치만 남긴다. 608 컷은 9/28에 만든 문장 경계(시작·끝 초)로 원본 세션에서 CPU로 다시 자른다.
- 자리 고르기: 위와 같은 규칙(앞 글자가 받침 있는 한글이면 제외). 클립 하나에서 짝마다 최대 3자리(시드 0 무작위). 바꾼 문장의 자모
  토큰이 원 문장과 정확히 한 자리만 다를 때(ㅎ 탈락은 ㅎ 토큰 하나만 더해질 때)만 쓴다.
- 짝(녹음의 자음 → 대어 채점한 목표 자음, 결과 전에 고정):
  - 앱 방향, 새 자음: ㄷ→ㅅ, ㄷ→ㅈ, ㅊ→ㅈ, ㅈ→ㅊ, ㄱ→ㅎ, ㅎ 탈락(녹음은 첫소리 없는 모음 음절 'ㅇ', 목표는 같은 음절에 ㅎ을 더한 것).
  - 된소리 확대: ㅅ→ㅆ, ㅈ→ㅉ(앱 방향), ㅆ→ㅅ, ㅉ→ㅈ(9/28 방향). 1,740개 전부를 써서 표본을 늘린다(9/28 31쌍·20쌍).
  - 9/28 방향 재확인: ㅅ→ㄷ, ㅈ→ㄷ, ㅎ→ㄱ.
  - 기준선(기존 3단계, 양방향): ㅂ↔ㅁ, ㅂ↔ㅍ, ㄷ↔ㅌ, ㄱ↔ㅋ.
- 지표:
  - 주 지표(같은 녹음 AUC, 9/28과 같은 꼴): 녹음이 Y이고 목표를 X로 바꾼 짝 Y→X에서, 양성 = 제 문장으로 채점한 그 자리 Y 음소의
    D-GOP, 음성 = 바꾼 문장으로 채점한 그 자리 X 음소의 D-GOP. AUC = 양성이 음성보다 높을 확률(동점 0.5).
  - 보조 지표(고정 목표 AUC, 앱의 문턱과 같은 꼴): 목표 X 음소의 D-GOP만 본다. 양성 = X를 맞게 낸 녹음(제 문장의 X 자리), 음성 = Y를
    낸 녹음을 X 목표에 댄 값. 낱말 속 소리 확인의 문턱 0.05(`PROBE_DGOP_MIN`)에서 맞게 낸 X 통과율과 Y의 X 통과율(오합격)도 적는다.
  - ㅎ 탈락은 같은 녹음에 짝이 되는 음소가 없어 고정 목표 AUC가 주 지표다.
  - 95% 신뢰구간: 화자 단위 부트스트랩(2,000번, 백분위).
- 판정(자음마다, 538과 608 각각): 주 지표 AUC >= 0.80이면 통과. ㅅ = ㄷ→ㅅ, ㅈ = ㄷ→ㅈ와 ㅊ→ㅈ 합산, ㅊ = ㅈ→ㅊ, ㅎ = ㄱ→ㅎ와 ㅎ 탈락이
  둘 다 0.80 이상. 구간이 0.80을 포함하면 판정 옆에 적는다. ㅆ·ㅉ은 두 방향이 모두 0.80 이상이어야 넣을 후보가 된다.
- 608에서 미달인 자음의 권고(결과 전에 정함): 그 자음의 음소 피드백은 '참고'로 표시하고 낱말 속 소리 확인(3단계 carryover 확인
  낱말)에서 뺀다. 코드는 이 측정에서 바꾸지 않는다.
- 한계(미리 적음): 608의 '제 문장' 쪽은 화자가 목표 자음을 실제로 냈다고 가정한다. 청각장애 화자는 이미 대치했을 수 있어 608 AUC는
  낮은 쪽으로 치우친다. 바꾼 문장은 합성 대치이며 실제 오조음과 다르다.
- 스크립트: `scripts/speak_app_direction_pod_eval.py`(파드, 자음과 포먼트를 한 번의 정렬로), `scripts/speak_consonant_app_analyze.py`(분석).
