# 학습 콘텐츠 품질 감사(2026-09-28)

9/27 감사(`docs/content-routine.md` 4절)에 이어 학습 콘텐츠 전체를 다시 점검했다. 대상은 단어 은행, 최소대립쌍·동구형이음 짝,
문맥 추론 문항(문맥 추론 화면과 2단계 레슨의 문맥 문항이 같은 풀), 대화·상황 문장의 대체 콘텐츠, 말하기 4·5단계 항목이다.
코드 기능이 아니라 콘텐츠의 질을 본다.

방법은 두 갈래다.

- **규칙 점검**: `scripts/content_audit.py`가 규칙으로 볼 수 있는 것을 센다(짝의 자모 거리와 입모양 열, 같아 보임 표시, 중복,
  단계별 길이, 대체 대사의 되풀이, 억양 표시와 문장 부호, 빈도 등급). 외부 파일은 받지 않고 `content_rules`가 쓰는 빈도 사전만
  쓴다. `--strict`는 아래 '오류' 조건이 하나라도 깨지면 종료 코드 1을 낸다. 테스트 `backend/test_content_audit.py`가 이 조건을 매번 본다.
- **사람 판정**: 단어 528개, 서빙 문맥 문항 91개, 대체 문장·대사 전부, 말하기 문장 16개를 읽고 뜻·자연스러움·답이 둘인지를 봤다.
  판정 결과는 `curriculum.STAGE2_EXCLUDED`·`CLOSURE_EXCLUDED`(항목마다 사유)와 이 문서에 남겼다.

```
python scripts/content_audit.py            # 보고서
python scripts/content_audit.py --strict   # 불변 조건 위반이 있으면 종료 코드 1
```

## 2. 최소대립쌍·동구형이음 짝

**관계 표시(10개 고침).** 짝은 두 종류다. 최소대립쌍(`minimal_pair`)은 자모 한 자리만 다르고, 동구형이음(`homophene`)은 보이는
입모양 열이 완전히 같다. 승인 짝 906개는 규칙(`check_lookalike_pair`)이 표시를 붙였지만 큐레이션 짝 10개에는 표시가 없었다. 규칙
값으로 붙였다(밥/맘·달/탈 등 8개 동구형이음, 말/물·우유/이유 최소대립쌍).

'모든 짝이 자모 한 자리만 다를 것'은 적용하지 않았다. 동구형이음 613쌍 가운데 307쌍이 두 자리 이상 다른데(밥/맘은 초성과
받침 두 자리), 이 짝은 '다르게 적어도 입모양은 같다'를 가르치는 것이 목적이라 자모 거리가 기준이 아니다. 대신 짝마다 둘 중
하나여야 한다는 조건을 테스트로 고정했다: 최소대립쌍은 정확히 한 자리, 그 밖은 입모양 열이 완전히 같을 것
(`test_every_pair_is_one_jamo_minimal_pair_or_homophene`). 지금 최소대립쌍 303쌍은 모두 한 자리 차이다.

**같아 보임 표시.** 엔진 입모양 규칙(`_visually_confusable`)과 어긋나는 짝 0, 주석이 표시와 어긋나는 짝 0, 중복 0, 발음이 완전히
같은 짝 0. 9/27에 고친 것이 유지되고 있다.

**드문 말이 든 짝.** 드문 말이 든 짝 410, 검사 정답이 든 짝 164이고 둘 다 없는 짝은 387이다. 추천 카드(`/api/curriculum/next`)는
이미 걸러 내고 있었지만 다자 대화의 닮은꼴 사전(`conversation_scenario.lookalike_map`)은 거르지 않아, 9/27에 뺀 드문 말 50개와
이번 30개, 검사 정답 28개(돈·반·문·딸 …)가 닮은꼴 오답과 빈칸 턴 보기로 나갔다. 드문 말은 어휘 지식만으로 지워지고 검사 정답은
사전·사후 검사 문항이 훈련에 노출된다. 둘 다 걸렀다(사전 단어 323 → 190).

**남긴 것.** 같아 보임 짝 111쌍은 입모양 무리가 같은 모음 차이를 담는다(ㅗ/ㅜ 79, ㅏ/ㅐ 21, ㅓ/ㅡ 6, ㅏ/ㅑ 4, ㅛ/ㅜ 1). 엔진
기준(`VISEME_MAP`)으로는 맞는 표시다. 다만 말하기 2단계 안내는 '오/우, 어/으는 턱을 벌리는 정도로 구별한다'고 가르쳐 두 설명이
다르다. 엔진의 모음 무리를 나눌지는 입모양 공간 측정(`docs/phoneme-visual-space.json`)과 함께 정할 일이라 이번에는 두었다.

맞지 않아야 해서 해가 작다. 서빙하지 않는 50개(게이트 23, 검사 정답 27)는 손대지 않았다.

## 4. 대화·상황 문장

**대화 대체 대사(`llm_service.FALLBACK_TURNS`).** LLM이 실패하면 상대가 말하는 대사다. 두 결함이 있었다.

- 단계 길이 초과 10건. 1단계 상한은 9자(`_CONV_MAX_CHARS`)인데 '어서 오세요. 무엇으로 드릴까요?'(18자), '어떤 업무 보러
  오셨어요?'(14자) 등이 1·2단계에도 나갔다. 상황마다 1단계에 맞는 대사가 2~4개뿐이었다.
- 되풀이. `len(history) % 대사 수`로 골랐는데 대화 기록에는 학습자 턴도 들어 있어 길이가 2씩 늘었다. 대사 4개 가운데 0번과
  2번만 번갈아 나왔다(모든 상황·단계 조합 35개에서 6턴 안에 되풀이).

`fallback_turn`을 새로 썼다. 그 단계 길이 안의 대사 가운데 이 대화에서 아직 하지 않은 것을 목록 순서대로 고르고, 다 쓰면 가장
오래전 대사부터 다시 쓴다. 대사는 대화가 흘러가는 순서로 상황마다 7~8개로 늘렸고(28 → 51), 1단계에 맞는 대사가 상황마다 4개
이상이다.

**상황별 대체 문장(`FALLBACK_BY_LEVEL` 30, 상황 기본 문장 15).** 규칙 게이트, 단계별 글자 수 상한, 최소 어절 수를 모두 지킨다.
3단계 '… 늦어지고 있어서 정말 죄송합니다, 잠시만 기다려 주세요.'는 두 문장을 쉼표로 이어 '… 늦어지고 있으니 잠시만 기다려
주세요.'로 고쳤다. 5단계의 동음이의어 문장(배·밤·눈·다리·차)은 문맥으로 뜻을 가르는 연습이라 두었다.

**다자 대화 대체 대사(장면 6 + 일반, 42).** '숙제 했어?'를 '숙제했어?'로, 응답어·감탄사 뒤에 쉼표를 넣었다(응, 여기 있어 / 네,
여기요 / 그럼요, 됩니다 등 9개). 쉼표에서 아바타가 짧게 쉰다.
