## 같은 증류와 학습

고정 선생 eval/no_grad로 학습 clip만 한 번 순회한다. 최대400프레임의 겹치지 않는 창, 중앙80자르기·원래 정규화의53로짓을 float16 캐시하고 마지막 창은 실제 길이만 쓴다. 검증 clip에는 캐시를 만들지 않는다. 학생 프레임 번호·속도·동일 화자 idle 연결로 목표도 재색인하는 같은 증강 일관성 증류다. 목표 저장 float16은 ONNX 가중치 양자화가 아니다.

손실은 `0.5×CTC + 0.5×T²×유효 프레임 평균 KL(teacher/T||student/T)`, T=2다. CTC는 배치 항목 평균, KL은 미니그룹 보정 후 배치 전체 유효 프레임 평균이며 패딩을 제외한다. 무작위80자르기·거울상0.5·시간마스크≤3·속도0.8~1.25·idle0.5 규칙을 유지한다.

각각 seed0 또는 seed1 한 번, AdamW lr3e-4 wd1e-4, **배치32·그룹 상한4000프레임**, 최대40에폭,2에폭마다 검증, patience6회 미개선, 기울기5, AMP0, CPU4스레드, 동기 배치, GPU 메모리 상한0.45다. 각 실행의 검증4지 dup1·2 화자평균의 평균 최고값(엄격한 개선)으로 체크포인트를 고른다. 초기 setup과 최종 원래 trainer 인자 모두 해당 시드를 전달한다. 출력 폴더가 비어 있을 때만 시작하고 resume·추가 시드·구조/배치/상한 변경 재시도는 없다.

학습 시간 예상은 **시드당30~50분**, 순차 두 시드 학습 합계 **약60~100분**이다. 자원 대기와 이후 main의 비교·내보내기 대기는 별도이며 즉시 완료를 약속하지 않는다. seed0 종료 뒤 결과·종료코드와 GPU 중복 부재를 확인하고 seed1을 새 출력에서 실행한다. 관문 미달은 seed1 취소 조건이 아니다. OOM/기술 실패는 그대로 남기며 두 시드 결과가 완전하지 않으면 안정 통과를 주장하지 않는다.

## 두 시드 각각의 관문

학습 종료 뒤 고정 선생과 각 시드의 선택 학생을 같은 검증12명에서 한 번 비교한다. hard CTC likelihood α1, idle75, dup1·2 각각 화자평균 후 평균을 쓴다. 미분할 문항을 버리지 않는다. CER는 같은 검증 문장 전체의 보조 보고이며 별도 관문으로 쓰지 않는다.

각 시드에서 다음을 모두 만족해야 그 시드 통과다.

1. 학생−고정 선생 검증4지 차 ≥−0.02.
2. FP32 학생 ONNX 바이트 ≤같은 선생 ONNX의 **75%**.
3. 같은PC·같은입력 CPU WASM 학생 중앙시간 ≤선생의 **60%**.

**seed0과 seed1이 모두 세 관문을 통과해야만 안정 통과**다. 하나라도 미달·기술 미확인이면 안정 통과가 아니며 각각의 수치를 그대로 남긴다. 더 높은 시드·중간 에폭·다른 저장형식·유리한 재측정으로 다시 고르지 않는다. 과거38%·50% 결과와 기준은 바꾸지 않는다.

## 비교·FP32 내보내기·WASM 순서

로컬 lab-sub에는 `onnx`가 없으므로 로컬 순차 controller는 **학습 두 번만** 실행한다. 로컬 학습을 내보내기 의존성 때문에 멈추거나 seed0 내보내기 결과를 기다려 seed1을 보류하지 않는다. 비교·내보내기는 D1 종료 후 사용 가능한 main의 승인된 환경에서 각 시드의 PT를 회수해 실행한다. 이때도 GPU 하나당 작업 하나, 같은 선생·자료·배치·정밀도와 cap0.45를 지킨다.

각 모델 FP32/opset17 입력은 원화소 범위 float32 `[B,T,80,80]`, 내부 시퀀스 z정규화, 출력 `[B,T,53]`다.75프레임 합성 입력에서 PyTorch 원경로↔wrapper 및 wrapper↔ONNX CPU 로짓 최대차이<1e-3를 기술 조건으로 확인한다. 기술 미확인을 다른 관문 통과로 덮지 않는다.

WASM은 같은 lab-sub CNSAI2025, onnxruntime-web1.19.2, Node24, WASM CPU EP1스레드다. PRNG xorshift seed20261102의 동일 `[1,75,80,80]` 정수0~255 float32 합성 입력이며 실제 평가 클립을 읽지 않는다. 모델당5예열 뒤 선생/학생 순서를 번갈아20쌍의 `session.run` walltime만 재고 각20회 중앙값을 쓴다. 로딩·입력 생성·출력 확인은 타이머 밖이다. 원시 시간·PC/CPU·ORT/Node버전·입력/모델 SHA를 보존한다.

전체 고정 순서는 **C0→C1→D0→D1→C65 seed0→C65 seed1**이다. C65 각 시드는 한 번만 측정하고 과거38%·50%를 다시 측정하지 않는다. 기존 공용 도구의50% 시간 보조 boolean 대신 원시 `latency_ratio`에 이 등록의0.60을 적용한다.75% 파일 기준도 별도로 적용하며50% 집계기의60% 파일 기준을 재사용하지 않는다. 타 PC·native ORT·Android 실측으로 대체하지 않는다.
