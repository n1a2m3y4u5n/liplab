# V3 데이터 기반 입모양 모델 간이판: 문맥 평균 궤적 표 (사전 등록, 2026-10-15)

종합 계획(`docs/master-plan-2026-10.md`) 트랙 V의 V3(글자열 → 52계수, 판정: V2 지표 우위 + 가독성 비열등)를 이 작업의 파드 예산 12달러
안에서 가장 싸게 시험한다. 앞선 결과는 다음과 같다. V2(`docs/avatar-validity-2026-10.md`)에서 지금 표는 확인 화자 RSA ρ 0.612, 2.0배 진폭 범위 안
무리 1/13으로 두 기준을 모두 넘지 못했다. V15 표 보정(`docs/viseme-calibration-2026-10.md`)은 RSA(0.865)는 넘었지만 2.0배 진폭(7/13), 1.0배 원순
돌출(0.787), 무리별 구별성이 기준에 못 미쳐 `VITE_VISEME_V15=1` 뒤에 있다. V18(`docs/lip-protrusion-v18-2026-10.md`)은 지금 표의 ㅣ 입꼬리 과다를
다시 확인했다. V14의 TTS→A4는 턱 벌림이 모든 무리에서 사람 10백분위 아래였다.

1~8절은 확인 자료를 재기 전에, 모델을 고르기 전에 적고 따로 커밋한다. 탐색 기록은 9절, 확인 결과는 10절에 덧붙인다.

## 1. 질문

1. 538 실제 화자의 MediaPipe 궤적을 입모양 무리·앞뒤 모음 문맥·구간 안 위치별로 평균한 표(문맥 평균 궤적 표)로 사람 계수 궤적을 만들고,
   앱의 음성 구동 경로(`bsFrameRef`, 리그 보정 `lib/rigMap.js`)로 아바타에 입히면, V2의 두 기준(거리 구조, 2.0배 진폭 범위)을 넘는가.
2. 그렇게 만든 아바타가 지금 표보다 읽기 어려워지지 않는가(가독성 비열등, 나1). Beskow(2004)는 궤적이 가장 잘 맞는 모델이 명료도가 가장 높지는
   않았다고 보고했으므로, 사람 범위와 가독성을 따로 본다.

## 2. 설계와 그렇게 고른 까닭

### 2.1 모델

- **입력:** 규칙 엔진(`backend/engine.py`)의 입모양 프레임과 그 타이밍(재생 속도로 나눈 `duration_ms`). 시간 정렬은 규칙 엔진을 그대로 쓴다.
- **출력:** 30fps 사람 MediaPipe 계수 13채널(`rigMap`의 입력과 같은 좌우 평균: jawOpen, mouthClose, mouthFunnel, mouthPucker, smile, stretch,
  upperUp, lowerDown, press, mouthRollLower, mouthRollUpper, mouthShrugLower, mouthShrugUpper). 좌우 모프에는 같은 값을 넣는다. 아바타에는 A4 음성
  구동과 같은 `bsFrameRef` 경로(rigMap 사상, LERP 34/s)로 입힌다.
- **표:** 엔진 프레임 하나를 구간 하나로 보고, 구간을 시간으로 세 칸(앞·가운데·뒤)으로 나눈다. 칸마다 열쇠 (무리 g, 칸 b, 앞 모음 갈래 p, 뒤 모음 갈래 n)
  를 붙인다. 모음 갈래는 같은 어절 안(쉼 14·중립 15를 넘지 않음)에서 가장 가까운 앞·뒤 모음의 무리(2 개방, 3 평순 ㅣ, 4 원순(9 포함), 5 중설)이고,
  없으면 0이다. 표의 값은 그 열쇠에 해당하는 실제 538 구간 칸들의 계수 평균이다.
- **조합:** (g, b, p, n) 칸이 있으면 그 값('full'), 또는 (g, b, *, n) + (g, b, p, *) − (g, b, *, *)의 덧셈 근사('add'), 또는 (g, b, *, *)만('base') 쓴다.
  어느 것을 쓸지는 탐색에서 고른다(5절). 칸이 없으면 덜 자세한 열쇠로 물러난다.
- **시간 보간:** 칸 가운데 시각에 표 값을 놓고 칸 사이를 선형으로 잇는다(구간 경계를 넘어 이어진다). 발화 앞뒤는 쉼(14) 구간으로 채우고, 쉼의 칸
  시각은 발화에 붙은 쪽 1초 안에 둔다.
- **이득:** 평균은 화자와 문맥을 섞어 움직임 폭을 줄이므로(V14의 A4가 그랬다), 표 전체 평균 μ를 중심으로 채널 무리별 이득을 곱한다:
  y = μ + γ(y − μ). 채널 무리는 벌림(jawOpen, lowerDown, upperUp), 돌출(funnel, pucker), 폭(smile, stretch), 닫힘·나머지(mouthClose, press, roll 2개,
  shrug 2개)의 넷이다. γ는 탐색에서 0.8~2.0 안에서 고른다. 결과는 0~1로 자른다.
- **양순 닫힘 규칙(선택 사항):** 양순 1·양순 전환 11 구간에서 rigMap 출력의 입술 닫힘을 보장하는 규칙을 둘지 탐색에서 고른다(규칙의 꼴은 9절에 적는다).

### 2.2 가장 싼 경로인 까닭

- 새 자료를 받지 않는다. 학습 자료는 V2에서 이미 뽑은 538 정면 900클립의 MediaPipe 계수와 CTC 정렬(`pod_runs/20261006_oel3rwn7y5zjbv/v2_part2/out/`)이다.
- 표를 만드는 일은 평균 계산이라 맥에서 몇 초면 끝난다. 신경망 학습이 없다. 파드는 렌더·MediaPipe 측정·확인 자료의 추출과 정렬에만 쓴다.
- 앱 실행은 표 조회와 선형 보간뿐이라 문장 하나에 1ms 안팎이고, 표 파일은 수십 KB다.
- 표의 값은 칸마다 20개 이상 구간, 5명 이상 화자의 평균이다(그보다 적은 칸은 버리고 물러난다). 클립·조각별 값이나 학습 가중치가 아니라 집계 값이라
  저장소와 앱에 넣을 수 있다(V15 표, rigMap 계수와 같은 수준).

### 2.3 등록 전에 본 것(확인 자료는 보지 않음)

설계를 고르려고 V2 탐색 자료(75명, 두 절반)에서 다음 두 가지를 맥에서 계산했다. 확인 자료(3절)는 열지 않았다.

- **천장:** 실제 538 계수를 rigMap 경로로 입힌 V15의 V13 렌더(탐색 74클립, 확인 74·76클립)를 V2 분석으로 재면 RSA ρ 0.89(탐색)·0.87(V2 확인 절반),
  진폭 범위 안 무리 13/13(두 절반), 양순 닫힘 0.95·0.91, 원순 돌출 범위 안 0.68·0.55다. 사람 궤적을 이 경로로 입히면 V2 두 기준은 넘을 수 있고,
  원순 돌출 범위 기준은 사람 궤적으로도 못 넘는다.
- **사람 공간 점검:** 반쪽 화자로 표('add')를 만들고 다른 반쪽 클립의 실제 정렬 시각으로 궤적을 만든 뒤 아바타 렌더 없이 V2 분석에 넣으면 RSA ρ 0.96~0.98,
  진폭 범위 안 무리는 이득 1.0에서 8·13개, 1.3에서 12·13개였다(무리 진폭 백분위 8~47). 같은 특징의 능선 회귀도 비슷했다(ρ 0.96).

## 4. 비교 조건(확인, 같은 문장)

- **지금 표(V1, 앱 기본)**, **V15 표**(`VITE_VISEME_V15=1`), **V3**(이번 표, `VITE_VISEME_V3=1`). 모두 기본 얼굴, 1.0배와 2.0배.
- 렌더 하네스·카메라·조명·시계는 V2와 같다(`scripts/v2_render`). V3 확인 렌더는 앱 모듈(`frontend/src/lib/visemeV3.js`와 동결한 표)을 하네스가 그대로
  불러 만든다. 파이썬 구현(`scripts/v3_avatar.py`)과 앱 구현이 같은 계수를 내는지 단위 테스트로 확인한다.

## 5. 탐색에서 고르는 것(확인 전에 모두 정해 커밋)

- 조합('base', 'add', 'full'), 채널 무리 이득 γ 네 개, 양순 닫힘 규칙 유무.
- 고르는 방법: 반쪽 교차 렌더(한 절반으로 만든 표로 다른 절반의 V2 기본 얼굴 문장을 렌더하고 그 절반의 실제 화자로 판정)에서 6절 기준을 몇 개 넘는지가
  먼저이고, 같으면 2.0배 무리 진폭 백분위가 50에 가까운 쪽이다. 렌더는 세 차례까지 하고 모두 9절에 적는다. 사람 공간 계산(렌더 없음)은 횟수 제한이 없다.
- 고른 설정으로 탐색 75명 전부에서 표를 다시 만들어 동결한다(`frontend/src/lib/visemeV3Table.json`, sha256을 9절에 적는다). 탐색 전체 문장으로 한 번
  렌더해 배관을 확인하되, 그 값으로 설정을 다시 바꾸지 않는다.

## 6. 판정 기준(확인, 한 번)

모두 기본 얼굴, 같은 확인 문장, 확인 화자 19명의 분포다. 분석은 `scripts/v2_avatar_validity.py`의 함수를 그대로 쓴다.

### 6.1 V2 지표 우위

- **RSA:** V3 1.0배 ρ ≥ 확인 화자 LOO 분포 하위 10백분위(13무리가 모두 찬 화자로 만든다), 그리고 V3 ρ > 지금 표 ρ.
- **진폭:** V3 2.0배에서 13무리 중 11개 이상의 스칼라 진폭 A가 확인 화자 10~90백분위 안, 그리고 그 수가 지금 표 이상.

### 6.2 가독성 비열등(나1), 1.0배와 2.0배 각각에서 모두

- **양순 닫힘:** 무리 1 구간 안쪽 입술 간격 최소값이 확인 화자 양순 구간 90백분위 이하인 비율 ≥ 0.95(V2 `legibility.bilabial_closure_rate`).
- **원순 돌출:** 무리 4 구간 돌출 R이 확인 화자 10~90백분위 안인 비율 ≥ 0.80(V2 `legibility.rounded_R_in_range_rate`).
- **실화자 판독 대리(종합 계획의 '독화기 −2%p'):** 탐색 75명의 실제 구간으로 학습한 무리 분류기로 조건의 구간을 판독한 무리별 재현율의 평균(13무리
  매크로 재현율)이 지금 표의 값 − 0.02 이상.
  - 특징 16개: RSA 특징 13개, 입술 폭 W(입꼬리 61–291 거리), 바깥 입술 높이 H(0–17), 안쪽 입술 간격 G(13–14). W·H·G는 눈꼬리 거리(33–263)로 나눈다.
  - 화자(조건)마다 그 화자(조건)의 모든 구간 값으로 특징을 z 점수화한다(표준편차 1e-4 미만은 0). V2 RSA와 같은 정규화다.
  - 분류기: 다항 로지스틱 회귀(scikit-learn, lbfgs, C = 1.0, 무리 균형 가중, 반복 2,000). 탐색 75명의 구간 전부로 한 번 학습하고 고정한다.
  - V15의 6.3 구별성(조건 안 최근접 중심)은 조건마다 자기 구간으로만 분리도를 재서, 과장된 표가 늘 유리하다(V15 10.5절). 사람 얼굴로 배운 판독기가
    아바타를 읽는 방식이 V2의 셋째 지표(실화자 독화기 판독)에 더 가깝다. V1 독화기는 아직 없다.

### 6.3 결정

- 6.1과 6.2를 모두 넘으면 V3를 앱에 넣는다. 기본값은 바꾸지 않고 `VITE_VISEME_V3=1`로 빌드할 때만 단어·문장 재생이 V3 궤적을 쓴다(기본 전환은 사용자 결정).
- 하나라도 못 넘으면 부정 결과로 적고, 앱 재생 경로에는 넣지 않는다(연구 코드와 하네스용 모듈만 남긴다).

### 6.4 보고만 하는 것

- V15 표의 같은 지표, 2.0배 RSA·1.0배 진폭, 채널별(J·R·S·C·G) 범위 안 무리 수, RSA에서 가장 어긋난 무리 쌍, ㅏ 벌림 백분위.
- ㅣ(무리 3)의 폭 S와 백분위(V2·V18의 ㅣ 입꼬리 과다), 무리별 판독 재현율, V15식 구별성(RSA 13특징과 16특징 두 가지).
- 확인 화자 실제 구간을 같은 분류기로 읽은 매크로 재현율(판독기 자체의 성능), 확인 화자 사람끼리의 진폭 기준 통과율(V2 6.2 보정 정보).
- 말 속도(초당 음절)와 탐색 절반 값.

  n개)이 사람 범위 안이었고, 양순 닫힘·원순 돌출·실화자 판독 대리에서 지금 표보다 나빠지지 않았다. 앱에는 플래그 뒤로 넣었다."
- 미달: "V3는 기준 k(값)에서 미달해 앱 재생에 넣지 않았다." 어느 기준을 얼마나, 탐색과 어떻게 달랐는지를 적는다.
- 주장 상한: MediaPipe가 재는 2D 정면 블렌드셰이프와 랜드마크에서의 유사도와 분리도다. 실화자 판독 대리는 사람 판독이 아니며, 청각장애 학습자의
  독화 정확도에 관한 주장이 아니다. 확인 화자는 전문가만이다.

## 8. 실행, 예산, 기록

- 코드: `scripts/v3_avatar.py`(자료, 표 만들기, 예측, 작업, 분류기, 분석·판정), `frontend/src/lib/visemeV3.js`(앱 구현), 하네스(`scripts/v2_render/main.js`에 V3
  재생을 더함, 텍스트 재생과 같은 일정에서 계수를 만들어 `bsFrameRef` 경로로 재생), 파드 운영 `scripts/v3_pod/`(V18 세션 틀, 상태 폴더 `.v3state`, 파드 이름
  `liplab-v3`).
- 파드: `liplab-lab/tools/pod/pod.sh`로만 쓴다. RunPod A40·A6000·L40S SECURE, 워치독(예상 시간 + 30분), 시작 전 `pod.sh status`(잔액 5달러 아래면 쓰지 않음),
  이 작업 지출 상한 12달러. 지출이 10달러에 닿을 때까지 확인을 마치지 못하면 멈추고 진행 정도와 남은 비용 추정을 10절에 적는다. 끝나면 종료하고 API로
  남은 파드가 없음을 확인한다. MediaPipe 추출은 파드에서만 한다(맥에서 크래시).
- 538 원자료와 클립별 파생 파일(MediaPipe JSON, 렌더 영상, 정렬)은 `liplab-lab/data/v3_avatar/`와 `pod_runs/`에만 둔다. 저장소에는 집계 표와 집계 수치만 넣는다.
- 확인 자료를 잰 뒤 분석 규칙을 바꾸면 10절에 '사후 변경'으로 따로 적고 판정은 등록 규칙으로 한다.
