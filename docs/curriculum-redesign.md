# LIPLAB 교육 커리큘럼 재설계

> 상태: 설계 확정, 구현 진행 중 (브랜치 `feat/curriculum`)
> 결정 요약: **대상별 트랙 분기 + 단계형 커리큘럼. 기존 좋은 자산은 유지·재구성.**

## 1. 문제 진단 (재설계 이유)

기존 LIPLAB은 잘 만든 **"연습 엔진"**이지만 **"커리큘럼"이 아니다.**

- 콘텐츠가 **가운데(상황별 문장 연습)만** 있음. 아래(기초 입모양·단어)와 위(학습 경로·진행)가 비어 있음.
- 앱의 개념적 토대인 **입모양 10그룹을 정작 학습자에게 안 가르침** (아바타 애니메이션에만 사용).
- 독화의 핵심 기술(**동구형이음** — 같이 보이는 소리를 문맥으로 판단)을 **채점엔 반영하나 교육은 안 함**.
- 배치·진행 잠금·간격 반복(SRS)이 없음. `current_level`은 XP 파생 단조증가라 **아무것도 게이팅하지 않는 장식**.
- 완전 초보가 첫 화면부터 8어절 통문장을 만나 이탈.

## 2. 대상 & 트랙

공통 기초 위에 **대상별 2트랙**으로 분기 (배치에서 배정, 사용자 변경 가능).

| 트랙 | 대상 | 특징 |
|---|---|---|
| **A. 독화 지각** | 중도·난청 (한국어 보유) | 순수 지각 훈련. 힌트 빨리 제거, 문맥 추론·변주 집중. |
| **B. 언어+독화** | 선천성 (수어 우선, 한국어=제2언어) | **의미 먼저** — 새 항목을 수어+지문자+뜻으로 앵커링 후 입모양. 어휘 램프 완만, 반복↑. 수어 모듈이 정식 스캐폴딩. |

## 3. 커리큘럼 척추 (5단계)

기존 5개 모드는 폐기하지 않고 **각 단계의 "활동"으로 재배치**한다. (모드 = 도구, 단계 = 커리큘럼)

| 단계 | 배우는 것 | 활동(자산 재활용) | 통과 기준 |
|---|---|---|---|
| **0. 입문·배치** | 독화 개념 + 동구형이음 개념 + 배치 | 가이드(개편) + 배치 문항 | 시작 단계·트랙 배정 |
| **1. 입모양 인지** ⭐신설 | 10개 입모양 그룹, "무엇이 보이고 무엇이 안 보이나" | **기존 3D 아바타** + 인지/변별 드릴 | 그룹 변별 정확도 임계치 |
| **2. 음절·단어** ⭐신설 | 음절→고빈도 단어, 최소대립쌍 | 4지선다 단어 → 주관식 단어 | 핵심 단어셋 정확도 |
| **3. 문장(상황별)** ✅기존 | 8상황 문장 + 문맥 추론(closure) 신설 | 학습→4지선다→주관식 (LLM 생성 + 취약음소 적응) | 상황별 정확도 |
| **4. 대화·실전** 🟡개선 | 6턴 AI 대화 + **채점·피드백 신설** | 대화 모드(채점 추가) | 실전 이해도 |

## 4. 가로지르는 시스템

- **숙달 기반 진행:** 단계별 통과 기준 충족 → 다음 잠금 해제. 배치로 건너뛰기 가능. 장식적 XP레벨을 이걸로 교체.
- **간격 반복(SRS):** 틀린 문장·취약 입모양이 다음날/+3일 재등장. 기존 `WeakViseme`+오답 데이터 재활용, due-queue만 추가.
- **적응형 난이도:** 사용자 수동 선택 → 최근 정확도로 자동 오르내림.
- **독화 전략 코칭:** 가이드를 "앱 설명"→"기술 코칭"으로 승격. 동구형이음 오답 시 맥락적 팁.
- **오늘의 학습:** 빈 메뉴 → 복습(SRS)→현재 단계 학습→짧은 도전 가이드 세션.
- **수어 모듈 재배치:** 트랙 B=정식 스캐폴딩, 트랙 A=선택 보조. (동일 코드, 두 역할)

## 5. 데이터 모델 변경 (현행 대비)

현행 모델: `User / Progress / WeakViseme / Bookmark / ScenarioCache` — 단계/숙달/복습 모델 **없음**.

신규(모두 새 테이블 → `create_all` 자동 생성, 기존 테이블 무변경이 원칙):
- **`StageProgress`** — 사용자×단계별 숙달/잠금 상태 `(user_id, stage, unit, status, mastery_score, updated_at)`.
- **`ReviewItem`** — SRS 큐 `(user_id, kind, ref, due_at, ease, last_result)`.
- `User`에 트랙 개념 추가(가산 컬럼은 마이그레이션 주의 — 기존 SQLite 테이블엔 `create_all`이 컬럼을 안 넣음; 별도 처리 또는 신규 테이블로 우회).

큐레이션 콘텐츠(신설, DB 아님): **`backend/curriculum.py`** — 입모양 10그룹 레슨, 동구형이음 무리, 최소대립쌍, 예시 단어.

## 6. 자산 재사용 vs 신규

| 재활용(그대로) | 신규 |
|---|---|
| 음운 유사도 채점 엔진(`scoring.py`) | 0단계 배치 + 1단계 입모양 인지 |
| 15 viseme 엔진(`engine.py`) + 3D 아바타(`visemeShapes.js`) | 2단계 큐레이션 단어(최소대립쌍) |
| LLM 문장/대화 생성(`llm_service.py`) | 숙달·잠금 진행 모델 + DB |
| 취약 입모양 추적(`WeakViseme`) | SRS 복습 큐 |
| 수어 모듈(`sign_service.py`) | 전략 코칭 + closure 드릴 + 대화 채점 |
| 5개 연습 모드 | 트랙 라우팅 + 오늘의 학습 UI |

## 7. 구현 단계

1. **Phase 1 — 척추:** 배치 + 1단계 입모양 인지(아바타 재활용) + 숙달 잠금. *(구멍 가장 큰 곳을 가장 싸게)*
2. **Phase 2 — 하단:** 2단계 큐레이션 단어 + SRS 복습.
3. **Phase 3 — 상단·트랙:** closure 드릴 + 대화 채점 + 트랙 B 수어 앵커링 + 전략 코칭.
4. **Phase 4 — 지능화:** 적응형 난이도 + 다듬기.

## 8. 입모양 인지(1단계) 교육 원리 — 참고

- **모음(2·3·4·5·9)이 가장 잘 보이는 '닻'** — 문장 뼈대를 여기서 잡는다.
- **양순음(1: ㅂ/ㅃ/ㅍ/ㅁ)** = 입술 닫힘. 잘 보이지만 **서로 구별 불가**(동구형이음).
- **입 안쪽 자음(6 치경·7 연구개·8 성문·10 경구개)** = 겉모습 거의 동일 → **문맥 필요**.
- 이 "무엇이 보이고 무엇이 안 보이는가"를 명시적으로 가르치는 것이 1단계의 목표.
