# 한글 → 한국수어(KSL) 번역 모듈 — 설계 논의 문서 (draft)

> 설계안. (K-AI 콘텐츠 공모전 "개발과정" 근거자료 겸용)

## ✅ 범위 확정 (2026-07-13)

논의 결과 아래로 확정한다(근거: [수요 인용문헌](sign-translation-references.md)):
- **LIPLAB 내부 학습 보조 모듈**로 한정. (범용 웹 번역기/브라우저 확장 → **범위 밖.** 시장이
  이미 이큐포올·KLcube 등으로 채워져 있고, 개인 임의-웹 수요 미입증 + 농인 검토자 부재)
- 렌더링 = **국립국어원 실제 수어 영상(딥링크) + LIPLAB 입모양(viseme) 아바타 시너지.**
  **자체 3D 손동작 아바타는 범위 밖**(단어별 모션 데이터 없음 → 수년·그래픽스 규모, 저품질 리스크).
- 포지셔닝 = **"학습·이해 보조(베타)"**. *통역* 아님, 인간 통역사 대체 주장 안 함.

## 0. 왜 필요한가 (문제 정의)

선천적 농인 상당수에게 **한국어는 사실상 제2언어**이고, 1차 언어는 한국수어(KSL)다.
따라서 "한국어 텍스트"만 제공하는 학습·정보 도구는 이들에게 접근성이 떨어진다.
LIPLAB이 한국어 문장을 **수어로도** 보여주면, 독화(입모양) 학습과 **상호보완**된다:

- 독화(기존 핵심): 한국어를 **입모양으로** 읽는 능력 훈련.
- 수어 번역(신규): 같은 문장을 **1차 언어(수어)로** 이해 → 학습 부담 완화·이해 보조.

---

## 1. 핵심 전제 — 이건 "치환"이 아니라 "번역"이다

한국수어는 한국어를 손으로 옮긴 것이 아니라 **문법이 다른 독립 언어**다.

| 한국어 | 한국수어(KSL) |
|---|---|
| 조사(은/는/이/가/를) 있음 | **조사 없음** |
| SOV, 문어 어순 | **주제-설명(topic-comment), 시간·장소 선행** 경향 |
| 선형(단어 나열) | **공간·동시성** 문법(위치·방향·분류사) |
| — | **비수지 표지**(얼굴 표정·눈썹·입모양)가 문법의 일부 |

예) "학교에 안 갔어요" → KSL 근사 gloss: `학교 / 가다 / 아니다(부정)` (+부정 표정)

그래서 **완벽한 KSL 통역은 학계 미해결**(KoSign/NIASL2021 병렬 말뭉치, SLTAT 워크숍
등 활발한 연구 단계). 우리가 목표할 현실적 수준을 명확히 정의하는 것이 이 문서의 핵심이다.

### 목표 충실도(합의 필요)
- ✅ **하는 것**: 문장별로 조사 제거 + KSL 어순 재배열 + 지문자 처리 + 비수지 표지 주석을
  거쳐 **실제 수어 영상 시퀀스**로 변환. (= 문장마다 다르게 "번역"됨. 하드코딩 아님)
- ⚠️ **한계(정직)**: 고립 사전영상 이어붙이기는 유창한 KSL이 아니라 **"수지한국어에 가까운
  근사"**. 공간·동시성·매끄러운 전환은 재현 못함 → UI에 **"AI 수어 번역(베타)"** 라벨 필수.
- ❌ **안 하는 것**: 인간 수어통역사 대체 주장 금지. "이해·학습 보조 도구"로 포지셔닝.

## 2. 시스템 아키텍처 (2단계, 둘 다 실제 처리)

```
한국어 문장
   │
   ▼
[Stage A] 언어 번역 (Claude API)   ← 이 앱이 이미 쓰는 LLM 확장
   │   · 형태소 정규화 → 조사 제거
   │   · KSL 어순 재배열(주제-설명, 시간/장소 선행)
   │   · 부정·의문·수량 처리
   │   · 사전에 없는 고유명사/외래어 → 지문자(지화)로 표시
   │   · 비수지 표지(표정/입모양) 주석
   ▼
수어 gloss 시퀀스 (JSON)  예: [{sign:"학교"},{sign:"가다"},{sign:"아니다",nmm:"부정표정"}]
   │
   ▼
[Stage B] 시각화 (실제 수어 자원)
   │   · gloss 단어 → 국립국어원 한국수어사전 영상 URL 매칭
   │   · 매칭 실패(OOV) → 지문자 자모 시퀀스로 합성 재생
   │   · 순차 재생 + 자막(한국어 원문/gloss) 동시 표기
   ▼
수어 영상 플레이어 (웹)
```

### 왜 이 구조가 "실제 번역"인가
- **Stage A**가 문장마다 KSL 문법으로 **실제 변환**한다(정해둔 매핑표가 아님). 이 앱이 이미
  시나리오 생성에 Claude를 쓰므로 자연스러운 확장이고, "LLM을 통역 엔진으로" 쓰는 서사가
  대회에서 강점이 된다.
- **Stage B**는 **국립국어원의 실제 농인 수어 영상**을 재생한다. 어설픈 자동 아바타보다
  정확하고, 농인 커뮤니티에 대한 존중 측면에서도 낫다.

## 3. Stage A 상세 — Claude 한국어→수어 gloss 번역

### 설계 결정 ①: gloss는 "영어 라벨"이 아니라 **한국어 표제어 시퀀스**로 출력
이유: Stage B의 영상 사전이 **한국어 대응표현(표제어)으로 색인**돼 있다. 그러니 Claude가
KSL 어순으로 재배열한 **한국어 기본형 단어 열 + 지문자 표시**를 내면, 그대로 사전을 조회할 수
있다. (영어 gloss로 내면 다시 한국어로 되돌리는 손실이 생김)

### 출력 스키마(안)
```json
{
  "source": "학교에 안 갔어요",
  "gloss": [
    { "type": "sign", "word": "학교" },
    { "type": "sign", "word": "가다", "negate": true },
    { "type": "nonmanual", "marker": "부정", "note": "고개 젓기 + 부정 표정" }
  ],
  "notes": "부정은 서술어 뒤 '아니다/못하다'로도 표현 가능",
  "confidence": "medium"
}
```

### 프롬프트 설계 포인트
- KSL 문법 규칙을 시스템 프롬프트에 명문화(조사 제거 / 시간·장소 선행 / 부정·의문 후치 /
  수량 표현 / 분류사 개념).
- **AI Hub 수어 병렬 말뭉치**의 (한국어 ↔ 수어문법 문장) 쌍 일부를 **few-shot 예시**로 삽입해
  근거 강화. (재배포 아님, 프롬프트 내 참고용)
- 고유명사/사전 미등재어는 `{type:"fingerspell", chars:["ㄱ","ㅣ","ㅁ"...]}`로.
- **자기평가 필드(confidence)**를 강제해, 낮으면 UI에서 "확인 필요"로 표시(정직성).

### 리스크
- LLM gloss 품질이 문장 난이도에 따라 편차. → 도메인을 **일상생활 문장(앱의 기존 시나리오)**로
  좁히면 품질↑. 평가셋으로 관리(§6).

## 4. Stage B 상세 — gloss → 실제 수어 영상

### 데이터 소스 (조사 완료)
| 소스 | 제공 내용 | 접근/라이선스 |
|---|---|---|
| **국립국어원 한국수어사전** (sldict.korean.go.kr) | 표제어별 **수어 동영상**·수형사진·수형설명 | 웹 공개. 통합 수어정보 **API가 영상/이미지 경로 URL 제공** (공공데이터포털 활용신청) |
| **공공데이터포털 한국어대응표현정보** | 표제어↔수형설명·결합정보(텍스트) | 파일데이터(공공누리, 출처표시) |
| **AI Hub 수어 번역 데이터셋** (KoSign/NIASL2021) | 한국어↔수어문법 문장, 형태소, **비수지(표정)** 정보 | 승인 필요. few-shot 참고용으로만 |

### 설계 결정 ②: 매칭 전략
1. gloss 단어 = 사전 표제어 **정확 일치** 조회 → 영상 URL.
2. 실패 시 **기본형/동의어** 재시도(예: "갔어요"는 이미 A단계에서 "가다"로 정규화됨).
3. 그래도 실패(OOV·고유명사) → **지문자(지화) 폴백**: 한글 자모를 지화 이미지/영상으로 순차
   합성. (지문자 세트는 유한하고 표준화돼 있어 자체 제작·확보 가능)

### 설계 결정 ③: 재생·자막
- 영상 클립을 순차 재생하되, **각 클립 아래 한국어 원문 어절 + gloss를 동시 표기**(학습 보조).
- 속도 조절(기존 LipSyncPlayer3D의 0.5x~2x 컨트롤 재사용 가능).

### 리스크(가장 큼)
- **B단계는 국립국어원 API 키 발급·영상 URL 임베드 가능 여부에 의존**. 여기가 확정돼야
  "실제 영상 번역"이 성립. → 착수 시 **가장 먼저 실측**할 항목.
- 사전 표제어 커버리지: 일상 어휘는 양호하나 신조어·고유명사는 지문자 폴백에 의존.

## 5. 기존 앱과의 통합 & 시너지

- **백엔드**: `llm_service.py`에 `translate_to_ksl_gloss(text)` 추가(Claude 호출). 신규
  엔드포인트 `POST /api/sign/translate`.
- **프론트**: 신규 페이지 `/sign` 또는 학습 화면에 "수어로 보기" 토글. `SignPlayer` 컴포넌트
  (영상 시퀀스 + 자막). 기존 재생 컨트롤 UX 재사용.
- **🔗 차별화 시너지(Phase 2 후보)**: 수어에 동반되는 **입모양(mouthing)**을 이 앱이 이미 가진
  **viseme 아바타**로 함께 표시 → "수어 + 입모양"을 한 화면에. 독화 모듈과 수어 모듈이
  기술적으로 연결되는 지점(대회 서사에서 강력).

## 6. 정직성·윤리·평가 (대회 심사에서 중요)

- **라벨링**: "AI 수어 번역(베타) — 학습·이해 보조용, 공식 통역 아님" 상시 표기.
- **농인 검증**: 가능하면 **원어민 수어 사용자/농인 검토자**가 샘플 출력을 검수 → 신뢰도·
  윤리 양면에서 결정적. (섭외 가능 여부 확인 필요)
- **평가셋**: 일상 문장 30~50개에 대해 (a) gloss 어순 정확도 (b) 사전 매칭률 (c) 지문자 폴백률을
  측정해 문서화. 완벽을 주장하지 않고 **측정된 한계**를 제시하는 게 더 신뢰를 준다.

---

## 7. 단계별 계획(안)

- **Phase 0 (실측)**: 국립국어원 수어 API 키 발급 + 영상 URL 재생 가능성 검증. ← 가장 먼저.
- **Phase 1 (Stage A PoC)**: Claude 한국어→gloss 번역 + 자기평가. 외부 의존성 0, 즉시 데모.
- **Phase 2 (Stage B)**: gloss→사전 영상 매칭 + 지문자 폴백 + 플레이어/자막.
- **Phase 3 (통합·평가)**: 앱 통합, 평가셋 측정, (선택) 입모양 시너지, 개발일지 기록.

## 8. 지금 합의가 필요한 열린 질문

1. **데이터 접근**: 공공데이터포털/AI Hub 계정(내국인 인증 필요)으로 API 키·데이터셋 신청
   가능한가? (Stage B와 few-shot 근거가 여기 달림)
2. **농인/수어 사용자 검토자** 섭외 가능 여부? (신뢰도의 핵심)
3. **도메인 범위**: 앱의 기존 일상생활 시나리오로 좁힐까, 자유 문장까지 볼까? (좁을수록 품질↑)
4. **위치**: 독화 핵심 기능에 **추가되는 보조 모듈**로 보는 게 맞나? (상호보완 전제)
5. **충실도 라벨**: "수지한국어 근사(베타)"로 정직하게 갈지, 표현 문구 조율.
