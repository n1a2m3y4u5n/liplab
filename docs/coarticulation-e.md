# 선행 동시조음 (3D 모션 E): 설계와 파드 검증 계획

작성 2026-09-29. 1~4절은 측정을 돌리기 전에 적었다(사전 등록). 파드 결과는 6절에 덧붙인다.

## 1. 문제

엔진(`backend/engine.py`)은 음소마다 입모양 프레임을 내고, 아바타(`frontend/src/lib/visemeShapes.js`)는 입모양마다 고정된
모프 목표를 쓴다. 입 안쪽에서 조음하는 자음(치경 6, 연구개 7, 성문 8, 경구개 10)과 받침 뒤 전환 프레임(12·13)은 입술이
할 일이 없는데도 모음과 상관없이 같은 입술 모양이다. 예를 들어 '수술'은 [6, 4, 6, 4, 6]이라 둥글림(funnel+pucker)이
0 → 1.10 → 0 → 1.10 → 0으로 다섯 번 오르내린다. 실제 화자는 ㅅ·ㄹ을 내는 동안에도 입술을 둥글게 둔다(선행·잔류 입술
동시조음). 아바타가 실제 화자에게 없는 단서를 가르치고 있다.

## 2. 설계

- 대상 프레임: 입모양 6·7·8·10과 전환 12·13. 받침 프레임은 평파열음화 뒤 1·6·7뿐이라 6·7이 여기에 들고, 양순 1과 양순
  전환 11은 입술을 닫아야 해서 뺀다.
- 섞을 모음: 같은 단어 안의 다음 모음(선행). 쉼(14)·중립(15)을 넘지 않는다. 다음 모음이 없으면(단어 끝 받침) 앞 모음을
  잇는다(잔류). 이중모음은 엔진이 활음 프레임(ㅘ: 원순 4 → 개방 2)부터 내므로 앞 자음은 활음의 원순을 미리 만든다. 정지
  모양 9는 엔진이 더 내지 않지만 들어오면 원순 4로 섞는다.
- 섞는 모프: 입술 둥글림·당김(`mouthFunnel`, `mouthPucker`, `mouthSmile*`, `mouthStretch*`)만. 턱(`jawOpen`, 턱 뼈 각도)과
  벌림(`mouthUpperUp*`, `mouthLowerDown*`), 양순 폐쇄(`mouthClose`, `mouthPress*`, `mouthRoll*`), 혀는 자음 값 그대로 둔다.
- 섞는 식: 모프마다 max(자음 값, (1 − w)·자음 값 + w·모음 값). 모음이 더 크게 쓰는 모프만 차이의 w만큼 늘고, 자음 자기 입술
  모양(경구개 10의 살짝 내밂·당김)은 줄지 않는다. w는 0.6(0.5~0.7 가운데 잠정값), 가상 화자의 동시조음 강도 `coart`를
  곱하고 0.85에서 자른다(화자 0.42~0.78).
- 서명: 프레임의 `viseme`은 바꾸지 않고 `coart_v`(섞을 모음)만 붙인다. 입모양 열 서명(`content_rules.word_visemes`), 채점,
  약점 기반 감속(입모양으로 고름)은 달라지지 않는다.
- 성능: `coart_v`는 프레임을 받을 때 한 번 붙인다(`applyCoarticulation`, 가상 화자 타이밍 변환 뒤). 섞은 모양은 화자별 모양 표마다
  (자음, 모음, w) 조합으로 한 번 만들어 캐시하고, 아바타는 입모양이 바뀔 때 한 번 읽는다. 화면마다 하는 일은 지금과 같다.
- 플래그: `VITE_COART_E=1`로 빌드할 때만 켜진다(`frontend/src/lib/coarticulation.js`의 `COART_E_ENABLED`). 5절의 파드 확인을
  통과하기 전까지 기본은 끔이다. 적용 화면은 프레임 열을 재생하는 `LipSyncPlayer3D`·`MouthAvatar`(단어·문장)이고, 입모양 하나를
  되풀이하는 1단계 순환(`visemeCycle`)은 이웃 모음이 없어 해당이 없다.

## 3. 판별 기준 (d) (단위 테스트)

가상 화자 판별 기준(`docs/talker-variation.md` 7절, `talkers.test.mjs`) (a)(b)(c)는 기본 목표만 보므로 켜고 꺼도 같다. 섞은
모양에는 새 기준 (d)를 둔다.

- 대상: 기본 화자와 가상 화자 6명, 자음 c ∈ {6, 7, 8, 10, 12, 13}, 모음 V ∈ {2, 3, 4, 5}(엔진이 내는 모음).
- 섞은 모양 B(c, V)에서 가장 가까운 기본 목표가 입 안쪽 무리 6·7·8·10(전환 12·13은 7절의 허용 무리도), 섞은 모음 V,
  또는 V와 같은 원순 무리(4·9) 가운데 하나여야 한다. 문맥에 없는 제3의 퀴즈 입모양처럼 보이면 안 된다는 뜻이다.
  전환 12·13은 입 안쪽 자음으로 가는 사이 모양이고 입 안쪽 무리는 (b)에서 서로 가를 수 없는 한 무리라 무리 전체를 허용한다.
- 여백은 (a)~(c)와 같게 잰다(허용 밖 최소 거리 − 허용 안 최소 거리, 모두 0보다 커야 통과).
- 섞는 식을 고른 근거: 자음 입술 모양까지 그냥 섞으면((1 − w)·자음 + w·모음) '자'의 ㅈ(10←2)이 입술 모양을 잃어 중설모음 5에
  가장 가까워진다(기본 화자 포함 7명 모두). max 방식에서는 모든 조합이 통과한다. 테스트가 두 방식을 모두 확인한다.

## 4. 파드 검증 계획 (사전 등록)

목적: 켠 아바타의 입술 궤적이 실제 화자의 입술 궤적에 더 가까운지 본다.

- 데이터: AI Hub 538(OLKAVS) 정상 화자 문장 클립, 정면(클립 이름의 촬영 방향 A)만. 화자마다 최대 12개(시드 0으로 섞어 고름).
  화자 절반은 지금까지처럼 `crc32(화자 ID) % 2`로 나눈다. 절반 0에서 탐색하고 절반 1에서 확인한다.
- 실제 궤적: MediaPipe FaceLandmarker(`face_landmarker.task` float16/1, VIDEO 모드, CPU)로 영상 프레임마다 블렌드셰이프를 뽑는다.
  둥글림 R = `mouthFunnel` + `mouthPucker`, 당김 S = (`mouthSmileLeft` + `mouthSmileRight` + `mouthStretchLeft` + `mouthStretchRight`)/2,
  벌림 J = `jawOpen`. 얼굴을 찾지 못한 프레임은 뺀다. 발화 구간(첫 음절 시작 0.15초 전 ~ 끝 음절 끝 0.15초 뒤)에서 얼굴을 찾은
  비율이 0.8 미만이거나 남은 프레임이 15개 미만인 클립은 뺀다.
- 음절 시각: 자체 정렬기(`backend/models/dgop_ours/aligner`)의 CTC 강제정렬(`dgop_acoustic.align_targets`)로 자모 토큰(초성·중성·
  종성) 시작 시각을 얻는다. 음절 수가 엔진과 다르면 그 클립은 뺀다(538·확장 문장 2,040개에서는 0건).
- 아바타 궤적: `engine.text_to_visemes`의 프레임을 정렬 시각에 놓는다. 초성·중성·종성 프레임은 해당 토큰 시작, 이중모음 둘째
  프레임은 중성 구간 35% 지점, 전환 프레임은 다음 음절 55ms 전(종성 구간 절반 뒤보다 앞서지 않게), 단어 사이 쉼은 앞 음절 끝에서
  시작하되 다음 음절까지 80ms 미만이면 뺀다. 정렬에 없는 앵커는 음절 안 비율로 채운다. 그 위에 아바타 전환 규칙(AvatarVRM:
  `transition_ms` 동안, 프레임 길이 60% 안, easeInOutCubic)을 그대로 흉내 내 영상 프레임 시각에서 R·S·J를 읽는다. 입모양 표와
  섞기 규칙은 앱이 쓰는 원본을 `scripts/viseme_shapes.json`으로 내보내 같이 쓴다(파이썬 이식은 표본 6개로 자체 확인).
- 조건: 끔, 켬 w = 0.5·0.6·0.7(기본 화자).
- 지표: 클립마다 아바타 궤적과 실제 궤적의 Pearson r(특징별). 화자마다 클립 r의 Fisher z 평균, 화자 평균을 다시 r로 돌린 값을 r̄로
  쓴다(화자 같은 무게). Δ = r̄(켬) − r̄(끔), 두 조건 모두 r이 정의된 클립만 쓴다.
- 탐색(절반 0):
  - 지연 L: 영상과 음성 사이 어긋남을 −132~+132ms(33ms 간격)에서 끔 조건의 J 상관이 가장 큰 값으로 고른다. J는 동시조음이
    바꾸지 않아 두 조건에 중립이다.
  - w: Δ_S ≥ −0.02, Δ_J ≥ −0.02를 지키는 w 가운데 Δ_R이 가장 큰 값.
- 확인(절반 1, 고른 L·w 하나만): Δ_R ≥ 0.05이고 Δ_J ≥ −0.02, Δ_S ≥ −0.02면 통과. 화자 재표집(2,000번, 시드 1) 95% 구간을
  함께 적는다(판정에는 쓰지 않는다).
- 전제 확인(서술, 판정 아님): 대상 자음 구간의 실제 둥글림(클립 안 z 점수)이 다음 모음이 원순(4)일 때와 아닐 때(2·3·5) 얼마나
  다른지 화자 평균으로 적는다. 실제 화자에게 선행 둥글림이 있으면 양수여야 한다. 같은 값을 끔·켬(0.6) 아바타에도 적는다.
- 조치: 통과하면 플래그를 기본 켬으로 바꾸고 `COART_W`를 고른 w로 바꾼 뒤 `node scripts/export_viseme_shapes.mjs`를 다시 돈다.
  불통과면 끈 채 두고 결과를 6절에 적는다.
- 한계:
  - J는 구현상 켬·끔이 같아 Δ_J는 0이다. 턱을 건드리지 않았는지 확인하는 구실이다.
  - MediaPipe 블렌드셰이프와 아바타 모프는 척도가 달라 값이 아니라 상관만 본다.
  - 정렬 앵커는 CTC 구간이라 뾰족하고(한두 프레임), 없는 앵커는 비율로 채운 추정이다. 두 조건에 똑같이 들어간다.
  - 정면 촬영만 쓴다. 입술 돌출은 옆에서 더 잘 보이지만 MediaPipe 블렌드셰이프는 정면 영상에서 가장 안정적이다.
  - 앱 재생 속도(프레임 길이 하한 120ms 등)가 아니라 실제 말 속도로 놓고 비교한다.

## 5. 실행

```bash
# 파드. 저장소 backend·scripts와 538 클립(mp4와 같은 이름의 wav·flac, manifest.tsv)이 있어야 한다.
# /workspace/c538에 mp4가 없으면 로컬 ~/Downloads/liplab_gpu_snapshot/expand538_more(클립 1,740개, 629MB)를 올려 --root로 준다.
pip install mediapipe==0.10.14 opencv-python-headless
curl -L -o /workspace/face_landmarker.task \
  https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task
python scripts/coart_pod_eval.py --root /workspace/expand538_more --out /workspace/out/coart_e_smoke \
  --face-model /workspace/face_landmarker.task --limit 3 --workers 1      # 먼저 3개로 MediaPipe·정렬기 경로 확인
python scripts/coart_pod_eval.py --root /workspace/expand538_more --out /workspace/out/coart_e \
  --face-model /workspace/face_landmarker.task --workers 8
```

결과는 `<out>/summary.json`(탐색 표, 확인 Δ와 판정)과 `<out>/clips.jsonl`(클립별 r·구간)이다. MediaPipe 결과는 `<out>/cache/`에
남아 다시 돌리면 영상 처리를 건너뛴다.

로컬 스모크(9/29, 맥): 맥의 mediapipe 파이썬(1.0.1)은 CPU로 고정해도 얼굴 검출에서 Metal 오류로 죽고(liplab-lab
`extract_blendshapes.py`에 적힌 것과 같다) torch가 없어 정렬기도 못 돌린다. 그래서 `--align uniform --face stub`(음절을 발화
구간에 고르게 놓고, '실제' 궤적을 켬 0.6 흉내에 잡음을 더해 만듦)으로 3클립(화자 3명)을 돌려 배관만 확인했다. 오류 0, 지연 0ms가
골라지고 Δ_J = 0, 켬의 Δ_R이 양수로 나와 분석 경로가 켬 쪽 향상을 잡는 것을 확인했다. MediaPipe와 정렬기 경로는 파드의 3클립
실행으로 확인한다.
