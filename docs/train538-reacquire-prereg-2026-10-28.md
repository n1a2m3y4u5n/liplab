사용자 결정(10/28): 없어진 모델 학습 자료를 AI Hub 538에서 다시 받는다. 근거 계획표는 `out/data-reacquire-2026-10-28.md`이다
(그 문서의 '71479·71683·71663 로컬만'은 10/28 정정으로 해외 처리 가능, `docs/decisions-2026-10-27.md`).

## 1. 목적과 범위

- 우선순위: ① V3 재적합용 538 정면 자료(D) → ③ V1 계열(V17·ROI 공용) → ⑦ 음성→블렌드셰이프 짝. 세 용도 모두 **같은 클립**을 쓴다.
  화자당 정면(A) 문장 클립 30개(30fps mp4 + 16kHz wav)를 받으면 ①은 그중 12개(V2 규칙), ③은 30개 전부, ⑦은 같은 클립의 음성을 쓴다.
- **옛 75명(V2 `sel.json`, sha256 3f73ba0b…)을 복원한다고 주장하지 않는다.** `sel.json`·`spkmap538_full.tsv`·`queue_v1.tsv`가 이 PC에
  없다. 아래는 같은 원칙(`docs/avatar-v3-2026-10.md` 3절, `docs/v1-data-plan.md` 2~4절)으로 만든 **새 선정 규칙**이다. 같은 배치를
  다시 받더라도 tar 앞부분의 첫 적격 인물이 옛 선정과 같다는 보장은 없다.
- 실제 받기는 이 작업에서 하지 않았다(키 파일을 열지 않음). 오케스트레이터가 예약 작업으로 실행한다.

  인물이 train538에 하나라도 있으면 멈춘다.

## 3. 큐와 분할(미리 고정)

- 큐: 위 제외 뒤 남은 라벨·영상 tar 짝을 배치 번호 순으로 놓고 **하나 건너 하나**(짝수 자리 먼저, 그다음 홀수 자리)로 섞는다.
  중간에 멈춰도 번호 범위 전체에서 고르게 받히게 하는 `v1-data-plan.md` 3절 규칙이다. 10/28 dry-run 결과 **92배치**, 요청 상한
  약 229.6 GiB(영상 1.8 GiB + 라벨 tar 크기 이하). 순서 파일 `out/train538-queue-dryrun-2026-10-28.tsv`(sha256 997cd895…).
- 한 배치 = 한 화자 = 한 인물. 영상 tar 앞 1.8 GiB에서 첫 적격 인물의 정면(A) 완결 mp4를 최대 4개 풀고, 라벨 JSON의 문장 순서로
  최대 30개 클립을 자른다(문장 0.4~12초, 앞뒤 0.08초 여유: `parse_sentences.py` 규칙). 15개 미만이면 실패.
- **V3(①) 분할:** 받은 화자 전부. 절반은 `crc32(spk) % 2`(V2·coart-e와 같은 규칙). 절반 0 = 탐색(표 만들기·설계 선택),
  절반 1 = 확인(판정 한 번). 큐 92배치 기준 43 / 49명. 화자당 클립 12개 선택은 `v2_avatar_validity.py select`(이름순 정렬 후 시드 0 섞기).
- **V1·V17·ROI(③) 평가 화자:** `sha256("liplab-train538-eval:" + spk)`의 앞 8자리(16진수) < 0.30 × 2³²인 화자. 화자마다 정해지므로
  받은 수·순서와 상관없이 바뀌지 않는다. 큐 92배치 기준 30명. 나머지는 학습(검증 그룹은 학습 화자 안에서 d_bench 규칙).
  `v1-data-plan.md` 4절의 '40명'은 이번 큐가 92배치뿐이라 비율 규칙으로 바꿨다. 평가 화자와 문장이 겹치는 학습 문장은 뺀다.
- **V17이 아바타를 판정할 때:** V17 학습에서 V3 확인 절반 화자를 뺀다.
- **⑦ 음성→블렌드셰이프:** 학습 = V3 탐색 절반이면서 V1 평가가 아닌 화자, 확인 = V3 확인 절반.
- 모든 분할은 E2 cohort와 겹치지 않는다(2절에서 배치·인물 모두 뺌).

## 4. 받기 규칙(`scripts/train538_fetch.py`)

- Stream은 `scripts/e2_retry_acquire.py`의 것을 그대로 쓴다: 키 파일 한 줄 규칙, 키는 임시 헤더 파일로만 curl에 넘김, 첫 응답에
  인증 실패·HTTP 401·403·502면 즉시 `AUTH_STOP`, 3분 뒤 평균 512 KB/s 미만이면 `SLOW_STOP`. 그 모듈의 ROOT를 train538 폴더로
  바꿔 임시 헤더·중단 표식·`transfers.jsonl`을 train538 쪽에만 쓴다.
- 요청 횟수: `D:\work\hq\projects\liplab-lab\data\train538\request-counts.json`, **파일당 최대 2회**. 요청 전에 먼저 센다.
  자동 재시도 없음. 실패 화자는 `--retry-failed`를 줄 때만 남은 한 번을 쓴다. Range 헤더를 쓰지 않는다.
- 요청 전마다 `train538\AUTH_STOP`, `e2_538\AUTH_STOP`(E2와 같은 파일, 읽기만), `train538\SLOW_STOP`이 있으면 멈춘다.
- 동시 연결: 538 서버로 가는 curl(E2 포함)이 2개 이상이면 1분씩 기다린다. 이 스크립트는 연결 하나만 쓴다.
- 양보: 시작할 때 E2 `transfers.jsonl` 최근 5건(60초 이상)의 평균 속도가 기준. 화자를 하나 마칠 때마다, 시작 뒤 새로 생긴 E2 전송
  최근 3건의 평균이 기준의 70% 미만이면 `TRAIN_YIELD`를 남기고 30분 기다린 뒤 다시 본다. 그동안 새 E2 전송이 없거나 회복되면 이어 받는다.
- 디스크: D: 여유 60 GB 미만이거나 C: 여유가 영상 상한 + 2 GiB 미만이면 시작하지 않는다(`status: disk_low`).
- 위치: 임시 원본 `C:\liplab-raw\train538\<spk>\`(화자마다 지움), 클립·메타 `D:\work\hq\projects\liplab-lab\data\train538\`
  (`clips\`, `manifest.tsv`, `manifest_meta.tsv`, `state.json`, `download.log`). 다시 실행하면 끝난 화자는 건너뛴다.
